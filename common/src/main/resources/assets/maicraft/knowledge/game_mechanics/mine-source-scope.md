# mine 源查询的公平语义与探矿授权（可见范围、生成带与保留意见）

acquire_items 的 mine 源族从**即时可见或先前见过的源**开始；不会从区块索引直接瞄准未知埋藏矿。安装 FTB Ultimine 且原生允许时，可以沿服务器实际展示的完整矿脉选区连锁采集，包括相连的埋藏矿。需要主动开路找矿时使用 `allow_prospecting`。

## 规则

- 候选源必须过公平闸：**即时可见 ∨ 观察记忆里见过**。见过一次的位置会被记住（随世界状态持久），之后重新被遮挡仍可挖；从未见过的埋藏矿不进目标集。
- 公平扫描空手时，回执是诚实的"范围内无可用源"，且不泄露被遮挡候选的数量、位置或存在暗示——没看到就没有这份数据。
- 原生整脉选区中的每格仍须属于请求材料和搜索范围，并遵守明确保护、工具与原生限制。预览不是完成证明：原生可能只挖掉部分选区，任务核对实际方块和背包变化后继续。FTB 把整批掉落集中在触发块，采矿会在那里收取。
- `allow_prospecting=true`（默认 false）：公平扫描空手后，向该物品的**已知自然生成带**开路（内置推荐值如钻石 -59、铁 16、铜 48、煤 96），到层后沿水平方向找矿。下降使用 FTB 原生 `mining_tunnel`，水平使用 `small_tunnel`；方向取实际命中面，竖向点击的下降形状沿角色水平朝向。
- 正常角色下降阶梯需要三格通行高度，水平通道需要两格；这是身体扫过的空间条件，不是固定挖三次或两次。原生线段遇矿物或不同材料中断后，重新选择剩余障碍与命中面补齐，完整断面和实底连续成立后才行走。没有原生连锁、选区超出许可或余量不足时，松开连锁键再逐格补齐。
- 表内没有该物品、或生成带在另一个维度时，探矿**如实拒绝**：没有生成带证据就猜一个下降深度，等于把透视伪装成探索。授权打开但探不成的回执会写明原因。
- 未授权（默认）：维持公平空手行为，不下降也不掘进——想要"挖着找"必须在同一次提交里带上授权位。

## 这个规则会怎么坑你

- 把"公平扫描空手"误读为"世界上没有这种矿"：它只覆盖已加载且过闸的范围；未加载区块与更深地层不构成"不存在"的证据，扩半径、换位或开探矿都可能改变结果。
- 地表提交 `acquire diamond` 不带授权，会得到诚实的空手回执——深层矿从未进过你的视野，也不该有；带 `allow_prospecting=true` 重新提交才走下降加掘进。
- 授权不是深度参数：模型无法指定"挖到 y40"；若目标物品没有已知生成带（表外物品），探矿会拒绝而不是照挖。
- 先用 `find_block` 定位的矿：命中坐标随回执携带（过视线闸的公平可知事实），可直接喂给 travel 作 destination，或 harvest_block 单点采收（需 `may_alter_terrain=true`，且该方块此刻仍是已加载的、匹配 block_id 的无方块实体实体方块）；被 find_block 看见过的矿同时进了 mine 的观察记忆，再次提交 mine 时它属于"见过的源"。

## 边界

就绪语义不变：观察快照 `query_complete: false` 时索引尚未就绪，不得得出"范围内无源"的结论；回执携带扫描中心、半径和索引就绪状态。`ultimine_actions` 完整保留原生选区的实际变化、未挖格及未知项；`prospecting.blocks_dug` 单独统计开路方块，材料完成数量仍按实际背包增量。预算包含下降断面和到层后的水平开路，耗尽时如实停止，不虚构剩余储量。
