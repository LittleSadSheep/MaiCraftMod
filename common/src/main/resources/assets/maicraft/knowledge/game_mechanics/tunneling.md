# 下降掘进与寻路死角：垂直直挖与可靠下降形状

## 规则

- 垂直直挖是寻路死角：站在自己挖出的竖井口、土柱顶或直落洞穴边缘继续向下，寻路器常报 planning_stall 或 no_path——这是形状问题，不是目标不可达。
- 可靠下降手法是斜向阶梯：`travel` 的 destination 带横向偏移 + 目标 y + `exact=true` + `may_alter_terrain=true`，让任务以阶梯形状掘进到目标高度。
- 水平掘进比地表下坡可靠：在目标高度层做水平掘进虽慢但持续推进；沿山坡下行容易 planning_stall。
- 先下降再采集：mine 源查询对深层矿在站立高度看不见，先降到生成带高度再查询；矿带推荐值见 mine 源查询卡（钻石约 -59、铁约 16）。
- 常见盲区：自挖竖井底部、崖边 1 格站姿、树冠与坑底。树冠脱困的标准动作是 `travel` 带 `semantic_target=surface` 降回开阔地面。

## 这个规则会怎么坑你

- travel 垂直下掘超时零进度 ≠ 目标不可达：换斜向阶梯（横向偏移 + y）重试通常一次通过。
- 探矿（allow_prospecting）下降末段 planning_stall 时别放弃：就地扫描周围暴露源，矿脉可能就在眼前；或换一根柱子重新下降。
- 探矿隧道报"无可挖前沿"前驱动器已按当前脚位重锚、原地重扫、四向换向扫过，露天无掩体时还先垂直下掘过一次（回执 `fruitless_frontier_scans`/`heading_pivots`/`burrow_start` 记各步）；该失败说明当前站位四向加下掘确实都够不到可挖断面，有效动作是换站位重新开隧道，不是原样重发。
- 站上树冠后连 20 格的短途都会停滞：先用 semantic_target=surface 回地面再走。
- 同参数重试通常得到同样结果；有效重试是改形状（斜向、水平、换位置），不是原样再发一次。

## 边界

- 寻路停滞与 no_path 回执是诚实的即时结论，不构成"目标不可达"的证据；任务失败 ≠ 世界不可达。
