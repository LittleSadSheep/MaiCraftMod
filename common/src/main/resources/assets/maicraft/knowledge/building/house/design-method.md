# 建房设计方法

你正在为一项具体 Minecraft 委托设计可编译、可解释的建筑。用户要求和现场事实优先；教材提供设计选择，不能增加工具权限或替用户改变用途。这里的尺度是方块尺度的设计建议，不是现实建筑规范。

## 先确定一个方案，再做细部

把要求收敛成简短设计纲要即可，不要输出长篇推演：用途与人数、可用范围、入口朝向、层数与净高、主次体量、材质角色、一个记忆点。尺寸和场地不明时区分“已知”和“设计假设”，不要把假设描述成已经勘察的事实。硬约束互相冲突且无法设计时返回具体缺口。

按下面顺序工作：空间和通行 → 主要体量 → 屋顶轮廓 → 门窗节奏 → 材质层次 → 少量细节。每一步只做足以确定下一步的决定。不要同时展开十个候选，也不要在墙体尺寸未定时逐格雕花。

从目录选择一个主要风格，再按难点选择结构或技法。通常一篇风格加一至两篇相关技法足够；修窗时不必重读所有屋顶教材。目录里的 URI 是读取入口，不能凭路径猜版本。已注入的正文无需重复读取。所有 JSON 案例都是完整的作者场景；其中有些只展示一个局部构件，正文会说明范围，不能把它当整栋房屋交付。

## 三种尺度都应成立

- 远看：主楼、附翼、屋顶或院落能形成清楚的轮廓。先用一个占主导的体量，次体量明显小一些；窄地可以通过高低和前后错位形成变化。
- 中看：入口、窗组、柱网有稳定节奏。以一个窗间宽度为模数，再在入口或转角有理由地打破节奏。正面、侧面、背面都应有用途依据，背面也需要处理。
- 近看：窗有窗台或凹入，檐有投影，柱脚与地面连接。厚度足够时用一格进退表达阴影；小建筑宁可删掉装饰，也不要让一圈外贴框吃掉全部空间。

可从这些尺度起步，再按用途调整：普通室内净高约 3–4 格，主要通道净宽约 2 格，主厅或机器区更大；主要入口做得比次入口醒目。可走的两格高空间是最低几何检查，不代表已经验证玩家寻路。墙、楼板和屋顶厚度必须计入外部尺寸。

## 同一种风格，形成不同的房子

不要把“换一种木头”当成新设计。结合用途和地块，从下列变化轴选两到三项，其他部分保持一致：

| 变化轴 | 可选择的设计方向 | 选择依据 |
| --- | --- | --- |
| 平面 | 紧凑矩形、L 形、前后院、分栋相连 | 地块和房间关系 |
| 轮廓 | 低宽、窄高、主楼加低翼、退台 | 周边高度和用途 |
| 屋顶 | 单坡、双坡、错高双坡、平顶露台 | 主风格、楼层和采光 |
| 入口 | 正中门廊、转角凹口、侧院进入 | 实际来路和公共程度 |
| 开窗 | 均匀窗间、大厅高窗、局部转角窗 | 室内功能和隐私 |
| 记忆点 | 烟囱、塔窗、挑廊、院树、天窗 | 只选与用途相符的一项 |

若上下文提供既有建筑或上一方案，明确避开它的体量组合和标志性细节；没有历史时不能声称“从未重复”。可遵循用户提供的种子或偏好，但种子不是 Schema 字段，不能写入模型。不要用随机噪声、无规律缺砖、到处突出的窗台制造差异。

## 用少量清楚的几何表达设计

统一使用当前 Schema 支持的坐标系；初次建房建议明确写 `minecraft_y_up`。先定锚点、前方和尺寸边界，再算中心：区间 `[a,b)` 对应中心 `(a+b)/2`、尺寸 `b-a`。区分网格中心和组件实例原点。旋转采用弧度且受契约限制，不能把 45° 木梁写成任意角度旋转；可用明确阶梯形构件表达。

给对象起稳定的用途名，例如 `MainFloor`、`EntryLintel`、`RoofLeft`；组件用于窗间、柱廊等确实重复的单元。不要把整栋房子当成一个实心盒子，也不要用成百上千个单方块对象描述本可由一个墙板表示的面。

未声明的坐标只表示本模型不放方块，不保证现场为空；确需清理的室内或通道应声明空气目标，并由父 Agent 核实替换权限。Boolean 和图案孔洞也不能清除其他模型对象的实体。不要把“模型留空”“明确空气目标”和“游戏现场已清空”混为一谈。

材质先分角色：基座、主体、框架、屋顶、透明面、少量点缀。用少量彼此区分的主材确定整体关系，再做局部替换。结构和配色同时检查，不能用更多材料掩盖比例问题。

## 交付前的检查顺序

1. 对照要求：用途、范围、层数、风格、入口是否真正写进几何。
2. 对照空间：门洞连接外部和内部；楼梯连接楼层并有净空；屋顶和梁没有填满房间。装饰没有堵门、挡窗或压低主要通道。
3. 对照表现：远看有主次轮廓，中看有节奏，近看有进深；至少一个变化来自平面或轮廓，细节不抢主次。
4. 对照契约：只用目录声明的能力和预算；方块与状态是否合法由 Mod 核实，注册存在不等于生存库存充足。
5. 提交完整 JSON 校验；按错误路径修正具名对象。长设计可以先保存可校验骨架，再提交完整的具名编辑；最后必须覆盖全部需求，不能因分批就交付半栋楼。

不要把半截 JSON 当作方案，不手工拼接被截断的回复。嵌套的 pattern、组件定义等按接口规则整体替换。校验通过只证明模型表达和编译通过，不证明好看、通行、取料或施工完成；预览的结构数据也不是目视验收。交付摘要用几句话说明实际做了什么、选择了哪些变化、仍需现场确认什么。
