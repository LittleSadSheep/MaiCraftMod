# 跟随（maicraft:follow）

像陪着走的玩家那样跟着一位玩家或一个实体，保持几格距离：它走就跟，它停就停。跟随是常驻的，不会自己完成；要停下用 goal 取消。玩家在聊天里说"跟着我"，就用 `player` 填说话人的名字。

## 怎么用

- 目标必填：`player`（一位玩家的名字）或 `seen`（先 `observe` 拿观察编号 e#）。
- `distance` 是保持的距离，单位格（2..16，默认 3）。以它脚下站得住的那一格为准：离这一格超过设定值 +2 格才起步，走进设定值就停，不会在临界距离一步一停；它在头顶飞时站到它正下方就算跟上。
- 它在走时一路换目标点跟着，不走一段停一段；离得远就跑，快追上了放慢，不冲过头撞上去。
- 停着时看着它；它朝角色走过来、或角色挡在它前进的路上，会让到一边。
- 认人按 UUID：编号被重用给了别的东西不会跟错；同一个人死了重生、换维度回来，照样认得。
- 它坐上船或骆驼、或装了机械动力时坐上列车，同一辆上还有空座就走过去坐上；它下来角色也下来。没空座就走路跟。
- 它走进下界门或末地门，角色跟着走进附近的门，过去后在那边找它（只走现成的门，不建门；末地的回程门跟不过去）。
- 它在跟敌对生物打（它刚挨了打、刚挥了手、或身边的怪刚挨了打），角色上去帮它打，打完回来接着跟；只打敌对生物，不打玩家与中立生物。`permissions.fight=self_defense` 时不帮。
- 夜里它不睡，角色也不自己走开去睡；它躺下了，角色才在附近找床睡。
- 要不要为跟过去搭桥挖路，由 `permissions.change_blocks` 表达。

## 跟不过去、跟丢了

这两种情况都不马上结束，先处理，同时发一条 `follow_status` 事件（他在哪、我在哪、发生了什么）：

- 跟不过去：停在原地看着它等，事件里说清为什么过不去、放开 `change_blocks` 能不能过去；它挪开 3 格以上就再试，走得通就接着跟。连续 2 分钟都没跟上，以 UNREACHABLE 结束。
- 跟丢了：分清是怎么丢的——走进了传送门（跟进去）、死了（原地等它回来）、下线了（原地等它上线）、走出视野（去最后看见它的地方，朝它离开的方向看）。30 秒内重新看见就接着跟；找不回来以 TARGET_GONE 结束，写明是哪一种。

坐上它那辆、下车、开始与结束帮打、又跟上了，也各发一条 `follow_status`。角色不因事件停下等回答，想改主意随时取消或换许可重下。

## 结果怎么读

| 字段 | 含义 |
| --- | --- |
| `targetId` | 跟的是谁（类型与实体编号） |
| `keptDistance` | 结束时与目标的距离 |
| `lastDirection` | 最后看到目标在哪个方位 |

常见问题：`TARGET_GONE`（下线、死了、过门后没找到或走远了，30 秒没找回来）、`UNREACHABLE`（连续 2 分钟跟不过去）、`NOT_FOUND`（名字或观察编号对不上）。
