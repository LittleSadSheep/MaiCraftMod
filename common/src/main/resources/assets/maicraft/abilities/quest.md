# quest — 对 FTB 任务书里的一个条目做一次动作

对 FTB 任务书里的一个条目做一次原生按钮动作：`submit` 把身上的东西交给一条"提交物品"的要求，`confirm` 勾选一条手动完成的要求，`claim` 领取一个任务的奖励（选择奖励要用 `choice` 指明选哪个）。编号从 lookup 的任务书资料里拿。只做一次、不自动推进、不替你选奖励；发出去了但任务书没反应会如实告诉你，不会连点。要看任务书的内容用 lookup。

## 参数

| 名字 | 必填 | 说明 |
| --- | :---: | --- |
| `operation` | ✅ | `submit` 交物品 / `confirm` 手动勾选 / `claim` 领奖 |
| `quest` | ✅ | 任务书里任务的编号（16 位十六进制，lookup 的任务书资料里给的） |
| `requirement` |  | 任务里那条要求的编号；`submit`、`confirm` 必填 |
| `reward` |  | 本任务的根奖励编号；`claim` 必填 |
| `choice` |  | 领选择奖励时选哪个候选（Mod 提问时列出的候选编号） |

## 边界与注意

- 本能力不接受 `target`：任务书不在世界里。
- 交什么是你的决定：交物品时身上的东西不够会以 `NEED_ITEM` 结束并写清差多少，不会自动去弄；先 `obtain` 再 `quest`。
- 只交有提交按钮的要求（消耗物品的物品要求、作者开了按钮的自定义要求），只勾手动勾选的要求；观察、击杀、到维度这类自动完成的要求会以 `NOT_POSSIBLE_HERE` 结束，说明这条要求是怎么完成的。
- 奖池里的子奖励不是能单独领的奖励：领奖要给本任务的根奖励编号。选择奖励没给 `choice` 时 Mod 会问你，列出候选与编号，不替你选。
- 任务还不能开始（前置没完成、被屏蔽）时不会白发请求，会带回任务书给的原因（`REFUSED_BY_GAME`）。
- 发出请求后逐刻看任务书与背包：东西少了、进度变了、奖励领了才算数；任务书一直没反应会按"没能确认"收场（结果在 `unconfirmed` 里），不会重发——想确认就等一会儿再看条目。
- 每次只做一个动作：交了又想勾、领完还想领下一个，分多次下达。

## 结果

- 结果细节 `entry` 是动作前后这个条目的样子（每条要求差几件、每份奖励领了没有），`sent` 是请求发没发出去。
- 变化用 `ITEM_CONSUMED`（交上去的）、`ITEM_GAINED`（领到的）记。
