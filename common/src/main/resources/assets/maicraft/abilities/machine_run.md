用一台机器做东西：备料、投料、开机、等产物、收产物，一台机器一次。target 指哪台机器（观察编号、坐标或记过的地点，指它的某一格）。`item` 是要做出什么，不给就只开机；`count` 要做几件；`collect` 要不要把出口的东西拿回背包（默认要）；`max_seconds` 最多等多久（默认 300）。一条生产线上有几台机器就是几次 machine_run，或者用 sequence 排。

## 蓝图桌与蓝图加农炮

这两种机器不按配方投料，整段由机器自己做：

- 蓝图桌：`file` 写游戏目录 schematics 下的 .nbt 文件名（和 build 的 file 同一个目录），`item` 不写或写 create:schematic。角色拿一张空白蓝图放进输入格，照界面上的上传按钮传上去，等输出格出现写着这份文件的蓝图，拿回背包。文件不在、不是压缩过的 .nbt、超过服务器上限时当场说。
- 蓝图加农炮：`file` 写哪份蓝图，`anchor` 写蓝图原点落在哪一格（`{"x":..,"y":..,"z":..}`；蓝图已经摆好时可以不给），`rotation` 转 0 / 90 / 180 / 270 度。身上要有蓝图桌写好的那张蓝图；角色把它摆到原点、放进加农炮的蓝图格，加农炮没火药时放火药，按开动，然后看它放。料从贴着加农炮的箱子里拿。`produced` 是这次放了几格；报完工算完成，卡在缺料（写明缺什么）、没火药、太远、蓝图失效，或一分钟没多放一格、到等待上限都按部分完成收场，加农炮不替它停。
- 自己动手照结构文件施工用 build(file=...)；两条路都行，挑合适的。

## 结果怎么读

- `recipe`：用的配方（类别与注册 ID）和按 `count` 算出的批数；查到多条都能做时用第一条并写明。
- `fed[]`：投进机器的东西与数量；配方要的流体、化学品带不进机器，写进 `notes`，做不做得看机器里还有没有。工作盆、石磨、朝上的锯、粉碎轮只收落到上面的东西，角色站到旁边把料扔上去：`fed[]` 记真进去的件数，落在机器上还没被收走的、落到别处的各在哪写进 `notes`，没进去的不重扔。一件都没落到机器上时按 `NOT_POSSIBLE_HERE` 收场。
- `produced`、`collected`：出口里这次新增几件（开始时已有的不算）、拿回背包几件。
- `machine`：结束时机器的读数与挂着的网络读数。机器在转不、动力够不够这里不预判：照常投料开机，等不到产物时读数会说明原因（转速 0、过载）。
- 没加工完的原料留在机器里不收回，下一次接着用；出口里拿不走的如实写。
- 带界面的机器（通用机械的机器）投料是走过去点开界面，把料搬进去：整堆快速移动由机器自己放进收它的格，只放一部分时拆出这几件放进收它的空格，不往输出格、电池格里塞。
- 等产物期间可以插别的事，回来接着等。

## 问题种类

- `NOT_POSSIBLE_HERE`：查到的配方里没有这台机器做这个的，先 lookup 查它能做什么；或扔的料一件都没落到机器上、机器旁边没有扔得准的站位（只站正挨着它的四格，出手点要比收料的地方高）。
- `NEED_ITEM`：投料要的东西没拿齐。
- `UNSUPPORTED`：这格没有机器类型认领（缺对应模组的联动），或这台机器不收这种料；或出口这里读不到（通用机械的机器格子在界面里；机械动力的石磨产物留在肚子里，锯、粉碎轮做好的东西掉在地上）：料照样投进去，按部分完成收场，做没做好之后用 use 打开它看或到出口那边找。
- `STUCK`：到等待上限或久无新货时出得不够，按部分完成收场，附机器读数。
