# obtain：拿东西

让背包里的某样东西再多几件。火把、木板、铁锭、面包——要"弄到 N 个"都用它，不用管是买是做还是挖。

## 怎么做

角色会像真人一样盘算：

1. 先看身上（主背包与副手）够不够，够了直接完成，一个动作都不用做；
2. 不够就问遍各个来源——记得的箱子和眼前看到的箱子、游戏里真实的配方（合成、烧炼、石切台）、
   96 格内成熟的庄稼（村庄的田也算）、看得见的能挖出它的方块（埋在石头里看不见的不算，不透视；石头例外，见下）、
   附近能做买卖的村民、打掉会掉出它的动物或生物——挑总代价最低的路动手；
3. 做完一个来源就重新清点身上，还缺就重新盘：世界在变，箱子里说不定刚放进了货；
4. 做合成或烧炼缺原料、缺燃料时，会按同一套办法先去弄原料，不会凭空变出来（有防转圈的深度上限）。
   所以要什么直接要成品，不用自己先一步步做中间件：同一样东西有几条配方时（大齿轮既能用传动杆加两块木板，
   也能用齿轮加木板），按身上现有的和最省的挑；原料也按同一套办法挑最近的来源（ME 网络、箱子里有的先拿，不先去砍去挖）。

几条事先定好的做法：

- `via` 给了就只走那条路；备料（原料、工具、燃料）仍然想办法治，不受这条限制。
- 附近没有熔炉（或工作台）时，会在身边就地放一个——这受 `change_blocks` 许可管，放下的位置会记进世界记忆。
- 收庄稼会顺手把种子种回去；种子从这次收获里出，没有就不补，不额外去找。
- 附近没有会掉出 wanted 的方块时（例如铁锭），采掘这条路直接说给不了——铁锭是烧出来的，不是挖出来的。
- 成批砍树、挖石头前先备一把顺手的工具：砍一片树先做石斧，拿木镐挖石头挖够三块就换石镐（要铁镐的矿按铁镐）；身上已有一样快、耐久够的就不备；开局两手空空先徒手砍够做工作台、木镐、木棍的几根木头，再去备。工具只是建议，备不来照样徒手干。
- 挖矿、砍树按批：相邻的同种方块（原木只沿树干竖向）连成一批，要几件挖几格，整批挖完再捡；砍树只砍顶上有树冠的树，玩家用原木搭的东西不拆。附近的方块还没扫完时先等它扫完再下结论，最多等 5 秒。
- 要圆石（或石镐、熔炉要的石头类材料）而附近看不见石头时，从脚下斜着往下挖一段楼梯去找：没镐先备一把，
  每下一级从上往下挖开前面三格再走下去，挖出来的土一并捡起；挖够就停在楼梯底，回地面顺着楼梯走上去。
  前面挨着水或岩浆、下一级脚下是空洞、碰到挖不动或不许动的方块、挖了 32 级还没见到石头，就停在那里如实说。
  要挖天然方块，`change_blocks` 低于 `natural` 时不走这条路。煤、铁这些矿石仍然只挖看得见的。
- 容器只翻记得的和现场看到的；别人的箱子（别的玩家放的、在玩家地盘里的、受保护地标旁的）不翻，自己和自家人（所有者配置的信任玩家）放的照常翻；开了箱以现场为准，记忆可能过时。
- 要水桶：网络里有水（含无限水元件）就拿空桶在终端里装；不然拿空桶去 48 格内的池塘、河、海边舀（`via=fill`），只舀两边都挨着水源、舀了会自己补回来的那一格，刷石机、机器里孤零零的水和刚放的落地水不碰；身上没有空桶先弄一只。
- `via=trade`：和附近已加载的村民或流浪商人买。要花绿宝石这类付款，所以只有点名 `via=trade` 才买，不给 via 时不会自己去买。
  一笔一笔地买，要几件买几件，不会把付款格里的一组绿宝石一口气花光。只有成年、有业的村民开得出交易界面，幼年、无业、傻子的不搭话；
  有名字、拴着绳、圈养着的和记住的玩家地盘里的，是别人的，也不搭话。报价要开了他的界面才知道，
  按界面摆的价买，不还价；缺几件买几件，同一条报价买多了他临时抬价，就换下一条报价或换个村民。
  付款不够时先按同一套办法去凑，凑不到如实结束。付款里是稀有消耗品的报价，照 `use_rare_items` 挡。
  村子在哪归勘察与出行：只跟已经加载的村民交易，附近没有就如实结束，先 `travel` 或 `find` 再来。
- `via=hunt`：打掉会掉出 wanted 的动物或生物，捡走掉落。哪种生物掉什么按写死的原版对照（客户端读不到生物掉落表），
  对照没有的物品打猎直接说没有。候选在已加载、`radius` 内都算（猎物会走动，墙后的羊也是候选），出手前必须看得见才下手；
  幼崽不打（不掉东西）、剪过毛的羊和毛色不对的羊身上没有羊毛、有名字/被驯服/拴绳/圈养的是别人的，都不挑。
  许可逐只判断：动物照 `kill_animals`、不伤人的野生生物同档、敌对生物照 `fight`；一只都不许动时这条来源不参与，写明卡在哪项。
  打倒了就地捡掉落，副产物没收完如实写、不影响这一单；打了一只没见到要的东西换下一只，概率掉落（兔子脚这类）多试几只再下结论。
  附近没有候选时：给了 `max_distance` 就按它出去找，走到一片再看一片；没给就如实结束，不带身体进没有上限的搜索。
- 随身背包是身上的仓库（装了精妙背包才有）：要的东西包里可能就有，开包取出来就算拿到，`details.obtained_via` 记 `carried`，
  不另立途径。问价按上次开包读到的存货（本次启动内，五分钟内算数）报明确数量；没读过报"包里可能有，不知道有多少"，
  排在数量明确的来源后面；读数里没有的如实说。执行用模组自己的打开请求开包（玩家按 B 键的那一下），只看主存储
  （升级槽与幽灵槽不算货），按要的量搬进主背包；主背包放不下就停，已取的照算；带无限格升级的背包读数对不上，
  如实说取不了。往包里塞是腾地方的事，不归这里管。

## 结果怎么读

- `status`：`done` 拿够了；`partial` 拿到了一部分（`remaining` 写还差几件）；`failed` 一件都没拿到。
- `changes`：这次实际拿到的数量（`item_gained`）。做合成、烧炼过程中消耗和挖掉的东西也照实记。
- 要的是标签（一类东西）时，`summary` 括号里写拿到的是哪几样、各几个；吃的各补多少、带什么效果，看 `observe` 看自己时 `inventory` 里那一项的 `food`。
- `details.obtained_via`：东西实际从哪些途径拿到的（craft / smelt / container / mine / harvest / trade / hunt / carried），
  按拿到先后排。`count` 是这次再多拿几件，身上原有的不算这次拿到的。
- `problem`：`NEED_ITEM` 时 `attempts` 与 message 写清试过哪些来源、各差多少——缺料、缺台子、
  缺工具、附近已采完，说的是哪一种看 message。概率掉落（例如砾石出燧石）允许方差，会多试几轮才下结论。
- `unconfirmed`：从箱子这类来源点出去了、游戏却没能确认结果的点击，一笔一条写在这里
  （note 写明从哪只箱子拿、要搬几件、当时看到什么）。这些不能盲目重做，也别当成拿到了或没点过；
  备料时嵌套去箱子里拿原料遇到同样的事，也一样交回。

## 参数

| 参数 | 必填 | 说明 |
| --- | :---: | --- |
| `item` | ✅ | 物品 ID 或 `#` 开头的标签；写岔了（不存在的物品、空标签）不进游戏就报 `INVALID_PARAMETER`。要吃的不用一样样点名：`#maicraft:foods/edible` 是"能吃的口粮"一大类（含模组食物；按物品自己的食物组件认，吃了有害的、金苹果这类特殊的不算，生肉算） |
| `count` | | 再多拿几件，默认 1；不设上限，做不完如实 partial |
| `via` | | `craft` / `smelt` / `container` / `mine` / `harvest` / `trade`，联动模组接入的途径装了才有，以参数表列的为准；不给按代价自己挑 |
| `radius` | | 容器与采掘的搜索范围（格），给了就冻结在范围内，上限 64 |
| `max_distance` | | 愿意为此走多远（格）；太远的来源不参与 |
| `prefer` | | 倾向用的材料（物品 ID 或 `#` 标签的列表）：几种做法都行时用到它们的排前面（例如做木板时 `["minecraft:spruce_log"]`），备料时沿配方链往下传；只影响先后，不禁用别的做法 |

拿东西不针对某个东西做动作，所以不带 `target`；范围用 `radius` 与 `max_distance` 表达。
许可（`permissions`）约束容器、就地放工作站、采掘与采集的挖掘，狩猎的逐只判断（`kill_animals` 与 `fight`）。
