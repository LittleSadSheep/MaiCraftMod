# obtain：拿东西

让背包里的某样东西再多几件。火把、木板、铁锭、面包——要"弄到 N 个"都用它，不用管是买是做还是挖。

## 怎么做

角色会像真人一样盘算：

1. 先看身上（主背包与副手）够不够，够了直接完成，一个动作都不用做；
2. 不够就问遍各个来源——记得的箱子和眼前看到的箱子、游戏里真实的配方（合成、烧炼、石切台）、
   成熟的庄稼、看得见的能挖出它的方块（埋在石头里看不见的不算，不透视；石头例外，见下）——挑总代价最低的路动手；
3. 做完一个来源就重新清点身上，还缺就重新盘：世界在变，箱子里说不定刚放进了货；
4. 做合成或烧炼缺原料、缺燃料时，会按同一套办法先去弄原料，不会凭空变出来（有防转圈的深度上限）。

几条事先定好的做法：

- `via` 给了就只走那条路；备料（原料、工具、燃料）仍然想办法治，不受这条限制。
- 附近没有熔炉（或工作台）时，会在身边就地放一个——这受 `change_blocks` 许可管，放下的位置会记进世界记忆。
- 收庄稼会顺手把种子种回去；种子从这次收获里出，没有就不补，不额外去找。
- 附近没有会掉出 wanted 的方块时（例如铁锭），采掘这条路直接说给不了——铁锭是烧出来的，不是挖出来的。
- 挖矿、砍树按批：相邻的同种方块（原木只沿树干竖向）连成一批，要几件挖几格，整批挖完再捡；砍树只砍顶上有树冠的树，玩家用原木搭的东西不拆。附近的方块还没扫完时先等它扫完再下结论，最多等 5 秒。
- 要圆石（或石镐、熔炉要的石头类材料）而附近看不见石头时，从脚下斜着往下挖一段楼梯去找：没镐先备一把，
  每下一级从上往下挖开前面三格再走下去，挖出来的土一并捡起；挖够就停在楼梯底，回地面顺着楼梯走上去。
  前面挨着水或岩浆、下一级脚下是空洞、碰到挖不动或不许动的方块、挖了 32 级还没见到石头，就停在那里如实说。
  要挖天然方块，`change_blocks` 低于 `natural` 时不走这条路。煤、铁这些矿石仍然只挖看得见的。
- 容器只翻记得的和现场看到的；别人的箱子（别的玩家放的、在玩家地盘里的、受保护地标旁的）不翻，自己和自家人（所有者配置的信任玩家）放的照常翻；开了箱以现场为准，记忆可能过时。
- `via=trade` 目前如实回答"交易还没接入"。

## 结果怎么读

- `status`：`done` 拿够了；`partial` 拿到了一部分（`remaining` 写还差几件）；`failed` 一件都没拿到。
- `changes`：这次实际拿到的数量（`item_gained`）。做合成、烧炼过程中消耗和挖掉的东西也照实记。
- `details.obtained_via`：东西实际从哪些途径拿到的（craft / smelt / container / mine / harvest / trade），
  按拿到先后排。`count` 是这次再多拿几件，身上原有的不算这次拿到的。
- `problem`：`NEED_ITEM` 时 `attempts` 与 message 写清试过哪些来源、各差多少——缺料、缺台子、
  缺工具、附近已采完，说的是哪一种看 message。概率掉落（例如砾石出燧石）允许方差，会多试几轮才下结论。
- `unconfirmed`：从箱子这类来源点出去了、游戏却没能确认结果的点击，一笔一条写在这里
  （note 写明从哪只箱子拿、要搬几件、当时看到什么）。这些不能盲目重做，也别当成拿到了或没点过；
  备料时嵌套去箱子里拿原料遇到同样的事，也一样交回。

## 参数

| 参数 | 必填 | 说明 |
| --- | :---: | --- |
| `item` | ✅ | 物品 ID 或 `#` 开头的标签；写岔了（不存在的物品、空标签）不进游戏就报 `INVALID_PARAMETER` |
| `count` | | 再多拿几件，默认 1；不设上限，做不完如实 partial |
| `via` | | `craft` / `smelt` / `container` / `mine` / `harvest` / `trade`，联动模组接入的途径装了才有，以参数表列的为准；不给按代价自己挑 |
| `radius` | | 容器与采掘的搜索范围（格），给了就冻结在范围内，上限 64 |
| `max_distance` | | 愿意为此走多远（格）；太远的来源不参与 |

拿东西不针对某个东西做动作，所以不带 `target`；范围用 `radius` 与 `max_distance` 表达。
许可（`permissions`）约束容器、就地放工作站、采掘与采集的挖掘。
