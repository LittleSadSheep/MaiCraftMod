按机器蓝图在 target 处建一台机器：蓝图落到锚点、逐格施工（缺料自己拿、挡着的挖掉、够不着垫临时方块）、装安装段与部件、改装后设置，建成后记进机器档案。target 是锚点（坐标、脚下、观察编号或记过的地点）；target 指已有档案的名字就是修改——blueprint 是补丁，新声明的格覆盖同位旧目标，范围外旧目标保留，照档案锚点合并施工。operation=remove 拆档案里的整台，target 指档案名，逐格挖掉、档案标为已拆除（蓝图保留，随时可以照着再建）。

## 参数

- `blueprint` / `design_id` 二选一：机器蓝图正文（cells 逐格、parts 部件、installations 安装段、settings 装后设置）或已保存的设计编号；写错的地方一次报全，不进游戏。
- `name`：新机器的档案名；不给就按锚点起"机器@x,y,z"。修改已有档案时不用给。
- `operation`：`build`（默认）或 `remove`。

## 结果怎么读

- 动作成没成（`changes` / `unconfirmed`）、结构对不对（`check`）分开给；机器能不能转不在这里判，用 machine_run 试或 machine_inspect 看读数。
- `check`：整机比对各结论几格；有格没加载时 `check_complete` 为假，不给"整机一致"的结论。
- `installations[]`、`parts[]`、`settings[]`：每段、每个、每条各自做成没有，没做成的带原因；安装段与部件占的格由机器按最终结构核对，不冒充逐格放好。
- 施工子任务失败按它的问题结束，已放的不回滚；补丁已并入档案（存不进档案只记问题，不影响施工）。
- 开始时就已经和蓝图一致 → 完成，一个动作都不做。

## 问题种类

- `INVALID_PARAMETER`：蓝图或参数写法不对，一次报全。
- `NEED_APPROVAL`：有格是玩家的东西或在别人的地盘里，没动；同意拆改把 change_blocks 设为 any 再来一次。
- `NEED_ITEM`：材料用完了，拿到后再下达一次会从没建完的地方接着做。
- `UNREACHABLE`：有格够不着，或档案在另一个维度。
- `UNSUPPORTED`：安装段、部件或设置没有登记的机器联动认领；装了对应模组的联动后再来一次。
