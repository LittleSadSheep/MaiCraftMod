# 术语表

按部分分组。每个词给"游戏里具体指什么"，不给抽象定义。

---

## 信条

| 词 | 意思 |
| --- | --- |
| **发出 ≠ 成功** | 请求发出去了、画面变了、背包里本来有，都不等于任务成功 |
| **投影** | 对外只给必要事实，剔除内部坐标、路线、点击位置 |
| **不确定** | 已提交但没能确认结果；不谎报成功，也不自动重发 |
| **幂等** | 同一件事只做一次（同一个编号重复发来，不会开出第二份） |
| **契约** | 一个能力"声明接受什么参数、有哪些限制"的正式规定 |

---

## ① 入口

| 词 | 意思 |
| --- | --- |
| **公开工具** | 对外的四个入口：`perceive` / `plan` / `execute` / `task` |
| **能力** | 写在 `goal.ability` 里的具体目标，例如 `maicraft:sleep`；**不是工具** |
| **`onClient`** | 把工作排到游戏客户端线程执行，用 future 交回结果 |
| **撤回状态** | 区分"请求还没开始"还是"已经开始改状态"，网络超时时用 |
| **形状校验** | 只查字段名、类型、长度、枚举；不查业务含义 |
| **`request_key`** | 调用方给同一次提交起的稳定名字，用来识别网络重试 |
| **`task_id`** | 对外总任务的 UUID，查询、暂停、取消都用它 |

---

## ② 语义

| 词 | 意思 |
| --- | --- |
| **语义** | 项目的中文用词。包名是 `intent`（英文），中文一律叫"语义"：这一层接的是"**用意思表达的目标**"，不是"心里想的意图" |
| **语义 vs 机制** | 项目最重要的一条对比。**语义**是"要什么"（`maicraft:sleep`）；**机制**是"怎么做"（转头、点床、等确认）。这一层的活就是"把语义翻成机制" |
| **`IntentRuntime`** | 语义状态仓储 + 生命周期协调；不碰身体 |
| **总任务单**（`IntentTaskRecord`） | 一件事的全生命周期档案：步骤、进度、问题、暂停、结果 |
| **`IntentTask`** | 逐刻推进总任务的执行者 |
| **`Plan`** | 带编号的步骤清单；`plan` 只展开并登记，不算路、不算材料 |
| **步骤** | 总任务单里的一项语义目标；由 `sequence` 展开而来 |
| **世界身份** | "这份任务属于哪个存档/服务器"的标识 |
| **`bindingKey`** | 任务创建时的世界身份键；换世界后对不上就拒绝复用 |
| **检查点** | `config/maicraft/state/<哈希>.json`，存计划、总任务单、请求键、地标 |
| **决策** | 任务做不下去时提出一个问题并暂停，等调用者回答 |
| **微观指令** | `route` / `click` / `cells` 之类；语义目标里**一律拒绝** |

## ③ 翻译

| 词 | 意思 |
| --- | --- |
| **`Goal`** | 想做成什么：能力、结果描述、目标对象、参数 |
| **`IntentAction`** | 翻译结果：下一步动作，八种变体之一 |
| **`Pending`** | 信息还没查完，下一刻再用新信息判断 |
| **`Report`** | 不用做动作，直接给结果（只读设计走这条） |
| **`Native`** | 直接带一张任务单的动作 |
| **`Tool`** | 只带"工具名 + 参数"，让工具去造任务单 |
| **`Chain`** | 依次做一组内部动作 |
| **`Decision`** | 做不了，暂停等回答 |
| **`Remember`** | 记一个地标 |
| **`Wait`** | 等一个可观察的条件成立 |
| **适配器** | `AbilityAdapter` 等；**只读现场、不写世界**、每刻可能重跑 |

---

## ④ 调度

| 词 | 意思 |
| --- | --- |
| **`CompanionBrain`** | "同伴角色的大脑"；每刻选出唯一的身体使用者 |
| **`CompanionTickDispatcher`** | 客户端线程入口；持有 `CompanionBrain`，管身体生命周期 |
| **`TaskSlot`** | 任务单 ↔ 执行器：换任务、推进、超时、结算 |
| **`TaskSelector`** | 纯选择逻辑：反射 > 同步槽 > 当前槽 > 空闲 |
| **`sync` 槽** | 临时动作槽：短、有界、调用方在等结果 |
| **`current` 槽** | 当前任务槽；总任务单在这里 |
| **反射** | 自救行为（落地、换气、自卫、休息），优先级最高 |
| **`PREEMPTED`** | 被抢占：进度留着，回来接着干 |
| **`REPLACED`** | 被换掉 |
| **`BODY_GONE`** | 身体没了（死亡、下线、换世界） |

---

## ⑤ 任务

两种任务都实现同一个 `Task` 接口，是**嵌套**关系。

| 词 | 意思 |
| --- | --- |
| **语义任务**（`IntentTask`） | 有步骤、会翻译、会造并驱动子任务的那种 |
| **动作任务**（`CompanionTask`） | 真的动手的那种（走路、挖矿、施工…） |
| **子任务** | 语义任务私有的执行器；**不进任务槽**，由父任务亲自驱动 |
| **`captureNext`** | 父任务调用工具时摆的"网"：把工具**要提交**的任务单接住，变成私有子任务（见[关键机制](04-mechanisms.md)第 1 节） |
| **`Task`** | 两种任务共用的接口：`start` / `tick` / `result` |
| **`TaskRecord`** | 一件工作的输入和期限；纯数据，不会自己动 |
| **`TaskFactory`** | 按任务单类型创建执行器；没登记就造 `UnsupportedTask` |
| **`start`** | **一次性准备**；不是"以后每次拿到身体都重来" |
| **`tick`** | 逐刻做一点 |
| **`result`** | 收尾 + 给结果；会关菜单、停导航，**不只是查询** |
| **`FailureType`** | 失败分类：`NO_PATH` / `NO_MATERIAL` / `TERRAIN_BLOCKED` … |
| **`PlayerNav`** | 统一导航入口；底下是交通协调 + 内嵌寻路 |
| **地形许可** | 这次导航允许不允许挖 / 搭 / 用落地水；默认只走不改 |

## ⑥ 心跳与身体操作

| 词 | 意思 |
| --- | --- |
| **刻**（tick） | 游戏每 1/20 秒更新一次 |
| **`ClientRuntime.tick`** | 每个游戏刻的总入口 |
| **`lastTickStage`** | 本刻停在哪一步（`no_body` / `preview_review` / `running_tasks` …） |
| **`LocalPlayerContext`** | 本刻的玩家 / 世界 / 动作入口；**下一刻必须重新取** |
| **`body()`** | 按键与镜头端口 |
| **`actions()`** | 原生操作端口（提交 + 对账） |
| **`menus()`** | 容器菜单端口 |
| **身体操作** | ⑥ 这个部分的名字：按键、镜头、点击、菜单的总称 |
| **原生操作** | **一次**真实的玩家操作（挖一个方块、点一下）；不是外挂接口 |
| **回执**（`NativeActionReceipt`） | 提交后拿到的小票；记判定条件和状态 |
| **判定条件**（`NativeConfirmation`） | 读客户端事实、回答"成了没"的函数 |
| **稳定刻** | 要连续几个客户端刻满足条件才算确认（防预测回滚） |
| **`DIVERGED`** | 出现了第三种状态：不是没变，也不是期望，是要调查的意外 |
| **操作额度** | 一个游戏刻只允许提交一次原生操作 |

---

## ⑦ 结果与观察

| 词 | 意思 |
| --- | --- |
| **Attention** | 任务事件流；有进展或要回答时推送 |
| **`wake_reason`** | 为什么被唤醒：`events` / `decision_required` / `task_terminal` / `timeout` … |
| **`next_attention`** | 服务端拼好的"下次等待参数"，原样拿去调 `perceive` |
| **冻结回执** | 超大内容的临时只读快照；失效要重新观察，不能重跑任务 |
| **`outcome_uncertain`** | 已提交但结果无法确认 |
