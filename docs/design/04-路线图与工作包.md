## v0 的维护规则

- **冻结功能**：不加新能力、新参数、新行为。
- **只修影响直播的问题**，并且修法以最小改动为准。修复时顺手在对应领域旧逻辑清单里记一笔（"v0 在这里出过这个问题"），供 v1 规格参考。
- v0 的提交规则不变（`dev` 分支、签名、中文 Conventional Commits、更新日志）。
- `dev` 上的 `docs/refactor/` 改为一份指向说明，设计文档以 `v1` 分支的 `docs/design/` 为准。

## 切换标准（每个里程碑都一样）

某类直播从 v0 切到 v1，需要同时满足：

1. 该里程碑包含的所有领域规格都已实现，离线测试全部通过；
2. 下文"实机验收清单"中，该里程碑的条目全部通过；
3. 一次完整的试播（不少于 1 小时，按真实直播流程，由 Amaidesu 的 v1 Agent 驱动）没有阻塞问题；
4. Amaidesu 的 v1 Minecraft Agent 提示词与 skills 已按新能力更新；
5. 两位确认。

切换后，该类直播出问题只在 v1 修。

#### WP-4.4a 原版船当出行方式（`via=boat`）🟡 ChangingSelf

现状：v1 只有 Sable 物理结构的上下船（`compat.sable.DeckMode`，`via=board`）和原版船的同乘（`ability.follow.VanillaRideAlong`：跟着的人坐了船就走过去坐上空座），自己划一条原版船去对岸还没有；隔着湖、海的目的地只能泅渡或绕。v0 的做法在出行旧逻辑清单 T-40：出发时坐在船上就先驾船走水路到离目标最近的水格，靠岸或搁浅都接步行，船留在原地不收（"船是她的船，不是垃圾"）。

真人怎么做：要过湖就掏出船放到水边、坐上去、对着对岸划、靠岸跳下来接着走；身上没船、岸边又没停着船，就游过去或绕路，不会为过一次湖现做一条船。

要做成（登记成一种出行方式，和电梯、折跃门一样由行程规划比报价）：

- 报价（`offer`，只读）：目的地和人隔着一片水（两岸之间的水面连成一片、宽过泅渡划算的距离，或走路算不出干路）且身上有船物品、或 32 格内停着一条没人坐的船，就出一份：从岸边到对岸岸边按原版船在水上约每秒 8 格估，加上放船、上船、下船各几秒；没船、下界（没有水）、水面被冰封住不出报价并说清原因。人正坐在原版船上时这一段非它不可（`claims`）：先按船的规则开到最近的岸或下船，不交给走路。
- 一段（`TravelLeg`）：备船（身上有船先拿到主手；岸边停着的船走过去用）→ 走到岸边能放船的站位（脚下站得住、前面一格是水面）→ 放船（对着水面右键，确认一条新的船实体出现在那一格附近，和落地救援放船用的是同一个确认办法：`behavior.landing.BoatRescue` 按计划落点附近扫船实体）→ 上船（右键船实体，确认自己的乘骑对象就是它；同乘那套上船动作可以复用）→ 划船：按住前进、按左右转向朝目的地岸边的落点开，每刻看前方水面：撞岸、搁浅、顶到睡莲或冰就倒退一步再转向，连着三次没前进换一个靠岸点；中途被怪打、饿了，照常按生存需求打断，船停在原地，回来接着划→ 靠岸（船贴到岸边、人能跳上站得住的岸）→ 下船（潜行键，确认自己不在船上、脚下站得住或在水里游得上岸）→ 船留在原地不收，位置记进世界记忆（下次从这边回去报价时优先用它）→ 交还行程从岸上接着规划。
- 结果：`legs` 里这一段 `via=boat`，`changes` 记"放下了一条船 x, y, z"（物品少了一条）和"船留在 x, y, z"；没划到对岸就如实写停在哪、为什么（撞岸三次、船被打碎、人被拉下船）。
- 不做：身上没船不现合成（所有者 2026-10-16 定，不为过一次湖做船）；不在船上打架；不替别人划（同乘归跟随）；下界不出报价。
- 离线测试：报价、`claims`、靠岸点挑选、划船的转向状态机做成纯函数可测；按出行方式规格第 9 节的样子给替身。
- 实机验收：①站在湖边、身上有船、目的地在对岸：放船、划过去、下船走到；②岸边停着一条船、身上没有：走过去坐那条；③划到一半被僵尸打：停船应付，回来接着划；④身上没船没停船：不出报价，行程照常泅渡或绕路，结果写明。

#### WP-4.4b 原版矿车当出行方式（`via=minecart`）🟡 ChangingSelf

现状：Create 火车按时刻表坐（`via=train`，里程碑三），原版铁轨上的矿车没有任何支持；主播铺好的一条轨道，角色只会沿着走。

真人怎么做：轨道起点放一辆矿车坐上去，有动力铁轨就自己走，没有就靠下坡；到站按潜行下车。原版矿车坐着的人不能自己推动，所以没有动力铁轨又没有下坡的线路不走。

要做成：

- 报价：读已加载区的铁轨方块连成的线路（普通、动力、探测、激活四种铁轨），从离人最近的轨道格到离目的地最近的轨道格之间有连通的一段、沿途有动力铁轨通电或整体下坡能把车送到头，且身上有矿车物品或轨道上停着一辆没人坐的矿车，就出报价：按原版矿车约每秒 8 格估；线路读不全这一刻不答，下一刻再看；没车、线路不通、没有动力就不出报价并说清。人正坐在矿车里时这一段非它不可：先下车或开到头。
- 一段：备车 → 走到起点轨道旁 → 放车（对着轨道右键，确认矿车实体出现在那一格）→ 上车 → 启动（动力铁轨通电就自己走；起点是普通轨道就先从旁边推一下再跳上去，或放在下坡起点）→ 坐着等：每刻看车动没动、到哪了，停在半路（动力铁轨没电、撞到停着的车、轨道断了）就下车如实记在哪停的 → 到离目的地最近的轨道格下车 → 车留在原地，位置记进世界记忆 → 交还行程。
- 结果与不做：同船；另外不铺轨、不放动力铁轨、不给红石通电（那是建造和 `use` 的事）。
- 离线测试：铁轨线路连通与可达性纯函数（四种铁轨、拐弯、坡道、丁字路口按原版规则）；实机验收：①一条带动力铁轨的直线：放车、坐到头、下车；②线路中间没电：停在那里下车，结果写明；③身上没车、轨道上停着车：坐那辆。

## 实机验收清单

每个里程碑结束、每次切换前，由人在实机跑一遍。领域规格第 9 节的实机项会追加到这里。

**里程碑一**

1. 新世界开局：砍树 → 工作台 → 木镐 → 挖石头 → 石镐 → 熔炉 → 烤肉 → 吃。
2. `observe(scene)` 的描述与画面一致；用观察编号让它去砍"左前方那片树林"里的树。
3. 天黑：世界里有床、背包里有床、只有羊毛和木板、什么都没有，四种情况。
4. 打开附近箱子取指定物品；背包塞满后继续取物，看它怎么腾地方。
5. 记住一个地点，走远后让它回去。
6. 野外遇到僵尸和苦力怕：打得过就打，打不过就跑；夜里露天没床又打不过时挖三填一。
7. 干活时掉进深水、被沙子埋住，先自救再继续。

**里程碑二（建造）**，来自建造规格第 9 节：

1. LLM 用 `design(create)` 画一间 7×5 的木屋（墙、门、两扇窗、屋顶），`inspect` 看一眼，`preview` 投到空地上观众能看见半透明屋子；`build` 在同一处盖起来，门最后关好，结果每格 MATCHES。
2. 同一张图纸换个地方转 90 度再盖一次；盖到一半 `goal(cancel)`，垫的土被收走，世界里只剩已砌好的部分；再下达一次接着盖完。
3. 身上只有一半的石砖：盖到石砖用完停下，结果 partial 写明还缺多少；`obtain` 补齐再 `build`，从停下的地方接着砌。
4. 工地上有一棵树和一个坑：树被砍、坑被填，余土进旁边的箱子或被丢掉。
5. 工地边缘压着玩家的箱子：提问 NEED_APPROVAL 列出那几格；回答不同意 → 跳过那几格盖完其余。
6. 图纸里有一个水池：实心格放完后倒水；再盖一个岩浆池，倒下去成黑曜石时结果如实记。
7. 高塔：够不着的格先垫土柱，放完沿柱下撤，塔底没有残留的土。
8. 导入一个 .litematic 的小房子，箱子是空的、展示框没装，结果写明没装几个。
9. 施工中天黑：夜休在两格之间插进来，睡醒回到工地接着砌。
10. 只放一个火把：`build` 给 `block=minecraft:torch` 和 `target=seen b#`（墙面），火把贴在墙上。

**里程碑二其余领域与三**：在对应领域规格批准时补充（WP-4.4c 第 1 条）。

**里程碑四**，来自 WP-4.4a、WP-4.4b：

1. 站在湖边、身上有船、目的地在对岸：放船、划过去、下船走到。
2. 岸边停着一条船、身上没有：走过去坐那条划。
3. 划到一半被僵尸打：停船应付，回来接着划。
4. 身上没船也没停船：不出报价，行程照常泅渡或绕路，结果写明。
5. 一条带动力铁轨的直线：放矿车、坐到头、下车。
6. 线路中间没电：停在那里下车，结果写明停在哪。
7. 身上没车、轨道上停着车：坐那辆。
