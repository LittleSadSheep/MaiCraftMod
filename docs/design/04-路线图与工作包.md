每个工作包在自己的分支上做，分支名用 `v1-<内容>`（`v1/<内容>` 会和 `v1` 分支冲突，推不上去）；合入 `v1` 前由另一边看过。

## v0 的维护规则

- **冻结功能**：不加新能力、新参数、新行为。
- **只修影响直播的问题**，并且修法以最小改动为准。修复时顺手在对应领域旧逻辑清单里记一笔（"v0 在这里出过这个问题"），供 v1 规格参考。
- v0 的提交规则不变（`dev` 分支、签名、中文 Conventional Commits、更新日志）。
- `dev` 上的 `docs/refactor/` 改为一份指向说明，设计文档以 `v1` 分支的 `docs/design/` 为准。

## 切换标准（每个里程碑都一样）

某类直播从 v0 切到 v1，需要同时满足：

1. 该里程碑包含的所有领域规格都已实现，离线测试全部通过；
2. 下文"实机验收清单"中，该里程碑的条目全部通过；
3. 一次完整的试播（不少于 1 小时，按真实直播流程，由 Amaidesu 的 v1 Agent 驱动）没有阻塞问题；
4. Amaidesu 的 v1 Minecraft Agent 提示词与 skills 已按新能力更新；
5. 两位确认。

切换后，该类直播出问题只在 v1 修。

## 实机验收清单

每个里程碑结束、每次切换前，由人在实机跑一遍。领域规格第 9 节的实机项会追加到这里。

**里程碑一**

1. 新世界开局：砍树 → 工作台 → 木镐 → 挖石头 → 石镐 → 熔炉 → 烤肉 → 吃。
2. `observe(scene)` 的描述与画面一致；用观察编号让它去砍"左前方那片树林"里的树。
3. 天黑：世界里有床、背包里有床、只有羊毛和木板、什么都没有，四种情况。
4. 打开附近箱子取指定物品；背包塞满后继续取物，看它怎么腾地方。
5. 记住一个地点，走远后让它回去。
6. 野外遇到僵尸和苦力怕：打得过就打，打不过就跑；夜里露天没床又打不过时挖三填一。
7. 干活时掉进深水、被沙子埋住，先自救再继续。

**里程碑二（建造）**，来自建造规格第 9 节：

1. LLM 用 `design(create)` 画一间 7×5 的木屋（墙、门、两扇窗、屋顶），`inspect` 看一眼，`preview` 投到空地上观众能看见半透明屋子；`build` 在同一处盖起来，门最后关好，结果每格 MATCHES。
2. 同一张图纸换个地方转 90 度再盖一次；盖到一半 `goal(cancel)`，垫的土被收走，世界里只剩已砌好的部分；再下达一次接着盖完。
3. 身上只有一半的石砖：盖到石砖用完停下，结果 partial 写明还缺多少；`obtain` 补齐再 `build`，从停下的地方接着砌。
4. 工地上有一棵树和一个坑：树被砍、坑被填，余土进旁边的箱子或被丢掉。
5. 工地边缘压着玩家的箱子：提问 NEED_APPROVAL 列出那几格；回答不同意 → 跳过那几格盖完其余。
6. 图纸里有一个水池：实心格放完后倒水；再盖一个岩浆池，倒下去成黑曜石时结果如实记。
7. 高塔：够不着的格先垫土柱，放完沿柱下撤，塔底没有残留的土。
8. 导入一个 .litematic 的小房子，箱子是空的、展示框没装，结果写明没装几个。
9. 施工中天黑：夜休在两格之间插进来，睡醒回到工地接着砌。
10. 只放一个火把：`build` 给 `block=minecraft:torch` 和 `target=seen b#`（墙面），火把贴在墙上。

**里程碑二其余领域与三、四**：在对应领域规格批准时补充。
