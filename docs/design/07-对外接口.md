# 07 对外接口（MCP）

对外接口是 LLM 认识这个角色的唯一途径。它要做到两件事：**LLM 不用读说明书就能猜对怎么用**，以及**LLM 能看到玩家看到的东西**。v0 两件都没做好（见 01 症状 9，以及 00 第 1、2 层的发现）。

接口的使用方有两个：

- **LLM**：通过 Amaidesu 宿主调用，宿主会把工具改名为 `maicraft_*`；
- **宿主程序**：开局读取状态、等待任务事件、分页回读结果。

v1 为这两个使用方分别设计，不再让一个工具同时服务两者。

本文里的"工具"都指 **MCP 工具**（observe、lookup……），不是游戏里的镐和斧。

## 1. 设计原则

1. **一个工具只做一件事；一个参数只有一种含义。** v0 的 `perceive` 一身兼五职（观察、查能力、查知识库、上网、等事件），`focus` 一个参数有六种含义。
2. **名字脱离上下文也不会被读成别的意思。** LLM 往往只看字段名就动手；字段名、枚举值、问题种类都按 [09-命名与术语](09-命名与术语.md) 的原则起名，例如问题种类不用 `NEED_TOOL`（会被读成"需要调用另一个 MCP 工具"）。
3. **工具描述里不写具体能力的特例。** 某个能力的用法只写在它自己的能力说明里。
4. **平铺的 schema，不用 `anyOf` / `oneOf`。** 已经实测有宿主（MiniMax）解析不了 `anyOf`。要表达"多选一"，就拆成两个工具或两个字段。
5. **藏执行细节，不藏观察事实。** 路线、点击、槽位不给 LLM；看到的东西是什么、在哪、怎么指着它，全部给。
6. **同一个概念全接口只有一个名字**（第 5 节参数名表）。
7. **所有工具用同一个返回格式**（第 6 节），所有能力用同一个任务结果结构（第 6.1 节）。
8. **默认值就是正常玩家会做的事**：许可用 M7 的默认值；数量、范围有合理默认；布尔参数默认 `false` 时表示"不做特别的事"，不用布尔参数表示许可。

## 2. 工具集

| 工具 | 给谁 | 做什么 | 取代 v0 |
| --- | --- | --- | --- |
| `observe` | LLM | 看世界和自己：角色状态与背包、周围场景、某个看到的东西的细节、世界记忆 | `perceive` 的 situation / surroundings / landmarks / exploration |
| `lookup` | LLM | 查资料：能力列表与能力说明、离线知识库、Minecraft Wiki、配方 | `perceive` 的 abilities / knowledge / web_knowledge |
| `execute` | LLM | 开始做一件事（下达一个目标）；`dry_run=true` 只检查、不动手 | `execute` + `plan` |
| `task` | LLM | 查看、暂停、恢复、取消任务，回答任务提出的问题，分页读证据 | `task` |
| `events` | 宿主（也可开放给 LLM） | 按游标读任务事件，没有新事件时可以等一会儿 | `perceive(view=attention)` |

依然是 LLM 面对 4 个工具，但每个都只做一件事。

- `execute` 不是 Minecraft 的 `/execute` 命令；要发命令或聊天，用能力 `chat`。工具描述里写明这一点。
- 读任务事件的工具叫 `events`，不叫 `wait`：`wait` 已经是能力名（在游戏里等一个条件），两者同名会让 LLM 分不清。

一些 v0 里塞在 `perceive` 里的**领域分析**（施工场地勘测 `construction_site`、Create 动力源 `kinetic_sources`、机器界面、探索目录），改为**只读能力**，通过 `execute` 调用并当场返回报告。它们有自己的参数和能力说明，不再污染观察工具的参数表。原则是：**`observe` 只管"玩家此刻能看见什么"；需要分析、计算的，都是能力。**

### 2.1 `observe`

| 参数 | 含义 |
| --- | --- |
| `what` | `self`（生命、饥饿、背包、装备、当前任务一句话、当前许可）、`scene`（周围场景，默认）、`detail`（一个看到的东西的细节）、`world_memory`（角色记得的地点、容器、见过的资源与结构；不是对话记忆） |
| `id` | 只在 `what=detail` 时用：观察编号（`e12`、`f3`、`b5`）或地标名 |
| `grid` | 只在 `what=scene` 时用：`true` 时附带近处的俯视网格（原 `LookAroundTool`） |

返回内容见第 7 节。

### 2.2 `lookup`

| 参数 | 含义 |
| --- | --- |
| `topic` | `abilities`（默认）、`knowledge`、`wiki`、`recipe` |
| `id` | 精确条目：能力 ID、知识 URI、物品 ID |
| `query` | 关键词搜索；与 `id` 二选一 |
| `url` | 只在 `topic=wiki` 时用：直接读一篇条目 |

不带 `id` / `query` 的 `lookup()` 返回全部能力的一行签名：名称、用途、参数名与类型。宿主开局可以直接把它放进上下文。

### 2.3 `execute`

| 参数 | 含义 |
| --- | --- |
| `goal` | 目标（第 3 节） |
| `dry_run` | `true` 时只做校验和预检（原 `plan`），返回 `plan_id` 和发现的问题 |
| `plan_id` | 执行一次 `dry_run` 通过的计划；与 `goal` 二选一 |
| `request_key` | 网络重试用的幂等键；不给时由 MCP 入口自动生成 |

只读能力（`mode=READ_ONLY`）在 `execute` 里当场返回报告，不控制角色，也不产生后台任务。

### 2.4 `task`

| 参数 | 含义 |
| --- | --- |
| `operation` | `get`、`list`、`pause`、`resume`、`cancel`、`answer`（与 v0 的操作集合相同） |
| `task_id` | 除 `list` 外都要给 |
| `answer` | 只在 `operation=answer` 时用：所选回答的编号 |

改动只有一处：工具描述里不再出现任何能力的特例，问题的选项说明写在问题本身里。

### 2.5 `events`

参数：`task_id`、`stream_id`、`after_cursor`、`wait_ms`。语义与 v0 的 attention 相同（游标、重新同步、唤醒原因）：`wait_ms` 内没有新事件就空手返回，有就立刻返回。拆成单独工具，是为了让宿主可以只把它留给自己用。Amaidesu 一侧仍可以把这些事件叫 attention。

事件的 `kind` 取小写枚举名：`started`、`asked`、`paused`、`resumed`、`step_finished`、`finished`、`temporary_task_started`、`temporary_task_finished`、`need_unhandled`。后三种与目标无关（`goal_run_id` 为 -1）：临时任务的开始与结束是生存需求自己派活（自卫、回洞、退开）与收工；`need_unhandled` 是角色自己处理不了的生存需求（饿了、弄不到吃的这类），主任务不受影响，照常推进。

### 2.6 去掉的东西

| 去掉 | 原因 |
| --- | --- |
| 每个工具都带的 `server_id` | Mod 里没有任何代码读取它；如果宿主路由需要，由宿主自己处理 |
| 附加在每个工具返回值里的 `reminders` | 角色自己能处理的交给生存需求（M6）；处理不了的作为任务事件推送，并显示在 `observe(self)` 里，不再随每次调用重复出现 |
| `perceive` 的 `detail=names/summary/signatures`、`sections`、`limit/offset` 混用 | `lookup()` 默认就返回签名；分页只出现在确实需要分页的地方（`task get` 的证据） |

## 3. 目标（goal）

```json
{
  "ability": "maicraft:sleep",
  "purpose": "天黑了，去睡觉",
  "target": { "kind": "landmark", "name": "家" },
  "parameters": {},
  "permissions": { "fight": "self_defense" },
  "steps": [],
  "on_failure": "stop"
}
```

| 字段 | 必填 | 说明 |
| --- | :---: | --- |
| `ability` | ✅ | 能力 ID |
| `purpose` | | 一句话说明为什么要做这件事，只用于日志和直播解说，Mod 不据此行动。v0 叫 `outcome` 且必填；v1 改名并改为可选，避免和"任务结果"混淆 |
| `target` | | 目标对象：要去的地方或要处理的东西（第 4 节） |
| `parameters` | | 本能力的参数，由它的参数规格定义 |
| `permissions` | | 这次任务的许可（03-M7），省略的字段用默认值。不是游戏或服务器的 OP 权限 |
| `steps` | | 只用于 `maicraft:sequence`：按顺序的每一步目标 |
| `on_failure` | | 只用于 `sequence` 里的一步：这一步失败后 `stop`（整件事停下）还是 `continue` |

`permissions` 的字段：

| 字段 | 取值（默认值加粗） | 含义 |
| --- | --- | --- |
| `change_blocks` | `none` / `temporary` / **`natural`** / `any` | 能改变哪些方块：不改 / 只搭临时方块并收回 / 天然方块和无主的东西 / 一切不受保护的方块 |
| `fight` | `self_defense` / **`hostile_mobs`** / `any` | 只自卫 / 主动处理敌对生物 / 可以攻击指定的任何目标 |
| `use_rare_items` | **`false`** / `true` | 能否用末影珍珠、不死图腾、钻石这类稀有消耗品 |
| `kill_animals` | `none` / **`wild`** / `any` | 能否为了具体需要击杀动物（剪毛、挤奶不算） |
| `survival_needs` | **`on`** / `off` | 是否处理生存需求（吃饭、睡觉、自救）；只有寻死这类任务关闭 |
| `protected_landmarks` | 地标名列表 | 额外不许碰的地方 |

**删除 `preferences` 和 `constraints`**：v0 里没有任何一个能力接受它们（所有声明都是空的），却要求每次调用都带上这两个空字段。

## 4. 目标对象（target）

全接口只有这一种"指一个地方或一个东西"的方式：

| kind | 字段 | 含义 | 取代 v0 |
| --- | --- | --- | --- |
| `here` | — | 角色当前的位置 | `current_place` |
| `seen` | `id` | 观察时看到的东西：`e#` 实体、`f#` 地形特征、`b#` 方块或设施 | `entity`、`nearest` 的大部分用法 |
| `landmark` | `name` | 记住的地点，或附近告示牌上的文字 | `landmark`、`area` |
| `position` | `x`、`z`，可选 `y`、`dimension` | 坐标；**`y` 可以省略**，到了附近再找能站的高度（M10） | `coordinates`，以及 `travel` 的 `parameters.destination` 特例 |
| `player` | `name` | 一位玩家 | `player` |
| `direction` | `toward`、`distance` | 朝某个方向走多远：`toward` 取 `forward` / `backward` / `left` / `right` / `north` / `south` / `east` / `west`，例如"往北 100 格" | 新增 |
| `previous` | 可选 `step` | 前面某一步确认过的位置 | `prior_result` |

- "某片区域"等于任意目标对象加上 `parameters.radius`。
- "最近的某种东西"不再是一种目标对象：要么先 `observe` 拿到观察编号再用 `seen`，要么由能力自己按参数去找最近的（例如 `use` 一台熔炉时只给 `block`）。
- 观察编号对应的东西不在了（实体走远、方块被拆）时，能力以问题 `TARGET_GONE` 结束，并说明最后一次看到它的方位。

## 5. 参数名表

| 概念 | 名字 | 类型与规则 | v0 的各种写法 |
| --- | --- | --- | --- |
| 物品 | `item` / `items` | 物品 ID，或 `#` 开头的标签（`#minecraft:logs`） | `item_id`、`item_ids`、`item_tag`、`item_tags`、`item_resource_id`、`ingredient_item_id`、`output_item_id`…… |
| 方块 | `block` / `blocks` | 方块 ID 或标签 | `block_id`、`block_ids` |
| 实体类型 | `entity` | 实体类型 ID | `entity_type_id`、`entity_type_ids` |
| 数量 | `count` | 这次要多做多少：拿东西就是"**再多拿几件**"（不是背包里的总数），做动作就是"**做几次**" | 已统一的部分保留 |
| 范围 | `radius` | 工作或搜索范围，单位格 | `radius`、`search_radius`、`max_search_radius`、`horizontal_radius`、`source_radius`…… |
| 距离上限 | `max_distance` | 出行或搜索的最远距离，单位格 | `max_distance`、`max_search_distance`、`max_resource_search_distance`、`max_portal_search_radius`…… |
| 保持距离 | `distance` | 跟随时与目标相隔的距离，单位格（2..16） | v0 的 follow 专属 `distance`（并入统一参数名表） |
| 等待条件 | `condition` | 等什么：`elapsed` / `day` / `night` / `health_full` / `not_hungry` | v0 的 `wait_for_condition` 专属参数 |
| 先等时长 | `after_seconds` | 先至少经过多少秒，再开始做检查（0..3600） | `after_s`、`wait_seconds` |
| 时间上限 | `max_seconds` | 单位秒，不用游戏刻 | `max_wait_seconds`、`max_duration_ticks`、`timeout_seconds` |
| 要说的话 | `message` | 发到游戏聊天的一句话，对全体玩家可见；以 `/` 开头的是游戏命令，角色不执行 | — |
| 操作 | `operation` | 一个能力内部的几种操作选哪一种（`enable` / `disable` / `status`，`deposit` / `withdraw`） | 各种 `op`、`mode`、`action` |
| 途径 | `via` | 拿东西时指定只走哪条路，取值：`craft` 合成 / `smelt` 烧炼 / `container` 容器 / `mine` 采掘 / `harvest` 采集 / `trade` 交易（随里程碑接入） | — |
| 栏位 | `slot` | 装备与卸下的目标栏位：`mainhand` / `offhand` / `head` / `chest` / `legs` / `feet`；`armor` 只配合 `unequip`，表示整套护甲卸下 | `equipment_location` |
| 保护 | `permissions.protected_landmarks` | 不许碰的地标名 | 散在各能力里的 `protected_labels` |
| 许可 | `permissions.*` | 方块、战斗、稀有物品、击杀动物、生存需求 | 12 种 `may_*` / `allow_*` 共 44 个开关 |

规则：

- 单位用人能直接理解的：格、秒、件。
- 新能力**只能**使用参数名表里的名字；确实需要新概念时，先加进参数名表（代码里是 `ParamNames`），再在能力里使用。
- 宽松写法（`"6"` → `6`、`"true"` → `true`、参数放错一层）只由 MCP 入口统一处理，并在返回的 `notes` 里说明做过哪些规范化。

## 6. 返回格式与错误

所有工具返回同一个结构：

```json
{
  "ok": true,
  "data": { },
  "notes": ["parameters.count: \"6\" 按整数 6 处理"],
  "next": { "tool": "events", "arguments": { "task_id": "…", "stream_id": "…", "after_cursor": 42, "wait_ms": 30000 } }
}
```

失败时：

```json
{
  "ok": false,
  "error": {
    "code": "invalid_parameter",
    "field": "goal.parameters.count",
    "message": "count 必须是 1 到 256 的整数",
    "expected": "integer 1..256",
    "example": { "ability": "maicraft:obtain", "parameters": { "item": "minecraft:torch", "count": 8 } }
  }
}
```

- `error.code` 是一个小而稳定的枚举：`invalid_parameter`、`unknown_ability`（附相近能力建议）、`unknown_id`（观察编号或任务编号不存在）、`not_in_world`、`busy`、`internal_error`。
- 校验错误一次报全，而不是改一个错报下一个。
- 任务的结果走第 6.1 节的任务结果，不放进错误：**工具调用成功、任务失败**是两回事。

### 6.1 任务结果

所有能力用同一个结构告诉 LLM 做得怎样（代码里是 `TaskResult`，设计见 03-M8）：

```json
{
  "status": "partial",
  "summary": "床备好了，现在是白天睡不了",
  "changes": [ { "kind": "item_gained", "what": "minecraft:white_bed", "count": 1 } ],
  "remaining": ["入睡"],
  "problem": { "kind": "WRONG_TIME", "message": "现在是白天", "suggestion": "约 5 分钟后天黑" },
  "unconfirmed": [],
  "attempts": [ { "tried": "从门口那一侧靠近床", "result": "被墙挡住，看不见床头" } ],
  "details": { "bed_source": "crafted" }
}
```

| 字段 | 含义 |
| --- | --- |
| `status` | 目标达成情况：`done` / `partial` / `failed` / `cancelled` |
| `summary` | 一句话结论，可以直接用于直播解说 |
| `changes` | 已确认发生的变化（拿到、用掉、存进、丢掉的物品，放下、拆掉的方块，移动……） |
| `remaining` | 没完成的部分 |
| `problem` | 卡在哪：`kind`（下表）、`message`（用游戏里的话说清楚）、`suggestion`（怎样能继续；没把握时不给） |
| `unconfirmed` | 已提交、但没能确认结果的交互；这些不能盲目重做 |
| `attempts` | 试过的办法摘要 |
| `details` | 能力特有的细节，每个能力在自己的能力说明里列出 |

问题种类（`problem.kind`）：

| 种类 | 意思 |
| --- | --- |
| `INVALID_PARAMETER` | 参数在游戏里立不住：物品或方块 ID 不存在、标签下一件注册物品都没有；不用进世界就能发现 |
| `NEED_ITEM` | 缺东西（材料、食物、床、够格的工具），而且自己弄不到 |
| `NEED_APPROVAL` | 要做的事超出这次任务的许可，需要 LLM 同意；通常伴随一个提问 |
| `UNREACHABLE` | 到不了：试过的站位和路线都不通 |
| `NOT_FOUND` | 查无此物：观察编号或名字对不上任何东西（"曾经见过、后来没了"用 `TARGET_GONE`） |
| `TARGET_GONE` | 目标对象没了 |
| `NOT_FOUND` | 查过的范围里没有找到；查了多大范围随问题写明，与 `TARGET_GONE`（原来有、现在没了）分开 |
| `DANGER` | 继续下去会死，或大概率重伤 |
| `REFUSED_BY_GAME` | 游戏或模组拒绝了这次交互（包括服务器的领地保护、权限不够），附上游戏给的原因 |
| `WRONG_TIME` | 时间不对，例如白天不能睡 |
| `NOT_POSSIBLE_HERE` | 在这里按游戏规则就做不到，例如下界用床会爆炸 |
| `INVENTORY_FULL` | 背包满，而且腾地方要动到贵重物品 |
| `STUCK` | 卡住了：换过办法仍长时间没有真实进展，或超过了最多能做的时长 |
| `UNSUPPORTED` | 目前不支持这件事，或需要的模组没装 |
| `INVALID_PARAMETER` | 参数给得不对：缺了必填的、取值超了范围、几个参数凑不到一起；不进游戏就能发现 |
| `INTERNAL_ERROR` | 程序出错，不是游戏里发生的事 |

## 7. 观察视图（`observe`）

## 8. 能力目录（草案）

v0 有约 50 个能力，粒度从"吃一口东西"到"拿到鞘翅"不等，好几组能力的结果互相重叠，能力说明一半中文一半英文。v1 的规则：

- **一个能力等于一个玩家能用一句话说清的意图**，并且有明确的完成标准；
- **两个能力的结果不重叠**；需要区分途径时，用参数（例如 `via`），不新开能力；
- **能力名不和 MCP 工具名、Minecraft 命令重名**，免得 LLM 分不清该调哪个；
- **长线目标由 LLM 规划**，不在 Mod 里写死。Mod 只提供 LLM 无法实时完成的部分（例如打龙时躲龙息、射水晶这类快速反应），Amaidesu 已有 `skills/progression` 这类攻略文档；
- 能力说明统一用中文（直播和解说都用中文），字段名用英文。

| v1 能力 | 一句话 | 吸收的 v0 能力 |
| --- | --- | --- |
| `obtain` | 让背包里某样东西再多几件；可用 `via` 指定途径（合成、烧炼、采掘、从容器取……） | `acquire_items`、`craft`、`cook`、`stonecut`、`trade`，以及 `manage_container` 的取出 |

## 9. 迁移方式

- v1 从第一天起只提供本接口，不兼容 v0 的四个工具和 v0 的能力目录。
- Amaidesu 新增一个面向 v1 的 Minecraft Agent，通过配置在 v0 / v1 之间选择（Harness 本来就支持按配置选 Agent）。v0 的 Agent 原样保留，继续服务还没切换的直播类型。
- 能力目录随里程碑增长（04）。每加一个能力，接口快照的 diff、`CHANGELOG.md`、v1 Agent 的提示词与 skills 同步更新。
