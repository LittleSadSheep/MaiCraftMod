# 10 调试面板

> 状态：已批准（2026-10-09，第 11 节五项都按建议）；LittleSadSheep 与 Claude 实现中。设计：Claude，2026-10-09。
> 范围：F9 调试面板显示什么、怎么切、从哪读、怎样保证不出事；导航路线的开关。施工预览随里程碑二的建造规格另定，这里只定它和面板的边界（第 9 节）。

## 1. 给谁看

| 谁 | 怎么看 | 要回答的问题 |
| --- | --- | --- |
| 直播中的主播 | 余光扫一眼，几秒钟 | 它在干什么？是不是卡住了？要不要我出手？ |
| 实机调试的开发者 | 盯着看，对照日志 | 为什么停在这一步？谁插进来了？LLM 发了什么、哪些调用出错了？ |

面板画在游戏画面里，开着直播时观众也看得到。所以简要档按"观众看得懂"来写：中文整句，不出现枚举名和内部代号。

## 2. v0 的面板教会了什么

v0 的面板（`client/debug/DebugHudController`，657 行）从 2026-10-01 到 10-07 一共 29 个提交。几乎每一行都是因为实机里有人问了一个问题才加上的，也有几行因为没人看被删掉。这些问题在 v1 照样成立：

| v0 的行 | 回答的问题 | 来历 | v1 |
| --- | --- | --- | --- |
| MCP（端口、会话数） | 宿主连上了吗 | 首版 | 保留，加"宿主有没有在等事件" |
| 感知（最近视图、距上次行动的感知次数） | LLM 是不是光看不动手 | `fc55efcd0` | 保留，按工具计数；新增"最近出错的调用" |
| 身体（就绪；自动操控 / 等待接管 / 玩家操控） | 谁在操作角色 | 首版 | 保留 |
| 性能（TPS、MSPT） | 游戏跑得动吗 | `7650c1f9f` | 保留；只有掉速时才进简要档 |
| 蓝图（预览等确认） | 施工为什么停在半路 | `07690c650` | 删除，见第 9 节 |
| 任务（标题、尝试次数、队列） | 在做什么 | 首版 | 保留，改读目标运行：编号、能力、purpose、第几步 |
| 进度（done/total、步骤 n/N） | 做到哪了 | `ad39c5ea7` | 改为"进展"：上次真实进展是什么、多久之前、离判卡住还有多久 |
| 行动（执行器自答的一句话，生存需求接手时整行黄色） | 这一刻角色在干什么 | `0518dfd3c` → `c36f0c07d` → `ad39c5ea7`，改了三次才定 | 保留，来源是 v1 的 `Task.describe()`；临时任务照样标黄 |
| 等待决策 + 选项（完整两行，附已等时长） | 在等谁 | `0a18ebb3c`、`58054416d`、`c36f0c07d` | 保留，选项照样不截断 |
| 已暂停（原因、时长） | 为什么不动 | `58054416d` | 保留 |
| 最新报错（折行；连续相同的写 ×N） | 为什么没做成 | `1a89e79e9`、`58054416d` | 保留，补"多久之前"，免得把十分钟前的失败当成眼下的 |
| 事件区（attention 尾窗，全部 / 最新一行 / 隐藏三档） | 刚才发生了什么 | `4cee84a10`、`bb6d32cd3`、`375214721`、`e4a021402` | 只放在详细档 |
| 任务列表页（F9+H） | 这段时间都干了什么 | `31d64a8f6` | 保留 |
| Menu 行、Scan 行、未定回执行 | —— | `3e911fab5`、`fc55efcd0` 已删 | 不要 |

另有四个结构上的问题，v1 从设计上避开：

1. **一块面板既当状态表又当日志。** 事件区折行后"遮住小半屏幕"（`375214721`），于是又加了 F9+A 三档。根子是两种看法挤在同一档里，v1 分成简要、详细两档。
2. **宽度跟着内容变。** v0 先按每刻的内容撑出宽度，再按这个宽度折行。`4e9766a09`、`c446a75fd`、`1a89e79e9` 三个提交都在修折行和背景框对不齐；而且内容一变面板就伸缩，直播画面上一直在跳。v1 每档固定宽度。
3. **读数把客户端读崩过。** 任务刚接单时阶段字段还是空的，面板一读就崩（`87f779607`、`73db0b8bf`，v0 维护记录 098）。v1 的面板读出错只显示一行，不往外抛。
4. **按键和原版撞了。** F9+A 的 A 是原版"向左走"，人在操作时按下去，角色会往左挪；F9+P 的 P 是原版"社交互动"界面。

## 3. 原则

1. **每一行回答一个问题。** 说不出回答什么问题的行不加；没人看的行删掉。
2. **正常时安静，出事时显眼。** 一切正常时，简要档只有两行。连接断了、在等人、快卡住、生存需求想插进来却插不进，这些时候才多出提醒行，越要紧越靠上。
3. **先说在等谁。** 角色不动，一定是在等某一方：等 LLM 回答，等玩家按 F8 交回，等重生，等宿主下达目标，或者在等自己的进展。"在等谁、等了多久"是 v0 实机里最常要回答的问题，放在最显眼的位置。
4. **应答依据完整显示。** 提问和选项是 LLM（和看面板的人）作答的依据，不截断；其余文字超长可以截断，以"…"结尾。
5. **只读，什么都不卡。** 面板不调用任何会改变状态的方法，也不被任何层依赖；它出错或关着，角色照样干活。
6. **面板不认识能力。** 能力特有的等待（施工等玩家确认、熔炉等烧完）由能力自己的任务阶段说清，面板不为哪个能力开专门的行。
7. **用 v1 的词。** 目标、步骤、任务、阶段、动作、主任务、临时任务、生存需求都和 09 一致；面板上的字和日志、MCP 返回里指同一样东西时用同一个词。

## 4. 两档一页

| 档 | 给谁 | 内容 |
| --- | --- | --- |
| 关 | —— | 什么都不画 |
| 简要 | 直播 | 两行常驻（目标、此刻），出事时加提醒行 |
| 详细 | 调试 | 连接、目标、任务、生存需求、结果、事件六段；可以切到"最近的目标"页 |

### 4.1 简要档

目标和此刻两块常驻，位置固定，看惯了一眼就知道往哪看：

| 行 | 内容 | 颜色 |
| --- | --- | --- |
| 目标 | 第一行只放不会变长的：能力短名 · 第 i/N 步（sequence 时）· 已做多久。purpose 另起一行写在下面（没给就用目标对象的说法），最多两行，再长以"…"结尾 | 青 |
| 此刻 | 此刻在推进的那个任务说的一句话（`describe()`）。临时任务在推进时以需求名开头，例如"自卫：……"，整行黄色 | 青 / 黄 |

手上没有目标时，目标行写"空闲，等 LLM 下达目标"；本刻没有任何任务在推进时，不显示此刻行。

提醒行按下表顺序排，越要紧越靠上：

| 情况 | 例子 | 颜色 |
| --- | --- | --- |
| MCP 没在监听，或没有宿主连着 | MCP 没在监听：端口 8766 被占用 | 红 |
| 服务端 MaiCraft 没握手 | 服务端没装 MaiCraft，交互只能靠客户端自己确认 | 红 |
| 角色死了 | 角色死了，等重生 · 已挂出死亡恢复的问题 · 40s | 红 |
| 角色在玩家手上 | 角色在玩家手上（F8），再按 F8 交回 | 黄 |
| 在等 LLM 回答 | 在等回答：要拆掉玩家盖的墙才过得去，拆吗？· 40s；下一行"选项：1 拆 / 2 绕路 / 3 放弃" | 黄 |
| 在等回答，但宿主没在听 | 同上，后面加"宿主 2m 没来读事件" | 红 |
| 暂停 | 已暂停（LLM 要求 / 重启后恢复）· 3m | 黄 |
| 主任务停在半路 | 主任务停在半路：回不到打点，等 LLM 换活 | 黄 |
| 快卡住 | 自"走到床边"之后 25s 没进展（30s 判卡住） | 黄 |
| 生存需求想插进来却插不进 | 饿了，等手上这一下做完再吃（现在停下不安全） | 黄 |
| 自己处理不了的生存需求 | 饿了，身上没吃的 · 1m 前 | 黄 |
| 刚失败 | 没做成 travel：到不了，试过的路线都不通 · 20s 前 | 红 |
| LLM 的调用接连出错 | execute 接连 3 次报错：goal.parameters.count 必须是 1 到 256 的整数 | 红 |
| 掉速 | TPS 14.2 · MSPT 70ms | 黄 / 红 |

- 行首标签只有三种：MCP 与服务端两种写"连接"；死亡、F8、等回答、暂停、停在半路写"在等"；其余写"提醒"。
- 标签只写这一行说的是谁，处境写在正文里，用整句话说。急迫程度、"被按住""没做成正在等"这类状态不当标签。
- 几个词各只指一样东西：**步骤**是目标里的第几步，只出现在目标行；**阶段**是此刻在做的那个任务的阶段；**进展**是任务报告的真实进展，判卡住就看它。"进度""经过"不用。时长只在目标行写一次（目标做了多久）。
- 前五种（连接、服务端、死亡、F8、等回答）总是显示；其余最多再显示三行，多出来的合成一行"还有 N 条，按 F9 看详细"。
- 快卡住：没进展的时长超过判卡住的一半时出现，有了新进展就消失。
- 刚失败、处理不了：从面板第一次看到起显示 60 秒；下一个目标开始时，刚失败那行提前收起。
- 接连报错：同一个工具连着两次以上报错才显示，下一次调用成功就消失。

| 段 | 行 | 内容 |
| --- | --- | --- |
| 连接 | MCP | 地址与端口 · 几个宿主 · 宿主有没有正在等事件 |
| | 调用 | 最近一次调用了哪个工具、多久前；自上次 execute 起 observe、lookup 各几次 |
| | 报错 | 最近一次调用出错：工具、`error.code`、`field`、`message`、多久前 |
| | 服务端 | 握手状况（已握手 / 协商中 / 没装 / 被拒绝 / 断开）与原因 |
| | 控制权 | 自动化 / 玩家（F8）/ 等交接；交不出去时写原因 |
| | 性能 | TPS · MSPT；连的是外部服务器时写"外部服务端，测不了" |
| 目标 | 目标 | 第一行：#编号 · 能力 · 处境（进行中 / 在等回答 / 已暂停）· 第 i/N 步 · 已做多久；purpose 另起一行，最多三行 |
| | 提问 | 在等回答时：问题与全部选项，完整显示 |
| | 许可 | 只列和默认值不同的几项，用 MCP 的字段名，例如"change_blocks=any"；全是默认值时不显示 |
| 任务 | 任务 | 控制循环的运行栈，从上往下画：第一行是角色此刻在听的那个任务，下面每行缩进一级，写被它压着的任务。临时任务写成"自卫插进来（尽快处理）：攻击，砍僵尸"，主任务写成"主任务：采掘，走到矿点"；主任务被临时任务停在半路时写"主任务停在半路：……" |
| | 阶段 | 第一行那个任务最近走过的阶段：选床 → 拿床 → 放床（现在） |

| 生存需求 | 生存需求 | 只在有需求想插进来却没插、或者上次没做成正在等着再试时出现，每个需求一句整话。例如"饥饿想插进来，可手上这一下现在停下不安全，等做完再说"；"落地防护上次没做成：快捷栏里没有水桶。32 秒后再试（已接连没做成 2 次）" |
| 结果 | 上一个 | 上一个结束的目标：编号、能力、结果状态、summary、多久前 |
| | 失败 | 最近一次失败：问题种类、`message`、`suggestion`；连着几个目标都这样失败时写 ×N |
| 事件 | —— | 最近的任务事件：时:分:秒 · 种类 · 消息；每条最多三行，整段最多十行，放不下时旧的先让位 |

### 4.3 最近的目标

在详细档里按 F9+H 切过去，再按一次切回"此刻"。首行"最近的目标 · 共 N 个 · F9+H 返回"，下面每个顶层目标一行，最近的在上，最多 12 行。sequence 里的步骤不单列，只写"第 i/N 步"。这一页是用来扫一眼的：编号、处境、能力、步骤、时间这些短字段先排，purpose 或 summary 放在最后，放不下的部分截断，完整的用 `task(get)` 看。

```text
#12 进行中 · obtain · 第 2/3 步 · 2m10s · 做一把铁镐
#11 完成 · eat · 用时 8s · 1m 前 · 吃了 1 个面包
#10 没做成 · travel · 5m 前 · 到不了：试过的路线都不通
```

颜色和 v0 相同：进行中青，在等回答与暂停黄，没做成红，完成绿，取消灰。

## 5. 每一行从哪读

面板只认一份现状快照 `StatusSnapshot`，由启动层每刻取齐（`StatusReader` 由启动层实现）。面板包不碰 MCP 入口和能力，读不到的值显示"读不到"。

| 行 | 来源 | 现在有没有 |
| --- | --- | --- |
| MCP 地址、会话数 | `EmbeddedMcpService` 的 `isRunning`、`port`、`sessionCount` | 有；启动失败的原因要补 |
| 调用、报错、在等事件 | MCP 入口在 `ToolDispatcher` 处记下的最近调用 | 没有，要补 |
| 服务端握手 | `ServerCapabilityState` 的 `state`、`reason` | 有，`ServerLinkSession` 还没露出来 |
| 操作 | `PlayerControlBoundary`：`automationOwnsControls`、`humanTookOver`、`controlUnavailableReason` | 有 |
| 性能 | 集成服务端的 `getAverageTickTimeNanos` 与 `tickRateManager` | 有；v0 的 `perfText`、`perfColor` 纯函数照搬 |
| 目标、步骤、许可、提问 | `GoalRunTable` 的 `mainGoal`、`recent`、`pendingQuestion` | 有 |
| 任务 | `ControlLoop` 的运行栈 | 只有 `currentTask()`，要补只读的栈 |
| 生存需求想插没插、停在半路、等重生 | 每刻 `ControlLoop.tick` 返回的 `Decision` | 有，但启动层现在把它丢了 |
| 生存需求没做成在等再试 | `ControlLoop` 里的 `backoffs`、`failureStreaks`，以及上次没做成的原因 | 私有，要补只读视图；原因现在没记，要补 |
| 进展、阶段 | `ProgressTracker` 与 `PhasedTask` 的阶段 | 私有，要补（第 8 节） |
| 事件 | `TaskEventLog.read`：按游标读，不推进任何读者的游标 | 有 |

**时长按现实时间算，由面板自己记。** 现状快照每刻都取，面板关着也取（只是不排版）。面板记下每个状态第一次被看到的时刻，比如某个目标进入"在等回答"、某条事件出现，"已等多久""多久之前"都从这里算。这样不用给任务事件和目标运行补时间字段；LLM 的等待和直播都按现实时间走，单人游戏按 ESC 暂停时也照实累计。

唯一例外是"进展"行：它直接用进度跟踪的刻数（只算任务真被推进的刻，被打断的时间不算），行里写明这一点。判卡住用的也是这把尺子，两者放在一起才对得上。

## 6. 按键与设置

| 按键 | 做什么 |
| --- | --- |
| F9 | 关 → 简要 → 详细 → 关 |
| F9+H | 在"此刻"和"最近的目标"之间切换；面板关着或在简要档时，直接打开详细档的"最近的目标" |
| F9+N | 开关导航路线（世界里的线：地面路线、飞行路线、目的地、当前转向点），和档位无关 |

- 和 v0 一样直接读窗口按键（GLFW），容器界面打开时也能切，调试容器界面的流程正需要这个。按住 F9 时再按字母只算组合键，不会顺带切档。
- 不用 A（原版向左走）和 P（原版社交互动界面）；H、N 在原版 1.21.1 都没有默认绑定。实测实例的模组有没有占用 H、N，实机验收时核对。
- 档位和路线开关存在 `config/maicraft-debug.properties`，不再和施工预览共用一个文件。第一次装上默认是关，免得直播画面里突然多出一块。页不存，每次打开都从"此刻"开始。
- 每次切换在动作栏提示一句，例如"调试面板：详细（再按 F9 关闭，F9+H 看最近的目标）"。

## 7. 排版

- 画在左上角。按 F1 隐藏界面时不画；打开原版 F3 调试屏时让位不画，两者都占左上角。容器界面打开时照画。
- **每档固定宽度**：简要档取界面宽度的 30%（200 到 280 个界面像素），详细档取 45%（300 到 420）。宽度只随窗口大小和界面缩放变，不随内容变；文字在这个宽度里折行。
- 一行内容折行后最多两行（简要）或三行（详细），超出的以"…"结尾；提问和选项不受这个限制。
- 详细档总高度不超过界面高度的 60%。放不下时先让事件段里旧的事件让位，再截断结果段。
- 底色沿用 v0 的半透明深色。颜色语义也沿用 v0：青是在做，黄是在等或在让路，红是出错或断开，绿是完成或正常，灰是标签和次要文字。
- 时长写成 `45s`、`3m20s`、`1h05m`；事件时间写成 `时:分:秒`，方便和日志对照。

## 8. 包内结构与要补的接口

`debug` 包只读，可以依赖到玩家行为层与 Minecraft 客户端，只有启动层引用它（`LayerRulesTest` 已经这样检查）：

| 类 | 做什么 |
| --- | --- |
| `DebugPanel` | 每刻读按键、切档、取现状快照、交给排版，留下排好的行给渲染 |
| `StatusSnapshot` | 一刻的现状：第 5 节表里的全部字段，都是不可变的值 |
| `StatusReader` | 取一份现状快照的接口；启动层实现，把 MCP 入口、控制循环、目标运行表读到的值抄进来 |
| `FirstSeenTimes` | 每个状态、每条事件第一次被看到的现实时间 |
| `PanelLayout` | 纯函数：现状快照 + 档 + 页 + 宽度 + 量字宽的函数 → 一组带颜色的行，离线可测 |
| `PanelRenderer` | 把排好的行画出来，不做任何判断 |
| `NavigationPathRenderer` | 世界里的路线；从 v0 移植，读 `NavigationPathSnapshot` |
| `PanelSettings` | 档位与路线开关的读写 |
| `PanelLevel`、`PanelPage` | 关 / 简要 / 详细；此刻 / 最近的目标 |

- 取快照和排版都在客户端线程上做，和控制循环同一线程，读到的状态前后一致；渲染只读最近一份排好的行。
- 取快照或排版抛异常时，面板只显示一行"面板读取出错：异常类名"，同一种异常只记一次日志；异常不往外抛，不影响这一刻的其他工作。
- 现状快照由启动层抄好再交进来，面板手里没有任何能改状态的对象。"只读"由依赖关系保证，不靠自觉。

别的层要补的接口，都只加读、不改行为：

| 层 | 补什么 | 给哪一行 |
| --- | --- | --- |
| `kernel.task` | `Task` 加一个默认为空的只读进展视图。`PhasedTask` 返回：这件事的名字、当前阶段与动作、最近 5 次换阶段（从哪到哪、理由）、上次进展、多少刻没进展、多少刻判卡住、已推进与最多推进的刻数。`GoalRunner` 和其他运行子任务的地方转给正在跑的那一层 | 进展、阶段；此刻行也改用最深一层的说法，去掉"目标 obtain："这层重复前缀 |
| `kernel.interrupt` | `ControlLoop` 的只读栈（每层：任务、哪个需求插进来的、急迫程度、是否停在半路），以及没做成正在等着再试的需求（名字、急迫程度、等到哪一刻、接连没做成几次、上次为什么没做成） | 任务段、生存需求段 |
| `bootstrap` | 留下每刻 `ControlLoop.tick` 返回的 `Decision` | 生存需求想插没插、停在半路、等重生 |
| `game.serverlink` | `ServerLinkSession` 露出握手状况 | 服务端 |
| `mcp` | 在 `ToolDispatcher` 处记最近的调用：每个工具最近一次调用的时刻、最近一次出错的调用、同一工具接连出错的次数、自上次 execute 起各工具的次数、正在等着的 events 请求数；另记 MCP 启动失败的原因 | 连接段，以及"接连报错""宿主没在听"两条提醒 |

`PhasedTask.describePhase` 默认用枚举名。面板如实显示：看到英文枚举名，就说明这个任务还没写阶段的中文名。缺口留在面板上让人看见，不在面板里替它翻译。

## 9. 施工预览与面板的边界

v0 的预览通过 `BuildPreviewGate` 和心跳卡住任务调度，所以面板专门有一行"蓝图"，显示"等待确认"。v1 的预览不再卡住任务（02 第 6 节）：施工任务要等玩家确认时，自己停在一个阶段里，并在 `describe()` 里说清楚，面板照常显示在此刻行。预览的渲染、开关和逐层查看随建造规格一起定，它的开关不和面板档位绑在一起。

## 10. 验收

离线（`PanelLayout` 是纯函数，用假的现状快照和假的量字宽函数）：

1. 彻底空闲：简要档只有"空闲，等 LLM 下达目标"一行。
2. 很长的 purpose：目标行第一行的短字段完整，purpose 在下面折两行后以"…"结尾。
3. 单步目标正常推进：目标、此刻两块，没有提醒行。
4. 临时任务插进来：此刻行以需求名开头、变黄；详细档任务段两行，临时任务在上，主任务缩进在下。
5. 在等回答：问题与全部选项完整显示，不受行数上限截断；宿主没在听时变红。
6. F8 接管、死亡等重生、停在半路、暂停：各自的提醒行和颜色。
7. 快卡住：没进展超过判卡住的一半时出现，有新进展后消失。
8. 提醒行超过上限：前五种都在，其余最多三行，末行写"还有 N 条"。
9. 宽度：内容长短变化时宽度不变，折行不超出宽度。
10. 取快照抛异常：只有"面板读取出错"一行。
11. 按键：F9 三档循环；面板关着时按 F9+H 直接打开详细档的"最近的目标"；按住 F9 再按 H 不会顺带切档。

实机（实测实例与开发客户端各一遍）：

1. 简要档开着，挖矿、被僵尸打、吃东西、睡觉各来一轮，录屏看画面是否安静、提醒是否及时。
2. 打开箱子时面板照常显示；按 F1 隐藏；打开 F3 时让位。
3. F9+H、F9+N 不触发任何原版或模组按键（核对实测实例的按键设置）。
4. 分别关掉 MCP 宿主、去掉服务端 MaiCraft，看提醒行。
5. 面板开着跑一小时，MSPT 与不开时没有明显差别。
