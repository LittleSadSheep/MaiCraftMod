# 08 实现规范（v2 的代码怎么写）

02 定的是"包和层"，03 定的是"游戏行为"，这一份定的是**一个类、一个方法该怎么写**。v1 的很多问题出在这一层：

| 现状 | 数量 |
| --- | ---: |
| 执行层（`core/task`、`core/integration`）里直接读写 `JsonObject` 的文件 | 193 |
| `Map<String, Object>` 的出现次数（回执、进度、诊断几乎全用它） | 1129 |
| 一个执行器的私有字段数（`FirstPersonBuildCompanionTask`） | 108 |
| 同一个执行器里的 `if` | 525 |
| 静态工具类 `*Ops` | 13 个，2038 行 |
| `TaskRecord.setState` | 不校验状态迁移，任何状态都能改成任何状态 |
| 失败类型 | 一部分用字符串比较（`"occluded".equals(...)`） |

本规范约束 v2 的全部代码，包括从 v1 移植过来、又做过整理的文件。

## 1. 一个能力包的标准结构

```text
ability/sleep/
├─ SleepModule.java          注册入口：描述符、翻译、执行器工厂（唯一对外的类）
├─ SleepParams.java          类型化参数 record + ParamSpec
├─ SleepPlanner.java         翻译：Goal + 现场 → 下一个动作（纯函数为主）
├─ SleepExecutor.java        执行器：按阶段推进
├─ SleepFacts.java           本能力特有的回执事实 record
├─ BedChooser.java           本能力特有的决策（纯函数，可离线测试）
└─ （api/、spi/ 仅在确有外部使用方时才建）

resources/assets/maicraft/abilities/sleep.md      契约正文
test/…/ability/sleep/                             离线场景测试
```

除了 `SleepModule`，包里的类一律包内可见（不写 `public`），让 Java 本身挡住跨能力的内部依赖。

## 2. 类型纪律

| 规则 | 说明 |
| --- | --- |
| **`JsonObject` 只出现在入口与参数规格框架** | 入口用 `ParamSpec` 把参数解析成类型化的 `Params`，能力再转成自己的参数 record；翻译和执行器从不 `getAsInt` |
| **回执用 record，不用 Map** | 每个能力定义自己的 `Facts` record；统一回执（03-M8）由 `Outcome` record 表达；序列化成 JSON 是入口的事 |
| **失败用枚举** | `Blocker.Kind` 是枚举；任何地方不比较失败字符串 |
| **状态用枚举阶段，不用布尔字段** | 执行器的进度是一个 `Phase` 枚举，加上每个阶段自己的少量数据。禁止用 `boolean enteredSleep; boolean morningObserved; boolean nightSkipped…` 拼出隐式状态机 |
| **任务单是不可变输入** | 任务单（record）只描述"要做什么"；执行中的可变状态只在执行器里。生命周期由 `TaskHandle` 校验（PENDING → RUNNING → FINISHED，终态不可再改） |
| **不用静态可变状态** | 服务从构造函数注入（内核服务、行为模型，见 02 第 5.7 节）。不写 `X.get()` 单例，不写可变 `static` 字段（护栏强制） |
| **不用静态工具类装业务逻辑** | 业务规则属于某个模型或能力；纯几何、纯数学的小工具可以是静态方法 |
| **时间单位** | 内部用游戏刻；对外（参数、回执）用秒；换算只在入口和回执组装处做 |

## 3. 执行器的写法：阶段

v2 所有执行器都继承 `kernel.task.PhasedExecutor`（以代码为准，这里说明怎么用）：

| 子类要写的 | 作用 |
| --- | --- |
| 构造器 `super("睡觉", Phase.CHOOSE_BED, new ProgressMeter(停滞窗口, 总上限))` | 名字、第一个阶段、按本能力节奏给出的进度表 |
| `Step enter(P phase)` | 进入某阶段时调用一次，返回这个阶段的子步骤；纯决策的阶段返回 null |
| `Next<P> tick(P phase, TickContext context)` | 每刻推进当前阶段：`Next.stay()`、`Next.go(阶段, 原因)`、`Next.done(回执)`、`Next.fail(卡点)` |
| 可选：`facts()`、`remaining()`、`describePhase()`、`onTransition()` | 能力特有事实、没做完的部分、阶段中文名、换阶段后的扩展点 |

| 基类提供的 | 作用 |
| --- | --- |
| `runThen(context, () -> 下一步)` | 推进子步骤一刻：还在做就留在本阶段，失败就把卡点原样上抛，做完了才执行给定的转移 |
| `run(context)` | 只推进子步骤一刻并返回状态，用于需要自己看失败原因的阶段 |
| `achieved(效果)`、`uncertain(效果)`、`attempt(办法, 结果)` | 记下效果、未确认的操作、尝试过的办法；结束时自动进回执 |
| `progressed(信号)` | 报告一次不经过子步骤的真实进展 |

基类统一负责：换阶段时关闭旧子步骤、准备新子步骤并写日志；被抢占时暂停子步骤，结束时收尾；
停滞判定（**换阶段本身不算进展**）；组装统一回执；被替换、取消或失去身体时如实交代已发生的效果；
处在阶段之间时汇报"空闲"，让舒适需求可以插进来。

### 样例：睡觉执行器的骨架

按 06 规格，只展示结构。`behaviors.*` 的子步骤 API 是示意，以阶段 3 行为模型的实现为准。

```java
/** 公开"睡觉"的执行器：选床 -> （没床就放自带床或现做一张）-> 走到床边 -> 躺下。 */
final class SleepExecutor extends PhasedExecutor<SleepExecutor.Phase> {

    enum Phase { CHOOSE_BED, GET_BED, PLACE_BED, APPROACH, LIE_DOWN }

    private final SleepRecord record;
    private final Behaviors behaviors;
    private final BedChooser chooser;
    private BedChoice bed;                       // 选中的床：世界里原有的，或刚放下的自带床
    private BedSource source = BedSource.WORLD;

    SleepExecutor(SleepRecord record, Behaviors behaviors) {
        super("睡觉", Phase.CHOOSE_BED, new ProgressMeter(STALL_TICKS, MAX_TICKS));
        this.record = record;
        this.behaviors = behaviors;
        this.chooser = new BedChooser(behaviors.memory(), record.mandate());
    }

    @Override protected Step enter(Phase phase) {
        return switch (phase) {
            case CHOOSE_BED -> null;
            // 身上没床：用身上、随身背包、已知箱子里的材料拿到一张床（M4），羊毛不够就剪羊毛或打野生羊
            case GET_BED -> behaviors.procure().errand(ItemTags.BEDS, 1, Purpose.SLEEP);
            // 把床放到站位能看见床头、又不会压到自己的两格上（M2 选位 + M3 放置）
            case PLACE_BED -> behaviors.place().carriedBed();
            // 走到同时满足服务端床距离盒、交互距离和视线的工位；被挡住时由 M2 换工位
            case APPROACH -> behaviors.reach().approach(Workspot.forBed(bed.head()));
            // 右键床头并确认真的躺下；确认窗口内日期前进，说明一觉睡到了天亮，也算成功（M3）
            case LIE_DOWN -> behaviors.act().use(bed.head(), SleepConfirmation.INSTANCE);
        };
    }

    @Override protected Next<Phase> tick(Phase phase, TickContext context) {
        return switch (phase) {
            case CHOOSE_BED -> chooseBed(context);
            case GET_BED -> runThen(context, () -> {
                source = BedSource.CRAFTED;
                return Next.go(Phase.PLACE_BED, "拿到了床");
            });
            case PLACE_BED -> runThen(context, () -> {
                bed = BedChoice.placedAt(behaviors.place().lastPlaced());
                if (source == BedSource.WORLD) source = BedSource.CARRIED;
                achieved(Effect.of(Effect.Kind.BLOCK_PLACED, bed.blockId(), 1));
                return Next.go(Phase.APPROACH, "床放好了");
            });
            case APPROACH -> runThen(context, () -> Next.go(Phase.LIE_DOWN, "到床边了"));
            case LIE_DOWN -> lieDown(context);
        };
    }

    private Next<Phase> chooseBed(TickContext context) {
        // 下界、末地用床会爆炸，这是原版规则：不提问，直接结束并说明
        if (!WorldRules.bedsWork(context.body().level())) {
            return Next.fail(Blocker.of(Blocker.Kind.WORLD_RULE, "这个维度用床会爆炸"));
        }
        Optional<BedChoice> found = chooser.choose(context, record.area());
        // 已加载范围分几刻扫完；没扫完不能当成"附近没有床"
        if (found.isEmpty() && !chooser.scanComplete()) return Next.stay();
        if (found.isPresent()) {
            bed = found.get();
            progressed("选中了" + bed.describe());
            return Next.go(Phase.APPROACH, "选中了" + bed.describe());
        }
        // 附近没有能用的床：身上有就放自带的，没有就先去弄一张
        return behaviors.inventory().has(context, ItemTags.BEDS)
                ? Next.go(Phase.PLACE_BED, "附近没有能用的床，放自带的")
                : Next.go(Phase.GET_BED, "附近没有床，身上也没有，先弄一张");
    }

    private Next<Phase> lieDown(TickContext context) {
        StepStatus status = run(context);
        if (status instanceof StepStatus.Running) return Next.stay();
        if (status instanceof StepStatus.Done) return Next.done(Outcome.done("躺下了"));
        // 被服务端拒绝时，按提示语分流（完整分流见 06 第 3 节）：被占用就换床，床边有怪交给威胁评估
        Blocker refusal = ((StepStatus.Failed) status).blocker();
        return switch (SleepRefusal.of(refusal)) {
            case OCCUPIED -> {
                chooser.exclude(bed);
                yield Next.go(Phase.CHOOSE_BED, "床被占了，换一张");
            }
            case MONSTERS_NEARBY -> Next.go(Phase.CHOOSE_BED, "床边有怪，重新选床");
            case OTHER -> Next.fail(refusal);
        };
    }

    @Override protected Facts facts() {
        return new SleepFacts(source);
    }
}
```

和 v1 的 `SleepCompanionTask` 加上 `AbilityAdapter.sleep()` 对比：瞄准、确认、回执归还、换工位、面板描述、停滞判定、回执组装全都不在这里了；这里只剩"睡觉"这件事本身的流程。

## 4. 决策与执行分开

- **决策类**（`BedChooser`、`Workspot` 的选位、`ThreatAssessment`、`Procurement` 的询价）写成纯函数：输入只读接口（`WorldQuery`、`InventoryView`、`MemoryView`、`MandateView`），输出结论 record。不碰身体，不读 `Minecraft.getInstance()`。
- **执行类**（执行器、子步骤）只负责把结论变成原生操作，并如实对账。
- 好处：决策类可以用替身做离线测试，覆盖率要求 100%；执行类用"子步骤替身"测试（第 8 节）。

## 5. 规则常量

每个会改变角色行为的常量（距离、阈值、上限、窗口），都写成命名常量，并在注释里标明类别与来源：

```java
/** 醒来的实体包和时间包不在同一刻到达，醒后留出的同步窗口。F 游戏事实，来源：122 实机。 */
static final int WAKE_SYNC_TICKS = 200;
```

类别用 03 第 4 节的五类。**v2 不允许出现 P、G、S 类常量**：发现需要它们，说明某个模型有缺陷，应该修模型。

## 6. 每刻预算

昂贵的扫描（找方块、找床、场景感知、路线探测）不得在单刻内跑完，也不得各自实现分帧。统一使用平台层的分帧扫描服务：提交查询，之后每刻查询进度，结果带"是否扫完"。"没扫完"永远不能当成"没有"。

## 7. 日志、面板与事件

- 阶段切换、子步骤开始和结束、阻塞原因，由基类统一记录，同时驱动调试面板和 Attention 进度事件。
- 能力代码里只在出现领域特有的关键事实时才写日志，每个类用 SLF4J 的 `LoggerFactory.getLogger(本类.class)`，不再手写 `[maicraft-sleep]` 这类前缀。

## 8. 测试

测试用 JUnit 5，放在 `common/src/test/java`，与被测类同包。`./gradlew :common:test` 跑全部，`--tests <测试类>` 只跑相关的。

| 被测对象 | 写法 |
| --- | --- |
| 决策类 | 用替身接口构造场景（世界、背包、记忆），直接断言结论 |
| 执行器 | 用子步骤替身（参考 `kernel/task/ScriptedStep`）：按脚本逐刻返回"在做 / 有进展 / 做完 / 失败"，断言阶段走向、最终回执和事实 |
| 行为模型 | 决策部分同"决策类"；执行部分用平台端口替身（脚本化的回执结果） |
| 能力契约 | 契约快照（WP-2.4） |
| 真实游戏 | 只在实机验收清单里验证，离线测试不模拟 Minecraft 物理 |

- 测试不使用 `Unsafe`，不用反射改私有成员（护栏强制）。需要读执行器内部状态时，说明这个状态该进回执或事实。
- 断言用 JUnit 自带的 `Assertions`。
- 每个领域规格第 9 节的场景，都要有对应的离线测试或实机验收项。

## 9. 线程

- 所有游戏状态只在客户端线程读写。网络线程只在入口层通过 `onClient` 把请求交给客户端线程（沿用 v1 的做法，它是对的）。
- 禁止自己开线程或使用 `CompletableFuture` 链访问游戏对象。联网资料等确需后台线程的工作，集中放在 `gateway.knowledge`。

## 10. 大小上限

| 对象 | 上限 | 超过怎么办 |
| --- | ---: | --- |
| 类 | 800 行（护栏强制） | 拆阶段或拆决策类；确需例外，登记在 `common/src/test/resources/architecture-exemptions.txt` 并写明理由 |
| 方法 | 80 行（护栏强制） | 拆方法 |
| 执行器的字段 | 15 个 | 阶段私有的数据收进阶段自己的小 record |
| 一个阶段的 `tick` | 40 行 | 说明这个阶段做了不止一件事，再拆 |

## 11. 术语对照（一个概念只有一个名字）

| 中文 | 类名 | 含义 |
| --- | --- | --- |
| 能力 | `AbilityModule` | LLM 能下达的一种意图 |
| 任务单 | `TaskRecord` | 一件具体工作的不可变输入 |
| 执行器 | `PhasedExecutor` | 逐刻做事的对象 |
| 任务生命周期 | `TaskHandle` | 内核记录的编号、状态、结果与起止时刻 |
| 阶段 | `Phase` | 执行器流程中的一段 |
| 子步骤 | `Step` | 行为模型提供的可组合动作 |
| 工位 | `Workspot` | 能对目标做某个动作的站位 |
| 差事 | `Errand` | 为主任务或身体维护顺带做的一件小事（取物、吃饭、睡觉） |
| 需求 | `Need` | 身体维护的一项需要，带紧急程度 |
| 授权 | `Mandate` | 允许伙伴改变世界到什么程度 |
| 句柄 | `Ref` | 观察对象的短期编号（`e12`、`f3`、`b5`） |
| 卡点 | `Blocker` | 任务做不下去的原因，以及解除它需要什么 |
| 结果 | `Outcome` | 统一回执 |
| 事实 | `Facts` | 能力特有的回执字段 |
