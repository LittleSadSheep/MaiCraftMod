# MaiCraft v1 设计总览

> 设计：Claude（Opus 5.5），2026-10-08
> 执行：ChangingSelf 及其 Agent
> 拍板：LittleSadSheep、ChangingSelf

版本叫法：**v0** 是旧项目（`dev` 分支，0.1.x），**v1** 是这次的重建（`v1` 分支）。

## 结论

先把整个 v0 从入口到测试、从 Mod 到 Amaidesu 宿主逐层看了一遍（[00-全景审查](00-全景审查.md)），再下的结论：

> **从零重建 v1（`v1` 分支），v0 冻结维护（`dev` 分支）。**

- v0 冻结：不再加功能，只修影响直播的问题；继续承担直播，直到 v1 在对应里程碑达到切换标准。
- v1 从零按新架构建设。v0 里已证明正确的基础代码按[移植清单](移植清单.md)搬过来；其余全部按领域规格重写。
- 直播按里程碑分批切到 v1：生存开局 → 建造与采矿 → 机器 → 载具与飞行。
- Amaidesu 新增面向 v1 的 Minecraft Agent，通过配置在 v0 / v1 之间选择。

总的取舍原则（LittleSadSheep，2026-10-08）：**怎么合理怎么来**；这是直播项目，**能做事就不干等**。

## 完成标准（整体）

- 内核层和游戏接口层不认识任何具体能力（架构检查强制）。
- 新增一个能力只需要：写它自己的包，在启动清单里加一行，再补能力说明资源、能力文档和更新日志。
- 同一条游戏事实（交互距离、可以睡的时间、背包满、饥饿……）全仓只有一处实现。
- LLM 通过 `observe` 能看到玩家视野里的地形和实体，知道它们在哪个方向、多远，并能用观察编号直接指定目标。
- 每个能力都有接口快照和场景测试；测试不反射进私有实现（架构检查强制）。
- 任何"拒绝执行 / 提前失败"都登记了类别（03 第 4 节五类），P、G、S 类不存在。
- 四个里程碑全部达标，所有直播使用 v1，v0 打 `v0-final` 标签归档。
