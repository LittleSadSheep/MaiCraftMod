# 记地点、聊天与按顺序做事 领域规格

> 状态：已批准（两位，2026-10-09），按第 9 节建议执行。
> 依据：v0 `dev` `aa97940c9` 的 `remember_place`（`SemanticAbilityCatalog` 第 430–491 行）、出行旧逻辑清单 T-18、感知旧逻辑清单 S-48；`sequence` 的推进已由 WP-2.3 在 `GoalRunner` 里实现，本规格只补能力本身和许可怎么往下传。

## 1 范围

| 能力 | 做什么 | 执行方式 |
| --- | --- | --- |
| `remember` | 记住或忘掉一个按名字叫的地点 | 只改记忆，当场完成 |
| `chat` | 向游戏聊天发一句话 | 控制角色（已实现） |
| `sequence` | 按顺序做几件事 | 控制角色 |

## 2 真人怎么做

- 记地点：站在家门口想"这是家"，或者指着远处的矿洞口说"那是矿洞"。记的时候不用停下手上的活。改记一个名字时，心里清楚原来记的是哪儿。
- 忘地点：只能忘掉记得的；说不出名字时会去想"我记得的都叫什么"。
- 按顺序做事：一件做完再做下一件；中间哪件没做成，要么停下来想办法，要么跳过接着做，取决于这件事要不要紧。整件事开始时说好的规矩（别打动物、别碰家），每一步都照样守。

## 3 remember

**参数**

| 名字 | 必填 | 说明 |
| --- | :---: | --- |
| `name` | ✅ | 地点名。首尾空白去掉后原样比较，不改大小写 |
| `operation` | | `remember`（默认）/ `forget` |

**目标对象**（只用于 `remember`，省略就是 `here`）

| kind | 记下的位置 |
| --- | --- |
| `here` | 角色此刻脚下那一格 |
| `seen` | 观察编号指向的位置；实体是最后一次看到它的位置 |
| `landmark` | 另一个记住的地点的位置，用来给同一个地方再起一个名字 |
| `position` | 给的坐标；**必须给 `y`**（见 D4） |

`player`、`direction`、`previous` 不接受：玩家在场景里有观察编号，用 `seen`；`previous` 见第 6 节缺口。

**规矩**

- 记下的位置都带维度：没写维度的，按角色此刻所在的维度记。
- 同名覆盖。结果写出原来记在哪；位置没变时直接完成，说"本来就这样记着"。
- 忘掉：只忘名字对得上的那一个。名字没记过就失败（`NOT_FOUND`），结果附上记得的全部地点名。
- 不移动角色、不读地形、不核实那里能不能站人。这些交给真正去那里的能力。
- 当场完成：`execute` 直接返回结果，不成为主任务，也不打断手上正在做的事。放进 `sequence` 时，按顺序轮到它才记。

**结果**

`summary` 一句话说记了什么。细节：`name`、`operation`，记住时有 `position`，改记或忘掉时有 `previous_position`。

## 4 chat

已按 v1 实现（`ability/chat`），本规格只把它的决定写下来：

- 完成以聊天栏出现自己那条（本地回显）为准。5 秒内没看到回显，结果仍是完成，同时在 `unconfirmed` 里记一条，提醒不要盲目重发。
- 以 `/` 开头的是游戏命令，一律不执行，开局就以 `REFUSED_BY_GAME` 结束（D6）。

## 5 sequence

- 能力本身没有参数，也不接受目标对象，只接受 `steps`。每一步是一个完整的目标：能力、参数、目标对象、许可、`on_failure`。
- 逐步跑，上一步结束才开始下一步。某一步没做成时，看这一步的 `on_failure`：`stop`（默认）整件事停下，`continue` 接着做下一步。
- 结论：全部做成是完成；一步都没做成是失败；其余是部分完成。`remaining` 列出没做成和没开始的步骤。每一步已经发生的变化都并进整件事的结果。
- 某一步要问 LLM 时，整件事停下等回答；`goal(answer)` 回答的就是这一步的问题。
- 暂停、取消都作用于整件事。重启后整件事恢复为暂停，解除暂停后从中断的那一步接着做。
- `sequence` 里还能套 `sequence`，最多 3 层。
- **许可往下传**（D5）：步骤自己没写的许可字段，沿用整件事的；写了的以步骤为准。`protected_landmarks` 取两边的并集。

## 6 缺口（不在本次实现）

- `previous` 目标（"前面某一步确认过的位置"）：内核还没记各步骤确认过的位置，没有东西可以解析。`use`、`deposit` 的规格原先声明接受它，实际用不了，现已从两者接受的目标里拿掉，接上后再加回去。要做的话，先在任务结果里加"确认过的位置"，再由目标推进按步骤号查。

## 7 和 v0 不同的地方

| v0 | v1 | 理由 |
| --- | --- | --- |
| `remember_place` 是普通任务，会抢走角色、替换手上的任务 | 当场完成，不打断手上的事 | 记一下地点不需要停下来 |
| 地标超过上限时按先后悄悄淘汰最旧的，结果里不说（T-18） | 不设条数上限，不淘汰 | 悄悄丢掉记忆会让后面的出行莫名其妙失败 |
| 坐标省略维度时维度"不确定" | 按此刻所在的维度记 | 记忆里的地点要能直接拿来出行 |
| 参数 `label`、`area_role`（`managed_settlement`） | 参数 `name`；没有 `area_role` | 名字统一用参数名表里的 `name`。要保护一片地方，记住它之后在任务许可的 `protected_landmarks` 里写它的名字 |
| 名字忽略大小写 | 原样比较 | 中文名字没有大小写；英文名字写法不一的情况等实机见到再说 |

## 8 验收

- 用 MCP 客户端：`execute` 记住 `here` 为"家"，`observe(world_memory)` 看到"家"；走开几步再 `observe(detail, id="家")` 给出方位与距离；`forget` 之后查不到。
- 主任务在跑时记一个地点，主任务不受影响。
- `sequence`：`travel` 到一个坐标，再 `remember` 当地为一个名字，再 `chat` 说一句话；三步都做成，结果是完成。中间一步给错（例如去不了的地方）且 `on_failure` 为 `stop` 时，结果是失败或部分完成，`remaining` 列出没开始的步骤。

## 9 待拍板

| 编号 | 问题 | 建议 |
| --- | --- | --- |
| D1 | `remember` 是否当场完成、不占主任务 | 是 |
| D2 | 同名覆盖、不设上限 | 覆盖，结果写出原来记在哪；不设上限、不淘汰 |
| D3 | 忘掉没记过的名字 | 失败（`NOT_FOUND`），附上记得的地点名，免得写错名字被当成已经忘掉 |
| D4 | 按坐标记地点要不要必须给 `y` | 必须给。记住的地点会被出行当作确认过的目的地，不能存猜的高度；不知道高度就先走过去，再用 `here` 记 |
| D5 | `sequence` 的许可怎么往下传 | 步骤没写的字段沿用整件事的，`protected_landmarks` 取并集 |
| D6 | 指令禁令（待拍板清单第四节的缺口） | 归 `chat` 能力，已实现：角色不执行任何游戏命令。实机验收要用的命令由测试者自己在游戏里敲 |

## 10 修订（2026-10-09，所有者已追认）

指令禁令由「一律拒绝」修订为「**默认拒绝，实例配置可由所有者放开**」：

- 开关在实例配置文件（`config/maicraft.json` 的「允许执行游戏命令」），默认关；只有启动游戏的所有者能改，LLM 的任何工具都触不到它。
- 放开时 chat 对 `/` 开头的消息放行，走原生命令通道，以玩家自身权限执行——服务器仍是最终裁决者；能力说明如实告知 LLM「本实例允许执行游戏命令」。
- 关闭（默认）时维持「角色不执行任何游戏命令」，实机验收要用的命令由测试者自己在游戏里敲。
- 动机：直播承诺由默认值与主播把关守住；个人玩家（不开直播、单机开作弊玩）对「让角色帮我执行命令」有正当需求，且这不引入新权限——命令本来就在玩家自己的权限内。

## 11 收到的聊天（2026-10-09，所有者批准）

**真人怎么做**：玩家看聊天栏知道谁说了什么——别人在公屏说话、有人私聊自己、服务器播报谁进来了谁死了。看到了怎么回应，是人自己的判断，聊天栏里的话不会替他做决定。

**做法**：

- 收到的聊天单独一条流，宿主用 `events(topic=chat)` 按游标读、没有新消息时等一会儿；字段与规则写在 07 的 `events` 一节。不进任务事件流：服务器刷屏时不能把目标的事件挤掉。
- 玩家说的话带发言人名字与 UUID；别人私聊角色时标 `private`，念不念、怎么回由宿主决定。
- 服务器的系统消息全收（进出、死亡播报、公告、命令反馈），由宿主筛。
- 角色自己说的话按发言人 UUID 认出来，不进这条流；动作栏提示不是聊天，也不进。
- Mod 不限流、不去重，照实记；只把超过 1024 字的原话截断并标 `truncated`（原版玩家聊天上限 256 字，只有系统消息可能很长）。
- 原话是不可信的外部文字，只是别人说的话，不带任何许可，也不让角色做任何事。
- 读聊天由加载器的聊天事件转进来（NeoForge 的 `ClientChatReceivedEvent`、Fabric 的 `ClientReceiveMessageEvents`），能拿到发言人与消息类型；聊天栏的 Mixin 只拿得到文字，留给 `chat` 确认回显用。

**和 v0 不同的地方**：v0 在 Mod 里限流（10 秒 8 条）并压掉 5 秒内重复的话，只报被压掉的条数；v1 照实记，由宿主处理。v0 把自己的回显标 `from_self` 交给宿主滤，v1 在 Mod 里就不收。v0 不区分私聊，v1 标 `private`。

**验收**：

- 离线：玩家聊天、私聊、系统消息、自己的回显、动作栏提示、空白消息、超长消息各一条，流里的内容与上面一致；换世界后旧游标得到 `stream_changed`。
- 实机：另一位玩家在公屏说一句、私聊角色一句、有人进出服务器，`events(topic=chat)` 依次读到；角色用 `chat` 说的话不出现在这条流里。
