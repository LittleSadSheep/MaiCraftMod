# 出行 旧逻辑清单（v0 dev 提交 aa97940c9）

术语说明：v0 把公开能力叫「语义能力」，把一次能力调用产生的执行单元叫「任务单」（任务记录），把任务完成后的结构化返回叫「回执」；「走行段」「登岸段」「中转段」指一次移动里按交通方式或地形切出的子行程。下文直接使用这些原叫法。

## 2 主流程

1. **能力入口**：`goal.ability = "maicraft:travel"` → `AbilityAdapter.adapt()`（82 行）→ `travel(goal, player, runtime)`（578 行）。规划阶段 `SemanticGoalContract`（165 行）先做一次参数校验（`invalid_travel_contract`）。
2. **适配层分发**（按优先级）：
   - 已登记飞机 → `AircraftTravelIntent`（飞行，不在本文范围）；
   - 电梯楼层 → `ElevatorTravelIntent`；
   - `structure_id`（船体编号）→ 校验独占后发 `board_structure`（只支持 jetpack 登船）；
   - 发现类目标 `discovery=platform` → `travel_region`（方向 + 半径 8–128，默认 64）；
   - `discovery=surface` → `travel_surface`（无方向）；
   - `destination` 坐标（`TravelDestination.fromGoal`）→ 校验维度：目标维度 ≠ 当前维度 → **提问**（先 `maicraft:travel_dimension` 还是取消）；
   - 只有语义目标（地标 / 群系 / 海岸）→ 解析地标；解析不了或需要飞行方式才能去未定位目标 → 各种**提问出口**（见第 4 节）；海岸 / 群系发现 → 发 `explore`；
   - 都没有 → 发 `goto`（带 `exact`、`horizontal_radius`、`vertical_tolerance`、三个许可开关）。
3. **goto 工具**（`MoveToTool` → `MovementOps.moveTo`）→ 建 `MoveToTaskRecord`：按字段组合定四种目标之一（`resolveKind`：block 单独给=FIND；x+z=COLUMN；x+y+z=BLOCK；只有 y=YLEVEL；非法组合抛异常）。
4. **MoveToCompanionTask.onStart**：坐船且目标适合水路 → 先建行船段（`BoatNav`）；FIND → 校验方块 id、踢后台扫描；否则建步行导航 `PlayerNav`。初始期限 = 600 刻 + 剩余直线距离 × 20 刻/格，上限 5 分钟额外量。
5. **PlayerNav → TransportNavigator → 内嵌 Baritone**：目标经 `GoalCompiler` 编译（站位目标附 sacred 格）；地形许可 `ContextProvider`（DEFAULT 只走不改 / WATER_ONLY / LANDING_ONLY / TERRAFORM）由 `may_alter_terrain` / `allow_landing_assists` / `allow_water_bucket_fall` 决定；终点未加载时由 `LoadedTravelLeg` 改成「向前进方向 56 格内取得水平进展」的宽松中段（`ForwardTravelGoal`），中段到头再恢复原终点。
6. **每刻 onTick**：先消费交通原生回执 → 到达短路 → 关闭残留界面 → 行船段 / 喷气背包地面模式准备 → 水中贴岸登岸段判定 → FIND 候选收割 → 规划停滞与收敛熔断检查 → 导航 tick（RUNNING/ARRIVED/FAILED）。
7. **到达判定**（`reached()`）：脚位格与支撑格都在目标范围内，且落地（非精确允许水中到达）；精确目标额外等重力落下（`strictLandingInProgress` 排除游泳 / 攀爬 / 飞行 / 缓降等非落地过程）。导航报 ARRIVED 后还要按身体复核：精确目标必须真的站进那一格，否则 NO_PATH 失败；非精确目标做到达认证 → 等身体停稳（最多 20 刻，位移 < 0.05 视为停稳）→ `successAtBody()` 保存实测位置。
8. **回执**：成功话术带 `ArrivalVerdict` 分级（`arrived_exact` / `arrived_within_tolerance` + 剩余水平距离 + 八向方位 + 高度差）；`details` 交付 `final_x/y/z`、`ground_y`、`y_hint_delta`、规划预算诊断、熔断工作量、脚下自有垫柱清单、水中登岸 / 换气注记、导航失败证据。进度事件里剩余距离按 16 格量化档上报。
9. **跨维度**（`travel_dimension` → `dimension_travel` → `DimensionTravelCompanionTask`）：按维度对解析门方块（主世界↔下界=下界传送门，主世界↔末地=末地传送门，其余 `unsupported_dimension_route` 失败）→ `TargetIndex` 分批扫已加载区域找最近的活门 → 走到门口（复用 goto）→ 第一人称朝门格直走进门（20 秒上限）→ 距门 8 格内预先挂「维度交接」授权，30 秒内抵达目标维度才恢复父任务。附近没门且允许 → 触发 `PortalPreparationTask`（建门/浇筑，归传送门领域）。

## 4 向 LLM 提问的出口（逐个列出问题和选项）

v0 travel 适配层共 **10 种提问**（都在 `AbilityAdapter`，都是同一种「决策」——挂起任务并把选项交回调用方）：

1. **目的地在其他维度**（T-05）：「目的地在别的维度，先到那个维度。」选项：recover（先 `maicraft:travel_dimension`）/ cancel。
2. **地标名解析不了**（T-14）：「名字没在这个世界记住，32 格内也没有唯一同名告示牌；不肯用当前位置、猜坐标或把名字重读成探索目标。」选项：recover（提供 details.goal 先去记住）/ replace_goal（用 perceive(view=landmarks) 里的确切名字、current_place 或明确的海岸/群系发现）/ cancel。
3. **地标记在别的维度**：同上话术的另一分支（「is remembered in another dimension」），选项同 2。
4. **prior_result 绑定失败**（T-15）：「无法把 prior_result 绑定到一次权威的更早成功地点。」选项：recover / replace_goal / cancel。
5. **exact 无定位终点**（T-11）：「精确移动需要已知高度的定位终点。」选项：replace_goal（exact=false 或给坐标）/ cancel。
6. **无定位终点却指定飞行/电梯**（T-12）：「未发现的海岸/群系给不出可信交通终点。」选项：replace_goal / cancel。
7. **无定位终点却开落地辅助**（T-13）：「落地辅助需要先有被观察到的目的地。」选项：replace_goal / cancel。
8. **完全无法解析目标**（T-16）：「travel 需要坐标、记住的地标、block_id、海岸、群系 id 或群系标签。」选项：replace_goal / cancel。

## 10 v0 直播中在这个领域出过的问题（来自 v0 维护记录）
