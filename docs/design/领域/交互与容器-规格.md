## 1 范围

能力：

- `use`：对一个方块或实体用一下手上的东西。取代 v0 的 `interact`、`use_item`、`use_container`。
- `deposit`：把背包里的东西存进容器。取代 v0 `manage_container` 的存入。

`manage_container` 的取出并进 `obtain`（指定 `via` 和容器，见物资规格），配平删除，理由见第 10 节 D1。

本规格同时定下 M11 容器界面里"认界面、算搬法、逐笔搬"的规矩。`deposit`、`obtain` 从容器拿东西、M5 腾地方时存进附近容器，都用这一套。

## 2 真人怎么做

**用东西**：走到够得着、看得见的地方，看准，右键，看有没有反应。要用的东西不在手上就先拿出来，身上没有就去弄一个。开门、开箱子空着手，免得手里的方块被放出去，或者工具被塞进机器。桶只能从水源舀水；倒水、点火要点在旁边方块的面上，水和火落在那一格；不会把火点在自己站的地方。没反应就换个角度再试一次；拿不准刚才那一下有没有点上，就不再花一次材料去赌。打开箱子扫一眼里面有什么，看完关上。剪下来的羊毛顺手捡起来。

**存东西**：背包满了或者回到家，把挖到的东西放进箱子。先找已经放着同类东西的箱子，没有就找有空位的，一只满了换下一只。工具、武器、护甲、吃的、火把和一组垫脚方块留在身上。别人的箱子不乱塞，除非对方叫你放。箱子盖被上面的实心方块压住就先把它敲掉（树叶、台阶压不住箱盖，木桶不看上面）。旁边站着人照样能开箱。

## 3 新逻辑

### 3.1 `use`

```text
0 已满足     目标是角色正骑着的坐骑 → 完成（"已经骑在上面"）
1 找目标     seen 的 b#、e#，position，previous → 就是那一个
             landmark、seen 的 f#、here，加上 block 或 entity → 在那片地方 radius 内找最近的（按路径代价）
             只给 item、没有目标 → 不对着任何方块和实体用
             观察编号对应的东西不在了 → TARGET_GONE，附最后看到它的方位
             那一格现在不是 block 说的方块 → TARGET_GONE，附"应为 X，现在是 Y"
             范围内没有 → NOT_FOUND，附查了多大范围（只能查已加载的区域）
             坐标没加载 → 先走过去（M10），到了再找；在别的维度 → UNREACHABLE（跨维度出行随里程碑二）
2 安全       对下界、末地的床，或主世界、末地的重生锚右键会爆炸 → 不点，DANGER
3 手上       给了 item：选到主手（快捷栏原生切换）；身上没有 → M4 拿 1 件；拿不到 → NEED_ITEM
             没给 item：空手。选一个空的快捷栏格；没有就把主手的东西挪进背包（M5）
             这次会多出一件东西（一摞空桶舀水，多出一桶水）→ M5 先腾一格
4 点哪里     ItemUseAim：按手上的东西定下点哪一格的哪个面、效果落在哪一格、怎样算生效（下表）
5 靠近       M2：站位够得着、看得见要点的那个面；效果落格不能和角色身体重叠，免得点着自己
6 交互       M3 AimAndInteract，确认条件来自 ItemUseAim
7 写字       给了 text：确认告示牌编辑界面打开 → WriteSign 逐行输入、按完成、核对告示牌上的真实文字
8 打开了界面 M11：等内容同步完 → 记下里面有什么（写进结果细节和 M9）→ 关上
9 掉出东西   交互让东西掉在地上（剪羊毛）→ 顺手捡起（附近几格、限时）
10 重复      count > 1：每次确认生效后再做下一次，用掉的东西再拿（回到 3）；某一次没有效果 → 停下，partial
```

**M3 的结论怎么变成任务结果**：

```text
APPLIED       记进 changes；做满 count 次 → done
NOT_APPLIED   遮挡、够不着 → 交给 M2 换站位，再试一次（M3 的通用规则）；仍不行 → UNREACHABLE
              游戏给了提示语（"箱子已上锁"、领地保护）→ REFUSED_BY_GAME，附原话
              服务端说这次右键没被任何东西处理，目标也没变 → NOT_POSSIBLE_HERE（"这样用没有效果"）
UNEXPECTED    done，changes 照实写。例如水倒进岩浆变成黑曜石，倒桶本身生效了，设计对不对交给 LLM 判断
UNCONFIRMED   partial，记进 unconfirmed；会用掉东西的交互绝不再试
```

**ItemUseAim**（`behavior.interaction`，纯函数）：手上拿的东西决定点哪里、怎样算生效。

| 手上 | 点哪里 | 怎样算生效 |
| --- | --- | --- |
| 空手 | 方块朝向角色的可见面；实体本身 | 服务端确认生效，或者目标状态变了、打开了界面、骑上了 |
| 空桶 | 流体源格，射线只认源格。点到的是流动的格子 → 改舀 8 格内最近的同种源格；没有 → NOT_FOUND | 手上变成满桶 |
| 满桶（水、岩浆、细雪、带鱼的桶） | 目标是空气或可被替换的格子（草、水）：点它旁边方块朝向它的面；目标是实心方块：点它朝向角色的面，流体落在那个面外面的格子 | 手上变成空桶，落格出现流体，或者出现流体反应的产物（黑曜石、圆石、石头） |
| 打火石、火焰弹 | 目标是空气：点它下面或侧面的支撑面；目标是 TNT、营火、蜡烛这类能点着的方块：点它本身；其他方块：点顶面 | 20 刻内落格出现过火，或者火变成了下界传送门（火可能自己熄灭）；能点着的方块变成点着的样子 |
| 锄、锹、斧（耕地、压土径、去皮） | 目标的侧面或顶面，不点底面；锄和锹要求目标上方是空气 | 方块变成耕地、土径、去皮的木头 |
| 刷子（可疑的沙子、沙砾） | 点目标，按住直到刷完 | 方块变回普通沙子或沙砾，掉出东西 |
| 其他对东西用的物品（骨粉、染料、剪刀、拴绳、命名牌、鞍、给牛挤奶的桶……） | 目标本身 | 手上的物品少了或变了，或者目标变了 |
| 只给物品、没有目标（喝药水、吹山羊角） | 看向交互距离内没有任何方块和实体的方向 | 物品被用掉或变了 |

几条通用的规矩：

- 手上拿着东西时，准星下的方块如果自己有右键行为（箱子、门、工作台），会先触发方块的行为。倒桶、点火挑支撑面时避开这类方块；实在没有别的面可选，就潜行再点。
- 要按住的物品，按到它自然用完为止（药水、蜂蜜瓶、刷子）。弓、弩、三叉戟、盾牌、望远镜这类没有自然结束、要凭时机松手的物品，以及钓竿，`use` 不接受：计划阶段就返回 `invalid_parameter`，并指向 `fight`、`fish`。
- 掉落物、经验球、射出去的箭这类准星选不中的实体 → UNSUPPORTED，"捡东西用 gather"。
- 准星必须真的命中这个实体；别的实体走进来挡住，就等一下或换站位。对马、船、矿车用就是骑上去，确认条件是角色正骑着它。
- 村民这类实体的界面打开后，列出内容就关上。交易随里程碑二由 `obtain` 负责。

**WriteSign**（`behavior.interaction`，一个动作）：

- 目标必须是告示牌（立着的、挂墙的、悬挂的）；不是 → NOT_POSSIBLE_HERE。
- 空手右键才会打开编辑界面；手上拿着染料或荧光墨囊，会变成给字上色。
- 从哪一面点就编辑哪一面。默认写正面，M2 只选正面那一侧的站位。
- 上过蜡的告示牌打不开 → REFUSED_BY_GAME。
- 编辑界面最多等 60 刻；逐行输入后按完成；告示牌上的真实文字在 60 刻内和请求一致，才算写好。
- 每行有宽度上限，超出的字游戏会截掉。结果里写实际写下的字，被截掉的部分写进 remaining。

**此刻能不能打断**：会用掉东西的交互已经提交、还在等确认时，报 UNSAFE_TO_STOP；其余按 M6 的通用规则（两次使用之间是 BETWEEN_ACTIONS）。

### 3.2 `deposit`

```text
0 已满足     身上没有要存的东西 → 完成（"身上没有要存的 X"）
1 存什么     items → 匹配的物品；不给 → 随身要留的东西以外的全部
               （按 M5 的物品价值分级：工具、武器、护甲与盾牌、食物、火把、一组垫脚方块留在身上）
             count → 一共存几件；不给 → 匹配的全存
2 挑容器     ContainerChooser
               target 是一个容器（b#、position、previous）→ 只用它
               target 是一片地方（landmark、f#、here，或者不给）→ 那片地方 radius 内的容器，
                 加上世界记忆里那片地方的容器（到场核对）
               只留：M7 允许的（LLM 点名的算允许；自己挑时不选别人的）、界面布局认得的（M11）
               排序：已经放着同种东西的 > 还有空位的 > 路径代价小的；大箱子算一个容器
               一个都没有：附近只有别人的容器 → 提问 NEED_APPROVAL，列出是哪几个；连容器都没有 → NOT_FOUND
3 打开       M11 MenuSession.open：M2 靠近、M3 点开、确认界面打开并等内容同步完
               盖子被上方方块压住（原版只有箱子类会被压住，且只认实心导电方块；树叶、台阶压不住，木桶、潜影盒不看上方）
                 → 压住的那一格不受保护、许可允许挖天然方块就先挖开，否则 NEED_APPROVAL，写明是哪一格
               上面坐着猫，或者锁着、被服务器拒绝 → 记进 attempts，换下一个容器
4 搬         TransferPlan 算要点哪几下：先并进同种的堆，再占空格，只搬放得下的
             逐笔点击，MoveConfirmation 逐笔核对，TransferSettlement 只记确认过的量（3.3）
5 关上       M11 关闭；光标上有东西先放回原来的格子
6 还没存完   换下一个容器，回到 3；候选用尽 → partial，remaining 写没存下的，problem NOT_FOUND（"附近的容器都满了"）
```

第 3–5 步是 M5 提供的存放动作 `StoresInContainer`（`InventorySpace` 腾地方时存进附近容器也用它），挑容器用同在 M5 的 `ContainerChooser`。`deposit` 自己只决定第 1 步和在哪片地方存。

**此刻能不能打断**：界面开着、逐笔搬运时是 WORKING；光标上拿着东西的那一下是 UNSAFE_TO_STOP；两个容器之间是 BETWEEN_ACTIONS。被打断时先关界面（光标上的东西放回去），恢复后重新打开。

### 3.3 容器界面里的搬运规矩（M11，所有存取共用）

下面这些规矩大部分已经由 `behavior.menu` 实现；验收时逐条对照，缺的补上。

- **认界面**（`MenuLayout`）：角色背包这一侧必须正好是主背包 36 格。原版的箱子、大箱子、木桶、潜影盒、漏斗、发射器、投掷器、熔炉类、酿造台、运输矿车、箱船按已知布局认。模组的界面只有"全是普通格子、背后只有一个容器"才认，联动模组可以登记自己的布局。认不出 → UNSUPPORTED，一格都不点。AE2 这类专用存储在里程碑三的联动模组到位之前也是 UNSUPPORTED。
- **等同步**：界面刚打开时格子可能还没同步；内容同步完之前不读，也不记进世界记忆。
- **算搬法**（`TransferPlan`，纯函数）：在界面副本上把要搬的数量分到目标格。先并同种、同组件的堆，再占空格；服从格子"能不能放"的限制和堆叠上限。整堆用快速移动（潜行点击）；只搬一部分时明确指定目标格（64 个取 49 个，拆成 32、16、1），不用快速移动，因为它会多搬。指定了数量时，不和别的物品整堆交换。
- **先确认放得下再拿**：不把东西拿在光标上再找地方放。
- **每笔点击前核对**：界面还是这次打开的那个（菜单编号和对象都对得上），光标是空的。每刻只推进一小步。
- **每笔确认**：角色背包这一侧精确少了多少，容器那一侧精确多了多少。熔炉燃料格、漏斗这类会马上吃掉物品的格子，只核对角色这一侧精确减少、光标为空。
- **别人同时在动这个容器**（内容和计划对不上）→ 对还没点的部分重新算，已经确认的不撤销。
- **只有确认过的数量才算数**，写进 changes；点了但没确认的写进 unconfirmed，不盲目重做。
- **界面被别的界面顶掉** → 停下，不点不属于自己的界面。
- **收尾**：失败、被打断或做完时，光标上的东西放回原来的格子（放不回就放进任意空格），再关闭。打开者负责关闭；玩家自己打开的界面不碰。

### 3.4 组合的模型

- `use`：M1（已满足、缺的自己补）、M2、M3、M4（缺物品、捡掉落物）、M5（空手、腾格子）、M7（目标许可）、M8、M9（记住用过的工作台、熔炉和看过的箱子）、M10（走到没加载的坐标）、M11。
- `deposit`：M2、M3、M5（存什么、存放流程）、M7、M8、M9、M11。

本能力特有的部分只剩：`use` 的找目标顺序、爆炸检查和结论映射（`UseDecider`）；`deposit` 的"存什么"（`DepositDecider`）。其余放进玩家行为层，供别处复用：

- `ItemUseAim`、`WriteSign` 放 `behavior.interaction`：M4 舀水剪毛、M6 落地前倒水也会用到。
- `ContainerChooser` 放 `behavior.inventory`：M5 腾地方也用。
- 搬运规矩落在已有的 `MenuLayout`、`MenuSession`、`TransferPlan`、`MoveConfirmation`、`TransferSettlement`。

## 4 能力说明

### 4.1 `use`

`target` 允许 `here`、`seen`、`landmark`、`position`。`previous` 要等内核记下各步骤确认过的位置才解析得了（见[记地点聊天与按顺序做事-规格](记地点聊天与按顺序做事-规格.md)第 6 节），在那之前不列进接受的目标，免得说接受却用不了。

| 参数 | 类型 | 含义 |
| --- | --- | --- |
| `item` | 物品 ID 或标签 | 手上拿什么；不给就空手。标签表示其中任意一种，例如 `#minecraft:hoes` |
| `block` | 方块 ID 或标签 | 没指定是哪一个时，按它找最近的；指定了时，核对目标是不是它 |
| `entity` | 实体类型 ID | 同上，对实体 |
| `count` | 整数 1–64，默认 1 | 做几次 |
| `radius` | 格，默认 32 | 按 `block`、`entity` 找的范围 |
| `text` | 文字，最多 4 行 | 写到告示牌上；给了 `text` 就必须空手 |

计划阶段拒绝的组合：`block` 与 `entity` 同时给；`text` 与 `item` 同时给；`target`、`block`、`entity`、`item` 一个都没给（不知道要对什么用）。

能力说明：

> 对一个方块或实体用一下手上的东西，就像玩家按一下右键：开门、按按钮、拉拉杆、打开箱子看看里面有什么、骑上马或船、剪羊毛、挤奶、用桶舀水或倒水、用打火石点火、用锄头耕地、在告示牌上写字。不给 item 就空着手用；身上没有 item 会先去拿一件。target 指定对哪个东西用；只给 block 或 entity 时，用附近最近的那一个。count 是做几次。打开的界面会在列出内容后关上。放方块用 build，挖和砍用 gather，打怪用 fight，吃东西用 eat，存东西用 deposit，从箱子里拿东西用 obtain。

本能力特有的结果细节（`details`）：

| 字段 | 含义 |
| --- | --- |
| `applied_times` | 确认生效了几次 |
| `opened` | 打开过的界面：是什么、里面有什么（按物品合并） |
| `sign_text` | 告示牌上实际写下的字，逐行 |
| `riding` | 骑上的东西 |

`changes` 用到的种类：`ITEM_CONSUMED`、`ITEM_GAINED`、`BLOCK_PLACED`（流体、火）、`BLOCK_CHANGED`（门开了、锄成耕地；新增，见 D3）、`ENTITY_AFFECTED`、`MOVED`（骑上）。

### 4.2 `deposit`

`target` 允许 `here`、`seen`、`landmark`、`position`；`previous` 同 `use`，等内核记下各步骤确认过的位置再接。

| 参数 | 类型 | 含义 |
| --- | --- | --- |
| `items` | 物品 ID 或标签的列表，可以混写 | 存哪些；不给就存随身要留的东西以外的全部 |
| `count` | 整数 ≥ 1 | 一共存几件；不给就全存 |
| `radius` | 格，默认 32 | 自己挑容器时的范围 |

能力说明：

> 把背包里的东西存进箱子、木桶、潜影盒这类容器。items 指定存哪些；不给就把工具、武器、护甲、食物、火把和一组垫脚方块留在身上，其余全部存掉。count 是一共存几件，不给就全存。target 指定存进哪个容器，或者在哪片地方存；不给就在附近挑，优先挑已经放着同种东西的箱子，一只满了换下一只。不会往别人的箱子里放，除非 target 点名了它。从箱子里拿东西用 obtain。

本能力特有的结果细节（`details`）：

| 字段 | 含义 |
| --- | --- |
| `containers` | 存进的每个容器：观察编号、方块、位置、存进了什么、存完后里面有什么 |

`changes` 的种类是 `ITEM_STORED`，`note` 写存进了哪个容器。

- 扫描服务能按方块或实体类型、按区域查，结果带"是否扫完"。
- 快捷栏原生切换有确认。

## 9 验收

**离线场景测试**（不使用 `Unsafe`）：

1. `ItemUseAim`：空桶只瞄源格，点到流动的格子改瞄最近的源格；满桶对空气格时点旁边的面，且不点箱子、门这类有右键行为的方块；打火石对空气格找支撑面，对 TNT 点它本身；锄头不点底面、上方不是空气时不点；没有目标时瞄向交互距离内什么都没有的方向；会点着自己的落格被排除（178）。
2. `UseDecider`：观察编号、坐标、地标加方块类型分别找到正确的目标；只给类型时选路径代价最小的；没找到 → NOT_FOUND 并带范围；观察编号失效 → TARGET_GONE 并带方位；方块不对 → TARGET_GONE 并带应为和现为；目标是正骑着的坐骑 → done；下界的床、主世界的重生锚 → DANGER；身上没有 item → 请求 M4 拿 1 件。
3. 结论映射：APPLIED → done；有提示语的 NOT_APPLIED → REFUSED_BY_GAME 并带原话；没被处理且目标没变 → NOT_POSSIBLE_HERE；水倒进岩浆 → done，changes 写黑曜石；UNCONFIRMED → partial 并进 unconfirmed，会用掉东西的不再试；count=3 时第 2 次没效果 → partial 并写明做成了 1 次。
4. `WriteSign`：上过蜡 → REFUSED_BY_GAME；超宽的行按实际写下的字返回，截掉的进 remaining；只选正面那一侧的站位。
5. `ContainerChooser`：已放着同种东西的箱子排最前；别人的容器不选；大箱子算一个；AE2 不选；只有别人的容器 → NEED_APPROVAL；什么都没有 → NOT_FOUND；盖子被天然方块压住且许可允许 → 先挖开，不允许 → NEED_APPROVAL。
6. 对照已有的 `TransferPlan`、`MoveConfirmation`、`TransferSettlement`、`MenuSession`、`MenuLayout` 测试，补齐缺的场景：只计划放得下的（不整笔失败）；外部改动后只重算还没点的部分；界面被换掉就停；关之前把光标上的东西放回去；"全是普通格子、背后一个容器"的模组界面认得。
7. `deposit`：不给 items 时随身要留的东西留下；多种物品时 count 按总数算；第一只满了换第二只；都满了 → partial、NOT_FOUND。
