# 交互与容器 领域规格

> 状态：待两位批准的草稿。
> 依据：基础交互-旧逻辑清单（119 条，v0 `dev`，`aa97940c9`）。
> 说明：第 5 节里的旧文件都指 v0（`dev` 分支）；v1 按本规格重写，不移植这些文件。

## 1 范围

能力：`maicraft:use`（对一个方块或实体用手上的东西做事，含打开容器）、`maicraft:container`（容器存取）。两者吸收 v0 的 `interact`、`use_item`、`use_container`、`manage_container` 四个能力。

不含：放方块与挖掘（建造采矿域）、攻击（战斗域）。

**v1 已就位的件**（规格落实现时直接依托，不再重建）：

- `game.interaction`：交互提交（`InteractionSender`）、逐刻确认（`PendingInteraction`、`InteractionConfirmation`）、每刻一次的交互机会（`InteractionOpportunity`）、选物（`ToolSelect`）、快捷栏（`VanillaHotbar`）、第一人称瞄准与遮挡判断（`FirstPersonInteractionTargeting`）。
- `game.menu`：界面点击与搬运（`MenuActions`）、界面可见性（`MenuVisibility`）、界面同步（`MenuSynchronization`）、打开前的准备（`GuiPreparation`）。
- `server`：方块归属记录（`BlockOwnershipRecord`，只读操作 `ownership.query`）与"这个玩家刚才交互了哪一格"的确认通道（`ServerConfirmations`）——M7 保护判断的依据。
- `behavior.interaction`（M3）、`behavior.menu`（M11）目前只有 package-info：这两个玩家行为包的主体随本域落地，是本域的主要新代码。

## 2 真人怎么做

要用一个东西：走过去，看准，点一下，看有没有反应。没反应就想为什么——被挡了就换个角度，够不着就换站位；点上去告示牌要写字就在弹出的框里写。要用东西手上没有，就先翻背包找一件；包里也没有，顺手做一件或去箱子拿（这才是"顺手"，刻意凑一套装备是另一件事）。对动物做事前看一眼对不对——剪白羊的毛，不会拿近处的黑羊凑数；剪过了的羊不剪第二下。

用箱子：走到箱子前开盖，拿要拿的、放要放的，关上。别人正站在箱子前用，就等一下或者换一只。箱子上方堆了东西打不开，挪开就是了。往箱子里放东西会先想好放多少——"拿十个"和"拿到背包里剩十个"是两件事。放到一半发现箱子满了或有人动了箱子，就按实际放进去的数目算账，不会把没放成的也记成放了。

## 3 新逻辑

### 3.1 `use`：对目标做一次（或几次）原生交互

```text
0 已满足     要的效果已经在世界上（例如告示牌上已是这段字）→ 完成，不做任何动作
1 定手势     Gesture.decide（纯函数）：从参数推出一次原生交互
               对象 = 目标对象（seen 的 b#/e#、position、landmark；省略 target 时沿当前视线持用手上的东西）
               持什么 = 空手 / 指定物品；预期效果与确认条件随手势类型：
                 开容器（方块或驮箱实体）→ 确认新界面出现（M11）
                 写告示牌 → 确认正/背面文字逐行一致（R-01 的行宽校验在参数规格）
                 点火 → 确认落格出现火或传送门（火自然熄灭、有效门框把火换成传送门都算生效）
                 锄地 → 确认变成耕地
                 持用 → 确认产物出现（声明了产物时）或确认提交
                 剪毛/挤奶/骑乘 → 确认对象属性变化；剪毛的"剪下"与"入包"分开结算
               手势类型由特征接口表达，任务输入携带；内核不认识具体手势
2 补条件     指定物品不在背包 → M4 弄一件（有预算）；弄不到 → NEED_ITEM 结束
             空手手势但主手有物 → 换到快捷栏空格（全满时先安置手持物）
             锄地未点名工具 → M4 取锄后继续，不结束
3 靠近       M2 StandSpots.forInteraction(目标, 手势)：够得着（InteractionRange，按手势取
             方块/实体/床的规则）、看得见、站得稳；被挡住时 M2 内部换站位
4 瞄准与提交 M3 AimAndInteract：转向并等真实镜头到位 → 射线核对命中（命中了别的就换位重试）
             → 冻结提交时现场（目标格状态、射线命中者）→ 提交
5 确认       M3 逐刻确认 + 本手势的确认条件；UNCONFIRMED 进结果的 unconfirmed，绝不盲试
6 结算       APPLIED / NOT_APPLIED（附最近的动作栏提示语与现场）/ UNEXPECTED（如实上报）
             目标在手势中途消失：已提交 → 按已提交结算；未提交 → TARGET_GONE
```

### 3.2 `container`：往容器里存、取、配平

```text
1 选容器     ContainerChooser（纯函数）
               候选 = target 指定的那一只（seen b# / position / landmark）
                      ∪ 省略目标时已加载区块内按 radius 扫到的容器 ∪ M9 已知容器（到场复核）
               过滤 = 还在且还是容器、上方没有被堵、不在 M7 保护内
                      （保护 = 服务端归属记录 ∪ 记住区域 ∪ protected_landmarks，M7 统一判断，
                       不再写死 12 格半径）
               排序 = 名字匹配 > 路径代价；默认选最近，结果里写明选了哪一只
               候选为空时按原因分流：上方被堵 / 受保护 / 类型不符 / 半径内确无容器
2 走到并打开 M2 靠近 → M3 空手右键 → M11 MenuSession.open 确认界面真的打开
               旁边有别的玩家 → 按"不抢别人正在用的箱子"处理（见待决定 D3）
3 分侧与规划 MenuLayout.classify（纯函数）：玩家侧 36 槽、容器侧；认不出的模组布局 → UNSUPPORTED
               数量语义：count 是增量，target_count 是终态（存入看箱内、取出看背包），
               两者都缺时搬运来源侧全部
               在界面副本上把要搬的量完整分配到目标槽（先并同类堆再占空格，服从槽规则与容量）；
               装不下在任何点击之前就知道，先收缩计划或以 partial 结束
4 搬运       逐笔经 M11 MenuActions：整堆走快速移动，尾数拆成二分堆（64 取 49 → 32/16/1）
               每笔前核对界面身份、光标为空；外部改动时对未提交部分重新规划
               机器槽（熔炉燃料等）按"源格确切减少 + 光标空"结算（放置回显到达前物品可能已被吃掉）；
               普通槽按双侧精确增减核对
5 确认       双侧数量与按物品增减全部对上才累计搬运量；对不上 → 进 unconfirmed，绝不盲试
               已确认的搬运量不会清零，也不会被后续抽走撤销
6 关闭       M11 close()；失败或取消时鼠标上有物先放回，再关界面；任务结束时内核保证界面关闭
```

**组合的模型**：M1（总流程）、M2（站位与靠近）、M3（瞄准、交互、确认）、M4（补指定物品、锄地备锄）、M7（保护判断、许可）、M8（进度跟踪、重试、结果）、M9（已知容器、用过的工作站）、M11（界面所有权、点击、关闭）。

**本能力特有的部分**只剩：`Gesture`（手势判定与确认条件）、`ContainerChooser`、`MenuLayout`（分侧与布局证明），以及各确认条件里的游戏事实（点火、写字、剪毛、产物）。

## 4 能力说明

### `maicraft:use`

| 参数 | 必填 | 含义 |
| --- | :---: | --- |
| `item` | | 这次要用的东西（物品 ID）；不在背包时先去弄一件。省略即空手交互 |
| `block` | | 目标是方块时的类型确认（不给就不核对类型） |
| `count` | | 做几次（默认 1；只对持用、锄地这类可重复手势有效） |
| `text` | | 写到告示牌的文字（≤4 行，每行 ≤64 字符；只对告示牌目标有效） |
| `max_seconds` | | 持续手势最多按多久（Create 手摇曲柄等），单位秒 |
| `radius` | | 省略 target 时在附近找最近的匹配，单位格（默认 16） |

target 接受 `seen`（`b#`/`e#`）、`position`、`landmark`、`here`；省略 target 表示沿当前视线持用手上的东西。可选 `permissions` 按 M7 处理。

能力说明：

> 对一个方块或实体用手上的东西做事：开门、按按钮、拉杆、点火、锄地、剪羊毛、挤奶、骑乘、往告示牌写字、打开箱子或驮箱动物。不指定目标时沿当前视线使用手里的东西。要用的东西不在身上会先去弄一件。剪毛和挤奶会对着对的动物做，剪过的羊不剪第二下。

本能力特有的结果细节：

| 字段 | 含义 |
| --- | --- |
| `menu_opened` | 这次交互打开了一个界面（界面归 M11 管，本能力不替调用方关） |
| `sign_written` | 告示牌文字已确认写入 |
| `ignition` | `fire`（点着了）/ `portal`（火被有效门框换成了传送门）/ `none`（没看到火） |
| `output_gained` | 确认到的新增产物（物品与数量） |
| `applied_count` | `count` 大于 1 时实际确认完成的次数 |

### `maicraft:container`

| 参数 | 必填 | 含义 |
| --- | :---: | --- |
| `operation` | ✅ | `deposit` 存入 / `withdraw` 取出 / `balance` 配平 |
| `item` / `items` | | 搬什么（物品 ID，或 `#` 开头的标签）；标签与单件二选一 |
| `count` | | 这次要多搬多少件 |
| `target_count` | | 搬完之后的总量终态（`balance` 必填；存入看箱内、取出看背包） |
| `radius` | | 省略目标时的搜索范围，单位格（默认 32） |

`count` 与 `target_count` 互斥；都省略时搬运来源侧的全部。target 接受 `seen`（`b#`）、`position`、`landmark`、`here`。

能力说明：

> 往容器里存东西、取东西，或把背包和容器里某样东西配平到指定数量。不指定容器时会就近选一只合适的并在结果里说明选了哪只。箱子上方被堵、受保护或认不出界面布局时会直接说明原因。放到一半被打断，已放进的部分不会丢账。

本能力特有的结果细节：

| 字段 | 含义 |
| --- | --- |
| `moved` | 已确认搬运的物品与数量 |
| `container_at` | 用的哪只容器（位置与方块） |
| `now_in_container` | 完成时容器里现有多少 |
| `now_in_inventory` | 完成时背包里现有多少 |

## 5 旧逻辑归类表

## 9 验收

**离线场景测试**（不使用 `Unsafe`，判断类用替身接口、任务用动作替身）：

1. `Gesture.decide`：每种手势的对象、持物、确认条件正确；坐标目标 + count>1 拒绝；写字参数越界拒绝。
2. 站位：点火时"能成门"的站位排前；遮挡时 M2 换站位；命中别块时 NOT_APPLIED 附命中者。
3. 补条件：物品不在背包 → M4 动作被创建；M4 失败 → NEED_ITEM；锄地无锄 → 先取锄。
4. 确认条件：点火窗内见火/见传送门/两者皆无三分支；写字逐行一致；产物晚到不重复使用；剪毛"剪下"与"入包"分开。
5. `ContainerChooser`：上方被堵/受保护/类型不符/确无匹配四种原因分流；指定目标时不再扫描；M9 记忆到场复核。
6. `MenuLayout`：原版箱、熔炉、漏斗的两侧划分；认不出的布局 UNSUPPORTED；装不下在任何点击前失败并收缩计划。
7. 搬运：尾数二分分堆（64 取 49 → 32/16/1）；机器槽按"源格扣减+光标空"结算；外部改动后只重排未提交部分；双侧对不上进 unconfirmed。
8. 收尾：取消时鼠标有物先放回再关；任务结束界面必关（含打开失败路径）。

**实机验收**（追加到冒烟清单；含第 5 节所有 P/G/S 类的原事故场景）：

1. 空手右键开箱、拿东西、放东西、关上；结果里 moved 与双侧现存数量一致。（基础）
2. 箱子上方放一个漏斗（或红石导体）再让它开箱 → 结果说明"上方被堵"，不再报"没有匹配容器"。（100）
3. 洪水区让它用空桶取水 → 只对真水源出手；面对流水时说明"取不了流动水"。（032）
4. 高低差站位下播种、取水 → 站位不合适时自动换位，不再整批静默失效。（064）
5. 岸边锄地连续失败 → 换站位后成功；结果的建议里提到站位或水源。（076）
6. 让它往告示牌写字：先写后读，文字逐行一致；对着箱子的写字请求被参数校验拒绝。（089）
7. 用打火石在门框里点火 → 结果报 portal；对着不会成门的格点火 → 报 fire 或如实的 none。（174）
8. 让它剪白羊的毛，旁边有黑羊 → 只剪白羊；剪过的羊不剪第二下。
9. "从箱子里取 49 个圆石" → 箱内少 49、背包多 49，无整堆多取。
10. 往熔炉存煤（燃料槽）→ 按"源格扣减+光标空"确认，数量准确。
11. 搬运到一半取消任务 → 已放进的部分在 changes 里，界面已关闭，鼠标上无残留物品。
12. 两位玩家场景：别人站在箱子前时 → 按待决定 D3 的尺度处理（等待或换箱），不抢操作。

## 10 待两位决定

| # | 问题 | 选项与倾向 |
| --- | --- | --- |
| D1 | v0 的"批量持用"（副手原料 + 主手工具，按新增产物计数）归谁 | a) 留在 `use`，`count` 即次数（本规格现写法）；b) 并入 `obtain` 作为一个来源（`via` 指定），use 只做单次。倾向 a：手势和确认条件都在 use 手里，obtain 只需调用它；里程碑一先按 a 实现 |
| D2 | `container` 要不要保留 `balance` 操作 | a) 保留三操作（deposit/withdraw/balance），`target_count` 表达终态；b) 砍掉 balance，deposit/withdraw 直接接受 `target_count`。倾向 b：balance 在语义上就是"搬 |背包−终态|"，两个操作 + 终态参数已覆盖，少一个枚举值 |
| D3 | 容器旁有别的玩家怎么办 | a) 沿用 v0：6 格内一律失败；b) 常识处理：对方贴着容器（≤2 格）且未离开时先等一会儿，等不到就换一只或先干别的，结果如实说明；c) 完全不管，原版允许同时开箱。倾向 b：v0 的一律拒绝拦了正常玩家会做的事（G 倾向），但完全不管又不符合"不抢别人正在用的箱子" |
| D4 | 对脚下格点火（可能自燃）要不要预判拦截 | a) v0 遗留的 pending：拦截"目标格与站位重合的点火"；b) 不拦截：火本来就需要相邻空气格才落得下，点不着就如实失败，点着了烧到自己由 M6 着火自救处理。倾向 b：预判拦截（G 类）不允许新增，让原版结算再如实报告 |
| D5 | `use` 的 `count` 对"开容器、写字"这类一次性手势是否报错 | a) 参数校验直接拒绝（count 只对可重复手势有效）；b) 静默忽略多余次数。倾向 a：一个参数只有一种含义，拒绝并说明 |
