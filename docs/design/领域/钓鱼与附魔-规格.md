# 领域规格：钓鱼与附魔

> 范围：能力 `fish`（钓鱼）与 `enchant`（附魔），里程碑二。两个能力共用一份旧逻辑清单、各自都很薄，合在这一份里。
> 依据：[钓鱼附魔交易狩猎-旧逻辑清单](钓鱼附魔交易狩猎-旧逻辑清单.md) 的钓鱼组（F01–F31）与附魔组（X01–X32），v0 `dev` 基线提交 `aa97940c9`。同清单的交易、狩猎、随身背包三组归物资规格的补齐节，本规格不写。
> 边界：等待与进度归 M8，等待期间被生存需求打断归 M6；走到钓位与附魔台用已有的走到（M10）与站位（M2）；附魔台界面的点格、搬运、关闭归 M11（原版布局）；缺鱼竿、缺可附魔物品与青金石的补齐交给 M4；战利品拾取复用顺手捡起；许可按 M7，两个能力都不新增许可开关。
> 说明：第 5 节"内容"描述的都是 v0（`dev` 分支）的做法；v1 按本规格重写，不移植这些文件（弹道解算一处除外，见第 8 节）。

## 2 真人怎么做

钓鱼：拿根鱼竿走到水边，找块站得稳的干岸，把钩甩到开阔的水面上，盯着浮标，一沉就抬竿，钓上来的东西飞到脚边捡进包，再甩下一竿。甩竿之前没人知道会钓上来什么，鱼、旧靴子、附魔书都照单全收。站的地方要干的，落点要开阔，别让钩子挂在树上、掉在岸上或钩住路过的生物。竿断了就换一根，没有就先去弄一根。

附魔：把要附魔的东西和青金石带上，走到附魔台前放进去，看三档各要多少级、提示可能附出什么，挑一档点下去，附完把东西拿回来。附出什么是什么，不会拆掉重来碰运气——一件东西在台子上只有一次机会。等级不够就不硬来，等级要自己攒；青金石不够就先去弄齐再来。

## 3 新逻辑

### 3.1 fish：钓鱼

```text
1 检查鱼竿   背包（含副手）找原版鱼竿；没有 → M4 弄一根，弄不到 NEED_ITEM
             有 → 换到主手（M5）
2 找钓位     钓位 = 一个干站位加一个能抛到的落点（纯函数，离线可测）：
               干站位：两格无流体、能穿过、脚下能站；受保护的格子不选（M7）
               可抛落点：水源最上层且上方无碰撞（流动水、顶上有实物挡着的水不算）；
               水平 4～10 格、上下 4 格内挑，偏好约 6 格远、周围水面多的；
               弹道按抛竿初速逐刻模拟（最多 80 步），中途碰到任何方块即拒绝
               （沿途实体不查，钩住了在等待段处理）
             已站在干岸 → 只看从原地能不能抛到，找不到就如实结束
             （原地无落点不能说成附近没有水）
             不在干岸 → 12 格圈、上下 4 格内搜"站位+落点"组合，
             最多核对 256 个候选，就近取
3 走到钓位   交给走到（M10）；接近段的进度按 M8 上报，不出现静默空转
4 抛竿       转向落点，等真实视角转到位（M3）；按弹道俯仰角右键抛出，
             以角色关联上新的鱼钩确认抛出；游戏没确认 → 记一次失败抛竿
5 等咬钩     咬钩看客户端同步的咬钩状态（不等服务端粒子）→ 立即收竿；
             鱼钩消失、钩住实体（先收竿）、抛出 5 秒还没入水、一竿 60 秒没咬钩
             → 失败重抛，没入水或钩住实体的水面进排除集；
             连续 5 次失败抛竿 → 结束（UNREACHABLE，建议换开阔的岸边；
             成功一次清零、清排除集）
             小池塘可能只有一个落点：所有落点都试过一轮后清空排除集再算一次，
             不因一次不走运就判"这里钓不了"
6 收竿取获   再次右键收线，以鱼钩消失确认；先等约 1 秒让原版把战利品抛向玩家，
             还留在地上的走近让原版吸附（顺手捡起的同一套），以背包增长确认拿到；
             到不了的放弃留地上，结束时报剩几件；
             可归属的钓获与背包实收对不上 → 如实结束，不冒充钓到
7 下一竿     短暂冷却再来一轮；钓满 count 完成；背包放不下先走 M5 腾，
             腾不动 INVENTORY_FULL
```

count 与预算：count 是"钓到几次收竿"，一竿钓到垃圾或宝藏也算一次；不给 count 就建常驻任务一直钓，直到 LLM 换活或取消。钓多久、多久没进展算卡住，都归 M8（`max_seconds` 可给），不按竿数折算期限。

打断：等咬钩是正常干活（SOON 需求可打断）；收竿已提交、等鱼钩消失确认的几刻停下不安全。被生存需求打断时先收竿再让位，回来重抛——挂着钩让位会咬了不收。

### 3.2 enchant：附魔（附魔台）

```text
1 校验       item 必填且在注册表里；tier 1..3（默认 1）
             台子解析：target 是 seen 的 b#、position、landmark → 就是那一个
             （那格现在不是附魔台 → TARGET_GONE；在别的维度 → UNREACHABLE）
             不给 target → radius 内已加载区找最近的，没有 → NOT_FOUND 写明找过哪里
2 选料       背包视图里第一件与 item 匹配、台子肯收的东西
             （未附魔、无储存附魔；已附魔的台子不再接受）；
             身上没有 → M4 拿一件，拿不到 NEED_ITEM
             匹配的物品是堆叠 → M5 先腾一个空格接成品
3 凑青金石   第 tier 档要 tier 个，同组件的堆叠合并计数；
             身上不够 → 按 M4 补（范围见第 10 节 3），补不到 NEED_ITEM
4 开界面     走到台子、M11 点开等同步；工作槽或光标已有内容 → 不认领，如实结束
             （不挪走不属于自己的东西）
5 装料       一件待附魔物品、逐叠搬恰好 tier 个青金石进工作槽，
             绝不整堆快移超额；每笔按 M11 核对
6 看报价     报价同步稳定后冻结三档：每档写门槛等级、实扣等级
             （当前等级与档位数取小，最低归零）、青金石数、附魔线索；
             创造模式门槛与青金石按 0 计
             选的档位不可用（等级没到门槛、没有线索）→ 如实结束，
             写清当前等级与门槛多少
7 提交       提交前再核一遍报价没变（等级、随机种子、线索、工作槽都对得上），
             变了就重读再等稳定；点第 tier 档按钮，一次提交；
             以"成品与费用同刻吻合"确认：青金石少了 tier 个、等级扣了实扣数、
             成品出现且报价线索那条附魔在里面；成品、青金石、经验分包抵达就继续等
8 取回       成品与剩余青金石搬回背包；核对"原物减一、成品加一、青金石实扣"
             游戏明确说按钮没执行 → 原物与青金石全数归还，重读报价再试一次，
             再不行如实结束；结果不明 → 记进 unconfirmed，绝不重发
9 关闭       M11 关上（关界面会把工作槽的东西还回背包）；
             结果里列出实际附上的全部条目与等级——报价线索不冒充最终结果
```

不重滚：随机性如实——附出什么列什么。台子对已附魔物品本来就不收第二次，本能力也不提供"洗掉重来"；要指定具体附魔是铁砧、村民或战利品的事（见第 10 节 1）。

附魔不改世界（消耗的是自己的等级与青金石），不需要额外许可；台子按 M7"无主的东西照常用"。

组合的模型：M1（总流程）、M3（抛竿、收竿、按钮的提交与确认）、M4（缺竿、缺物品、缺青金石的补齐）、M5（换手、腾格）、M6（等待期间被打断）、M8（等待与进度）、M10（走到钓位与台子）、M11（附魔台界面）。本能力特有的部分只剩：fish 的钓位几何（钓位组合、落点偏好、弹道模拟）、咬钩等待与钓获差集记账；enchant 的选料判据、三档报价的冻结与校验、成品确认判据。

## 4 能力说明（参数与结果）

### maicraft:fish

不接受目标对象：只从当前位置找水，要去别的水域先 travel。

| 参数 | 必填 | 说明 |
| --- | :---: | --- |
| `count` | | 钓到几次收竿（垃圾、宝藏也算一次）；不给就一直钓（常驻） |
| `max_seconds` | | 最多钓多久（秒）；超时按 M8 以 STUCK 结束，已钓到的照算 |

能力说明：

> 在附近的水边钓鱼。要求背包里有鱼竿，没有会先去弄一根；自己找站得稳的岸边、把钩抛到开阔的水面上，咬钩就收，钓上来的东西照单全收——鱼、垃圾、宝藏都算一次。count 是钓到几次；不给就一直钓，直到换别的活或取消。只从当前位置找水面，要去别的水边先 travel。

结果细节：

| 字段 | 含义 |
| --- | --- |
| `caught` | 完成的收获次数 |
| `casts` | 抛了几竿 |

changes：钓到的每样东西一条 `item_gained`。

### maicraft:enchant

| 参数 | 必填 | 说明 |
| --- | :---: | --- |
| `item` | ✅ | 附魔哪件：物品 ID 或 `#` 标签（身上第一件匹配且台子肯收的） |
| `tier` | | 选三档报价里的第几档，1..3，默认 1；第 n 档消耗 n 级和 n 个青金石 |
| `radius` | | 不给 target 时找台子的范围，格，默认 32 |

target 允许 seen（b#）、position、landmark；不给就在 radius 内找最近的附魔台。

能力说明：

> 在附魔台给一件东西附魔。item 点名附魔哪件（身上没有会先去拿一件），tier 选三档报价里的第几档——第 n 档消耗 n 个经验等级和 n 个青金石，各档另有等级门槛（最高三十级，和旁边的书架数有关），等级不够会写清差多少。附出什么由游戏随机决定，结果列出实际附上的全部条目和等级；一件东西在台子上只有一次机会，不会拆掉重来碰运气。target 可以点名用哪个附魔台，不给就在附近找最近的一个；附近没有台子时如实说明，不会就地造一个。

结果细节：

| 字段 | 含义 |
| --- | --- |
| `offers` | 冻结的三档报价：门槛等级、实扣等级、青金石数、附魔线索 |
| `tier` | 这次用的档位 |
| `enchantments` | 实际附上的条目与等级（只有按钮确认后才给） |
| `levels_spent` / `lapis_spent` | 实际扣掉的等级与青金石 |

changes：`item_consumed` 记原物一件与用掉的青金石，`item_gained` 记成品（note 写自什么附魔而来）。

| X24 | 成品判据（书转附魔书、装备只许附魔组件变化、线索必须在成品里） | F | 保留：成品判据 |
| X26 | 搬运失败提交前刷新最多 2 次 | C | M11 搬运重试 |
| X28 | 取回核验（已消费全对账、未消费只核归还） | F | 保留 |
| X30 | 控制权移交、结果不明时保留界面不关 | F、G | 改写：结果不明记 unconfirmed，界面按 M11 收尾（东西回背包），不重发；玩家收回角色时 M11 本来就不碰界面 |
| X31 | 只有按钮确认后才列附魔条目 | F | 保留：报价线索不冒充结果 |

**汇总**：F 类事实全部保留，各有归属；C 类保留为策略或交给既有模型。原 G 类（X01、X05 的入口拦截、X20、X21、X32，以及 X16 的预算侧）不再以"预测会失败"拒绝任何一次本来可以尝试的交互——预算拦截随预算参数一起消失，重发防护改由"提交前重核 + unconfirmed 不盲目重试"承担。S 类 2 处（F03、X07）改写或放宽。

## 9 验收

**离线场景测试**（判断类用替身接口，任务用动作替身，不使用 `Unsafe` 与反射）：

1. 钓位判断：干站位判据；流动水、顶上有实物的水被排除；落点只认水平 4～10 格内的候选；弹道被方块挡住即拒；所有落点排除后清空再算一次；小池塘单落点可用。
2. 定位失败分流：干岸无落点、圈内无干站位组合、圈内无可钓水面三种 message 分开，都带扫描范围，后者带"有界扫描不构成圈外无水的证据"。
3. 等待段：同步咬钩立即收竿；钩消失、钩住实体、未入水 5 秒、60 秒无咬钩各自重抛；连续 5 次结束，成功后清零与清排除集。
4. 取获：先等飞回窗口再走近；到不了的放弃并报件数；可归属钓获与背包实收不符 → 如实结束；背包放不下先腾（M5），腾不动 INVENTORY_FULL。
5. 打断：等咬钩可被 SOON 需求打断且先收竿；收竿确认窗口停下不安全。
6. 常驻：不给 count 不设完成时刻；给 count 钓满即停。
7. 附魔选料：已附魔、含储存附魔的不选；堆叠需空位（M5）；青金石同组件合并、不足 NEED_ITEM；到台后原物找不回不换另一件。
8. 报价判断：三档门槛与实扣分开展示；创造模式门槛与青金石按 0；档位不可用如实说（带当前等级与门槛）；提交前报价变化重读再等。
9. 成品判据：书转附魔书、装备组件保真、线索必须在成品里；费用同刻吻合才算确认；分包抵达继续等；按钮明确没执行重试一次后仍不行如实结束；结果不明进 unconfirmed 不重发。
10. 结果展示：只有确认后才有 `enchantments`；未确认的结束附 `offers` 与已扣费用的事实。

**实机验收**（追加到里程碑二清单；含 P/G/S 类的原事故场景）：

1. 有竿有水，让它钓 3 条 → 抛竿、咬钩收竿、捡回，changes 与背包一致；钓到垃圾也算完成。
2. 身上没有竿 → 自己弄一根再钓（F01 场景）。
3. 站在干岸但半径内没有水 → UNREACHABLE，话术写明扫描范围与"圈外不算无水"（049）。
4. 接近钓位时导航停在假运行 → 有界结束并带进度，不静默楔死（117）。
5. 钓鱼途中饿到 SOON → 先收竿去吃，回来接着钓；收竿确认那几刻不被连环打断（011 的现象归 M6 的在岗判断，这里看现象）。
6. 把竿耐久磨到将尽钓到竿坏 → 如实结束，已钓到的照算，事件流出现 gear_broken。
7. 附魔台、青金石、装备齐备 → 附出什么结果里逐条列出，扣的等级与青金石数目和档位一致（X28/X31 场景）。
8. 身上没有青金石 → 按 M4 补齐或 NEED_ITEM（按第 10 节 3 的拍板执行）。
9. 等级不够门槛 → 结束并写清当前等级与门槛，不刷经验。
10. 附近没有附魔台 → NOT_FOUND 写明范围，不就地造台。
11. 附魔进行到一半把台子拆了 → 如实结束，装进去的物品随界面收尾回到背包。
12. 给 fish 传一个地点目标 → 参数错误，不悄悄从当前钓。

## 10 定下的做法

| # | 问题 | 做法 |
| --- | --- | --- |
| 1 | 附魔走附魔台还是连铁砧一起支持 | 本规格只做附魔台。铁砧是另一种界面与花费（书加物品合并、修理、改名，只扣等级不扣青金石），放进来会把规格撑大一截；真要用时另补一节。能力说明写明"铁砧不支持" |
| 2 | 附近找不到附魔台要不要就地造一个 | 不造。造台要黑曜石和钻石，想附出好词条还得摆书架，是 build 加 obtain 的组合活，由 LLM 自己安排；找不到就 NOT_FOUND 写明找过哪里 |
| 3 | 缺青金石与可附魔物品时补到什么范围 | 按 M4 补，但不为一次附魔去世界里现采：身上、记得的容器（随身背包随里程碑二）先算；要下矿才够就 NEED_ITEM 交回 LLM 决定。经验等级不刷：不够就如实说差多少 |
| 4 | fish 的 count 上限与常驻用法 | 撤掉 1..64 的上限（同物资规格"不设魔法上限"的取向）；不给 count 就一直钓（常驻任务），与 `wait` 的用法一致 |
