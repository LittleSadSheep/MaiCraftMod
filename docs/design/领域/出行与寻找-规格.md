# 领域规格：出行与寻找

> 状态：已批准（2026-10-09）。起草方 ChangingSelf；所有者委托 Claude 逐项审过第 10 节并授权直接修改：改了第 3 项（精确到达由 radius 表达，与实现一致），其余按建议。改了的做法与实现要跟进的地方见待拍板清单第六节。
> 范围：能力 `travel`（去一个地方，里程碑一只有步行）、`find`（找到某种方块、生物或结构，返回观察编号），里程碑一。
> 依据：出行旧逻辑清单（63 条）与探索与寻找旧逻辑清单（92 条），均为 v0 `dev`，`aa97940c9`。
> 边界：走到目标才能做的交互（靠近、换站位）归 M2 站位与靠近，交互与容器域用；travel 只负责"从这里到那里"的整段行程与到达确认。途中被怪打的自卫、坠落溺水的自救由 M6 打断规则处理，归战斗与生存需求域。挖矿采集中"走到矿边"同样走 M2，不经过 travel。世界记忆（地标、见过的资源与结构）的存储与查询归 M9，本域只往里写"亲眼看见"的事实。跑图勘察 `explore`、群系发现、跨维度、乘船、飞行与电梯：跨维度在里程碑二；喷气背包、飞行器、电梯、火车在里程碑三（2026-10-11 随 Create 全部并入）；原版乘船在里程碑四。本规格不做，只标注不做。
> 说明：第 5 节"内容"描述的都是 v0（`dev` 分支）的做法；v1 按本规格重写，不移植这些文件。寻路的内核件是对外的唯一寻路入口，内部调用集中在 BaritoneInternals；本规格只写能力保证什么（到达确认、中途停下、跨水、上坡），不写它内部怎么算路。

## 2 真人怎么做

去一个地方：知道坐标或叫得出名字就直接去；只听过名字没记住，就先问清楚，不会拿脚边随便顶替。近的走过去，遇到河就游过去，遇到坡就爬上去；要挖开挡路的东西或垫两块才能过，先想想允不允许动地形——允许就动手，不允许就绕。走到一看，脚下站实了、位置对了才算到；差着几格不算到，也别嘴硬。垫上去的方块记得自己垫过哪些。水底憋气憋不住了先浮上去换气，再接着赶路。

找东西：要找某种方块，就把附近看一遍——看得见的才算找到，墙后面的不算；刚放下去的方块不能转过身就找不到了。要找某种生物，数得清眼前这几只，一条龙不会数成九条，有主人的、拴着的、圈里的不会当成无主野怪。要找一处结构，靠见过的线索和记忆，到了附近亲眼确认。找到就报告在哪、离多远，找不到就说清"找了哪一片、这一片里没有"，不会因为没找到就说全世界没有。

## 3 新逻辑

### 3.1 travel：去一个地方（里程碑一：步行）

```text
0 已满足     已按到达标准站在目标位置 → 直接完成，写"开始时已到达"
1 解析目标   目标对象：position（y 可省略：先走到那一列附近，到了再找能站的格子——
             高度纪律：不把高度没核实的坐标直接交给寻路）、landmark（M9 世界记忆，
             含附近唯一同名告示牌）、seen（f# 地形特征）、here、direction（往某方向走多远）
             landmark 解析不到 → 提问 UNCLEAR_TARGET（M8 ③：目标说不清是三种合法提问之一），
             不拿当前位置顶替，不把名字猜成别的东西
             目标在别的维度 → UNSUPPORTED（跨维度里程碑二）
2 规划       行程规划 TravelPlanner.plan（玩家行为层 behavior.travel）：给寻路一个目标位置与许可；
             能不能动地形来自 permissions.change_blocks（M7）：
               natural（默认）可挖天然方块、垫临时方块；none 只走不改
             垫路用什么方块、哪些方块挖不得，写进寻路共用的方块通行判断与垫料规则，全仓一份
3 走         交给寻路执行（对外只有寻路这一个入口，内部调用集中在 BaritoneInternals）：
               到达保证：站着算到，跳到最高点不算；非精确目标允许水中到达，空中经过不算
               跨水保证：水里游得动、上岸上得去；憋气先浮上去换气再接着走（M6 的溺水需求，
               行进中停下不安全时按 M6 的停下不安全处理，换气不被切碎）
               上坡保证：能走上去的坡走上去；许可允许时可以垫柱上去，垫的方块如实列进 changes
               下坎：按此刻的身体（血、黄心、护甲附魔、药水）算，摔完还剩一半以上的血（满血时十三格以内）就照跳，
               扣的血按每点约四格路折进路线代价，附近能走下去就走下去；再高才用水桶、干草这类落地办法，没有就绕；
               意外踩空同一条线：摔完还剩一半以上不开救援；卡坑判断认的往下跳高度也按这条线（至少三格）
               中途停下：任何时刻可以被生存需求打断（M6），处理完从原地接着走；取消时人留在
               实际位置，如实报告
4 到达确认   以身体为准：脚位格与支撑格都在目标范围内且落地；radius=0 的精确目标
             还要等重力落下去（游泳、攀爬、滑翔不算落地）；导航报了到达但身体没进格，不算到
             到达后等身体停稳（短暂位移收敛）再取坐标，不拿滑行快照报成功
             已在容差内立定却报无路的误导性失败不存在：立定了就按到达结算
5 结算       到达位置（实测 x/y/z）、剩余水平与垂直距离、八向方位进 details；
             本次垫的临时方块逐格进 changes；走到一半取消 → partial，写明停在哪
失败         UNREACHABLE（附试过的证据与建议：授权动土或带垫料）
             STUCK（M8 进度跟踪：剩余距离长时间不缩短，或超过 max_seconds）
             DANGER（M6 判定继续走会死，例如前方岩浆）
```

组合的模型：M1（总流程）、M6（途中生存需求与停下安全）、M7（change_blocks 许可、保护格不入寻路）、M8（进度跟踪、问题种类、结果）、M9（landmark 解析）。本能力特有的部分只剩：目标解析、到达确认标准、跨水与垫料的行程保证。

### 3.2 find：找到某种方块、生物或结构

```text
0 解析       找什么：block/blocks（方块 ID 或标签）、entity（实体类型，可几种）、structure（结构 ID）
             三者一次只给一种；radius 是扫描范围（单位格，以角色为圆心），
             max_distance 是愿意为"附近没有"承担的更远搜索声明——里程碑一只扫已加载区
1 扫描       已加载区只读扫描（game.world.BlockScanService 分刻推进，不动身体、不改方块）：
               命中先复核实际方块状态，再过视线闸：眼睛能看见才算找到；
               半透明材质（玻璃、树叶、冰）不挡观察；视线穿过未加载格判不可见
               刚被放置或破坏的方块经"最近方块变化"通道补查，不能刚放下就找不到
2 实体       身边已加载区扫描：类型过滤、视线闸；多部件实体（末影龙）折叠到逻辑主体，一条是一个；
             具名、驯服、拴绳、圈养的实体照常找到，但结果里带保护事实（M7 的判断），
             不冒充"无主的找到了 count 个"
3 结构       已加载区内按结构证据扫描；线索与记忆查 M9；附近没有 → 如实结束：
             "半径 X 格的已加载区没有，再远要靠勘察"（里程碑二 explore）
4 收束       找满 count 个即收工；扫完仍不足 → partial/failed，写清找到了几个、查了什么范围；
             "查过没有"不等于"世界里没有"写进结果话术
5 记忆       视线验证过的命中写进 M9 世界记忆（来源=亲眼看见），供后续 gather/travel 使用
6 结果       每个命中一个观察编号（b# 方块、e# 实体、f# 结构线索）+ 位置 + 三维距离；
             LLM 下一步 travel 过去或 gather 采掉，本能力不代劳、不写死指路话术
```

里程碑一 find 不移动身体：要找更远的东西，LLM 组合 travel + find。要不要在 v1 就让 find 自己走动搜索，见待两位决定 1。

组合的模型：M9（命中入记忆）、M12（观察编号、实体特征、多部件折叠）、M7（保护事实）。本能力特有的部分只剩：视线闸与命中过滤、实体计数纪律、"最近变化补查"。

## 4 能力说明（参数与结果）

### `maicraft:travel`

| 参数 | 必填 | 说明 |
| --- | :---: | --- |
| `target` | ✅ | 去哪：`position`（y 可省略）、`landmark`、`seen`、`here`（回头顶见天的地面上，第 13 节）、`direction` |
| `radius` | | 到达容差，单位格，默认 2；给 0 表示必须站进那一格 |
| `max_seconds` | | 最多走多久（秒）；超时以 STUCK 结束，写明停在哪、离目标多远 |

可给 `permissions`：`change_blocks` 决定能不能挖路、垫路（默认 `natural`）；`protected_landmarks` 把地方加入寻路禁改。

能力说明：

> 走到一个地方：给坐标（高度不确定可以不给 y，到了附近自己找能站的格子）、叫得出名字的地点、看得见的东西，或"往某方向走多远"。默认可以挖开天然方块、垫临时方块来开路，垫了什么会如实告诉你；不许动地形时只走不改，走不过去会说明原因。过河靠游，上坡靠爬或垫。走到、站实、落地才算到。

本能力特有的结果细节：

| 字段 | 含义 |
| --- | --- |
| `arrived_at` | 实测到达位置 x/y/z |
| `remaining` | 没走到时的剩余水平与垂直距离、八向方位（partial / STUCK / UNREACHABLE 时） |
| `placed_blocks` | 本次垫的临时方块（也在 `changes` 里） |
| `crossed_water` | 这段行程有没有泅渡 |

### `maicraft:find`

| 参数 | 必填 | 说明 |
| --- | :---: | --- |
| `block` / `blocks` | 与 `entity`、`structure` 三选一 | 找哪种方块（ID 或 `#` 标签） |
| `entity` | 同上 | 找哪种实体（类型 ID，可给几种） |
| `structure` | 同上 | 找哪种结构（命名空间 ID） |
| `count` | | 要找到几个，默认 1 |
| `radius` | | 扫描半径，单位格，默认 48（方块）/ 64（实体）；只扫已加载区 |

可给 `permissions`：`protected_landmarks` 使受保护区域里的命中照常报告但带保护事实。

能力说明：

> 在附近找某种方块、生物或结构，找到的每一样给一个观察编号，可以直接拿它下达别的指令（"去那里""采掉它"）。只算看得见的：墙后面、埋在石头里的不算找到，但会说明搜了哪一片。刚放下的方块不会漏掉。一条末影龙是一条，不是九条。圈起来的、拴着的、有名字的生物照常报告，但会注明受保护。找不到时说清查了多大范围，不等于那里没有。

本能力特有的结果细节：

| 字段 | 含义 |
| --- | --- |
| `found` | 命中列表：观察编号、类型、位置、三维距离、是否受保护（实体） |
| `searched` | 实际查过的范围（半径、已加载区覆盖情况、跳过的未加载段数量） |
| `count_by_type` | 按类型分别找到几个（给多种类型时） |

## 9 验收

**离线场景测试**（判断类用替身接口，任务用动作替身，不使用 `Unsafe` 与反射）：

1. 目标解析：position 带全 y / 省略 y / landmark 记得 / landmark 记不到四种走向；landmark 记不到 → UNCLEAR_TARGET 提问；异维度目标 → UNSUPPORTED。
2. 到达确认：脚位与支撑都在范围内且落地 → 到达；只碰最高点 → 未到；精确目标进格未落地继续等；导航报到达但身体没进格 → 未到；到达后取停稳坐标。
3. 容差纪律：radius=0 差 2 格 → partial 写明差几格，不放宽成功。
4. 许可映射：change_blocks=none 时寻路只走不改；natural 时可挖垫且垫的方块进 changes；受保护格不入寻路。
5. 进度：剩余距离长时间不缩短 → STUCK；超过 max_seconds → 超时，结果写明停在哪、离多远。
6. find 扫描：命中复核实际状态后过视线闸；视线穿未加载格判不可见；半透明材质不挡；最近变化通道让刚放的方块被找到（实机 099 场景）。
7. find 实体：多部件折叠到主体（实机 062 场景）；被遮挡不计入；同一轮可见才计数；受保护实体照常报告但带保护事实。
8. find 收束：找满 count 即收工；扫完不足 → 写清找到几个、查了什么范围；扫描中换世界 → 作废如实结束。

**实机验收**（追加到里程碑一清单；含第 5 节 P/G/S 类的原事故场景）：

1. 平地让它走到 50 格外的坐标 → 走到、站实，结果位置与实际一致；给全 y 与只给 x/z 各来一次。
2. 隔一条河让它去对岸 → 泅渡过河、上岸站实（跨水）；中途憋气先浮上来换气再接着走，不被打断切碎（T-38/T-39、实机 073/130/176）。
3. 让它上一面山坡 → 走上去或垫方块上去，垫了什么在 changes 里（上坡；实机 169 的垫块留存取向见待两位决定 4）。
4. 不给动土许可让它去一个被树挡住的地方 → 如实 UNREACHABLE，建议里写明授权动土能过；授权后同一路线能走通（实机 132：全程不踩农田）。
5. 让它去脚边 1.5 格的一个位置 → 直接完成"已经到了"，不报无路（实机 191）。
6. 让它去一个永远到不了的高度（y 提示过高）→ 高度纪律生效：先走近那一列，如实报告找不到能站的格子，不空转烧尽预算（实机 177/182）。
7. 地下让它去一个要挖洞才能到的目标 → 授权后能挖到或以 STUCK 如实结束，不无限烧预算（实机 071/110/117）。
8. 走到一半取消 → 人停在实际位置，结果 partial 写明停在哪、离目标多远；进度事件里剩余距离与真实位置一致（实机 119）。
9. 让它找附近的煤矿 → 返回观察编号与位置，编号能直接用来下达"去那里"（实机 040 的交接在这里成立）。
10. 放一个方块后立刻让它找这种方块 → 能找到（实机 099）。
11. 让它找末影龙（创造模式生成）→ 一条龙一个编号，详情带血量（实机 062）。
12. 让它找一种附近没有的方块 → 结果写清"半径 X 格的已加载区没有"，不冒充全世界没有。
13. 到达判定与结果一致：报到达时人确实站在目标容差内，话术与容差同源（实机 070/199/136）。

## 11 travel 的跨维度与传送门

> 范围：`travel` 的跨维度行程与传送门：找活门、走到门口、直走进门、到达确认与坐标换算，附近没门且许可允许时的建门，以及末地门的找要塞与激活（进不进第一版见定下的做法 4）。吸收 v0 的 `travel_dimension` 与 `prepare_portal`——跨维度不另立能力，是 travel 自己的一段行程。
> 接管：批准并实现后，3.1 第 1 步的"目标在别的维度 → UNSUPPORTED"由本节取代，在那之前里程碑一行为不变。5.1 标着"推迟：跨维度里程碑二"的 T-52 至 T-57 由本节接管：T-52 的同维度直连与中间维度建议、T-53 的找活门、T-54 的进门与门格回避、T-55/T-57 的建门都进下面的新逻辑，T-56 的维度名必填由参数校验表达。浇筑调查的去留见定下的做法 3：B-03/B-05 维持丢弃——find 找岩浆就是找岩浆，不为浇筑留用途参数；B-13/B-14 的岩浆池连通分析随拍板同去留。
> 边界：打末影龙归战斗域（`fight`），龙死后走出口门回主世界归本节 11.6；要塞的大范围走动搜索归探索域与 find；下界里的着火、岩浆、恶魂照旧由生存需求与战斗处理；乘船、飞行、电梯不做。

### 11.1 真人怎么做

要去别的维度，先看附近有没有现成的门：有就走过去，对着门走进去，站一会儿人就在另一边了；到了先离门口几步，免得又传回去。附近没门就自己搭一个：找块平整空地，有残缺的黑曜石框先补齐再点，没有就摆十个黑曜石、用打火石点门框内侧，门面出现了就进去；身上没有黑曜石就先去弄。要下界深处的某个坐标，过去之后接着走。要去末地，得先找到要塞，把末地门空着的眼逐个插上末影之眼，插满门就开了——那是条单程路，回来要么打败末影龙走出口门，要么死回来。

### 11.5 验收

**离线场景测试**（判断类用替身接口，任务用动作替身）：

1. 维度路由：同维度不出跨维度段；下界↔主世界、主世界↔末地各认对门方块；其余维度对 → NOT_POSSIBLE_HERE 建议中转；模组维度 → UNSUPPORTED；维度名缺失或非法 → 参数校验一次报全。
2. 找活门：门方块还在才算活门；扫描没完成不报没找到；整扇连通识别与上限；按列底部挑入口；接近失败只排除已试入口，同门另一侧仍在候选里。
3. 门格回避：途经的下界门格不可走；行程点名要进的那扇门的门格放行（`BlockPassability` 离线测试，实机 198 场景）。
4. 进门与到达：进门前门没了 → TARGET_GONE 换下一候选；20 秒进不去排除；维度变了才算完成，没变如实试败；到达先离门口再取落点。
5. 坐标换算：主世界→下界、下界→主世界的预期落点纯函数；结果带实测与偏差。
6. 建门：残缺框补齐优先于新建；缺材料 NEED_ITEM；门框没成型 → 结束、保留施工事实、不循环；change_blocks=none → 按没门结束并建议授权。
7. 许可：插眼在 use_rare_items=false 时照插，结果写用了几只眼、还剩几只；身上的眼不够插满、备不齐 → NEED_ITEM；建门在 change_blocks=none 时不提问，按没门如实结束。
8. 打断与收尾（定下的做法 6）：建门、末地门房间、建门里的砌框与浇筑，整趟暂停时跟着暂停，能不能打断照它们手上的动作，整趟被收尾时按取消收尾、交代的事实并进这趟结果。

**实机验收**：

1. 主世界走近现成的下界门让它去下界 → 走到门口、直走进门、传送，报告的落点与 1:8 换算预期相符（偏差如实写明）。
2. 从下界同一扇门回来 → 双向往返跑通，进门后离门口结算，不被重入冷却绊住。
3. 没门的区域让它去下界（默认许可）→ 勘察、备黑曜石与打火石、搭门框、点火、验活、进门，一个目标里完成。
4. change_blocks=none 时同样目标 → 按没门如实结束，建议授权动地形。
5. 出发点紧邻一扇下界门，让它去同维度附近的目标 → 路线不穿门抄近路（实机 198 场景）。
6. 让它去一个模组维度 → UNSUPPORTED，如实说明目前只支持主世界、下界、末地。
7. （拍板 4 通过时）让它去末地 → 到要塞、插眼激活、进门落在末地平台上，结果写明单程。

```text
折跃门是一种出行方式（via=end_gateway），由行程规划来问；只在末地用得上。

0 要不要过门  出发与目的地分在虚空两边（一头在主岛：离 0,0 水平 512 格内；另一头在外岛）
              → 这一段非它不可，只问它：走路过不去近千格虚空
              给了 via=end_gateway → 用它；只给 via=end_gateway 不给 target → 过最近的一扇门，到了对面就算到
              两头在同一片 → 不出报价："两头都在主岛（都在外岛），折跃门只通虚空另一边"（走不走得通由走路自己说）
              不在末地 → 不出报价
1 许可        要扔掉一颗珍珠：过门就是这一段的目的，珍珠是为它扔的，不看 use_rare_items（它只管不是目标本身的消耗）；
              身上没有珍珠按第 3 步去弄
2 找门        先看原版那一圈的 20 个固定位置（离 0,0 约 96 格、高 75）哪几格是折跃门方块，
              再扫已加载区的折跃门方块（外岛的门、改过地形的末地）；没扫完不下"没有"的结论
              一扇都没有 → NOT_FOUND：在主岛说"那一圈一扇折跃门都没有：每打败一次末影龙才开一扇"，
              在外岛说"已加载区没有折跃门：外岛的门悬在当初落地处头顶十来格"
3 报价        按"走到门边 + 过完门再走到目的地"挑最省的三扇，每扇一份：从门口出发；送到哪按原版估——
              主岛的门送到同方向约 1024 格外，外岛的门送回同方向那一圈；
              耗时按走到门边加扔珍珠、等传送算。非它不可时挑"过完门再走到目的地"总耗时最短的那扇
              （门朝着目的地的方向）；一扇门这一趟没过成，行程换下一扇
4 备珍珠      身上没有末影珍珠 → 交拿东西的引擎弄一颗（许可原样传下去）；弄不到如实结束这一段（NEED_ITEM）
5 走到站位    站位：门洞只在四个侧面敞着，眼睛要对着侧面——门旁 2 到 4 格、脚比门洞低 0 到 2 格，
              从眼睛到门洞侧面中心一路是空气，伸手够得着（4.25 格）；脚下本来站得住的优先，离人近的优先
              门悬在半空、没有现成落脚处：许可允许垫方块（change_blocks=natural）就交给走到垫柱、搭桥上去；
              change_blocks=none 只挑现成站得住的，没有就 UNREACHABLE，说要把 change_blocks 放开到能垫方块
6 扔珍珠      珍珠换到主手，朝门洞用一下（用东西的瞄准交互：转过去、准星对上门洞再出手）；手上珍珠少了一颗算扔出去了
              站在那里还是看不见门洞（被挡）：换下一个站位，这次不算扔过
7 等传送      以落在哪为准：人到了虚空另一边（主岛与外岛对调）就是过去了；
              等的时候停下不安全：珍珠在天上，人被拉走了也照样被传过去。12 秒为限
              12 秒没过去：珍珠没进门（撞在门框基岩上、门刚用过在冷却、飞过头了），如实记一笔
              （从哪扔的、人现在在哪），回第 4 步再扔一次；第二次还没过去 → UNREACHABLE，两次经过都写上
8 落地        过去后等身体站稳（半秒不动，最多 3 秒）再交回，行程从落点接着规划剩下的路
```

组合的模型：M2（走到站位，垫柱搭桥归走到）、M3（用东西的瞄准交互）、M4（备珍珠）、M7（change_blocks）、M8（进度与问题种类）、M10（行程规划与出行方式）。本节特有的只有：主岛外岛之分、那一圈门的位置与送到哪、扔珍珠的站位、以落到虚空另一边认过门。

#### 定下的做法

| # | 问题 | 做法 |
| --- | --- | --- |
| 1 | via 叫什么 | `end_gateway`，和方块 ID `minecraft:end_gateway` 同名。任务原文写的是 `via=gateway`；单独的 gateway 在 09 里是易误解词（会被读成 API 网关），类型名也禁用这个词，带上 `end_` 只会被读成末地折跃门 |
| 2 | 做成出行方式，还是像跨维度那样另立一段 | 出行方式：和电梯、火车用同一个接口，过门只是行程里的一段，过完从落点接着规划；"非它不可"、指定方式、`legs` 结果都是现成的。原版自带、不用装模组，所以 travel 的参数表里从此总有 `via`（至少 `walk`、`end_gateway`） |
| 3 | 不在末地的出行会不会因此都改走行程规划 | 不会：出行方式自报在哪个维度用得上；没指定方式、当下维度又没有用得上的方式时，照原来直接走路 |
| 4 | 主岛外岛怎么分 | 离 0,0 水平 512 格为界：原版主岛半径约一百格，外岛从约一千格外才生成，中间全是虚空。类别 F |
| 5 | 扔歪了怎么办 | 如实记，再扔一次（任务批准的做法）；第二次还不行，这一段 UNREACHABLE，行程换下一扇门。报价只给最省的三扇，一扇两颗，最多扔掉六颗就停下说明，不把身上的珍珠全扔进门框 |
| 6 | 门悬在半空够不着 | 交给走到去垫柱、搭桥，出行里不另写一份摆方块的活；站位怎么挑是折跃门特有的几何（门洞一格高、上下基岩），写在扔珍珠的站位里 |
| 7 | 门在冷却（刚有东西过去，原版两秒内不传） | 不预判：扔进去没过去就按扔歪处理，如实记、再扔一次 |
| 8 | 落到对面要不要离门口 | 不离：对面那扇门悬在头顶十来格，走不进去 |
| 9 | v0 穿门时另有的三处：主岛上边走边找门、门旁有受保护地标就不扔、站位上有敌对生物先打 | 都不另写：找门看主岛那一圈 20 个固定开门位置加已加载区扫描，那一圈有位置没加载就如实说几个没看到、让人走近再找；扔珍珠不改方块，受保护的格子由走到的保护格管（垫上去时不动）；站位附近的敌对生物交给自卫，打完回来接着这一段 |

#### 验收

离线场景测试（判断类用替身读格，一段用动作替身）：

1. `EndIslands`：主岛外岛分界、跨没跨虚空、那一圈 20 个位置、送到哪的估计。
2. `PearlThrowSpots`：能看见门洞侧面的站位才算；视线被挡的不算；change_blocks=none 只要现成站得住的。
3. 报价：不在末地、两头同一片各给各的原因；use_rare_items=false 照样出报价；跨虚空时非它不可；几扇门挑朝着目的地的那扇。
4. 一段：身上没珍珠先去弄；扔一次过去了；扔歪一次再扔一次过去了；两次都歪 → UNREACHABLE，两次经过都在；珍珠弄不到 → NEED_ITEM。
5. 出行能力：主世界没指定方式照旧直接走路；只给 `via=end_gateway` 不给 target 也能下。

1. 打过一次龙的主岛：`travel` 到外岛的一个坐标 → 找门、备珍珠、垫到门边、扔进去、落在外岛，接着走过去。

### 11.8 一趟跨维度串上折跃门：主世界去外岛、外岛回主世界

> 状态：已批准（2026-10-16，所有者，六条做法照建议）。起草：Claude（travel 跨维度串折跃门会话，查漏总账 A3 收尾）。
> 接管：11.6 做法 3 与 11.7 边界里的"这一程不自动串上、分两次下 travel"由本节改掉。
> 边界：折跃门本身怎么过照 11.7，出口门怎么走照 11.6，这里只管跨维度那一程前后在同一个维度里的那段怎么交出去。下界与主世界里跨完接着走的取舍不变（那两个维度没有原版自带的出行方式；装了联动方式时见定下的做法 1）。跟随过门不带坐标、不从末地出发，不受影响。

#### 真人怎么做

从家里去外岛的某个坐标：进末地门，落在黑曜石平台上，走到主岛外圈那扇折跃门边扔一颗珍珠，落地后接着走到地方。在外岛想回家：先对着头顶那扇门扔珍珠回到主岛，再走到中间的出口门跳下去。一趟走完，中间不停下来等人再说一遍。出门前就知道要扔珍珠：手上没有、或不让扔，就不进那扇单程的末地门。

## 12 建门的浇筑手法：找岩浆池现浇黑曜石

> 状态：已批准（2026-10-14，所有者按 12.4 的七条建议）。起草：Claude（浇筑迁移会话）。
> 范围：建门（第 11 节"没门 → 建门"）的第二种建法——身上没有黑曜石时，在附近岩浆池的岸边用一只桶、一桶水和十来块石头把门框浇出来。吸收 v0 的 `NetherPortalCastingTask`、`NetherPortalCastingLayout`、`PortalCastingStep`、`PortalCastingSurvey`、`PortalCastingTerrain`、`PortalLavaPoolSurvey`、`PortalResourceSearchTask` 与 `PortalPreparationTask` 的 CAST 分支（约 1500 行）。
> 接管：11.3 定下的做法 3 里"另立规格"的那份就是本节；B-13/B-14 的岩浆池连通分析进本节的勘察，B-03/B-05 维持丢弃（find 不加浇筑用途）。
> 边界：怎么挑门址、备打火石、点火、验活仍是 11 的建门；倒桶、舀桶、放石头、挖格、临时方块全部走施工引擎的公开接缝，本节不写第二份；浇完门框没成型照 T-55 结束不循环。

### 12.1 真人怎么做

速通玩家没有钻石镐也不等：带一只桶、一把打火石、十来块随手的圆石或泥土，找到地表岩浆池，挑一段直岸——岸边四格连成一线的岩浆，岸上站得住人。岸是弯的就填几块把它填直，身后铺个站台好站、好转身。先在岸边的岩浆里放一块石头挡住一格，紧挨着往岩浆里倒一桶水：水碰到的岩浆当场成黑曜石；再挖掉那块石头让水流过去，门底一行和两侧的底脚就齐了，把水收回桶里。然后在门右侧和顶部的后面砌一排挡水的石块，从高处倒一桶水让水顺着挡块贴着门的位置往下流，拿空桶去池里舀一桶岩浆，回来浇在门框该有黑曜石的格子里——岩浆碰水立刻成黑曜石，一桶一格，八桶浇完整圈框就成了。收水、拆掉挡块、点火。整个过程只用一只桶，池子里的岩浆就是材料。

### 12.7 验收

**离线场景测试**（判断类用替身读格，任务用动作替身，不用 `Unsafe`）：

1. `PortalCastingLayout`：四个岸向下框十格与 `NetherPortalFrame` 一致；模具六块不占框格；浇框水在框后方；净空、站台在模板范围内；浇框顺序每格都有已有的点击面（挡块、模具、底脚或上一格黑曜石）。
2. `LavaPoolSurvey`：直岸合规；弯岸给出要填的格；余量不足 15 拒；填台吃掉的源格不算余量；模板里有未加载格不下"没池"结论；受保护格拒；有干燥站位的候选排前；起手行已是黑曜石的接着认。
3. 建法选择：黑曜石够 → 直建；不够且有池 → 浇筑；都没有 → 直建备料，试过的办法里带勘察事实；残缺框在岸边 → 续浇。
4. 浇筑任务：替身世界里"岩浆源贴水即成黑曜石"，整条顺序走完框成十格、模具被收回、用桶次数对；已是黑曜石的格跳过；桶里没岩浆先舀再倒；倒出圆石记变化不重倒；收水时水源没了补一次水、再没就停；没水 → NEED_ITEM；中途失败模具仍收回、岩浆桶倒回。
5. 结果形状：`portal_built_how` 两种取值；试过的办法在全部失败时长度有界（同原因合并计数）。

**实机验收**（追加到里程碑二）：

1. 在岩浆池岸边、身上只有一只桶和打火石，让它去下界 → 舀水、填直弯岸、挡块放水、十桶浇出框、拆模具、点火、进门；观众看得到每一桶。
2. 同一处身上有十块黑曜石 → 直接摆框，不去碰岩浆。
3. 平原上没有岩浆、没有黑曜石 → 结果 NEED_ITEM 写清查了 128 格没池、缺黑曜石或钻石镐；LLM 用 `explore` 留意岩浆后再来能接上。
4. 池子只有一格深（底下石头）→ 底行先挖再浇，成型。
5. 浇到一半人为把水收走 → 任务补一桶水接着浇；再收走 → 如实停下，模具收回、桶里岩浆倒回池。

## 13 回露天地面

> 状态：所有者 2026-10-16 批准方向（查漏补缺 F9：采矿后回地表是常事）；本节写清细节，实现照本节。
> 范围：`travel` 的 `target` 写 `{"kind":"here"}` 时回到头顶见天的地面上。不新增目标对象：出行"没给 y 就是地面上"本来是一条规矩，`here` 不带高度，所以就是脚下这一带的地面。`explore(target=surface)` 照旧是"朝某个方向跑图找露天"，两者不合并。
> 行为变化：原先 `travel(here)` 一律当"开始时已经站在目的地"直接完成；现在只在已经站在露天的地上时这样，在地下、屋里、悬崖底下会动身回地面。

### 13.1 真人怎么做

挖完矿要回地面：旁边几步就见天（站在山崖檐下、洞口里）就直接走出去；在深处、允许动土，就对着前上方斜着挖一段楼梯上去——每一级先挖开头顶、前上方两格，跳上去，再挖下一级，直到头顶见天；前面挨着水、岩浆，或头顶压着沙砾就换个方向挖。不许动土就找路走出去，找不到说清找了多大范围。

### 13.2 新逻辑

```text

             给了 via 且不是 walk → INVALID_PARAMETER：回露天只走路和挖楼梯
1 看一眼     在已加载区里找露天落脚处（ReachOpenSky 的候选：那一列顶上是实心方块、不是液体，上面站得下人）：
               近处：水平 8 格内、上下 4 格内，每列都看
               远处：水平 64 格内，每 4 格看一列
             按离脚下的远近排
2 走出去     近处有露天落脚处且没试过 → 交给走到去最近的那几处之一（按这次的许可，许可让挖时走到也会挖路）
             走到了、脚下露天 → 完成；没走到或到了还不露天 → 记一次，往下
3 挖楼梯     许可能挖天然方块（change_blocks 是 natural 或 any）且没挖过 → 往上挖楼梯（behavior.acquire.ClientStairsUp）：

                 前方脚下是空的或是液体；头顶那格上面压着沙子、沙砾照挖：掉下来再挖，砸到头被埋住由被埋需求挖开

5 收场       都不行 → UNREACHABLE：说清找了多大范围（近处 8 格、远处 64 格的已加载区）、看到几处露天落脚处、
```

## 14 landmark 认附近告示牌上的文字

> 状态：待所有者批准。07 目标对象表、本规格出行新逻辑的"解析目标"与 T-14、T-17 都写着 landmark 含附近唯一同名的告示牌，实现只查记住的地点；查漏总账 C8（告示牌文字当动作目标）原先按衡量尺定为不做。批准就照本节实现；不批准就把那几处说法改成"只认记住的地点"。
> 范围：把目标对象 `landmark` 落成一个位置的地方共用一处解析：`travel`（睡觉指的目的地也走它）、`use`、`deposit`、机器的配置与连接、`enchant`、载具的组装与驾驶、`remember`（拿另一个地方的位置记新名字、圈地盘）。保护（`protected_landmarks`、家附近）、施工与读现场（那里的 landmark 是建筑档案名或记住的地点）、许可检查不认告示牌。
> 行为变化：原先名字没记过，travel 就提问、其余能力报"没记住"；现在先看附近看得见的告示牌，恰好一块写着这个名字，就把那块牌子所在的格子当地点。

### 14.1 真人怎么做

主播说"去仓库"，角色没记过仓库在哪，抬头看见一块写着"仓库"的路牌，就朝那块牌子去。两块写着"仓库"的牌子隔得老远，就问一句是哪一块，不自己挑；门两边各钉一块同样的牌子，那是同一处，不用问。牌子上写的是"张三的仓库"，不当成"仓库"。

### 14.2 新逻辑

```text
1 记住的优先   世界记忆里记过这个名字 → 用记住的位置，不看牌子（同名的牌子顶不掉记忆）
2 看牌子       没记过 → 看此刻场景里看得见的告示牌（observe 场景里的 signs：附近、视线看得见、客户端收到了字的那些），
               不另扫一遍；墙后的、还没收到字的不算
               写着这个名字 = 名字和牌子上的字"相同"，不比"包含"：
                 比之前两边都只留字母、数字、汉字（去掉空格、标点、箭头这类符号），不分大小写
                 正面、背面分开看；一面里某一行单独相同，或这一面所有非空行连起来相同，都算
                 字按画面上显示的比（客户端开着文字过滤就比过滤后的），和 observe 里看到的一样
                 例：名字"仓库"认得出 ["仓库"]、["【仓库】"]、["→ 仓库"]、["仓","库"]、["仓库","往前 20 格"]；
                     认不出 ["张三的仓库"]、["仓库往前20格"]
3 落位         恰好一块写着它 → 地点就是这块牌子所在的那一格（当前维度）
               几块写着它、都在离角色最近的那块 3 格以内（门两边、柱子上下）→ 当成同一处，取最近的那块
               几块写着它、隔得开 → 不挑：说清"附近有 N 块告示牌都写着「X」：b3（东北 12 格）、b7（西 30 格）"，
                 建议用 seen 指其中一块；travel 照旧以 UNCLEAR_TARGET 提问，其余能力照它们原来"没记住"的问题种类结束
               一块也没有 → 和原来"没记住"一样收场，句子里补一句"附近看得见的告示牌上也没有写着「X」的"
4 往后         落出来的位置和记住的地点一样用，后面的事照各能力原来的做法：travel 走到它旁边（到达容差照 radius），
               use、deposit 在它附近找，机器、附魔台、载具组装把它当那一格
```

拒绝与提前失败的归类：几块隔开的同名牌子不挑、一块都没有，都是"目标说不清"（C），不新增 P、G、S。
