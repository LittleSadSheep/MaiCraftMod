## 2 真人怎么做

**设计**：先在图纸上把房子定下来——几面墙、几扇窗、门开在哪、屋顶什么样、用什么料；拿不准就改一版再看。图纸不绑地点，画好了可以盖在任何地方。

**施工**：带上材料走到工地。先看地形：挡着的树和土挖掉，坑填上，用不上的土石顺手处理掉。从地基往上一层一层砌；站在刚砌好的墙上、台阶上继续，够不着就垫两块土或搭一截脚手架，用完拆掉。门、窗、火把这些贴附的东西等墙立好再装。材料用完就去拿，拿回来接着砌，已经砌好的不动。某一格暂时放不上（站不稳、被什么挡着）就先砌别处，回头再来。砌完走一圈对图纸：哪格不对补哪格，门关好。中途不想盖了，把自己垫的土收走再走。

**不做的事**：不因为一格放歪了推倒重来；不替作者改图（图纸要求石砖就不拿圆石凑）；别人的东西不碰——碰到玩家的箱子、围墙，停下来问。

## 3 新逻辑

### 3.1 `design`：建筑设计

设计 `BuildingDesign` 就是 v0 v2 作者模型的语义，原样保留（这是 v0 里最值钱的部分，离线测试也全）：材料表、对象（MESH / INSTANCE）、十二种图元、组件与实例、阵列与跳过、镜像与四分之一周旋转、布尔差切割、空心与壁厚、开口面、面材质与棱材质、平面图案、`block_state_axes`、`overlap_policy`、Blender 与 Minecraft 两种坐标系。在它上面加一种对象 `ROOF`（参数化屋顶：五种形状、举架曲线、出檐、翘角、脊、檐口、山墙、底衬），把 v0 内部工具里量出来的中式屋顶做法带进设计模型（第 10 节 D12）。

```text
design 的操作（参数 operation）
  create      drawing → 校验、编译、存盘 → design_id；返回统计（对象数、展开数、格数、每种材料几件、包围盒、叠加冲突）
  update      design_id + edits → 按名合并、整体重校验、编译 → 新 design_id（父版本保留，不就地改）
  inspect     design_id（+ name / component / page）→ 对象、组件、展开路径、面棱名；不动角色
  preview     design_id + target（+ rotation）→ 把蓝图落到锚点，交给预览叠加显示（不阻塞任何任务）；返回统计
  export      design_id + format（json / nbt）→ 写文件 schematics/maicraft-design-<id>.<format>
不再有的操作：revise_project（续建就是 goal(resume) 或再下达一次 build，见 3.4）、契约版本凭据
```

- 设计**不绑地点**：坐标相对设计原点，锚点在 `build` / `preview` 时由 `target` 给。v0 把锚点存进场景并禁止换地（B07），v1 改掉。
- 编译结果 `Blueprint`（相对坐标）由 `DesignCompiler` 给出；格式校验、变换、展开、涂装、叠加、状态随变换、预算这些纯判断原样移植，改名按末尾"需登记 09 的新名字"一节。
- 设计存储 `DesignStore`：按实例保存，不按世界（设计跨世界可复用，第 10 节 D5）。现有的文档库放在存档目录里按世界分，所以设计另开一个库，位置是实例目录下的 `config/maicraft/designs.sqlite`；换一个游戏实例设计不跟着走，要带走用 `export`。每次 `update` 新建版本并记父版本；不设数量上限，文件大小按预算。
- 格式说明走 `lookup(topic=knowledge, id=building/design)`：字段、默认值、图元与面棱名、图案规则、叠加规则，一篇讲清；`lookup(topic=knowledge, id=building/roofs)` 讲屋顶参数。不再提供 JSON Schema 资源和指纹（第 8 节）。
- 校验错误一次报全，带 `objects[下标](名字)` 这样的定位（M04 保留）。

### 3.2 蓝图 `Blueprint` 与计划格 `PlannedCell`

蓝图是逐格目标清单，所有施工入口都收敛到它：

```text
Blueprint
  anchor        世界坐标 + 维度（设计编译出的蓝图没有锚点，落地时加上）
  cells[]       PlannedCell
  summary       格数、每种材料几件、包围盒

PlannedCell
  pos           绝对坐标（相对蓝图里是 offset）
  kind          BLOCK 放一个方块 / AIR 清空这一格 / FLUID_SOURCE 倒一桶（水源或岩浆源）
  state         要求的方块状态（经 BlockStateRules 归一）
  item          放它要用的物品（土径、耕地按泥土；带花的花盆是盆加花）
  required      作者明确写的属性名；验收只比这些，其余按原生落法接受
  placedBy      BUILDER（默认）/ MACHINE（机器的安装段与部件格：引擎不放、不清障，仍算进场地范围与保护）
```

蓝图的来源：

| 来源 | 怎么变成蓝图 |
| --- | --- |
| 设计 `design_id` | `DesignCompiler.compile(design)` → 相对蓝图 → 按 `target` 与 `rotation`（0/90/180/270）落到锚点 |
| 逐格 `cells` | LLM 直接给 `{offset, block, properties}` 列表；门、床这类两格方块两格都要写 |
| 结构文件 `file` | `.litematic` / `.schem` / `.nbt` / `.snbt`，经导入（移植 v0 的解析、预算与安全白名单：方块实体数据只带装饰性的，容器内容、刷怪笼、战利品表不搬；展示框、盔甲架、画这些摆设实体不安装，结果里写明有几个没装） |
| 单格 `block` | 一格的蓝图 |
| 机器蓝图 | 机器规格的 `MachineBlueprint` 就是 `Blueprint` 加机器附加条目 |

- `BlockStateRules.normalize`：堆肥桶、炼药锅归默认；`age` 归最小；蜂蜜、孵化、stage 归零；浆果、含水、活塞伸出归否；树叶 persistent（ST01 全部保留）。作者明确写的属性被归一化改掉 → `INVALID_PARAMETER` 报这一格（SC13）。
- 不可建的：结构方块、拼图、活塞头、移动中的活塞 → `INVALID_PARAMETER`；液体改为 `FLUID_SOURCE` 格（v0 拒绝液体，v1 倒桶，第 3.3 节）。
- 蓝图**未声明的格子不是"必须为空"**；`AIR` 格才是"清空这一格"。
- 核对 `BlueprintCheck.compare(blueprint, 只读世界, 交给机器核对的格) → 每格 CellState`：

```text
CellState
  MATCHES             已符合要求（required 属性逐项一致；没点名属性时同方块即可，立式/墙式双形态互认）
  WRONG_BLOCK         方块不对
  WRONG_STATE         方块对、点名的属性不对
  MISSING             该有方块的格还是空的（或可替换的草、水）
  UNKNOWN             那一格没加载，不猜
  CHECKED_BY_MACHINE  placedBy=MACHINE 的格，由机器按最终结构核对
  EXTRA               只在"范围内未声明格有东西"的信息里出现，不算失败
```

`complete` = 没有 UNKNOWN；有 UNKNOWN 不给"整份一致"的结论。比对是纯函数，分几刻读世界（M12 的扫描服务）。

### 3.3 施工引擎 `behavior.construction`

施工是"把一份蓝图变成现实"的玩家行为，全仓只有一份：`build`、`light`、`machine_build` 都经它干活。放在玩家行为层（第 10 节 D1 给了另一种放法）。入口是一个任务：

```text
ConstructionInput（不可变）
  blueprint         绝对坐标的蓝图
  permissions       这次任务的许可（M7）
  purpose           用途标签，给 M4 备料与 M9 临时方块记账用

ConstructionTask（继承 PhasedTask）
  CHECK       BlueprintCheck 逐格核对（分几刻，未加载的格先走到那一列让它加载，M10 高度纪律）
              全部 MATCHES → 完成，结果写"开始时已满足"，一个动作都不做
              不可能的格（基岩、出界、世界边界外）→ 记进结果，照建其余（第 10 节 D3）
              受保护的格（M7 Protection：玩家的东西、记住的区域、额外保护的地标）→ 问题 NEED_APPROVAL，
                一次列出全部这些格；LLM 同意后以 change_blocks=any 继续，不同意就跳过它们照建其余
  SUPPLY      缺口 = 按未满足的格算材料 − 身上有的；经 M4 ItemAcquisition.need(物品, 数量, 用途=施工) 补
              补不齐不整单拒绝：有多少建多少，材料用完时停在材料尽头，结果 partial + NEED_ITEM（第 10 节 D2）
              临时方块的材料也在这里备（用途=垫脚），优先身上最不值钱的整块（M5 价值分级反过来用）
  CLEAR       要清的格（AIR 格里有东西；BLOCK 格里是别的、不可替换的方块；两格方块的另一半）按从上往下、按层清；
              能不能挖由 PermissionCheck.allows(DIG_BLOCK, 格) 回答，不另有替换档（施工引擎是它第一个真正的使用方，
                现在没人调用、目标对象 y 为空时会空指针：实现时先修好并补测试）；挖走 M3 BlockBreaking；
              连锁挖掘经 BreakAccelerator spi（behavior.interaction.spi，FTB Ultimine 实现）；
              Create 的机器件经 DismantleTool spi（新，behavior.interaction.spi：拿扳手潜行右键整块拆下并收回物品，
                Create 联动实现）；两个 spi 都要在联动登记表加槽，实现时在同一提交里加，动手前先告诉审查会话
              余土：背包要满时交给 M5（存进附近已知容器，或丢最不值钱的）
  PLACE       按 BuildOrder 从低层到高层，同层先骨架后贴附件，就近连放：
              站位 = M2 PlacementSpots（站得稳、够得着、看得见目标格的某个可点击面、放下后不卡住自己）
              点击 = M3 AimAndInteract(USE)，提交前用原版的放置预测（PlacementPrediction）核对落下来是不是要求的状态；
                     会开界面的方块点它时潜行
              确认 = 服务端确认 + 副格一起看（门上半、床头）+ 耗材变化；没能确认的记 unconfirmed，不重放
              多次放置（雪层、蜡烛、双层半砖）看进度，达到数量才算这一格完成
              某格放不上（站位用尽、暂时没支撑面）→ 先做同层别的格，回头再试；
              回头仍放不上 → 临时方块：从目标六向空气格找到最近的已有方块，垫一条可拆的链（第 3.3.1 节）
              床等按视角定朝向的两格方块：作者没点名朝向时按原生落法接受，并把另一半按实际落法核对
  POUR        实心格都放完后处理 FLUID_SOURCE 格：先收走声明范围内不该在的源液体（AIR 格里的源用空桶收），
              再逐格倒桶（M3 USE_HELD_ITEM，落点按 BucketWater）；源格被原版自补的跳过；
              倒进去变成了别的东西（黑曜石、圆石）如实记 changes，不判失败
  VERIFY      再 BlueprintCheck 一遍；WRONG_* 的格有限修补（同一批错误重复出现就停，不无限拆建）；
              只有点名的最终属性才修：可手开的门按 use 开关一次；其他状态差异如实报 UNSUPPORTED 记在这一格
  CLEANUP     收回自己垫的临时方块（M9 TEMPORARY_BLOCK，第 3.3.1 节）；收不回的列进结果
  结果        每格结局、变化、未确认、剩余、临时方块去向；全部 MATCHES → done，否则 partial 带问题
```

施工过程中的通用规矩，全部来自已有模型，这里只写它们怎么接上：

- **许可**（M7）：声明范围内的格默认允许拆改（天然方块与无主的东西按 `natural`，玩家的东西要 `any`）；`change_blocks=none` 时只放不拆，`temporary` 时只能垫临时方块。v0 的 `replace_existing`、四档 `ReplaceMode`、`replace_block_entities`、清障白名单、"目标格豁免自注册保护"全部不要。
- **打断**（M6）：两格之间报 `BETWEEN_ACTIONS`，吃饭、夜休可以插进来；正在等确认、站在临时方块链末端或檐边时报 `UNSAFE_TO_STOP`。
- **进度**（M8）：真实进展 = 一格的 CellState 变好、一格清掉、一桶倒下、一块临时方块收回；换阶段、换站位、重新算路都不算。
- **记忆**（M9）：开工时把蓝图包围盒记成 `SITE`（"这里在盖东西"），垫的方块记成 `TEMPORARY_BLOCK`。
- **跨重启**：目标存成暂停；`ConstructionTask` 不存进度，恢复后从 CHECK 重来，世界里已经对的格自然跳过；临时方块从 M9 读回。v0 的冻结施工单、`project_id`、支撑 sidecar 都不要。
- **机器格**：`placedBy=MACHINE` 的格 CHECK 时出 CHECKED_BY_MACHINE，PLACE 与 CLEAR 跳过，CLEANUP 照收临时方块。

#### 3.3.1 临时方块

```text
什么时候垫    某格够不着或没有可点击面，同层别的格也做完了；或出行层（M10）为到站位垫脚
怎么找        从目标六向的空气格向外找到最近的已有方块（水平 4、向下 24、向上 2 格内），链最长 32，
              链末端那块必须给目标提供原生所需的点击面；一条都找不到 → 这一格 UNREACHABLE，记进结果，继续别的格
用什么        用途=垫脚的材料，M4 从身上挑最不值钱的整块、易挖、无方块实体、非掉落方块；不读配置文件
记账          每块放下并确认后记 M9 TEMPORARY_BLOCK（位置、方块、用途）；"是不是自己放的"由服务端方块归属记录回答
收回          施工结束、失败、取消都收：先收站着够得着的，再沿自己的柱逐格下撤（每格拆前确认下一格落得稳），
              走不到的记进结果 temporary_blocks_left，不为收回再垫新的柱子超过 32 块；600 刻没有一块收回就停
不收的        放在蓝图里本来就要有方块的格（它就是成品）
```

v0 的支撑账、项目 sidecar、清理接近（为收旧支撑再搭 32 块）、停滞看门狗的做法，归并成上面几条；取消不收回（184）与残留（181）靠"任何终态都走 CLEANUP"解决。

### 3.4 `build`

```text
0 校验      design_id / cells / file / block 四选一；rotation 只配 design_id 或 file；
            target 必填（here / position / landmark / seen / previous），y 省略时取锚点那一列的地表高度
1 已满足    蓝图落地 → BlueprintCheck 全部 MATCHES → 完成，"开始时已满足"
2 施工      ConstructionTask（许可来自 goal.permissions；用途=施工）
3 结果      done / partial / failed 按引擎；details 见第 4 节
续建        同一设计同一锚点再下达一次就是续建（已对的格跳过）；目标跨重启存成暂停，goal(resume) 接着做
```

`build` 自己只剩参数校验、锚点解析和把结果转成能力细节；v0 的续建适配、冻结施工单、供料父任务、预览门、分批合同都不存在了。

### 3.5 预览

- `design(preview)` 把落地后的蓝图交给**预览叠加**：世界里画半透明的目标方块、红色的要清空格、蓝线包围盒；给直播观众和主播看，LLM 看不到也不需要看。
- 叠加不阻塞任何任务，没有"确认后才开工"；显示与否、按层切片由调试面板管（10 号设计的世界叠加入口），命令只剩关闭。
- 施工中的蓝图同样可以叠加显示（当前目标格高亮）；这是调试面板的事，不进本能力。

### 3.6 与机器施工的分界

机器规格的 `machine_build` 把普通格与流体格交给 `ConstructionTask`，自己只做三种附加条目：部件（装在宿主面上的 AE2 部件）、原生安装段（Create 传送带、链条输送机这类只能用模组自己的放置方式成型的一组格）、安装后设置（Mekanism 侧面、分拣过滤）。安装段与部件的格标 `placedBy=MACHINE`；整机比对用 `BlueprintCheck`，档案合并归机器。双方都不另写一套放置、清障、备料、临时方块或核对。

### 3.7 组合的模型

M2（放置站位、挖掘站位；`StandOpener` 为站位挖开或垫一块）、M3（放、挖、倒桶、开关门）、M4（备料、垫脚材料、挖掘工具）、M5（余土、背包满）、M6（两格之间插生存需求）、M7（能动哪些格、受保护的格提问）、M8（进度、重试、问题）、M9（工地与临时方块记忆）、M10（走到未加载的列、高度纪律）、M11（不用）、M12（观察编号作锚点）。

本领域自己特有的只有：设计模型与编译、蓝图与核对、施工顺序、放置预测、临时方块链、倒桶顺序、结构文件导入。

## 4 能力说明

参数名用参数名表里的；本规格新登记 `design_id`、`cells`、`file`、`rotation`、`properties`、`edits`、`format`、`page`（见末尾"需登记 09 的新名字"）。

### `design`

| 参数 | 必填 | 说明 |
| --- | :---: | --- |
| `operation` | ✅ | `create` / `update` / `inspect` / `preview` / `export` |
| `drawing` | create | 图纸正文（格式见 `lookup(topic=knowledge, id=building/design)`） |
| `design_id` | update / inspect / preview / export | 设计编号 |
| `edits` | update | 按名合并的修改：objects、materials、components、remove_objects、remove_components、block_state_axes、overlap_policy |
| `name` | | inspect 时看某个对象或组件（组件名前加 `component:`） |
| `page` | | inspect 的页码，从 0 起 |
| `rotation` | | preview 时绕锚点转 0 / 90 / 180 / 270 度 |
| `format` | | export：`json` / `nbt`，默认 json |

`target` 只在 `preview` 时用，含义同 `build`。执行方式 `MEMORY_ONLY`，当场返回。

能力说明（新）：

> 画一张建筑图纸、改它、看它、把它投影到世界里看效果，或导出成结构文件。图纸不绑地点，盖在哪由 build 决定。图纸用对象（盒子、板、楔形、棱柱、圆柱、圆锥、凸多面体、屋顶）、组件与实例、阵列、镜像、直角旋转、布尔开孔、空心与壁厚、面和棱的材质、平面图案来描述，一单位一格；格式与例子看 lookup 的 building/design 和 building/roofs。create 和 update 会告诉你这张图纸展开后有多少格、每种材料几件、哪里重叠；不会替你改图，也不检查地形。

结果细节 `DesignDetails`：`design_id`、`parent_design_id`、`object_count`、`expanded_count`、`cell_count`、`materials`（物品 → 件数）、`bounds`、`overlaps`（冲突格数与前几个例子）；inspect 给对象或组件的描述、展开路径（先按组件与阵列分组压成完整的一份，例如 `Arcade[0..2,0,0]/Shell`；确实太大才分页，结果带 `next_page`，按它接着读）、面与棱的名字；export 给文件路径与 `offset`（NBT 平移量）。

### `build`

| 参数 | 必填 | 说明 |
| --- | :---: | --- |
| `design_id` | 四选一 | 按设计施工 |
| `cells` | 四选一 | 逐格蓝图：`[{offset:[x,y,z], block, properties?}]`，`block` 为 `minecraft:air` 表示清空；水源、岩浆源表示倒桶 |
| `file` | 四选一 | `schematics/` 下的结构文件名 |
| `block` | 四选一 | 只放一格；配 `properties` |
| `properties` | | 单格时要求的方块状态属性 |
| `rotation` | | 绕锚点转 0 / 90 / 180 / 270 度（设计与结构文件） |

`target` 必填，是锚点：设计原点落在这里；`position` 省略 `y` 时取那一列的地表。`permissions.change_blocks` 决定能拆什么（默认 `natural`）。执行方式 `CONTROLS_PLAYER`。

能力说明（新）：

> 按图纸在 target 处施工：先对图核一遍，缺什么料自己去拿，挡着的挖掉，从底往上一层层砌，够不着就垫临时方块、用完收走，最后对图检查并把门关好。材料不够就建到材料尽头如实停下，再下达一次同样的目标会从没建完的地方接着做。玩家的东西不动，碰到会问你。蓝图没写的格子不会被清空；要清空的格子写 minecraft:air。只放一个方块给 block 就行。

结果细节 `BuildDetails`：

| 字段 | 含义 |
| --- | --- |
| `anchor`、`bounds` | 锚点与包围盒 |
| `cells` | 每种结局几格：`matches` / `placed` / `cleared` / `poured` / `wrong_block` / `wrong_state` / `missing` / `unknown` / `impossible` / `protected` / `checked_by_machine` |
| `problems[]` | 没做成的格按原因分组：原因、几格、全部坐标。默认完整交付；一组坐标多到结果放不下时，结果里保留总数与开头一段，并给直达路径：`goal(get)` 按原因分页读完这一组，不在中间层按固定数量删 |
| `materials_used` | 用掉的材料（物品 → 件数） |
| `temporary_blocks_left[]` | 没收回的临时方块坐标 |
| `fixtures_skipped` | 结构文件里没装的摆设实体数 |

`changes` 记 `BLOCK_PLACED` / `BLOCK_BROKEN` / `BLOCK_CHANGED`（倒桶、开关门）/ `ITEM_CONSUMED`；`remaining` 写"还有 N 格没砌：缺 X 件 Y"；`problem` 按引擎给（NEED_ITEM、NEED_APPROVAL、UNREACHABLE、STUCK、UNSUPPORTED）。进行中 `goal(get)` 的一句话："砌到第 N 层，x/y 格已对"。

## 9 验收

**离线场景测试**（判断类用替身接口，任务用动作替身，不用 `Unsafe`）：

1. 设计格式：字段错、材料名错、组件成环、阵列乘积超限、非整九十度旋转、对齐不上格网 → 一次报全并定位到 `objects[下标](名字)`；旧 v1 盒子格式 → 报不支持并指向知识文档。
2. 设计编译：移植 v0 的 `BuildingModel*Test` 场景（组件实例、阵列跳过、镜像、切割隔离、空心开口、面棱涂装、图案相位、叠加 last_wins / error、状态随旋转、倾斜拒绝、凸多面体）；ROOF 对象五种形状的格数与脊、檐、翘角位置。
3. 蓝图落地：设计 + target + rotation → 绝对坐标；`position` 省略 y 取地表；逐格蓝图重复坐标与门只写一格 → INVALID_PARAMETER 定位到格；作者写的属性被归一化改掉 → 报这一格。
4. `BlueprintCheck`：MATCHES / WRONG_BLOCK / WRONG_STATE / MISSING / UNKNOWN / CHECKED_BY_MACHINE 各一例；未加载不算空气，`complete=false`；立墙双形态互认；栅栏门朝向不比；EXTRA 只作信息。
5. 施工顺序：低层先；同层骨架先贴附后；依附件（火把、梯子、地毯、门）排在支撑之后；就近连放。
6. CHECK：全部 MATCHES → "开始时已满足"，零动作；基岩格记 impossible 其余照建；受保护格一次提问 NEED_APPROVAL，同意后继续、不同意跳过。
7. SUPPLY：缺口按未满足格算；M4 补不齐 → 建到材料尽头，partial + NEED_ITEM 写清还缺什么；垫脚材料从最不值钱的整块里挑。
8. PLACE：放置预测不符要求 → 换点击面或站位；多次放置的雪层数到数才完成；副格（门上半、床头）一起确认；耗材没扣 → 继续等同一单；没能确认 → unconfirmed 不重放；某格放不上先做同层别的格，回头再垫临时方块；六向都无附着面 → UNREACHABLE 带六向内容物。
9. POUR：先收 AIR 格里的源，再倒；自补的源跳过；倒成黑曜石记 BLOCK_CHANGED 不判失败。
10. VERIFY：外界改坏的格有限修补；同一批错误重复 → STUCK；只修可手开的门，其他最终属性差异 UNSUPPORTED 记这一格。
11. 临时方块：链搜索的范围与上限；收回顺序（够得着的先、沿柱下撤每格先确认落得稳）；取消与失败也收回；收不回的列进 `temporary_blocks_left`；600 刻没有一块收回就停。
12. 结构文件：litematic / schem / nbt 各一份；容器内容与刷怪笼被剔除；展示框、盔甲架、画不装并计数；旋转。
13. 结果：`BuildDetails` 的分组不丢格；进行中一句话"砌到第 N 层"。

**实机验收**（追加到冒烟清单，里程碑二）：

1. LLM 用 `design(create)` 画一间 7×5 的木屋（墙、门、两扇窗、楼梯屋顶或 ROOF），`inspect` 看一眼，`preview` 投到空地上观众能看见半透明屋子；`build` 在同一处盖起来，门最后关好，结果每格 MATCHES。
2. 同一张图纸换个地方转 90 度再盖一次；盖到一半 `goal(cancel)`，垫的土被收走，世界里只剩已砌好的部分；再下达一次接着盖完。
3. 身上只有一半的石砖：盖到石砖用完停下，结果 partial 写明还缺多少；LLM 让它 `obtain` 补齐再 `build`，从停下的地方接着砌。
4. 工地上有一棵树和一个坑：树被砍、坑被填（许可默认 natural），余土进旁边的箱子或被丢掉。
5. 工地边缘压着玩家的箱子：提问 NEED_APPROVAL 列出那几格；回答不同意 → 跳过那几格盖完其余，结果里列出来。
6. 图纸里有一个水池（水源格）：实心格放完后倒水，水面正确；再盖一个岩浆池，倒下去成黑更石时结果如实记。
7. 高塔：够不着的格先垫土柱，放完沿柱下撤，塔底没有残留的土。
8. 导入一个 .litematic 的小房子，里面的箱子是空的、展示框没装，结果写明没装几个。
9. 施工中天黑：夜休在两格之间插进来，睡醒回到工地接着砌。
10. 只放一个火把：`build` 给 `block=minecraft:torch` 和 `target=seen b#`（墙面），火把贴在墙上，结果 MATCHES。

## 10 待两位决定

| # | 问题 | 建议 |
| --- | --- | --- |
| D1 | 施工引擎放哪一层：玩家行为层新包 `behavior.construction`（算第十三个模型"施工"），还是 `ability.build.api` 供 light 与 machine 依赖 | `behavior.construction`。它是"怎么像个人一样砌墙"，三个能力共用，和站位、交互同级；放能力 api 里会让 build 变成厚能力。两种放法对调用方的接口一样，03 加一节"M13 施工"把 3.3 的规矩登记进去 |
| D2 | 缺料时整单不开工（v0），还是建到材料尽头如实 partial | 建到材料尽头。顺序是从低层到高，停下来就是一截墙，不会出现"墙立好了没屋顶材料"之外的奇怪半成品；缺什么写清，LLM 一句 obtain 再 build 就接上。v0 整单拒绝的理由是"避免半成品"，但不干等是直播的取舍 |
| D3 | 场地里有基岩、出界、受保护的格：整单拒绝（v0）还是逐格记录照建其余 | 逐格：不可能的格记 impossible 照建；受保护的格一次提问，同意拆、不同意跳过。整单拒绝是预判拦截 |
| D4 | 可走通契约（入口、房间、楼梯的只读扫描）和选址建议（半径 16 格内的平移位置）要不要保留 | 都删。两者都服务于不存在了的规划器；设计责任在 LLM，建完能不能走用 observe 看；选址是 LLM 看场景决定的事 |
| D5 | 设计按世界存还是按实例存 | 按实例，另开 `config/maicraft/designs.sqlite`（现有文档库按世界放在存档目录里）。图纸不绑地点、不含世界坐标，跨世界复用是常事；材料按注册表核对，同一实例的世界共用注册表；换实例不跟着走，用 export 带 |
| D6 | 流体格（水源、岩浆源）归施工引擎还是机器 | 引擎（已与机器规格会话商定）：实心格放完后先收后倒，机器不另做 |
| D7 | 预览：保留为不阻塞的世界叠加（观众看得到图纸）还是整个删掉 | 保留叠加。直播有看头，成本只是把 v0 的渲染类移植到 `debug`；审图确认流程删掉 |
| D8 | 结构文件导入的安全白名单与摆设实体 | 保留白名单（照搬容器内容等于凭空造物）；摆设实体不安装、结果写明几个。v0 也是这样 |
| D9 | 临时方块用什么材料：读配置名单（v0）还是从身上挑最不值钱的整块 | 从身上挑：M5 的价值分级反过来用，易挖、整块、无方块实体、非掉落；不再有配置文件 |
| D10 | 设计能力叫 `design` 还是 07 草案里的 `blueprint` | `design`。它是动词，而且"蓝图"要留给逐格目标清单（AGENTS 里"整份蓝图""未声明的格子"说的就是它） |
| D11 | 照明单独出规格 | 是（已与审查会话定）：它是引擎的使用方，判断是光照采样与灯位 |
| D12 | 屋顶：把 v0 内部工具里量出来的中式屋顶引擎做成设计的 ROOF 对象，还是写成知识让 LLM 自己用楔形拼 | 做成 ROOF 对象。那段是从四栋手工建筑逐格量出来的做法（半砖三态、举架、脊高出屋面），LLM 用图元拼不出同样的效果；参数化后一句话就是一个像样的屋顶 |
| D13 | 蓝图预算（maxTargets 等）保留配置文件还是写死常量 | 写死常量，实现时定初值；预算只防失控，不是设计空间 |
