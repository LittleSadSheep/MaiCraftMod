## 2 主流程

以能力入口为起点，按代码实际调用写：

- **inspect_machine**：`MachineAbilityAdapter.validate` 按操作种类查字段 → 带观察编号 `structure_id` 时直接读 `MachineControlInspection.structure`（移动结构控制回路）；否则定位机器（显式 machine_id → 档案锚点；target+label → 已记地点），`MachineInspectionBlueprintView.read` 按登记足迹扩展半径导出现状并附登记整机差异（full 模式），或只交回差异页（diff 模式）→ 场地已加载时 `MachineSnapshots.inspect` 做 `MachineSurvey` 扫描（结构指纹 + 组件/资源页）并附 AE2 终端观察与原生过程契约 → 返回 `ServerMachineObservationTaskRecord`（服务端辅助补读，期限 1200 刻）分页交付组件库存与资源库存。观察不派角色走近、不开菜单。
- **design_machine**：布局来源三选一（design 组件关系图 / blueprint 蓝图对象 / blueprint_uri 教程蓝图地址）→ 关系图交给后台布局作业（`MachineLayoutJobs.poll`，可能返回 Pending）；蓝图直接 `MachineBlueprintDocument.compile` 解析 → `MachineSurvivalMaterials.requireSurvivalBlueprint` 做生存材料核对 → 有 `design` 时 `MachineDesignReview.review` 出审阅报告；有 `expected_output` 时附 `MachineRecipeEvidence`（EMI 工艺入口）与配方知识链接 → 返回报告，明确说明"审阅完成不等于能建成"。
- **operate_machine**：先查 `allow_use` → 按 operation 分派：
  - `run_production`：绑定快照（结构指纹重验）→ `MachineProductionIntent.createTask`（期限 45 分钟）→ `MachineProductionTask` 按 PREPARE→CONFIGURE→SUPPLY→START→OBSERVE→VERIFY 阶段推进：近距交互站位、按配置清单逐条执行原生配置动作（ae2.*/create.* 前缀）并核对回执 applied/no_change、供料记账（记录接收端库存与事件起点）、进度看门狗（ProductionProgressWatchdog）判停滞、产物达标后还要核对真实连接（防断线后偶然入箱旧货）。
  - `watch_production`：要求服务器支持 `machine.watch` → `MachineWatchTask` 走近生产者→读配方→解析精确产物身份→分组走近授权各观察点→服务器登记后台观察→释放身体；不支持原生过程（原生过程只在前台跑）。
  - `open_menu`：`MachineMenu.openTask` → `MachineMenuOpenTask`：退出旧界面→走近（REACH 4.5）→腾空主手（空快捷栏格或 MachineMenuHandParking 停车）→瞄准+准星复核→右键一次→等回执确认新菜单+空鼠标+目标方块未变→登记菜单来源并 `MachineMenu.inspect` 生成观察报告与一次性存取编号。
  - `deposit` / `withdraw`：消费一次性菜单编号 → `MachineMenuTransferTask`：重选来源/去向槽→按 MachineMenuPolicy 决定整叠/半叠拿取→逐次 PICKUP 点击并等确认（游标、机器来源扣减、背包三十六格逐格比对）→放置（整放或逐件右键）→退回余量→最终核对数量、背包净变化、空鼠标。
  - `set_control`：带 snapshot_id 沿同址观察；不带时按坐标（半径 0）/地点（半径 4）/nearest（半径 6）找唯一拉杆 → `MachineControlTask`：退旧界面→腾手→瞄准拉杆→右键一次→等回执；拉杆已在目标状态则直接完成不再拨。
  - `station_process`：找 create:depot（坐标那格/周围唯一/6 格内最近）→ `DepotStationProcessTask`：手持原料右键顶面放整叠→等加工（max_wait_seconds）→空手右键收取→按台上物品变化与背包差额回执。
  - `ae2_supply`：要求 AE2 原生集成可用 → `Ae2ResourceSupply` 原生终端接口取物（allow_crafting 只能提交网络已有样板）。
  - `drive_vehicle` / `close_menu` / `cancel_watch`：分别交给 VehicleDriveTask、MachineMenuCloseTask、ClientMachineWatches.cancel。
- **modify_machine**：`allow_modify` 必须 → `apply_blueprint` 走 build 流程；`connect_mechanical_power` 走 `CreateMechanicalPower.preserving`（AUTO 比较传动方案成本；可用时直接构造 EconomicKineticTaskRecord）；`connect_external_input` 按档案接口的 medium 分派 kinetic（EconomicKineticTaskRecord）或通用 UtilityConnectionTaskRecord（期限 15 分钟）。
- **build_machine**：`allow_modify` 必须（带 production 还要 `allow_use`）→ 绑定施工锚点快照 → 编译布局（同 design）→ 生存材料核对 → `MachineConstructionPlan.compile`（explicit 蓝图从观察中心定位；自动布局先换算地板锚点）→ 按需标记修改/绑定自动替换或自有替换归属 → `ClientMachineCatalog.registerInstallation` 登记 → 期限 = max(45 分钟, (格数+部件数)×100 刻) → `MachineBuildTaskRecord`（或包装进生产任务）：缺料先补料（供料期间保护计划格）→ 逐格放置与拆换→ 部件按层安装（先支承后部件）→ 流体目标先倒桶 → 完工后自动留档并做一轮整机比对（按刻分段，每刻预算一格）。
- **quest_action**：`QuestAbilityAdapter.validate` 只查参数结构（FtbQuestActionRequest：submit/confirm/claim 三种操作、16 位十六进制 ID、choice_uri 直达候选）→ `QuestActionTask`：释放移动输入→等本刻动作机会→`FtbQuestSubmission.send` 经反射调 Architectury NetworkManager 发包（发包前 claimMutation 占用动作机会）→ 逐刻观察 FTB 信号与库存变化，收尾时点为最后一次变化后 250 毫秒或发送后 3000 毫秒→回执保留 request、submission_status、before/after、inventory_changes、outcome_uncertain。不自动推进、不自动选奖励、不把发包成功当成任务完成。

## 4 向 LLM 提问的出口（逐个列出问题和选项）

- **machine_precondition_failed**（`intent/MachineAbilityAdapter.java:84-91`）：所有入口校验拒绝统一落到 Decision 快照。问题文本为具体校验错误；选项固定两个：`replace_goal`（提供修正后的语义目标或新观察的机器证据）、`cancel`。
- **machine_layout_unresolved**（`MachineAbilityAdapter.java:590-602`）：布局编译不出可建方案。问题："The machine layout could not be compiled. Inspect the reported issues and revise the design or blueprint."；选项：`replace_goal`（修正蓝图、换教程结构或改语义设计）、`cancel`（保持已观察场地不变）。附 layout_compiler 报告、snapshot_id、target_label 与边界说明（点击脚本不受支持；施工核对声明的结构，使用另行验证）。
- **MachineSnapshotRejection**（`MachineAbilityAdapter.java:687-691`、`MachineSnapshots.java:526-528`）：不是提问，是失败回执附带一份新现场观察（machine_snapshot_missing / machine_snapshot_changed），调用方复核后提交新绑定。
- FTB quest 能力没有 Decision 出口：plan 阶段只查结构；执行期的资格检查失败直接按任务失败回执（含 not_submitted 等 submission_status）。
