## 2 真人怎么做

**电梯**：楼里装了 Create 电梯，就不爬楼梯。走到电梯口，按旁边的呼梯按钮（或者手里遥控器上对应的键），等轿厢下来停稳，走进去站到里面一点，对着控制器选要去的层，站着别动，到了走出去。电梯井里不乱走，轿厢会压下来。

**喷气背包**：穿上喷气背包、背上有气的背罐，打开飞行，飞到能落脚的平台上空；巡航时按着疾跑；到了正上方关掉背包往下掉，快落地再打开刹一下（这个模组慢慢落反而会摔伤），下面是水就直接关包落水；落地关掉。飞到一半挨打，就往远离怪的方向找地方先落下来。

**火车**：远的地方有铁路就坐车。先查哪趟车去（装了铁路导航就用它查换乘，没有就看站台的时刻显示），走到车站，等车进站停稳，找个空座位坐上去，坐着别动；到站车停稳了，潜行下车，走出站台。车要等太久，不如走过去就走。

**自己的载具**：去停着的飞艇或车旁边，走上去（或飞上去），坐到驾驶座，开到目的地附近找地方停稳，下车走完最后一段。怎么开归载具规格。

**会动的东西**：转着的风车、螺旋桨扫得到的地方不站；活塞、龙门在推的方向不挡；电梯井里不走；铁轨上火车开过来先等它过去。站在船上，船动人跟着动；下船走到船沿，跳到不高的地上，船顶低就蹲着走。

## 3 新逻辑

### 3.1 一趟行程，几段，每段一种出行方式

```text
TravelPlanner.plan(目的地, 许可, via?)
  报价       每个已登记的出行方式 TravelMode 对"从当前现场往目的地"答一份报价 TravelOffer：
             这一段从哪到哪、预计多少刻、要用什么（气罐、车票不需要……）、会改动什么（换上胸甲槽的喷气背包）
             只读、可以分几刻答完（M8 预算）；答不出来写一句原因（"附近没有通到那一层的电梯"）
  步行也是一种方式，报价 = 直线距离 / 步速，高差另加（与 v0 的"先走后换"不同，见 6-1）
  via 给了   只用这种方式（首尾不可避免的步行段除外）；它给不出报价 → 如实结束：
             UNSUPPORTED（装置不在、没装模组）或 UNREACHABLE（有装置但送不到），带它说的原因；不悄悄换步行
  via 没给   近处（水平 ≤ 32 格且高差 ≤ 6 格）直接走；
             远处或走路以"无路 / 地形挡住 / 困住 / 缺垫料"失败 → 比报价，取预计耗时最少的那份
             （所以同一层有电梯能到目标层时坐电梯，不硬爬楼，09-08 的事故）
  每段结束   身体真的挪动了（≥ 0.25 格，VT-04）才算进展；一段成功不等于到达，回到规划器按剩余距离继续（VT-05）
             试过的报价按（方式, 起点, 终点）记住，这一趟不再试（VT-12）；换了地方重新报价
  结算       每段进 details.legs：方式、起止位置、耗时、结果；整趟的到达确认照出行规格 3.1 第 4 步
```

- 指定方式不放宽许可：`via=jetpack` 不意味着可以挖路（v0 同）。
- 一段失败、但人还好好地站在某处：不判整趟失败（与 v0 VT-06 不同），把这段的结果记进 legs，从当前位置重新规划；只有"结果说不清"（例如飞行中断后不知道身上背包状态）的那一笔进 `unconfirmed`。
- 报价里写着要换装备的（喷气背包在背包里而不在身上），换上算这一段的一部分，落地后换回原来的胸甲（第 10 节第 2 项）。

### 3.2 出行方式 spi：`TravelMode`（`behavior.travel.spi`）

```text
interface TravelMode {
  TravelVia via()                                  取值 + 一句话说明，自报进 travel 的参数表（装了才出现）
  void offer(TravelRequest 请求, OfferSink 回答)    只读：从当前现场能把角色往目的地送一段吗；可以分几刻答完
  TravelLeg start(TravelOffer 报价)                跑这一段；拿到 PlayerServices（靠近、交互、换到主手、保护判断……）
}
TravelLeg（一个子任务）
  tick → RUNNING / ARRIVED（站稳在这段终点）/ ENDED（problem、已确认的变化、说不清的那一笔）
  requestSafeStop()   先到安全的地方再停：飞着的落地，电梯里的等停靠出轿厢，车上的等停车下车
  canHandleWhileRiding(打断)   坐着就能处理的打断（吃东西、打贴身的怪）就地处理，不让这段停
```

- 自带的实现：步行（包装现有的 `WalkTo`）。联动的实现：Create 电梯、Create 喷气背包、Create 火车（`compat.create`、`compat.createjetpack`）、自己的载具（载具规格，`ability.vehicle` 交给 travel 用的那一份）。原版船与矿车在里程碑四加。
- 跨维度（`DimensionTravelTask`）这次不改写成 `TravelMode`：它已批准、已实现；里程碑四全面切换前再看要不要收进来。
- 打断（M6）：腿上有段在跑时，打断先问 `canHandleWhileRiding`；不能就 `requestSafeStop`，到安全处再交身体，处理完从当前位置重新规划（v0 的"暂停 = 取消这一段、恢复时按新位置重新规划"，VT-19）。
- 交通中受伤（VT-16）：不再把整趟判失败；飞行的按 3.6 的受伤脱离先落地，交给自卫；坐车坐电梯的就地按 `canHandleWhileRiding` 处理。
- 身体只有一套按键（VT-03、VT-15）：内核的身体所有权已经保证；段结束、取消、人工接管时先松开这段按下的所有键再交出（VT-18）。

### 3.3 障碍来源 spi：`ObstacleSource`（`behavior.navigation.spi`）

```text
interface ObstacleSource {
  void obstacles(区域 AABB, ObstacleSink 回答)    当刻世界坐标的碰撞盒，每个盒带：
                                                 结构编号、运动（静止 / 平移 + 速度 / 转动 + 轴与半径）、读全没读全
}
```

寻路（`CalculationContext` 里已经留好的物理障碍供应者）每次规划、以及沿路每 10 刻对前方 16 格（VO-01）向所有已登记的来源要一次，按下面的规则换成"走不得"的格：

| 东西 | 当障碍的范围 | 理由 |
| --- | --- | --- |
| 读全了的静止结构 | 逐格的真实碰撞（门洞留着） | VO-03 |
| 读不全的结构 | 整体范围 | VO-03 |
| 转着的结构（风车轴承、螺旋桨、时钟轴承、搅拌器这类） | 整个扫过的圆盘：以轴为中心、最远一格为半径、沿轴的厚度 | 桨叶下一刻就转到那里（VO-06，10-04 事故） |
| 平移的结构（活塞、龙门、绳索滑轮、矿车装置、列车车厢） | 当前碰撞，再沿运动方向延长"速度 × 2 秒" | 别走到它要去的地方 |
| 电梯 | 轿厢碰撞 + 整条电梯井（最低到最高触点之间的竖直范围）；这一段就是坐这台电梯时除外 | 09-08 事故：寻路没避开电梯 |
| 自己正站在、坐在的那个结构 | 不算障碍；它的转子照样算（VO-07） | 不能把脚下的甲板当墙 |

- 路线被**正在动**的东西挡住：先原地等它过去（最多 5 秒，道口等火车同理），还挡着再绕。静止的挡住直接绕。
- 身体已经和障碍重叠：允许朝最近的面往外挪（VO-04，v1 已移植）。
- 实现：Create 的移动装置（含电梯、列车车厢）在 `compat.create`；Sable 的物理结构在 `compat.sable`。两边都在里程碑三。读格预算按 M8 分刻，不再写死 4096。

### 3.4 移动结构上：登上、站着、离开

**结构的身份与坐标**（VB-02、VB-03，事实）：Sable 的子世界有自己的局部坐标，按当刻姿态和世界坐标互换；坐在上面瞄准要换算到载具的相机坐标。这些归 `compat.sable` 的读写接缝，玩家行为层只拿世界坐标与"属于哪个结构"。

**登上**：`travel(target={seen: s3})` = 上去站稳。物理结构不是实体，观察给它新的编号种类 `s#`；列车车厢、Create 移动装置是实体，照旧用 `e#`：

```text
走得上去（停在地上、靠岸、有跳板、甲板边比地面高不过一格）→ 走上去
走不上去、身上有喷气背包 → 飞上去（VB-06 原来只能这样）
都不行 → UNREACHABLE，写明"甲板离地 N 格，没有喷气背包"
落点：甲板内部优先，再看路程；最多留 3 个明显不同的落点，优先另一高度的（VB-04）
站稳：原生接触且连续 8 刻没滑动（VB-05）
```

坐到座位上是 `use`（对座位空手右键，确认乘坐；入座不启动载具，VB-12）；下座是潜行（事实）。

**站着**：结构在动时不主动走动，等它停；要在甲板上走（去驾驶座、去船沿）用甲板几何（`compat.sable` 给出局部支撑面）走直线短路，不经过 Baritone（它看不见子世界的方块，VT-08）。

**离开**：一趟 travel 开始时身体在结构上 → 第一段固定是"下船"（VT-08）：结构停着才走；走到最近的船沿，台阶不用跳、落差三格内、避开禁入格与危险地面（VB-08）；低顶处先按潜行降到蹲姿再走（VB-09）；甲板斜着照样找出口（VB-10）。船沿全都太高、身上有喷气背包 → 飞下去；都不行 → UNREACHABLE 写明落差。结构一直在动不停 → 等，按 M8 进度跟踪超时如实结束（不跳下移动的船）。

### 3.5 电梯：`via=elevator`（`compat.create`）

**报价**：附近有电梯（客户端看得到轿厢装置）能连通"角色当前所在层"与"目标高度附近的一层"→ 报价；楼层表没同步就先走近发一次楼层表请求（VE-02，事实），同步到再答。目标在远处没加载 → 按目标的 y 找最近的楼层（VT-10）。

**一段**：

```text
走到呼梯点   本层触点旁半径 32 格内的按钮或无线链路（VE-05）；或身上遥控器某键的频率和呼梯链路一样（VE-06）
呼梯        按一次；电梯已在本层或正往这层来就不按（VE-07）
等          轿厢到本层停稳（arrived）；10 秒没有任何进展（轿厢没动、协议没回应）→ 安全停下（VE-13）
上          走进轿厢里有支撑、离门远的内部格（VE-08，09-07 用户要求"走的里面一点"）
选层        走到装置控制器前选目标层（原生选层包，VE-09）
坐          站着不动，视角跟着轿厢（VE-10）
下          停稳后走出到目标层的固定平台；最近的出口被挡就换下一个出口（VE-12 v0 只试一个）
到          固定平台上站稳 3 刻（VE-11）
```

- 选中的轿厢不同步了（走远、被拆）→ 停在当前安全处，结果写明（VE-14）。
- 出发时既不在平台也不在轿厢地板上 → 这份报价不成立（VE-16），由规划器换别的方式；不是整趟失败。
- 只坐电梯：`travel(via=elevator, floor="3F")`（不给 target）。`floor` 取楼层名、`top`、`bottom`、`up`（上一层）、`down`（下一层）（VE-17）。v0 的 `ask` 去掉（VE-18）：楼层表由 `observe` 列出（电梯的观察编号 b#，`what=detail` 看全部楼层与相对高度，VE-19），LLM 看了再下 travel；给的楼层不存在 → 参数错误，`received` 里带上实际楼层表。
- 大轿厢不跳过（VE-03 去掉）：读格按 M8 分刻读完。

### 3.6 喷气背包：`via=jetpack`（`compat.createjetpack`）

事实以事实清单第 5 节为准；**接入前要先补 CreateJetpack 5.1.2 与 FlightLib 的源码，或按实例 jar 核对**（需求总表 F1，本规格不重复）。

**报价**：

```text
身上有喷气背包（穿着，或在背包里——换上算这一段的一部分）+ 背罐有气
落点：看过的、能站的格（不是流体、岩浆、细雪、传送门、滴水石锥、垂滴叶、点着的营火、移动中的活塞、脚手架，VT-14）
燃料：优先气罐的余量 ≥ 路上耗时 + 140 刻余量（VJ-02、VJ-07）
范围：一次规划 64 格内（VJ-05）；更远的按前进方向分段，每段先落到中途平台（VT-20 的远端分段）
```

起飞前身体不必在地上：空中、水里打开背包本来就能飞（VJ-04 的限制去掉，规划从当前位置起算）。头顶被挡就先走到附近净空处再起飞，不设门（VT-07，09-30 用户原话）。

**一段**：

```text
开      打开飞行与悬停，等客户端读回一致（VJ-03）；读不回 → 这段结束，unconfirmed 写明背包开关状态不明
飞      六向网格路线，没看过的格不当空气（VJ-08）；落点上方优先留 2 格净空（VJ-09，09-06 "飞的不够高"）
        巡航按着疾跑（VJ-11）；偏差大先转头再前进（VJ-12 的 55° 留作调参）
        航段或落点支撑变了 → 重新规划（VJ-19）
降      到落点正上方、下面一列畅通：关包自由落，按速度和延迟提前重开刹车，确认真的减速了再接着落（VJ-14）；
        下面是水或落差伤不了人 → 直接关包落下（VJ-15）。这是绕开模组 bug 的玩家做法（09-07、09-26 用户原话）
落      原生接地；落在移动甲板上要确认是要求的那条船（VJ-17、VJ-18）
收      飞行、悬停开关恢复成出发前的样子（VJ-16）；为这段换上的胸甲换回去
```

- 气不够飞完剩下的路：先落到当前能到的最近平台（v0 `jetpack_landing_required`），从那里重新规划，不在空中耗尽。
- 飞着挨打（VJ-20）：比较往下、往前、往后与 8 / 16 格的侧向出口，挑离攻击者远的安全落点降落，落地后交给自卫，再从当前位置续程。
- 喷气背包当坠落救援（第 10 节第 3 项）：掉落会掉血、身上有喷气背包且有气 → 打开悬停，落稳再关；比落水桶优先。归 `behavior.landing`，调 `compat.createjetpack` 的开关。

### 3.7 火车：`via=train`（`compat.create`；铁路导航模组单独一个联动入口）

**客户端读得到的事实**（Create 6.0.11 源码核对）：

| 事实 | 出处 |
| --- | --- |
| 轨道图：节点、边、边上的点（车站、信号机……）全量同步到客户端，客户端有自己的一份铁路管理器 | `content/trains/graph/TrackGraphSync.java:54-80`、`CreateClient.RAILWAYS`（`CreateClient.java:65`）、`GlobalRailwayManager.sided` |
| 车站名 | `station/GlobalStation.java:41`（`name`），随边上的点同步 |
| 列车清单：编号、主人、车厢、名字、图标 | `entity/AddTrainPacket.java`、`Train.STREAM_CODEC`（`Train.java:87-95`）；**不含时刻表、运行状态与导航** |
| 车站方块的状态：有没有车在站、下一趟来的车、能不能拆、有没有时刻表 | `station/StationBlockEntity.java:114-118,172-191`（`imminentTrain`、`trainPresent`、`trainCanDisassemble`、`trainHasSchedule`，方块加载时同步） |
| 车厢是装置实体 `CarriageContraptionEntity`，加载范围内看得到位置与速度；座位在装置上，右键座位坐上去，潜行下来 | `entity/CarriageContraptionEntity.java`；装置座位规则同电梯轿厢 |
| 时刻表交给"坐在列车操纵台座位上的生物"（列车长），手里有时刻表右键它；暂停的时刻表空手右键列车长继续 | `schedule/ScheduleItemEntityInteraction.java:30-110` |

时刻表、各车去哪、几点到，客户端读不到。两条路都做（第 10 节第 4 项）：装了铁路导航模组（Create Railways Navigator，实例装了，所有者 10-10 说的"Create 铁路导航"就是它）就用它按时刻表查换乘；没装时由服务端只读操作 `create.trains` 回答各车时刻表上的站序（机器规格 3.10 的接法），只算直达和一次换乘。

**报价**：起点附近（步行能到）有车站、终点附近有车站、路线来源说有车把两站连起来（直达或一次换乘）→ 报价 = 走到站 + 等车 + 坐车 + 走出站。等车时间有就用（铁路导航给出发时间），没有按车的位置与速度估，估不出按第 10 节第 5 项的上限算。等车加坐车比直接走还慢 → 这份报价自然排在步行后面。

**一段**：

```text
走到站台   车站方块旁、轨道边能上车的地方
等车       要坐的车进站停稳（车站方块 trainPresent，或车厢速度为 0 且在站点上）；车在别处走、没过来 → 按进度跟踪等
上车       找最近的空座位右键坐上去，确认乘坐；没有空座 → 站进车厢里有支撑的格（装置会带着人走），
           记进 legs："站着坐车"
坐车       坐着不动；打断能就地处理的就地处理（3.2）
下车       到目标站（或换乘站）停稳 → 潜行下车 → 走出站台到地面；车不在这站停就坐到下一站再看
换乘       下车后再报一次价，接着下一趟
```

- 车在中途停很久（信号、堵车）：按进度跟踪，剩余距离长时间不缩短 → 在下一个停靠站下车，从那里重新规划。
- 组车、写时刻表、给列车长、手动开车归载具规格。

### 3.8 自己的载具：`via=vehicle`

`travel(target=…, via=vehicle, vehicle="<档案名>")`：走或飞到载具旁（3.4 登上）→ 坐到驾驶座（`use`）→ 交给载具规格的 `vehicle_drive` 开到目的地附近（落点在目的地 ±32 格内找）→ 停稳松手 → 下车 → 走完最后一段，最后一段照原 travel 的 `radius` 与高度要求（v0 VF-17）。不给 `vehicle` 时，用附近（看得见的）有驾驶座、有操纵表的自己的载具；有几辆就挑离自己最近的。

### 3.9 observe 的补充

- `scene`：电梯（编号、当前层名、楼层数）、车站（站名、有没有车在站、下一趟车名）、近处列车（车名、动没动、离自己多远）、物理结构（编号、是不是载具（有驾驶座和控制件）、动没动、空座数）。各类只列近处，远处计数（与第十九轮的实体列法同一个规矩）。
- `what=detail`：电梯的全部楼层（名字、相对高度、在不在当前层之上）；车站的站名、所在轨道图、下一趟车；物理结构的大小、座位、甲板高度；控制回路与受力归 `machine_inspect`（载具规格）。

### 3.10 组合的模型

M1（总流程）、M2（走到呼梯点、座位、控制器）、M3（按按钮、右键座位、潜行下车）、M6（段内的打断与受伤脱离）、M7（`via` 不放宽许可）、M8（进度跟踪、预算、问题种类）、M10（行程规划与 `TravelMode`）。本规格特有的只有：各方式的报价与段流程、障碍换算规则、甲板上的走法。

## 4 能力说明

`travel` 加两个参数（其余照出行规格第 4 节）：

## 6 行为变化清单（拍板用）

1. **自动挑方式**：v0 是"先走，走不通才换交通"；v1 近处先走，远处直接比报价。同一层有电梯能到目标层就坐电梯（09-08 的事故）。
2. **段失败不判整趟失败**：v0 交通出手后失败就以 UNKNOWN 结束整趟、要求 LLM 先检查；v1 记进 legs 后从当前位置接着规划，说不清的那一笔单独列出。
3. **电梯不再提问**：楼层用 `observe` 看、用 `floor` 给；大轿厢不再看不见；出口被挡换下一个。
4. **喷气背包**：空中、水里也能起飞；背包里的喷气背包会自动换上、落地换回；气不够先落到近处平台；受伤后落地交给自卫，再续程（v0 是整趟停）。
5. **上船**：走得上去就走，不再只能飞上去。
6. **会动的东西**：转着的整个扫盘、平移的前方、电梯井都当障碍；挡路的东西在动就先等它过去。
7. **新增火车**：坐 Create 列车出行（路线用铁路导航模组查，没装时用服务端读数）。
8. **`travel` 参数**：`transport_mode` 等七个交通字段收成 `via`、`floor`、`vehicle`，target 用 `seen` 指船。

## 9 验收

离线（替身读写端）：

1. 报价比较：近处只走；同一层有能到目标层的电梯时选电梯；`via` 给了只用它，给不出报价按原因结束、不改步行。
2. 段结果：没挪动不算进展；段成功后续走；段失败记进 legs 并重规划；试过的报价不重试。
3. 障碍换算：转动结构出整个扫盘；平移结构沿速度延长；电梯井只在坐这台电梯时放开；自己脚下的结构不算；挡路的东西在动先等再绕。
4. 电梯：楼层表没同步先请求；出口被挡换下一个；10 秒没进展停在安全处；`floor` 写错时 `received` 带楼层表。
5. 喷气背包：快速下降的每个阶段（关包、下落、重开、确认减速）；落水直接关包；受伤选离攻击者远的出口；落地恢复开关、换回胸甲。
6. 火车：等车、上车（有空座坐，没空座站进车厢）、到站潜行下车、换乘再报价。

实机（实测实例，先在占坑表占"实机"）：

1. 三层楼的 Create 电梯：从一楼 `travel` 到三楼某点，看到坐电梯而不是爬楼；`via=elevator, floor=top` 直接上顶楼；走过电梯井旁边时不进井。
2. 喷气背包飞上 20 格高的平台：不摔伤、疾跑巡航、落地后开关恢复；飞行中被骷髅射，往远离骷髅的方向落地。
3. 转着的风车、开着的螺旋桨飞艇旁走过：不被打、不卡。
4. 两站之间的列车：`travel` 到另一站附近，看到等车、上车坐下、到站下车、走完最后一段；车上被僵尸贴身时就地还手。
5. 停在地上的飞艇：`travel(target=s#)` 走上甲板站稳；再 `travel` 回地面时先下船。
