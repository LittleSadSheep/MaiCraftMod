## 2 真人怎么做

家里、田里、矿道里太暗了，就带上火把去补：先在要照的地方走一圈看看哪里暗，算算要几支火把、插在哪照得最广；身上火把不够就先做一批或去箱子里拿。插灯挑能站住就够得着的墙面和地面，不为了插灯去挖洞、垫脚；庄稼地不踩、不压，灯插在田边或没种东西的地上。插完再走一圈，哪里还暗补哪里，直到够亮。

走在路上天黑了进矿道，包里有火把就顺手往墙上插一支，照亮脚下的路接着走；火把用完了就摸黑走或找个亮处，不会为了插火把专门跑一趟补给。

## 3 新逻辑

### 3.1 两个入口收成一个能力

v0 的 `light_area`（照一片区域）与 `auto_light`（随行补光开关）收成能力 `light`，用参数 `operation` 分开（参数名表已有 `enable` / `disable` / `status`，区域补光补一个值 `area` 并作为默认）：

```text
light（operation 不给或 = area）   给 target 指的区域补光：量光 → 备光源 → 选灯位 → 交施工引擎放置 → 复测
light（operation = enable）        开随行补光，可给 minimum_light（1..13，默认 8）
light（operation = disable）       关随行补光；已插下的灯留着，副手与路线证据不动
light（operation = status）        查随行补光：开关、阈值、身上与副手的火把数、最近实测仍暗的路线格
```

enable/disable/status 当场完成，不走路、不放灯；enable 的结果写明"开关已开，插灯跟着走路发生"（L03 的话术事实保留）。

### 3.2 区域补光

```text
0 已满足    采样后全部样本达标 → 完成，结果写"开始时已满足"，一支灯都不插
1 量        采样：范围内的可行走格（或 crops 档的作物格与耕地上方格）逐格记下方块光，分几刻扫完
            敏感面记成保护事实：有方块实体、流体、作物与耕地、土径、火与营火与传送门、岩浆、
              红石信号源、非原版方块——不落灯、不改动（L08）
            样本格没加载 → 先走到那一列让它加载（M10），走不到的如实记进结果，不猜
2 备光源    选定光源：item 指定了就用它；没指定默认火把（身上捡到的发光方块不改默认，
              免得整片基地改成昂贵材料）。发射量达不到验收亮度的灯具不选（L09 的事实）
            身上不够 → 经 M4 去弄（用途=照明；合成火把、开箱取、去挖煤都它管），
              弄不到 → NEED_ITEM 写清要多少、什么发射量，不降验收冒充完成
            补到的新光源下一轮锁定沿用，不每轮重新挑
3 选灯位    候选：围绕暗格水平 1、2、4、6 格的八个方向、竖向 −2..+2，找能放灯具的格
            资格：空气或可替换的草丛；支撑面结实；灯具状态能放得下（灯笼不选悬挂态）；
              不是敏感面、不在 M7 保护里、不占只有两个以下出口的窄道、放下后不卡住自己
            覆盖估算 = 发射量 − 曼哈顿距离 ≥ 验收亮度，只是估计（隔墙不传播），验收以实测为准
            贪心：每支选新增覆盖暗格最多的，平局挑离角色近的；单轮最多 48 支（L16）
            候选一个都没有 → 如实结束：查过哪个范围、为什么放不了（L10）
4 放置      选中的灯位转成一份蓝图（绝对坐标，BLOCK 格，灯具物品与摆放状态），交施工引擎
              （用途=照明）。许可、备料、临时方块、受保护格提问、每格结局全按施工的规矩；
              照明不声明 AIR 格，蓝图没写的格子不要求为空
5 复测      放灯后等几刻（光传播与同步），在冻结的样本上逐格实测方块光（分几刻量完）
            比率按 coverage 档：all 与 crops 要求全部达标，most 九成；比率按能验收的样本算并写明分母
            没达标 → 还有暗格且这轮有真实进展 → 回到第 2 步再来一轮；
              同一候选前沿一整轮后原样重现、或选中集为空 → 结束（L11 穷尽判断）
6 结算      done / partial / failed 按"验收比率到了没有"；summary 分开两种话术：
              "一支都没放出去"（资格闸全拒）与"放了 N 支仍有 M 格暗"——不能混成一句（112、141）
```

单轮内已亮的候选直接省下：用放置后的实测光判断，不用距离猜它已经亮了。

### 3.3 范围怎么给

| 给法 | 含义 |
| --- | --- |
| target + radius | 以 target 为圆心、radius 为半径的圆（任意目标对象写法；y 省略取那一列） |
| target 不带 radius | 从 target 那一格出发的连通可行走空间：一间屋、一条矿道。沿可行走格泛洪，只数已加载的；到没加载的边界先走过去看看（M10），走不到的边界就量到这里为止，结果写明量到哪 |
| 要照刚盖好的房子 | LLM 组合：target 用 landmark 或 previous，加 radius；照明不读设计、不从图纸里推断灯位 |

target 解析不到（地标不存在、seen 编号失效）→ UNCLEAR_TARGET 提问或 TARGET_GONE，不改照脚下（L01 是预判拦截，v1 只问不做）。

### 3.4 随行补光：生存需求"太暗"

随行补光的"自动性"归生存需求（M6），不写常驻挂钩子：术语表把"太暗"列在生存需求的例子里，它和饿了吃一口是同一类事。v0 的随行助手靠借镜头随主任务行动，v1 的控制循环一刻只推进一个任务，没有这种共驾位置；插在两个动作之间的临时任务表达同样的事，不抢身体。

```text
评估（每刻）  脚部与眼部实测方块光的最小值 < 阈值，且头顶被遮住（脚、眼天空光的较大值 < 8：地下、屋里；
              露天的方块光处处是 0，白天黑夜都不算太暗），且包里有火把；
              一般任务在两个动作之间插（LATER 找空当），出行、探索这类沿路走的任务声明特征接口
              "沿路插火把"，走路途中落地站稳、停下安全时就插（SOON），不等走完整趟（所有者 2026-10-11 定）
插入          临时任务：在眼前够得着的墙面或地面选一个灯位（约正前方 78° 视野内，斜向走也提供正前灯位），
              经 M3 瞄准放置插一支，结束回到主任务原地
资格          站姿可及；不挖洞、不垫脚、不覆盖已有方块（AL7 的事实）；箱子、机器、工作台不作灯座
              （会开界面的方块判定复用 M3 的既有事实）；保护读不到按不动手（M7 的拿不准按受保护处理）
节制          距上次出手不足 2 格不再出手（原生被拒也算出手过，防原地撒灯）；亮度以实测为准，不用理论传播
缺火把        不插、不采购，这次临时任务都不开始；主任务照常（M6：临时任务没做成不牵连主任务）
让位          照明的施工任务声明任务特征接口"自己管照明"（见 3.5），太暗需求看到就让位，
              不往验收范围里插野火把；其余施工不声明——盖房途中顺手插一支无害
```

开关与阈值是启动时创建的一份会话设置，构造时同时交给需求与能力，进世界重置为默认（默认开还是默认关见第 10 节 D2）。随行的火把插在蓝图外，M7 保护判断照常管它。

### 3.5 与施工引擎的接缝

- **灯位清单 → 蓝图**：选灯位的结果是一组"在哪格放什么灯具、什么摆放状态"，转成 `PlannedCell`（BLOCK 格）交给 `ConstructionTask`。立式与墙式双形态互认、原生落法验收、会开界面的方块点它要潜行，全按建造规格的施工规矩，照明不另写放置。
- **验收分离**：引擎管"放没放对"（每格结局），照明管"亮没亮"（复测样本方块光）。引擎的 VERIFY 只修点名的方块状态，不管亮度；照明的复测在引擎结束后自己做。
- **复用而不污染**：照明的用途标签与普通施工分开记账；受保护的格由引擎 CHECK 一次提问（M7），照明不自己另列保护名单。
- **自己管照明**：任务特征接口，照明的施工任务声明它，太暗需求让位。特征接口挂在任务输入上，内核与引擎不认识具体能力。

### 3.6 只读亮度读取的新接口

按格选灯位要读任意位置的方块光。现在的游戏接口层没有这个读取——感知只有角色所在格的合成光（`observe` 的 `light`），夜晚分流读眼部的天空光与方块光，都是各自直接摸客户端世界。照明是第四处，而且是批量的。新增游戏接口层的只读接缝（名字按 09 定，建议 `ReadsLightLevels`，实现 `ClientLightLevels`）：

```text
按格（或格列表）读方块光；格没加载如实回答"没加载"，不猜
读法规则一次定死：方块光不受昼夜天气影响（白天量的区域夜里照样成立）；
  放置光源后光要过几刻才同步稳定，复测前的等待也归在这条纪律里
```

放接口层而不是玩家行为层自己摸，理由：方块光是感知、生存需求（夜晚分流、太暗）、照明共用的同一条游戏事实，全仓只实现一处，"未加载不猜"也只定一次；三处的离线测试共用同一个替身。它不携带任何能力的概念，只是"这一格多亮"。

### 3.7 组合的模型

M2（灯位站位、走到未加载的列）、M3（插灯的瞄准与确认）、M4（备光源）、M5（背包满腾地方）、M6（太暗需求、临时任务插队）、M7（能动哪些格、受保护提问）、M8（进度、穷尽、问题、结果）、M10（范围边界的走到）、M12（观察编号作 target）、施工引擎（批量放置）。

本领域自己特有的只有：样本采样与分类、选灯位（资格与贪心）、验收比率与复测、太暗需求、亮度读取接口。

## 4 能力说明

参数名用参数名表里的；本规格新登记 `minimum_light`、`coverage` 与 `operation` 的取值 `area`（见末尾"需登记 09 的新名字"）。执行方式 `CONTROLS_PLAYER`（enable / disable / status 当场完成）。

| 参数 | 必填 | 说明 |
| --- | :---: | --- |
| `operation` | | `area`（默认）/ `enable` / `disable` / `status` |
| `target` | area | 补光的区域：radius 给了是圆心，不带 radius 是连通空间的起点 |
| `radius` | | 圆形半径（格）；不给 = 连通可行走空间 |
| `item` | | 光源物品 ID；不给默认火把 |
| `coverage` | | `all`（默认，样本全部达标）/ `most`（九成达标）/ `crops`（只对作物与耕地验收，全部达标） |
| `minimum_light` | | 验收亮度 1..15，默认 8；`crops` 档默认 9（作物要光照够 9 才长）；随行的 enable 取 1..13（火把相邻格最高 13，再高永远点不满） |

能力说明（新）：

> 把 target 指的那片区域照亮：先量一遍哪里暗，选好灯位，自己备够火把（没有就合成或去拿），把灯插下去，再量一遍，直到达到验收亮度。radius 不给就是照亮整间屋、整条矿道。农田给 coverage=crops，按作物能生长的亮度（默认 9）验收，灯插在田边或没种东西的地上，不踩庄稼。玩家放的东西不动，碰到会问你。operation=enable / disable / status 开、关、查随行补光：开启后走路经过暗处会顺手把手里的火把插在旁边的墙或地上，不专门跑路、不挖不垫，火把用完只报告不采购。

结果细节 `LightDetails`（区域补光）：

| 字段 | 含义 |
| --- | --- |
| `source` | 实际用的光源物品 |
| `samples` / `lit` | 验收样本总数 / 达标数 |
| `coverage_achieved` | 实测覆盖率（分母是能验收的样本，结果写明） |
| `passes` / `placed` | 放灯轮数 / 放下的灯数 |
| `unlit` | 没达标的格按原因分组：`no_site`（找不到能放的灯位）/ `protected`（受保护）/ `unloaded`（没加载走不到）；每组带坐标，多到结果放不下给总数与开头一段，`goal(get)` 按原因分页读完 |

随行补光的 `status` 细节：`enabled`、`minimum_light`、`torches_carried`（背包火把数）、`torches_offhand`、`dark_on_route`（最近实测仍暗的路线格：坐标与亮度，只报走过并采样过的格，卸载的单列未知）。

问题种类按 M8：`NEED_ITEM`（弄不到光源）、`NEED_APPROVAL`（受保护的格，伴随提问）、`NOT_FOUND`（范围内没有可行走样本，或没有能放的灯位——写明查过哪个范围）、`STUCK`（换过办法仍没有真实进展）、`TARGET_GONE`、`UNCLEAR_TARGET`（提问）。

## 8 v1 里不再有的东西

实现时不要从 v0 搬：

- `AutomaticLighting` 的单例与整套借镜头机制（辅助瞄准、放完归还镜头）：太暗需求用临时任务加 M3 瞄准
- `OffhandTorchPlacer` 的副手交换快速通道（第 10 节 D5；113"换了副手看不见副手物品"随之消失）
- `TorchLightingPass` 的独立导航与逐站拒绝账：站位归 M2，拒绝进每格结局
- 快速轮与普通轮两套执行器：都走施工引擎
- `style`、`placement_preference` 参数与内部词表（wall / hanging / central_unplanted 这些取值）
- `max_placements`、`light_preferences` 列表、`allowed_sources`、`material_policy`、`allow_harm`、`protected_labels` 参数：归 M4 的代价比较、M7 的许可与保护
- `semanticTarget` / `resolveLoadedComponent` 的第二套目标表达：统一 target + radius
- `LandmarkProtection` 的地标扩边保护：归 M7 保护判断
- 断言上述机制的测试；表达游戏事实的场景按第 9 节重写

预计 v1 新代码约 700–1000 行（能力模块、样本采样与分类、选灯位、复测验收、太暗需求、亮度读取接口），新测试约 800 行。

## 9 验收

**离线场景测试**（判断类用替身接口，任务用动作替身，不用 `Unsafe`）：

1. 样本分类：可行走格、作物格、耕地上方格各一例进样本；敏感面（方块实体、流体、作物耕地、土径、火与营火、岩浆、信号源、模组方块）各一例不进样本不落灯；`crops` 档只采作物与耕地。
2. 范围：radius 圆内采样；不给 radius 从 target 泛洪连通空间；未加载的列先走近加载，走不到的记进结果。
3. 选光源：默认火把；指定 item 用 item；发射量不够阈值的不选；身上有别的发光方块不改默认；M4 弄不到 → NEED_ITEM；补到的新光源下一轮锁定。
4. 灯位资格与贪心：围绕暗格的候选范围；资格各一例（可替换格、支撑面结实、不占窄道、不卡自己、会开界面的方块不作灯座）；覆盖估算与贪心收益；平局就近；单轮上限 48。
5. 蓝图转换：灯位 → 计划格交给施工引擎的替身，核对蓝图内容、用途标签、没有 AIR 格。
6. 复测：等几刻后实测；三档比率；没到且有进展再一轮；同一候选前沿重现 → 结束；从未出手与出手不达标的 summary 分开；未验收样本写明分母。
7. 已满足：开始全达标 → done，"开始时已满足"，零动作。
8. 太暗需求：暗处 + 头顶遮住 + 有火把 + 两个动作之间 → 插一支；露天不插；沿路走的任务按尽快插；阈值内不插；两格间隔；不为灯位挖洞垫脚；箱子不作灯座；缺火把不插不报错也不采购；照明任务声明自己管照明时让位；临时任务没做成不牵连主任务。
9. 开关：enable / disable / status 各自的结果；进世界重置为默认。

**实机验收**（追加到冒烟清单，里程碑二）：

1. 白天一片农田给 `coverage=crops`：它备够火把（身上没有先合成或去拿），沿田边插灯，复测全部达到 9；结果写明光源与覆盖率。
2. 夜里一间没灯的屋子（landmark 不带 radius）：连通空间采样、插灯，全屋达标；"开始时已满足"的屋子再下一次 → 零动作。
3. 场地里有玩家的箱子和种着的耕地：箱子不作灯座、耕地不压不踩，照明其余；碰到受保护格提问 NEED_APPROVAL。
4. 身上只有几支火把要照大厅：用完如实 partial 写明还缺多少；LLM 让它 obtain 再 light，从暗格接着插。
5. 夜里让它 travel 一条无灯矿道（身上有火把）：途中顺手插火把，不专门停路；火把用完只报告、照常走。
6. 走到一半 `operation=status`：开着、阈值、身上与副手火把数、最近暗格如实。
7. 插火把的途中被袭击或饿了：随行让位（LATER 只在两个动作之间），自卫或吃饭照常，回来接着走。
8. `operation=disable` 后再走暗处：不再插；已插的灯留着。

## 10 定下的做法

| # | 问题 | 做法 |
| --- | --- | --- |
| D1 | v0 的 `light_area` 与 `auto_light` 怎么收进一个 `light` | 用参数 `operation`：`area`（默认）/ `enable` / `disable` / `status`。区域补光是动词本义做默认；开关复用参数名表已有的三个值。备选：随行补光不进能力、纯生存需求无开关——但 07 的能力目录已写明 light 含"开关随行补光"，保留入口 |
| D2 | 随行补光的"自动性"归谁、默认开还是关 | 归生存需求（M6"太暗"，术语表已列）：LATER 只插两个动作之间，走暗处顺手插一支；沿路走的任务（出行、探索）走路途中按 SOON 插。只认头顶被遮住的暗处：v0 只量方块光，靠默认关才没在露天乱插，v1 默认开就得把露天排除（所有者 2026-10-11 定）。默认开：像正常玩家一样，走暗处带火把插火把；v0 默认关是为"借镜头"可能干扰主任务的小心，v1 插在两个动作之间不抢身体，缺火把也只是不插。备选：默认关，LLM enable 才开（保火把的实例自己关） |
| D3 | 光源参数收多窄 | `item` 单值，不给默认火把；身上捡到的发光方块不改默认（防把基地改成昂贵材料）。`light_preferences` 列表、`allowed_sources`、`material_policy`、`allow_harm`、`protected_labels` 全删——来源与保护归 M4 与许可。v0 补料把 `#minecraft:coals` 收缩成单一物品翻过车（111），M4 的标签语义已在物资规格定好 |
| D4 | 灯位口味参数 `style`、`placement_preference` 与 coverage 档位 | 都删。`style`（wall/hanging）v0 本来就不支持；"不挡窄道、不压作物"写进灯位资格；口味差异 LLM 看结果不满意重下一次就行。coverage 收三档 `all` / `most` / `crops`（player_visibility 与 most 只差 5%）；`central_unplanted` 变成 crops 档的资格事实（未种植耕地可作灯位），不再是参数 |
| D5 | 副手插火把的快速通道保不保留 | 不保留。灯位全部转蓝图走施工引擎，就近连放已经够快；副手交换与"换了副手看不见副手"（113）的坑不再有。大批量农田照明若实测太慢，再议加回 |
| D6 | `max_placements` 显式预算删不删 | 删。穷尽（同一候选前沿重现）与卡住归 M8；控规模用小 radius 分段。v0"预算到线交还调用方"的语义由 partial 结果承担，LLM 看覆盖率自己决定下一步 |
| D7 | 不给 radius 的"连通可行走空间"量法做不做 | 做。一间屋、一条矿道是照明最常见的说法，v0 的连通泛洪已证明可做；radius 给圆、不给给连通，对 LLM 直观。量到没加载的边界走过去看看，走不到就量到这里为止、结果写明 |
