# 联动模组需求总表

> 状态：草稿，等两位批准。起草：Claude（机器规格会话），2026-10-10。
> 用途：v1 到底要适配每个模组的哪些功能、归哪个里程碑、现在有什么资料、还要用户定什么。这是所有模组会话的共同前提：一个模组一个会话，各会话只做自己那一行里写的事，表里没写的先回到这里补一行再做。
> 依据：[02-目标架构](../02-目标架构.md)第 5.8 节的接法、[04-路线图与工作包](../04-路线图与工作包.md)的里程碑与分工、[机器联动模组事实清单](机器联动模组事实清单.md)、[机器与任务-旧逻辑清单](机器与任务-旧逻辑清单.md)、v0 `docs/dev/` 下的机器与任务书文档，以及本机 `D:\STORAGE\Codes` 下各模组源码目录。

## 1 怎么看一个模组

每个模组按三件事列需求（起点是所有者 2026-10-10 随口给的三层骨架；他说"不一定是最佳实现"，这里只拿它当分类）：

| 三件事 | 意思 | 在 v1 里落到哪 |
| --- | --- | --- |
| **查资料** | LLM 按需查这个模组的玩法、配方、任务：Ponder 的思索、EMI 与 JEI 的配方、FTB 任务书 | 知识来源 `KnowledgeSource`，由 `lookup` 读；知识检索规格负责 |
| **认出来并用** | 角色能从世界里认出这个模组的东西，读它的状态，正确使用自己和别人建的：取物、投料、拨杆、配置、搭车 | 玩家行为层的 spi（物品来源、随身背包、出行方式、障碍来源、挖掘加速）与机器规格里的机器类型 `MachineType` |
| **自己造** | LLM 设计、角色建造大型机器，并正确接进应力网络、AE 网络、能量网络 | 机器规格：蓝图、施工（建在建造规格之上）、接网络、整机比对、机器档案 |

两条贯穿的规矩：

- **能从游戏数据认出来的不写联动**（方块标签、配方管理器、原版接口）。只有游戏数据认不出的才由联动模组补，补的方式是实现 spi 接口；spi 缺什么先回到公共会话补接口，不各自改玩家行为层。
- **节点—连接—网络**是 v1 新加的共同模型：机器是节点，线缆、轴、管道把节点连成网络（应力网络、ME 网络、能量网络、流体与物品管网）。v0 没有这一层（Create 只读过"这根轴转没转、有没有过载"；AE 只经终端界面取放，没读过控制器、频道、能量；AE 部件会装，但不会把线缆连回 ME 核心）。这一层的定义在机器规格里，各模组的联动只负责把自己的网络翻译成它。

## 3 每个模组的需求

### 3.1 Create

**查资料**：思索场景、配方类型（压缩、搅拌、切割、机械合成、机械手涂抹、鼓风机加工、砂纸打磨……）归知识检索。机器规格依赖它回答"做出 X 要哪种加工、哪台机器"。

**认出来并用**（里程碑三）：

| 功能 | 要读什么、点什么 | v0 有没有 |
| --- | --- | --- |
| 动力网络读数 | 每个动力方块：转速、是否接入网络、是否过载；整张网络：应力容量、当前应力、成员数（Create 把这三项同步到每个成员的方块实体，客户端读得到——要在源码里核一遍 `KineticBlockEntity.updateFromNetwork` 的三项是否随客户端包同步） | 只读过"转没转、过载没有" |
| 置物台加工 | 手持原料右键顶面放整叠、等加工、空手右键收回；证据只看台上物品被换成别的 | 有（`station_process`） |
| 传送带 | 带段的控制器、长度、坡度、方向；放料与收料的面 | 有（施工与比对） |
| 链条输送机 | 连接端点、代价、长度与连接数上限（读服务器配置） | 有 |
| 库存请求器 | 现货摘要（制作预览不算现货） | 有 |
| 机械手 | 向下使用的条件、持料 | 有（运行状态观察） |
| 手持加工 | 砂纸打磨：按产物计数，当拿东西的一个来源 | 有（批量持用，v1 改进 `obtain`） |
| 扳手拆机 | 空手或扳手右键拆下自己或被允许拆的机器方块，掉落进背包 | 有（建造的 `BuildWrenchRemoval`） |

**自己造**（里程碑三）：按蓝图放 Create 方块、按原生方式安装传送带（两端轴、带段、滚筒）；给机器接动力（轴、齿轮箱、链式传动箱、链条输送机，按材料与应力选线）；动力源本身（水车、风车、蒸汽机）也是机器，按蓝图建。

**里程碑四**：电梯（出行方式）、装置与载具控制（控制面板、红石链路）、火车（Create 铁路导航：车站、轨道图、时刻表；所有者 2026-10-10 定为要做）。这三项的规格随载具与出行领域另写，这里只登记需求。

### 3.2 Applied Energistics 2

**AE2 会话（当拿东西的来源，里程碑二）**：经 ME 终端界面读网络库存；取物（`obtain` 的一条途径，拟用 `via=ae2`，来源 `compat.ae2.Ae2TerminalSource`）、存物（`deposit` 与腾地方的去处，这一轮不做）、装桶（网络流体装进手上的桶）、提交网络已有样板的自动合成。全在客户端经菜单接口完成，不需要服务端读数；读写接缝拟用 `Ae2Terminals`（附近哪格哪面装着终端）与 `Ae2TerminalMenu`（打开的界面、网络清单、取货操作），联动入口拟用 `Ae2Compat`。自动合成只看终端界面里看得到的（确认界面、提交结果、清单数量变化），不碰服务端。

**机器会话（网络与施工，里程碑三）**：

- 把 ME 网络当"网络"认：控制器在不在、状态；频道模式与用量；能量是否在线、存了多少；存储总量；合成 CPU 的数量与忙闲；哪些机器挂在哪张网上。这些只能在服务端经 `IGrid` 的服务读（`IStorageService`、`ICraftingService`、`IEnergyService`、`IPathingService`），所以机器规格要定服务端读数的接法（第 5 节）。
- 施工：把部件（终端、接口、导入导出总线……）装到线缆面；把线缆连回 ME 核心（AE 线缆相邻自动连接，不同颜色不连，无控制器的临时网络有频道上限——这些事实要在源码里核）；放置并配置样板供应器与接口方块。
- 不做：空间存储、样板编码（LLM 把新配方编进样板）——第 4 节 A2。

两边的分界写在各自规格里：AE2 会话不碰网络读数与施工；机器会话不碰终端取放。服务端读数不进 AE2 会话的两个接缝，放 `server.compat.ae2`，服务端联动清单另起一行；客户端的 AE2 机器类型放 `compat.ae2`，由同一个 `Ae2Compat` 交给登记表。

### 3.3 Mekanism

**认出来并用**：读机器的侧面配置（每一面开没开、是输入还是输出、什么介质）与朝向；读管道（电缆、流体管、物品导管、化学品管）每一面的模式；读物流分拣机的过滤规则与自动弹出开关；读机器的当前配方与产出（服务端）；接能量：Mekanism 电缆接到 NeoForge 能量接口上。

**自己造**：手持配置器改侧面与管道模式（模式顺序按已装版本的枚举）；分拣机新增或调整一条精确过滤（多条与别的种类暂不做）；按蓝图建 Mekanism 机器。

**范围**：里程碑三先做物品、流体、能量三种介质；化学品只读不接（第 4 节 K2）。

### 3.4 精妙背包

已接入（读写端只认身上哪几格是精妙背包）。随里程碑二接上调用方：腾地方先往里塞（`CarriedBackpack`）、拿东西时当来源（`ItemSource`）。只读玩家自己打开并同步过的主存储；升级槽、幽灵槽不算。

### 3.5 FTB Ultimine

挖掘加速 `BreakAccelerator`：角色对准一格、按住连锁键，模组给出会一起挖的格子（原生预览），确认后持键挖触发块，松键后逐格复查哪些真挖了。v1 的要点：**整批每一格都过许可检查**（M7），任何一格不许就不启用连锁；批量的总数上限按 FTB 配置读，不自己定。事实清单要补这一节（源码 `FTB-Ultimine/`，v0 对照的是 2101.1.15）。

### 3.6 FTB Quests

**查资料**（知识检索会话）：任务书索引、章节、任务、要求、进度、奖励与奖池候选，只读自己队伍的。

**能力 `quest`**（里程碑三）：对一个任务做一次原生按钮动作——提交物品、勾选、领奖（选择奖励要指明候选）。发包一次、观察变化、如实报告"发出去了"与"任务完成了"是两回事；不自动推进、不替 LLM 选奖励。v0 的这套（Q01–Q11）大部分是游戏事实，v1 保留，去掉表外键名拒绝这类拦截。实测实例没装，验证版本范围要用户给一个装了 FTB Quests 的实例（第 4 节 Q1）。

### 3.7 Create 喷气背包

出行方式 `TravelMode`：穿在胸甲槽、开关飞行与悬停（经 FlightLib 按键事件，发出后等客户端读回一致）、燃料是 Create 背包气罐、可用飞行时间按余量估算。源码版本对不上实例装的 5.1.2，FlightLib 源码也不在本机，接入前要么补源码，要么按 jar 核对（第 4 节 F1）。

### 3.8 Create 航空学与 sable（物理结构）

里程碑四。移动结构（飞艇、船）在寻路里当障碍与甲板（`ObstacleSource`）；登船、离船、在甲板上站稳；载具的组装、配平、操控、飞行（`vehicle_*`）。v0 的客户端桥在 `core/integration/physics/`，服务端操作在 `server/physics/`。这一领域另写规格，这里只登记。

### 3.9 Ponder、EMI、JEI

知识检索会话负责（规格在 `知识检索-规格.md` 第 3.10 节，进行中）。机器规格向它要三样东西，形状已经对过口径：

1. 配方查询 `RecipeLookup`（内核）：`making(物品)` 什么能做出它、`using(物品)` 它当原料的配方、`atWorkstation(物品)` 这台机器能做什么。每条配方：配方 ID（查看器给不出就空）、类别、工作站列表（方块或物品 ID）、原料（物品 / 标签 / 流体 / 其他，带数量）、产出（标了几率才带）、`definition`（游戏里的原始配方定义，加热要求、加工时间都在里面，不解释）。没装 EMI 与 JEI 时退到游戏配方表，工作站列表为空。转速要求不在配方里，是机器的事实，由 Create 的机器类型给；Create 序列装配的几率是权重，由 Create 联动入口换算后补上。
2. 思索结构：每个场景一段 JSON：`blocks`（演示结构的全部格 [{offset, block, properties}]）与 `keyframes`（每帧的旁白编号、改动、移除）；某一帧的方块集合由机器这边叠出来。
3. 用法页：`lookup(topic=knowledge, id=<方块 ID>)`，有物品说明、按住 Shift 的用法、思索场景、配方去处、要交它的任务书条目。机器领域自己的资料（加工接口、动力要求这类）由机器实现 `KnowledgeSource`，经 `entriesAbout(注册 ID)` 挂到同一页。

"把快照当蓝图去建"归机器：机器蓝图的来源之一就是某个 Ponder 场景某一帧的方块集合，由机器能力换算成自己的蓝图再交给施工。v0 的 `blueprint_uri` 不保留。

## 4 要用户定的事

| 编号 | 问题 | 建议 |
| --- | --- | --- |
| C1 | 每台机器最多一个 `create:chain_conveyor` 的上限（v0 按用户要求加的）在 v1 保不保留 | 保留，但改成实例配置（`config/maicraft.json`）里的一个数字，默认 1；不写死在代码里 |
| C2 | 里程碑三的 Create 机器清单（实机验收要盖到哪些） | 动力源：水车、风车、蒸汽机（锅炉 + 引擎）；加工：压机、搅拌机、锯、机械手、鼓风机、置物台；物流：传送带、漏斗、链条输送机、库存请求器。其余（高炉、熔炉引擎之外的）随实机需要补 |

## 5 公共缺口：服务端读数怎么接

联动模组接入时留了一个缺口：服务端一侧的模组读数没有登记的位置，因为分层规则里 `server` 不能依赖 `compat`，而原来的想法是 `server.compat.<模组>` 经 `compat.<模组>` 的读写接缝去碰模组。

提案（细节在机器规格里定，这里只写接法）：

- **接缝放在服务端自己的包里**。`server.compat.<模组>` 定义这个模组在服务端要读什么的接口（只用 Minecraft 与 Java 的类型），实现放在 NeoForge 模块的 `neoforge.compat.<模组>`，和客户端读写端并排。`server` 只依赖自己和 `network`，分层规则不用改。
- **服务端也有联动入口**。`server.compat` 包根放 `ServerCompatModule`（和客户端的 `CompatModule` 一样包一层 `LinkageError` → 停用）与服务端登记表；联动清单的 `ServerCompatCatalog` 每行创建一个服务端联动入口，入口向 `ServerOperationRegistry` 登记自己的只读操作（例如 `ae2.network`、`create.network`、`mekanism.machine`）。
- **客户端经服务端链路读**。客户端的 `compat.<模组>` 需要这些数据时，经 `game.serverlink` 发只读请求；握手协商时没有这个操作（服务器没装对应模组，或所有者策略关了）就如实回答"读不到"，不影响客户端能认出来的部分。
- **只读，不替角色动手**：服务端操作只回答"网络里有什么、状态如何"，不执行放置、取物、配置。配置这类改变世界的事仍由角色在客户端做原生交互，服务端只提供确认。
