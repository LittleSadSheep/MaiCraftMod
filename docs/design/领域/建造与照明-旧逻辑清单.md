## 2 主流程

- **build（作者模型施工，maicraft:build）**：`AbilityAdapter.build` 判断请求形状——带 `project_id` 且不带场景字段走 `BuildProjectAdapter.plan`（读冻结施工单直接续建），否则走 `BuildingSceneAdapter.adapt`。`BuildingSceneContract.validate` 先校验操作名、字段表、来源三选一（scene / scene_id / blueprint）、契约版本与各操作的前置字段。适配器解析锚点（新模型必须有精确 current_place / 坐标 / 已记地标），把作者模型的 blocks 逐格加锚点偏移编译成绝对施工 ops（`BuildingSceneCompiler` 或 `BuildingSceneStore.prepare`），先经 `BuildTool.resolvedTargets` 确认每个注册名与状态可被当前游戏表达，再按操作分流：get_scene_info / get_object_info / get_component_info 只读分页报告；update_scene 合并编辑后另存新版本；export_scene 写文件；preview 要求全部格已加载且在建造高度内后发布世界层预览；revise_project 只更新冻结要求不开工；build 才返回 `IntentAction.Tool("build", args)`。保存、预览与施工是三份事实，回执一律带 `construction_started`。
- **build（内部工具）**：`BuildTool.onGameCall` 把 ops 展开为目标格集（set/box/walls/line/cylinder/sphere/roof/set_door/scatter 九种原语，调色板加权混色逐格确定性取色，后写覆盖先写），超过建筑预算 maxTargets 直接拒绝。材料记账随能力画像：创造免耗材直接开工；生存逐格真扣，生存且 allowPartial 时转 `SemanticBuildSupplyTaskRecord` 供料父任务，否则由 `BuildTaskRecord` 直接开工。
- **第一人称施工（FirstPersonBuildCompanionTask）**：预览门（开发预览要求玩家确认一次，整份建筑复用）→ 预检（拒绝普通放块做不了的内容：方块实体数据、摆设实体、多物品格；场地格全部加载；`BuildClearanceSurvey` 按替换模式与保护范围分帧调查清障准入；`BuildSiteConstraints` 查地下室与不可挖地形；汇总受保护/不可破坏格；按未完成目标完整材料数核对背包，缺料即拒或转分批）→ 开挖（余土先丢后存，需补料时先证明并走到施工区外出口）→ 自下而上逐批放置（`BuildOrder` 排序：同层先清空、再骨架、后贴附件；逐格核对材料在同步库存、现场未变、未被实体阻挡、有可站立站位与真实射线，原生点击后等服务器确认并复测 settling）→ 临时支撑（垫块从项目支撑账恢复所有权，收尾逐格下拆或近距直拆）→ 最终验证（逐格比对最终状态，门类做状态修复，入口/房间/上下楼按可走通契约只读扫描）→ 清理自有支撑并报告剩余。完成后保留 verifiedPosition 供下一步引用"刚建好的地方"。
- **blueprint（结构文件施工）**：`BlueprintTool` 的 list 列出 schematics/ 目录下 .litematic/.schem/.nbt/.snbt 文件；build 按最低角锚点与 90° 倍数旋转，经 `BlueprintPreparation` → `BlueprintFiles`（字节与 NBT 内存预算）→ `BlueprintFormats` 解析（litematic 与 schem 各自的调色板与方块数据校验）→ `BlueprintSafety` 白名单净化（方块实体数据与实体各自过白名单，载荷物品组件全等计价）→ `BlueprintStore` 生成逐格目标与逐格料单。执行走同一 `BuildTaskRecord`，替换模式 REPLACE_EMPTY（显式空气清场）、液体格跳过、allowPartial=true——整幢运不完就停在材料尽头并如实报缺，重发同一调用从已完成格继续。
- **light_area（区域补光）**：`AbilityAdapter.lightArea` 解析目标（点名地点解析不到就问，不改照脚下）、coverage（默认 all）、placement_preference、style、minimum_light（作物 9、其余 8）。`SemanticLightAreaCompanionTask` 分轮循环：观察（采样全部可行走/生长格的实际方块光，标出作物格、耕地、敏感面等不落灯的保护格）→ 选光源与灯位（贪心选覆盖暗格最多的安全候选，传播量只是估计）→ 取料（经供料协调器，缺料走 acquire 链）→ 施工（把灯位转成 `BuildTaskRecord.Target` 小批放置，受 max_placements 预算约束）→ 复测（按 coverage 比率验收，不足则再来一轮；同一候选前沿重复出现即判穷尽）。
- **auto_light（随行补光）**：`AutomaticLightingAdapter` 只改本会话配置（enable/disable/status，阈值 1..13 默认 8），配置成功不等于已换副手或插灯。`AutomaticLighting` 跟随已授权的身体移动：主脚/眼格实测方块光低于阈值、距上次出手 ≥2 格、主任务空闲、保护名可解析时，`RoutineTorchPlacement` 选前方约 78° 视野内站姿可及的壁面或地面灯位（不挖洞、不垫脚、不覆盖已有方块，箱子机器工作台不作灯座），`OffhandTorchPlacer` 完成副手换火把、平滑转向、容差内点击、按原生回执结算。缺火把只报告不采购；观察异常时撤回转向并保留事实，主任务不受牵连。

## 4 向 LLM 提问的出口（逐个列出问题和选项）

统一格式：`decision(goal, 问题文本, 选项列表, facts)`，应答经 `goalFromAnswer` 合并回参数。

1. **build，build 目标缺语义地点**：新模型必须有精确 current_place、坐标或已记地标，否则在适配层抛异常（不是 decision）。
2. **build，预览/审图**：开发预览或人工审图要求玩家确认（本玩家确认，不经 LLM decision）；取消走 CANCELLED，一次确认整份复用。
3. **build，缺料（missing_materials）**：非同步提问，而是终态失败回执附逐项缺口清单；分批模式下失败回执带"已完成格 + 剩余缺口 + 供料失败证据（含 planning_handoff、recovery_options）"。
4. **build，unsupported_blueprint_effects**：data 逐项列 block_entity_data / fixture_entities / multi_item_cell，各带 plain_blocks_only、finish_contents_separately、build_without_fixtures、cancel 等选项。
5. **build，blocked_site_cells / build_terrain_conflict**：失败话术逐格点名保护类型与坐标，出路是换址或申请清障。
6. **blueprint**：无 decision 出口；list/build 之外或缺参数直接抛异常。
7. **light_area，目标解析不到**：未解析地标 → 提问（remember or resolve first / retry with unambiguous label / cancel）；prior_result 不指向已验证地点 → 提问（produce or remember first / use current_place or exact label / cancel）；无目标 → 提问（replace_goal / cancel）。
8. **light_area，参数非法**：coverage、placement_preference、style、radius 越界 → 提问列出合法值（replace_goal / cancel）。
9. **light_area，终态决策**：no_usable_light_source、no_safe_placement_candidates、verified_coverage_not_reached、placement_budget_reached 都以 `requires_decision=true` + recovery_options 终态返回（取料、换光源或风格、缩小范围、降覆盖率、降阈值、加大预算、stop），并附逐站拒绝明细与实测覆盖。
10. **auto_light**：无 decision 出口；参数非法抛异常，status 只读。

## 5 失败出口（按失败类型统计，并列出位置）

失败类型取自 `core/FailureType`。建造与照明领域的主要出口：

- **NO_MATERIAL**：missing_materials（BuildTool 预检）、material_exhausted（逐格出手前）、no_usable_light_source（light_area）、供料链失败透传（SemanticBuildSupplyCompanionTask）。
- **NO_SUPPORT**：清障调查阻塞、blocked_site_cells、build_terrain_conflict、temporary_support_changed、no_safe_placement_candidates、verified_coverage_not_reached（light_area 终态）、multi_item_cell 等不支持项归 UNSUPPORTED 时分开计。
- **NO_PATH**：construction_supply_exit_unavailable、supply_access_not_reached、excavation_exit_blocked、scaffold_descent_failed、construction_worksite_unproven。
- **TARGET_LOST**：场地格未加载、观察过期（build_observation_stale）、现场中途变化、清障目标消失、保护标签失效或跨维度、支撑卸载、掉格无确认破坏。
- **UNSUPPORTED**：unsupported_blueprint_effects、unsupported_cells、native_placement_state_conflict、target_attachment_face_missing、unsupported_lighting_style。
- **UNKNOWN**：native_dismount_unconfirmed、误改其他方块（INTERNAL 单列）、wrench 拆除未结清、下降失败（带 uncertain 标记）、补光回执未确认。
- **ENTITY_BLOCKED**：placement_entity_blocked。
- **OCCLUDED / INTERNAL**：清障射线不可达；清理改了别的方块。
- **NO_SPACE**：excavation_spoil_drop_failed、excavation_spoil_storage_failed。
- **INTERRUPTED**：placement_budget_reached（light_area 显式预算到线）。
- **TIMED_OUT**：施工期限（BuildTool 估值）与供料父任务 45 分钟上限、construction_batch_timeout。

## 7 跨领域依赖（引用了哪些其他领域的类，各用来做什么）

- **物资/取物**：light_area 与 build 供料都经 `SemanticMaterialSupplyCoordinator` 与 acquire 链取料（source_hint、protected_labels、allow_harm 透传）；蓝图逐格料单复用物品解析。
- **出行/寻路**：`PlayerNav`、`NavigationSafetyContext`（保护格/禁行格继承、余土丢弃避让、开挖出口与站位导航）；开挖与走行本身归出行清单。
- **基础交互**：放置走原生"使用物品于方块"点击（与 place_block 同族原语）；门的最终状态修复用原生交互；搬手拆除（BuildWrenchRemoval）依赖联动模组的搬手。
- **联动模组（Create 等）**：普通建造拒绝 part/NBT 格并把它们引向机器能力（MachineAbilityAdapter）；搬手拆除与机器阶段档是分界点，整机比对归里程碑三领域。
- **感知/记忆**：`IntentRuntime.landmarks()`（light_area 与 auto_light 的保护标签解析）；预览经 `PreviewController` 显示世界层几何。
- **HUD/汇报**：各任务 `describe` 中文行动行；light_area 回执含观察、尝试、逐站拒绝与实测覆盖明细。
- **睡觉**：NightRestChain 可开启 auto_light（引用关系在睡觉领域清单覆盖）。

## 10 v0 直播中在这个领域出过的问题（来自 v0 维护记录）

素材取自 v0 维护记录，只摘游戏事实与结论：

- **020**：蓝图确认流与任务仲裁互锁——预览是世界层几何没有按钮、chat 命令确认会 REPLACED 掉正在等确认的任务、自动确认硬编码不可用；"收起预览"与"放弃目标"未区分。结论：确认路径必须不杀死它要确认的对象。
- **026**：craft/cook 放好工作站后进入脚手架清理阶段，清理目标单调下移而身体零位移，数分钟不重试不放弃；清理优先于交付把 5 秒的合成拖死，14 格支撑留在深井里。结论：清理在交付后做，清理寻路要有停滞兜底。
- **045**：挖矿工作流没有照明步骤，角色在暗处作业；引出 auto_light 随行补光与挖矿前的备火把提示。
- **058 / 172**：prepare_portal 建门期一律报 blocked_site_cells——距一切活动 460 格的原生荒地同样被拒，判断为把非空气地形误计入保护、未与 may_alter_terrain 授权打通；回执不点名是哪些格、被哪条保护拒绝，无解除出口。结论：目标格豁免自注册导航保护（B32），失败必须逐格点名保护来源。
- **059**：prepare_portal clear 阶段导航未继承 may_alter_terrain 授权，首试 PRESERVE 失败还产生"Retry with explicit terrain permission"的误导建议；修复是授权透传给导航段。
- **111**：light_area 补料把火把配方的标签原料 #minecraft:coals 收缩成单一物品 coal 走挖煤路线；煤路线失败导致整单 committed_prerequisite_unmet，已带的 16 支火把一支未放。结论：标签原料不得收缩成单物品，补给规划要保留全部合法成员。
- **112**：light_area 材料在手却零调查零放置（survey_legs=0、seed_columns_observed=0），仍以"穷尽"话术失败，recovery_options 与事实不符。结论：从未出手与出手不达标必须分开成两种话术（对应 L12）。
- **141**：light_area 补料链完整成功（65 支火把入包）后 build pass 零放置——27 个候选全部在原生出手前被资格闸拒绝，与 10 分钟前同点位能放 21 支自相矛盾。结论：放置资格闸的拒绝要逐站留明细（placement_rejections），同一前沿重复才判穷尽。
- **167 / 186**：place_block 对悬空贴附目标，工点证明分层缺口把贴身可达的目标一票否决为 construction_worksite_unproven，连带失败定位不点名附着面缺口、脚手架访问从不尝试（186 仍 open）。
- **181 / 184**：贴附放置站位路由绕远下潜穿树冠，途中立的 5 块泥土脚手架回执列明却 confirmed_removals=0 全部残留；进一步发现取消（CANCELLED）终态不清理自有支撑（仍 open）。
- **113**：light_area 补光把火把换入副手后，紧接着的 place_block 一度对副手物品不可见（pending-verify）。
- **169**：travel exact 上坡目标在出发前拦截取消后，改为施工式垫柱到达，垫柱与垫块留存在册成为新语义（pending-decision，取向待拍板）。

其余与机器蓝图、整机验收相关的事故归联动模组领域清单；与寻路、出行相关的事故（如 132 寻路踩农田、130 调查走进河）归出行清单。
