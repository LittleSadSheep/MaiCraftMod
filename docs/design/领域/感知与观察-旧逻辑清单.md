# 感知与观察 旧逻辑清单（v0 dev 提交 aa97940c9）

术语说明：v0 的感知分两层。对外是 MCP 工具 `perceive`，按 `view` 字段切换查看方式（situation 身体与背包、surroundings 周边事实、terrain_overview 等逐段投影、abilities 能力目录、attention 事件流等）；对内是一批注册在 `ToolRegistry` 的内部工具（`look_around`、`scan_blocks`、`scan_nearby_entities`、`inspect_block` 等），内部任务与旧调用通道直接调它们的 `onGameCall`。下文使用这些原叫法。

## 1 范围

## 2 主流程

1. **入口**：宿主调用 MCP 工具 `perceive` → `PublicToolCatalog.validateAndNormalize`（217 行）→ `validatePerceive`（258 行）做形状校验：字段白名单、view 枚举、各 view 专属参数互斥、sections 段名校验。默认 view=situation；给了 `url` 默认转 `web_knowledge`，给了 `resource_uri` 默认转 `knowledge`。
2. **分流**（`EmbeddedMcpService` 441–450 行 + `MaiCraftRuntimeFacade.perceive` 93 行）：`web_knowledge` 与 `knowledge` 不需要身体，分别走联网资料线程与离线知识库；`surroundings` 且点名 `terrain_overview` 时先在客户端 tick 里等地形采样完成再组装（`observeSurroundings` 107 行）；`attention` 且 `wait_ms>0` 挂起等待事件（`AttentionWait`）；其余全部排到客户端线程当次执行（`onClient`，要求世界存在且服务端已确认，`requireWorld` 904 行）。
3. **view 分发**（`perceiveOnClient` 297 行）：`attention` 走事件游标读取；`abilities` 无 query/focus 时列全能力名，带 query 走 `AbilitySearch.search`，带 focus 读单个契约；其余进入 switch。
4. **situation**（`situation` 537 行）：`BodyEnvironmentObservation.describe` 同刻读取位置与身体旗标 → 视角/朝向（物理结构观察的 view 段）→ 血量/饥饿/空气 → 时间语义与天气 → 近窗刻率 → 背包摘要（含副手与穿戴的 location_counts）→ 随身储物事实 → 装备明细（附组件事实）→ 载具 → 当前任务摘要 → 待答死亡问题。按 focus 追加诊断段（travel/elevators 楼层表；navigation/transport 全套导航诊断 + 碰撞几何；physical_structures 结构观察）。最后 `PerceiveSections.select` 按声明裁剪。
5. **surroundings**（`surroundings` 572 行）：身体旗标 + 天空光照 + 群系 → 半径 16 格实体全量清单（按距离排序，羊附颜色/毛量，掉落物附 drop_ref）→ 告示牌扫描（`NearbySignPerception`，半径 32）→ 脚下决策摘要（`LocalFloorSense` + 敌对计数并入 hazards）→ 点名才做的 `terrain_overview` 采样与 `nearby_facilities` 设施盘点 → 电梯楼层 → 物理结构观察。未点名 sections 时附 `additional_sections` 提示可选项。
6. **观察底座**：可见性判断统一走 `ObservationVisibility`（射线穿过的每格都须已加载；玻璃/冰/树叶/半透明渲染层不挡观察；中心 + 六面 + 内缩八角多点采样）；地形采样走 `RegionalTerrain`（稀疏取样，远处更疏）；批量找方块走 `BlockSearch` 分刻螺旋扫描（共享刻预算，600 刻期限，收集上限 8192）。
7. **内部工具路径**：`MaiCraftCore.registerTools`（180 行）把感知工具登记进 `ToolRegistry`；语义任务按名字取工具直接调 `onGameCall`（如采集任务复用 `scan_blocks` 的实现找目标）。旧 `LocalToolDispatcher` 调用通道保留但没有生产入口。
8. **事件流**（`AttentionSnapshot.read`）：按 `after_cursor` 游标取消息，`stream_id` 检测重启或换世界；指定 `task_id` 时直接附当前任务单（状态来自任务记录，不靠历史消息猜）；死亡决策挂在别的记录上时直接附上并立即唤醒。

## 4 向 LLM 提问的出口（逐个列出问题和选项）

感知域是只读观察，没有挂起待答的决策出口。v0 perceive 没有任何「提问」分支：参数不符合形状一律当场拒绝并附原因（S-01~S-08），观察不完整用结构化字段声明（sections_unavailable、scan_truncated、unloaded_chunks、partial、more_candidates_may_exist），不向调用方发问。与决策相关的出口在别的领域（如 travel 的地标解析提问会建议用 `perceive(view=landmarks)` 或告示牌文字重读名字），感知层本身只提供那些提问所引用的观察材料。

## 5 失败出口（按失败类型统计，并列出位置）

感知是只读操作，没有游戏世界失败；出口全部是参数拒绝、前置不满足与诚实声明：

| 类型 | 位置 | 场景 |
| --- | --- | --- |
| 参数拒绝（IllegalArgumentException） | `PublicToolCatalog.validatePerceive`（未知字段、非法 view、跨视图参数、段名拼错、互斥组合）；`ScanOps`（block_ids 全部无效）；`QueryExtraOps.readEnum`（type_filter 非法或缺失） | 规划阶段即拒，未触碰游戏 |
| 前置不满足（IllegalStateException） | `MaiCraftRuntimeFacade.requireWorld`（无可用世界或服务端未确认）；`NavigationOverview`（采样中途换身体/世界关闭：terrain observation body changed / world closed） | 观察无法进行，如实报错 |
| 部分覆盖声明（不失败，但结构化声明不完整） | `PerceiveSections.select` 的 `sections_unavailable`；`NearbySignPerception` 的 unloaded_chunks/scan_truncated/results_truncated；`NearbyFacilityPerception` 的 scope 文本；`ScanOps` 的 note（未加载柱列/期限/保留上限）；`LocalFloorSense` 的 partial；`KineticSourceQueries` 的 scan_complete/more_candidates_may_exist/sample_limit_reached；`NearbyCollisionPerception` 的 unloaded_cells/shape_errors/omitted_blocks | 缺少观察不当作世界里不存在 |
| 工具级失败（TaskResult.fail） | `QueryExtraOps.inspectBlockStorage`（坐标未加载、空气格） | 返回失败话术并给出路（走近、改用界面） |
| loaded:false 分支 | `PerceptionOps.inspectBlock`（未加载） | 返回 loaded:false 与「move closer」建议 |
| 观察原语不可用 | `TickRateObservation.observe`（间隔出窗/时间回退时声明刻率不可用）；`PhysicalStructurePerception`（射线或命中换算失败时返回 state=unknown + 错误类名） | 如实声明，不猜测 |

## 10 v0 直播中在这个领域出过的问题（来自 v0 维护记录）

摘自 v0 事故记录（编号 + 一句话事实/结论）：

- **002**：travel 回执「到达地表」实际是坑底——地形状态不可见导致下游选址返工（感知层此后全面补 route_verified=false 与 evidence 声明）。
- **017**：聊天屏占用无法辨识，readChat 观察面缺少占用来源事实。
- **018**：决策上下文缺现场事实，角色提问时调用方拿不到工地观察（决策上下文已补 site facts）。
- **019**：已知来源校准不可见，get_self_status 的结构列表与自救名册说明由此明确只承诺实际提供的字段。
- **030**：能力可发现性缺口——仅凭摘要选不中能力，abilities 索引改为一次列全名称 + focus 读全文。
- **035**：perceive 快照无版本号、无差分视图，各段新鲜度不统一且不可分辨；拍板不做，现状「实时直读不标注、有缓存带 age_ticks」。
- **036**：terrain_overview 采样粒度对导航决策无效；拍板为飞行着陆初选定位，返回补结构化 intended_use 明示降格。
- **037**：长任务「still working」兜底话术掩盖进度；改为记分牌事件流 + 变化驱动，零 still working。
- **038**：工具定义超共享上下文预算；段名说明固定排序等做法与该预算约束直接相关。
- **046**：attention 推与拉的模式取舍（传输用法与产品定位问题）。
- **061**：末影之眼三角定位停滞（定位观察的中间事实没有事件化）。
- **062**：末影龙实体扫描的多部件歧义（scan_nearby_entities 的实体身份与部件关系）。
- **072**：结构探索观察段曾每腿停滞数分钟（observe 阶段卡顿，重写后关闭）。
- **074**：提醒周期性重发刷屏 attention；改为仅在文案变化或十分钟窗口再唤醒。
- **083**：藤蔓遮挡的挖掘目标在观察层不可见、无坐标交接（可见性采样的空隙识别缺口）。
- **084**：cook 缺类事故在服务端日志里零痕迹（客户端线程调用曾只按 Exception 记日志，Error 系被吞）。
- **089**：告示牌文字初始化原语缺口——牌子刚放时文字不可读，地标按告示牌解析受影响。
- **091**：探索沿途地形特征曾不记录（跑图记忆的记录线缺口）。
- **096**：无刻率可观察性，失焦限流被误判为任务停滞（→ situation 补 tick_rate 段）。
- **099**：find 扫不到新放方块（扫描缓存失效缺口）。
- **103**：结构目击曾不记录进跑图记忆（扫描器重写后记录/触发/标签直达全部实机通过）。
- **133**：attention 分页曾丢事件。
- **180**：副手物品对能力背包事实不可见（InventoryComponentFacts 曾漏副手）。
