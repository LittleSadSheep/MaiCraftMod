# 机器联动模组事实清单

本文登记联动模组侧的、被实际使用过的事实：机器与装置、反射桥读取的字段与方法、菜单与槽位、配置项。每条事实带出处：模组源码引用写「模组目录内相对路径:行号」，实现侧引用写本仓库相对路径。

## 0. 版本核对结论

- 本项目构建脚本（`common/build.gradle`、`buildSrc/`）**不声明任何上述模组的编译或运行时依赖**，全部模组交互走运行时反射（`common/src/main/java/org/maiwithu/maicraft/core/integration/`），因此实际加载的模组版本无法从本仓库的构建声明核对。
- 各源码仓库均在 Minecraft 1.21.1 线上，与项目声明的 `minecraft_version=1.21.1`（`gradle.properties`）一致。
- 结论：以下事实按"源码版本 = 1.21.1 线"登记；**具体发布版本与实际安装的 JAR 是否一致无法从仓库内核对，涉及精确版本号的事实（如 Create 6.0.11、AE2 19.2.x）需在实机安装版本下复核**。依赖库 SophisticatedCore 与 FlightLib 的源码不在本机源码目录中，相关事实单独标注（见第 4、5 节）。
- 实测实例实际加载的 JAR（2026-10-09 在 LittleSadSheep 的实测实例里核对）与源码版本对照：

  | 模组 | 源码版本 | 实测实例安装的 JAR | 结论 |
  | --- | --- | --- | --- |
  | Create | 6.0.11 | create-1.21.1-6.0.11 | 一致 |
  | Applied Energistics 2 | 近 19.2.17 | appliedenergistics2-19.2.17 | 一致 |
  | Mekanism | 10.7.19 | Mekanism-1.21.1-10.7.19.85 | 一致 |
  | 精妙背包 SophisticatedBackpacks | 3.26.5 | sophisticatedbackpacks-1.21.1-3.25.69 | **不一致**：引用第 4 节的事实前要按 3.25.69 复核 |
  | 精妙核心 SophisticatedCore | 源码不在本机 | sophisticatedcore-1.21.1-1.4.72 | 只能按反编译核对 |
  | Create 喷气背包 CreateJetpack | 0.0.0-dev 快照 | create_jetpack-forge-5.1.2 | 版本对不上号：第 5 节的事实要按 5.1.2 复核 |
  | FTB Quests | 2101.1.36 | 实测实例没有安装 | 第 6 节只在装了任务模组的整合包里有用 |

- FTB Quests 一侧有文字依据：`docs/dev/quests.md:201` 写明初始实现对照的是 Minecraft 1.21.1 的 FTB 接口，不据此宣称任意版本兼容。

## 1. Applied Energistics 2（AE2）

v0 与 AE2 的全部交互集中在反射桥 `common/src/main/java/org/maiwithu/maicraft/core/integration/ae2/Ae2ReflectionBridge.java`（其余 `ae2/` 文件都是基于该桥的会话与任务逻辑，不再直接触碰 AE2 类）。桥在初始化时一次找齐以下接口，任一项缺失则整座桥不可用（`Ae2ReflectionBridge.java:377-439`）。

### 1.1 终端识别

- ME 终端是装在 `appeng.blockentity.networking.CableBusBlockEntity`（`CableBusBlockEntity.java:66`）各面上的 `appeng.parts.reporting.AbstractTerminalPart`（`AbstractTerminalPart.java:65`）；用 `getPart(Direction)` 逐面读取（`CableBusBlockEntity.java` 提供 `getPart`）。
- 终端菜单是 `appeng.menu.me.common.MEStorageMenu`（`MEStorageMenu.java:95`），菜单与部件的对应关系用 `MEStorageMenu.getHost` 与部件对象同一性核对（`Ae2ReflectionBridge.java:177-183`）。

### 1.2 库存读取（客户端仓库）

- `MEStorageMenu.getClientRepo()` 返回 `appeng.menu.me.common.IClientRepo`（`MEStorageMenu.java:661`；`IClientRepo.java:31`）；`IClientRepo.getAllEntries()` 给出 `appeng.menu.me.common.GridInventoryEntry` 的集合（`GridInventoryEntry.java:31`）。
- 条目读取方法：`getSerial()`、`getWhat()`、`getStoredAmount()`、`isCraftable()`（`GridInventoryEntry.java:56,67,74,88`）。`getWhat()` 是 `appeng.api.stacks.AEKey`，物品键为 `appeng.api.stacks.AEItemKey`（`AEItemKey.java:34`），用 `getId()` 取 `ResourceLocation`、`toStack(int)` 取样本物品。
- 网络连接状态：`MEStorageMenu.getLinkStatus()`（`MEStorageMenu.java:644`）返回 `appeng.api.storage.ILinkStatus`（`ILinkStatus.java:14`），`connected()` 表示在线。

### 1.3 取物、装水与合成操作

操作入口是 `MEStorageMenu.handleInteraction(long serial, InventoryAction action)`（`MEStorageMenu.java:374`），`appeng.helpers.InventoryAction`（`InventoryAction.java:21`）中被用到的枚举值：`PICKUP_SINGLE`（单取）、`PICKUP_OR_SET_DOWN`（放回携带物，serial 传 -1）、`AUTO_CRAFT`（发起合成）、`FILL_ITEM_MOVE_TO_PLAYER`（用网络流体装满手上的桶并放进玩家背包；`InventoryAction.java:29`，服务端处理在 `MEStorageMenu.java:423`）。所有点击类操作都要求对应界面在客户端真实可见打开（`Ae2ReflectionBridge.java:341-348`）。
流体单位以 `appeng.api.stacks.AEFluidKey.AMOUNT_BUCKET` 常量为权威（`AEFluidKey.java`；用量见 `GenericSlotCapacities.java:24`）。

### 1.4 自动合成

- 发起 `AUTO_CRAFT` 后进入 `appeng.menu.me.crafting.CraftAmountMenu`（`CraftAmountMenu.java:50`），用 `confirm(int amount, boolean craftMissingAmount, boolean autoStart)` 提交数量（`CraftAmountMenu.java:110`）；v0 固定传"不补足缺量、不自动开始"（`Ae2ReflectionBridge.java:301-308`）。
- 确认界面是 `appeng.menu.me.crafting.CraftConfirmMenu`（`CraftConfirmMenu.java:65`）：`hasNoCPU()` 判断无可用合成 CPU（`CraftConfirmMenu.java:340`）、`getPlan()` 判断计划是否同步完成（`CraftConfirmMenu.java:353`）、`startJob()` 提交作业（`CraftConfirmMenu.java:256`）。
- 提交失败信息读公共字段 `CraftConfirmMenu.submitError`（类型 `CraftConfirmMenu$SyncableSubmitResult`，`CraftConfirmMenu.java:102`），经 `result()` 拿到 `appeng.api.networking.crafting.ICraftingSubmitResult`（`ICraftingSubmitResult.java:10`），`successful()` / `errorCode()` 给出成败与错误枚举（`Ae2ReflectionBridge.java:326-335`）。

### 1.5 v0 没有用到的

未发现 v0 对 ME 控制器、能量（AE 能量单位）、空间存储、 Molecular Assembler 等的其他反射访问；v0 的 AE2 物资供应、存取与装水都建立在上述菜单接口之上（`ae2/` 目录其余文件的读数都经 `Ae2ReflectionBridge`）。

### 1.6 v1 接入时核对（2026-10-10）

- 版本：本机源码在 `1.21.1` 分支，`neoforge/v19.2.17` 之后只多 3 个提交（导出总线贴图、元件保存、`Platform`），不碰终端与菜单，以下按 19.2.17 登记。jar 按官方 Maven Central 坐标 `org.appliedenergistics:appliedenergistics2:19.2.17` 取，免登录；它的 SHA-1（`49c18d6a4af487957d7e5a6ad5dcbf71090b8e14`）与开发客户端、实测实例装的 `appliedenergistics2-19.2.17.jar` 一致。模组 ID `ae2`，加载器报的版本 `19.2.17`；运行时必需 GuideME（`[21.1.1,)`，实测实例装的是 21.1.16）。联动清单登记的范围 [19.2.17, 19.3)。
- 终端部件：ME 终端、合成终端、样板编码终端都继承 `appeng.parts.reporting.AbstractTerminalPart`（`ItemTerminalPart`、`CraftingTerminalPart`、`parts/encoding/PatternEncodingTerminalPart`）；装部件的方块实体实现 `appeng.api.parts.IPartHost`，`getPart(Direction)` 逐面读（`IPartHost.java:60`）。
- 面板形状：终端的碰撞形状是贴着所在那一面、厚 2 像素的 12×12 面板，加一块 8×8 的底座（`AbstractReportingPart.getBoxes`，`AbstractReportingPart.java:73-76`）；`appeng.parts.BusCollisionHelper(List<AABB>, Direction, boolean)` 按面把部件坐标转成方块内坐标（`BusCollisionHelper.java:49`）。右键线缆方块按命中点选部件（`CableBusBlock.useWithoutItem`，`CableBusBlock.java:238-246`），点到线缆芯不会打开终端；终端部件右键在服务端打开界面，不看有没有电（`AbstractTerminalPart.java:134-139`）。AE2 在 1.21.1 没有安全终端，打开界面不做权限检查。
- 菜单类型：`ae2:item_terminal`（`MEStorageMenu.java:101`）、`ae2:craftingterm`（`CraftingTermMenu.java:74`）、`ae2:patternterm`（`PatternEncodingTermMenu.java:87`），都是 `MEStorageMenu` 的实例；无线终端是 `ae2:wirelessterm`、`ae2:wirelesscraftingterm`。
- 客户端存货表：`MEStorageMenu.getClientRepo()` 只在客户端、由终端的界面画面 `MEStorageScreen` 创建时设上（`MEStorageScreen.java:143-144`），界面没画出来就是 null。`IClientRepo.getAllEntries()` 不受界面筛选影响（`IClientRepo.java`）。服务端每刻把变化增量同步过来（`MEStorageMenu.broadcastChanges`，`MEStorageMenu.java:231-290`）。
- 取货操作：客户端调 `handleInteraction(serial, action)` 发 `MEInteractionPacket`（`MEStorageMenu.java:374-378`），不是原版点格子；服务端在网络没连上时什么都不做（`MEStorageMenu.java:382`），条目编号已失效时也什么都不做（`MEStorageMenu.java:395-400`）。
  - `SHIFT_CLICK`：最多一组，直接放进角色背包里第一个能放的格子（能叠进没满的同种堆），放不下就不取（`moveOneStackToPlayer`，`MEStorageMenu.java:608-637`）。
  - `PICKUP_SINGLE`：取一件到光标上，光标上已有同一种就叠一件，满一组或光标上是别的东西就不取（`MEStorageMenu.java:467-490`）。
  - 把光标上的东西放回网络：`handleInteraction(-1, PICKUP_OR_SET_DOWN)`，编号 -1 指网络格子的空白处，网络放不下的留在光标上（`MEStorageMenu.java:388-394`、`439-445`、`590-606`）。
  - 往网络里存是原版的快速移动：终端界面里 Shift 点背包一格，`transferStackToMenu` 把整堆插进网络（`MEStorageMenu.java:672-687`）。

## 3. Mekanism

### 3.1 物流分拣机过滤

桥：`common/src/main/java/org/maiwithu/maicraft/core/integration/machine/assembly/MekanismFilterBridge.java`，只支持"一条指定普通物品的精确过滤"，多规则或其他种类一律报告冲突（`MekanismFilterBridge.java:35-42`）。

- 界面与容器：`mekanism.client.gui.GuiLogisticalSorter`（`GuiLogisticalSorter.java:36`）与 `mekanism.common.inventory.container.tile.MekanismTileContainer`（`MekanismTileContainer.java:19`）；容器经 `getTileEntity()` 拿到 `mekanism.common.tile.TileEntityLogisticalSorter`。
- 读取：`getFilterManager()`（`TileEntityLogisticalSorter.java:384`）、`getAutoEject()`（`TileEntityLogisticalSorter.java:208`）；过滤器管理器 `getFilters()` 返回过滤规则，物品规则类为 `mekanism.common.content.transporter.SorterItemStackFilter`（`SorterItemStackFilter.java:19`，实现 `IItemStackFilter`），字段 `fuzzyMode`、`allowDefault`、`sizeMode`、`color` 与方法 `clone()`、`getItemStack()`、`isEnabled()`（`IFilter.java:15`）。
- 操作包：关闭自动弹出用 `mekanism.common.network.to_server.PacketGuiInteract`，动作枚举 `PacketGuiInteract$GuiInteraction.AUTO_EJECT_BUTTON`（`PacketGuiInteract.java:251`）；新增规则用 `mekanism.common.network.to_server.filter.PacketNewFilter`，编辑规则用 `PacketEditFilter`（两文件在 `common/network/to_server/filter/` 下），发送统一走 `mekanism.common.network.PacketUtils.sendToServer`（`MekanismFilterBridge.java:83-119`）。发包前核对界面仍开着、开关状态与规则集合未变。

### 3.2 机器接口与管道模式

桥：`common/src/main/java/org/maiwithu/maicraft/core/integration/machine/assembly/MekanismNativeConfiguration.java`。

- 可配置面实体实现 `mekanism.common.tile.interfaces.ISideConfiguration`（该文件存在）：`getConfig()` 给出侧配置，`getDirection()` 给出机器朝向；`mekanism.api.RelativeSide.fromDirections(Direction, Direction)` 把世界方向换算成相对面；面信息对象提供 `isSideEnabled`、`getDataType`、`getSupportedDataTypes`（`MekanismNativeConfiguration.java:55-76`）。
- 管道实体是 `mekanism.common.tile.transmitter.TileEntityTransmitter`（该文件存在）：`getTransmitter()` 取发送器本体，`getConnectionTypeRaw(Direction)` 读某面当前模式，`getSideLookingAt(Player, Direction)` 取准星实际命中的分支（`TileEntityTransmitter.java:220`）；支持的介质类型来自 `getSupportedTransmissionTypes`（`MekanismNativeConfiguration.java:38-48`）。
- 配置器：`mekanism.common.item.ItemConfigurator`，`getMode(ItemStack)` 读模式，模式枚举顺序决定滚轮切换次序；推进模式的服务器请求是 `mekanism.common.network.to_server.PacketModeChange(EquipmentSlot, int)`（该文件存在）（`MekanismNativeConfiguration.java:83-145`）。
- 感应端口（induction port）的输入/输出读数不在上述通用路径里，由 `MachineCommissioning.inductionOutput` 单独处理（`MekanismNativeConfiguration.java:50-54`）。

## 4. 精妙背包（SophisticatedBackpacks）

桥：`common/src/main/java/org/maiwithu/maicraft/core/integration/backpack/BackpackMenuAccess.java`。只读玩家自己打开并已同步的随身背包主存储；升级槽、幽灵槽与未同步菜单不记入物资。

## 8. 思索（Ponder）

源码：`Ponder/`（分支 `mc1.21.1/dev`，`gradle.properties` 写的是 1.0，没逐提交对上 1.0.82）；实测实例里没有单独的 Ponder jar，Create 6.0.11 的 jar 里打包的是 `ponder-neoforge-1.0.82+mc1.21.1`（`META-INF/jarjar/metadata.json`），模组 ID `ponder`，加载器报的版本 `1.0.82+mc1.21.1`。编译用 maven.createmod.net 的同一坐标。读写端：`neoforge/src/main/java/org/maiwithu/maicraft/neoforge/compat/ponder/PonderClientReads.java`（2026-10-10 接入）。

- 场景注册表：`PonderIndex.getSceneAccess()` 的 `getRegisteredEntries()`，底下是 `LinkedHashMultimap`，按物品分组、组内按注册顺序（`PonderSceneRegistry.java:47-71`）。思索界面会再按 `StoryBoardEntry.getOrderingEntries()` 排（`PonderUI.java:202-240`），所以我们的序号按注册顺序编，不保证和界面一致。
- 编译并开场：`SceneRegistryAccess.compile(Collection<StoryBoardEntry>)` 自己新建 `PonderLevel`、摆好作者的结构文件并 `begin()`（`PonderSceneRegistry.java:93-112`）；要用客户端世界当原始世界，角色不在世界里时建不起来。
- 推进：思索界面跳着看时每刻先 `forEach(e -> e.whileSkipping(scene))` 再 `tick()`（`PonderScene.java:328-338`），不渲染。`MarkAsFinishedInstruction` 会提前把 `finished` 置真（只是让界面亮起下一个场景的按钮），时间要走到 `getTotalTime()` 才算放完（`PonderScene.java:299-326`）。
- 结构文件的全部方块开场就摆在演示世界里，`showSection` 一类指令只决定画不画；场景中途可以换方块、拆方块。区段的可见范围在 `WorldSectionElementImpl` 的非公开字段里，没读。
- 文字：`TextInstruction` 显示时把 `TextWindowElement` 加进 `getElements()`（`TextInstruction.java:30-37`）。文字在它的包内字段 `textGetter`（`Supplier<String>`，`TextWindowElement.java:34`）：场景自己的句子取自翻译键 `<命名空间>.ponder.<场景 ID>.text_<n>`，共用句子（如转速要求）取自 `PonderIndex.getLangAccess().getShared(...)`，不在场景自己的句子表里（`TextWindowElement.java:78-110`）。
- 操作提示：`InputWindowElement` 的包内字段 `icon`（`PonderGuiTextures.ICON_LMB / ICON_RMB / ICON_SCROLL` 或自定义图标）、`key`（`ponder:sneak_and` 潜行、`ponder:ctrl_and` Ctrl）、`item`（手持物）（`InputWindowElement.java:27-89`）。
- 所有者批准的反射例外（知识检索规格第 10 节第 3 项）只读上面四个字段：`TextWindowElement.textGetter`、`InputWindowElement.icon / key / item`；字段在创建读写端时取一次，取不到就给"读不到内容"。换 Ponder 版本前先核对这四个字段还在。

## 9. 配方查看器：EMI 与 JEI

实测实例与开发客户端都装着 EMI 1.1.24 与 JEI 19.38.0.366（实例里另有一个 `.disabled` 的旧版 JEI）。EMI 源码 `emi/`（1.1.24，与 jar 一致）；JEI 本机没有源码，接口按实例里的 jar 用 javap 核对。编译坐标：`dev.emi:emi-neoforge:1.1.24+1.21.1`（maven.terraformersmc.com），`mezz.jei:jei-1.21.1-common-api` 与 `jei-1.21.1-neoforge-api` 的 19.38.0.366（maven.blamejared.com）。读写端：`neoforge/src/main/java/org/maiwithu/maicraft/neoforge/compat/{emi,jei}/`（2026-10-10 接入）。

- EMI 与 JEI 同装时，EMI 的 JEMI 原样导入 JEI 插件注册的配方类别，类别 ID 不变；已有原生 EMI 类别的、或该命名空间已有原生 EMI 插件的跳过（`emi/xplat/src/main/java/dev/emi/emi/jemi/JemiPlugin.java:189-254`）。所以同装时问 EMI 就看到两者之和。
- Create 只写了 JEI 插件（`Create/src/main/java/com/simibubi/create/compat/jei/`），没有原生 EMI 插件；它的加工类别在 EMI 里是经 JEMI 导入的。AE2 有原生 EMI 插件（`appeng/integration/modules/emi/`）。
- EMI 读法：`EmiApi.getRecipeManager()` 的 `getRecipesByOutput / getRecipesByInput / getWorkstations / getRecipes(category) / getCategories`；`EmiRecipe.getBackingRecipe()` 给背后的 `RecipeHolder`（没有时为 null）；EMI 自己拼的展示配方 ID 以 `/` 开头。加载完没有看 `dev.emi.emi.runtime.EmiReloadManager.isLoaded()`（公开类，不在 api 包）；进世界后要加载几秒。标签原料是 `TagEmiIngredient`，公共字段 `key`。展示几率 `getChance()` 默认 1；经 JEMI 导入的配方可能没带几率。
- JEI 读法：运行时只经插件的 `IModPlugin.onRuntimeAvailable(IJeiRuntime)` 交出，`onRuntimeUnavailable()` 收回；插件按 `@JeiPlugin` 注解扫描、JEI 自己创建。查找用 `IRecipeManager.createRecipeCategoryLookup / createRecipeLookup(type).limitFocus(...)`，焦点由 `IJeiHelpers.getFocusFactory().createFocus(RecipeIngredientRole, VanillaTypes.ITEM_STACK, stack)` 建，默认不带隐藏的类别与配方；工作站是 `createRecipeCatalystLookup(type)`；每格候选从 `createRecipeLayoutDrawable(...).getRecipeSlotsView().getSlotViews(role)` 读。格子不带标签，也不标几率。
- 流体数量：NeoForge 上 EMI 与 JEI 的流体都按毫桶（一桶 1000）给，实机待核。
