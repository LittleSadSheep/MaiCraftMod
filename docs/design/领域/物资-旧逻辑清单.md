## 2 主流程

以能力入口为起点，按代码实际调用写：

- **obtain（maicraft:acquire_items）**：`AcquireAbilityAdapter.validate` → `SemanticAcquireApi.validateArguments`（格式检查，不碰游戏）→ 进入游戏后 `SemanticAcquireApi.newRecord` 展开标签并冻结仓库范围 → `SemanticAcquireTaskRecord` → `SemanticAcquireCompanionTask`。任务每刻：先核对目标物品主背包总数是否达标 → 维护 `AcquisitionNeed` 需求栈（根需求在底，缺的原料/工具/工作台压顶）→ 对栈顶需求按 `AcquisitionSources.order` 排序来源（INVENTORY 0、WIRELESS 2、STORAGE 3、NEARBY 10、HARVEST 24、CRAFT 25/50、COOK 26/55、MINE 30/60、HUNT 35/80、TRADE 70）→ 依次为每个来源创建子任务（OffhandSupply/BackpackSupply/Ae2ResourceSupply/SemanticContainer/CollectItems/HarvestCrop/Craft/SemanticCook/MineBlock/SemanticTrade/实体搜索+攻击）→ 子任务结束后按进度决定换源、换配方或失败。容量不足时先启动 `AcquisitionInventoryTidy` 整理随身存储。全部来源耗尽时按 `exhaustNeed` 分类终态（NO_MATERIAL / MINED_OUT / 决策类失败）。
- **gather（拾取）**：公开 `maicraft:collect_items` 与 acquire 的 NEARBY 来源都走 `CollectItemsTaskRecord` → `CollectItemsCompanionTask`：按 UUID 固定目标实体集合，走近让原版结算拾取，用背包数量变化确认。单格采掘是 `maicraft:harvest_block`：`GeneralAbilityAdapter.harvestBlock` 校验坐标/维度/`may_alter_terrain`/方块类型（必须是固体、无方块实体、无流体）→ `MineBlockTaskRecord.onlyAt` 单格挖取并确认掉落。
- **craft（maicraft:craft）**：`AbilityAdapter.craft` 把请求翻译成 `allowed_sources=[inventory, craft]` 的内部 `acquire_items`（count 是"再做几件"，启动时按已有数换算最终目标）→ acquire 链的 CRAFT 来源做 `CraftOps.plan` 只读配方规划 → `CraftTaskRecord` → `CraftCompanionTask`：关无关菜单 → 工作台协调器（找已有台/摆随身台/就近站位）→ 打开合成界面 → 配方簿快捷摆放或逐格原生点击 → PICKUP 取一批成品 → QUICK_MOVE 收游标 → QUICK_MOVE 归还网格剩料 → 关界面 → 回收自己摆的临时工作台。
- **smelt（maicraft:cook）**：`CookAbilityAdapter` → `SemanticCookApi.newRecord` → `SemanticCookCompanionTask`：解析炉子配方（CookingRecipePlanner，含补料成本比较与递归备料）→ 准备/接近/打开炉子（没有炉子时按规划就地放置）→ 装原料、装燃料 → 等烧制（跨刻等待并按炉子进度续期）→ 取成品、清剩料、关界面，按批次账本对账。
- **eat（maicraft:consume）**：`GeneralAbilityAdapter.consume` 在适配层选食物（点名食物校验存在与 FOOD 组件；未点名时只在无效果食物里选，按营养缺口与饱和度排序）→ 内部工具 `eat` → `EatCompanionTask`：前置检查（有饥饿机制、身上有该物品、默认 FOOD 组件）→ 选到主手 → 原生持续使用 → 以同类物品总量减少确认进食。
- **equip（maicraft:equip）**：`GeneralAbilityAdapter.equip` 决定动作与栏位（unequip 必须给栏位；equip 无 item_id 且候选唯一时自动选）→ 内部工具 `equip_item` → `EquipCompanionTask`（穿）或 `UnequipCompanionTask`（卸）。穿：主背包找不到时可先从副手换入空主格；副手走背包交换原语，盔甲走"拿主手 + 使用一次"，主手只做选中。
- **drop（maicraft:drop_items）**：`GeneralAbilityAdapter.drop` 核对物品与当时库存（超出可读库存要决策）→ 内部工具 `drop_items` → `DropCompanionTask`：先结清旧界面 → 固定本轮总量（接单后库存变少则缩小）→ `DiscardSitePreparation` 选丢弃点（开阔空地或挖侧袋，带打火石可选可烧毁点）→ 朝远处整份抛掷 + 部分数量的原生分堆点击 → 逐次确认扣数 → 按需点火销毁并回收耐火余物 → 原地丢弃时走出拾取范围再收场，登记丢弃避让。

## 4 向 LLM 提问的出口（逐个列出问题和选项）

统一格式：`decision(goal, 问题文本, 选项列表, facts)`，应答经 `goalFromAnswer` 合并回参数。物资领域的提问出口：

1. **consume，饱食度满**："Hunger is already full…" → skip / cancel。
2. **consume，点名食物非 FOOD**：→ replace_goal（选可食物或专用使用动作）/ cancel。
3. **consume，点名食物带效果且无 allow_effects**：附 effect_entries → retry(allow_effects=true) / replace_goal（无效果食物）/ cancel。
4. **consume，只有带效果食物或没食物**：附 available_food；互锁处境会写进问题文本 → recover（取得无效果食物；饿死且被堵时提 suicide 死亡重置或去已知食物点）/ retry（点名+allow_effects）/ cancel。
5. **equip，未知栏位** → retry（合法栏位列表）/ cancel。
6. **equip，unequip 缺栏位** → retry / cancel。
7. **equip，不支持的 action** → retry / cancel。
8. **equip，equip+armor** → retry（换单个栏位或省略自动路由）/ cancel。
9. **equip，未给 item_id 且栏位无候选** → recover（先取得装备）/ cancel；候选多件 → retry（给 item_id）/ cancel（附 compatible_item_ids）。
10. **drop，缺 item_id/count** → retry / cancel（"丢弃不可逆"）。
11. **drop，count 非法** → retry / cancel。
12. **drop，无该物品或超量** → missingItem 提问 / retry（不超过 available_count）/ cancel（附 requested/available）。
13. **use_item，缺 item_id / 长蓄力物品 / 定点批量混用**（相邻能力，物资边缘）→ retry / replace_goal / cancel。
14. **acquire 的失败回执不是同步提问，而是终态 `requires_decision=true` + `recovery_options`**：按失败码给不同组合——恢复无线访问、检查背包存储回执、整理容量（prepare_inventory_capacity）、恢复身体条件、读工艺知识（planning handoff）、逐个开放未授权来源（allow_mine/allow_trade/allow_hunt 等，附风险等级）、provide_source_hint、narrate_and_allow_harm、换区域继续搜索/采矿、语义前置（semantic_prerequisite）、travel_dimension、stop。
15. **harvest_block / 单格放置的地形授权**：`may_alter_terrain` 决策经同一 decision 机制询问（事故 179 记录了授权在自动前置步骤间不继承的问题）。

## 5 失败出口（按失败类型统计，并列出位置）

失败类型取自 `core/FailureType`。物资领域主要出口：

- **NO_MATERIAL（缺料/来源穷尽）**：acquire 的 `allowed_sources_exhausted`、`acquisition_decision_required`、`prerequisite_decision_required`、`committed_recipe_unavailable`、`committed_prerequisite_unmet`、`committed_recipe_failed_after_effects`（SemanticAcquireCompanionTask）；craft 的配方不认识、产物为空、批次边界不符、crafting_materials_missing（CraftCompanionTask）；eat 的背包无食物（EatCompanionTask）；equip 的缺料（EquipCompanionTask）；drop 的无可丢物品（DropCompanionTask）；craft 适配器缺 item_id。
- **MINED_OUT**：acquire 终态在 mine 子任务真实报采区耗尽时保真使用（SemanticAcquireCompanionTask.java:2022-2041）。
- **TARGET_LOST（目标消失/现场不可证）**：保护区标签失效、容器搜索范围未知、外来合成格、副手堆确认移动后不在主背包、丢弃分堆前物品消失、装备选中后不匹配、菜单被换。
- **UNKNOWN（无法归类/未结清）**：各类 outcome_uncertain（整理未结、无线查询未结、子任务效果未结、丢弃点击未确认、网格清理未确认、菜单关闭未确认）。
- **NO_SPACE（装不下）**：inventory_capacity_blocked（acquire）、成品/剩料无法安全收纳（craft）、卸下无空格（unequip）、副手取用无空格（equip）。
- **NO_SUPPORT（缺支撑面）**：inPlace 无可达 3×3 台面、工作面中途变化、合成菜单无结果槽（craft）。
- **NO_PATH（走不到）**：丢弃选址失败（drop）。
- **STANCE_DUD**：丢弃站位变动（drop）。
- **TIMED_OUT / INTERRUPTED**：无进展租约到期（acquire / craft / cook 各自的 PROGRESS_LEASE）；外部取消。
- **INTERNAL**：需求栈丢失、递归父需求缺失、批次边界异常（acquire / craft）。
- **UNSUPPORTED**：非普通合成配方（craft）。

## 10 v0 直播中在这个领域出过的问题（来自 v0 维护记录）

素材取自 v0 维护记录归档，只摘游戏事实与结论：

- **001**：合成失败回执同时报"缺材料"与"菜单超时"，两个都不指向真实卡点（EMI 知识页标签输入解析不到）；修复方向是失败要区分"材料在但配方匹配失败"与"材料真不在"。
- **010**：砾石取燧石，3 次低概率未掉落 + 一次重力方块塌落引起的瞬时寻路失败就让 41 个源全部作废；对照重发立刻成功。教训：概率掉落要有方差预期，瞬态寻路失败不该当终态。
- **014**：`allowed_sources=[storage]` 只搜 AE2 终端，不认原版箱子；用户直觉的"仓库"是箱子。后改为普通箱子与 AE2 共用仓库许可。
- **019**：mine 的 known_sources 逐轮波动无统计说明（扫描中心随玩家移动、分片收敛、截断），无法区分正常重扫与证据丢失。
- **021**：自己砍掉的掉落物被 NEARBY 拾取按"归属未证明"排除；mine 内部自管归属但两条路径零交叉。后改为归属交给服务器结算。
- **028**：craft 递归补料放弃原版直路去追模组奇异替代品（wood_chip、stripped_umbran_log）；与配方图搜索顺序有关。
- **041**：工具前置的配方原料被窄化成非本地木种，原地空转 20+ 次尝试；修复是先扣现货再查循环、工具 lineage 只保留工具祖先。
- **043**：source_hint 键名是隐藏契约，hunt 家族在"模型不知道键名"的现实下不可用；修复把六个键名写进能力契约。
- **047**：丢弃物品逐个抛在脚边被自己瞬间吸回，回执却全 success；修复是朝最开阔远处整份丢弃、登记避让、走开阶段。同条中"合成 fit 误拒"经取证撤回（感知计数漏了一堆）。
- **049**：深层食物-战斗互锁（饥饿低+血量低时 combat 拒战、consume 又没安全食物）无出口；拍板为双方回执点破处境并列全部出路（含可授权的死亡重置）。
- **057**：反射战斗耗空石镐耐久全程无回执；修复走装备同步包观察并发布 `agent.item_broken` 事件。附带观察：反射武器选择不看耐久。
- **063**：craft 族不把背包内的合成台计为可用工作面，且把"工作面"当合成目标递归展开全部原木，回执超 80KB；acquire 的 craft 族却能自建临时台——两条路径行为不一致。
- **131**：工具在背包没拿在手上时 harvest_block 报"没有可行路径"，话术误导（实际卡点是工具）；cook 缺炉会就地放炉，harvest 不自动装备，行为不一致。
- **179**：单格挖掘的 `may_alter_terrain` 授权问了两轮（主步骤与自动前置步骤各一次），授权答复未传递给前置。
- **183**：丢弃选址把开阔地形邻接的所有可走格判成"通往远处的边界"，露天反而无可丢弃区（`blocksFrontier` 判定）。
- **129**：drop_items 回执报"菜单格子对不上"失败，但背包对账物品已丢出；原则"回执是线索、实物是裁决"要求回执不得与实物相反。

未找到其他独立归档的物资领域维护记录；`pending-verify`、`pending-decision`、`outbound` 目录未逐条展开，其中与挖矿走行、寻路相关的事故归出行清单。
