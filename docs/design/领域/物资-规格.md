# 领域规格：物资

> 状态：已批准（2026-10-09）。起草方 ChangingSelf；所有者委托 Claude 逐项审过第 10 节并授权直接修改：第 10 节 5 项都按建议（第 5 项"不碰玩家的箱子"实现还没做到，见待拍板清单第六节）。改了的做法与实现要跟进的地方见待拍板清单第六节。
> 范围：能力 `obtain`（让背包里某样东西再多几件）、`gather`（采掉、收获、捡起世界里指定的东西），里程碑一。obtain 先做身上、容器、合成、烧炼、采集、采掘六种来源；交易、狩猎、AE2 无线网络、随身背包随里程碑二、三补齐，本规格不展开设计。
> 依据：物资旧逻辑清单（v0 `dev`，`aa97940c9`）108 条。其中吃（E01–E07）、装备（Q01–Q09）、丢弃（D01–D10）与容量腾挪（A46）共 27 条已归吃穿与背包域，本规格不重复归类。
> 边界：吃（`eat`）、穿（`equip`）、丢（`drop`）归吃穿与背包域；饥饿驱动的临时弄吃的任务归战斗与生存需求域。本域的 obtain 是它们背后的取物来源，只保证那个临时任务能直接复用。挖矿的走行、探路归出行域，本域只负责"挖到东西"。放方块与拆方块的原生交互归交互与容器域、建造与采矿域，obtain 内部用到时直接组合。
> 说明：第 5 节"位置"都指 v0（`dev` 分支）的文件；v1 按本规格重写，不移植这些文件。

## 2 真人怎么做

要 8 个火把：先看身上有没有、够不够；不够就想想哪个箱子记得有煤和木棍，或者干脆砍点木头现做；要烧的就去烧。挑最省事的路，做一步看一眼，世界变了就重新盘算；只拿需要的量，不做无用功。缺料、缺台子、缺工具都是先想办法自己补，补不上才说"拿不到，缺什么"。箱子不是见箱子就翻：记得的、眼前看到的才开，别人上锁的、看着像人家家里的不碰。

采东西：看到成熟的庄稼就收，顺手把种子种回去；要挖一块石头就走到跟前换对的工具挖，掉出来的东西捡进包；地上有自己刚砍出来的掉落物，走过去让游戏自己收进包。工具不够格挖不动，就说缺一把什么等级的镐。

## 3 新逻辑

### 3.1 obtain（拿东西）

```text
0 起算       count 是"这次再多拿几件"（A08）：记下点名物品身上原有几件，多出 count 件才算拿够，原有的不算这次拿到的
1 校验       item 必填、count ≥ 1、物品 ID 在注册表里、`#` 标签至少命中一件注册物品
             → 参数校验一次报全，不进游戏
2 盘来源     问 M4 的各物品来源，各给"能拿多少、大概多久、是否超许可"：
               身上（主背包、副手；随身背包随里程碑二补齐）
               容器（M9 世界记忆里记过的、现场看到的箱子；AE2 随里程碑二补齐）
               合成、烧炼（配方从真实配方管理器读；石切台同途径机制）
               采集（成熟作物）、采掘（只算看得见的，不透视；含换不出方块的加工品拒绝）
               交易、狩猎 → 随里程碑二、三补齐，现在写了也是 UNSUPPORTED
             超出这次许可（M7）的来源不参与，不逐个开关
             via 给了 → 只走指定途径；都没给 → 按总代价从低到高全部考虑
3 动手       逐个来源做；做完一个重新清点，还缺就重新盘（世界在变）
             合成、烧炼的原料、工具、工作台、燃料缺口 → 递归回到第 2 步（带深度上限与防环）
             背包要满 → 先走 M5 腾地方（保留本任务的目标与原料，从低价值往高价值腾）
             容器来源：先走近再开箱（M2 / M11），箱子里有什么开了才算数
4 结算       changes 记 item_gained；部分拿到 → partial + remaining 写清还差几件
             全部来源试完仍不够 → NEED_ITEM，attempts 写清试过哪些来源、各差多少
             采区真挖空了 → 如实写"附近已采完"；概率掉落（砾石出燧石）允许方差，
             多试几轮再下结论（010 实机）
```

本能力特有的部分只剩：来源问询的组合与代价比较、合成与烧炼作为来源的递归补料。站位、界面、许可、腾背包、进度全是 M2 / M5 / M7 / M8 / M11。

### 3.2 gather（采集、采掘、拾取）

```text
1 校验       target 必填（seen 的方块或实体、position 加 block）；item 可选（认为会掉出的
             东西，用于确认；不给就按实际掉落如实记录）
2 走到       M2 站位到交互距离内；工具不够格 → 结束 NEED_ITEM，写清缺什么等级的工具
             （决定 1）；工具在身上 → 先换到手上再动手
3 动手       作物：只收成熟的；收完顺手把种子种回去（没有种子就不补，不额外去找）
             方块：原生挖掘（M3），挖不动换下一个候选
             掉落物：走近让原版结算拾取；自己刚砍出来的也照收，归属交给服务器结算（021）
4 确认       按背包同类数量变化确认拿没拿到；拾取冷却中的掉落物照常等，不误报"附近没有"
5 结算       changes 记 block_broken 与 item_gained；补种失败不冒充没收成，
             保留已收的进度结束
```

gather 是薄能力：单点动作，不接来源排序，也不递归补料；要"弄到 N 个"用 obtain，它的采掘与采集来源在内部走同一条原生交互。

## 4 能力说明（参数与结果）

gather 的目标用 `target` 定位；obtain 不带 `target`——拿东西是往背包里凑齐，不是对某个东西做动作，范围由 `radius` 与 `max_distance` 表达。可选的 `permissions` 按 M7，obtain 的容器、采掘来源与 gather 的挖掘都受它约束。

### obtain

| 参数 | 必填 | 说明 |
| --- | :---: | --- |
| `item` | ✅ | 要多拿的物品 ID，或 `#` 开头的标签 |
| `count` | | 再多拿几件（不是背包里的总数），默认 1 |
| `via` | | 指定途径：`craft` / `smelt` / `mine` / `harvest` / `trade`；不给就按代价自己挑 |
| `radius` | | 容器与采掘的搜索范围，单位格；不给用当前加载视距，给了就冻结在范围内 |
| `max_distance` | | 愿意为此走多远，单位格 |

结果细节：`obtained_via`（实际拿到东西的途径列表，一条没拿到则为空）。

### gather

| 参数 | 必填 | 说明 |
| --- | :---: | --- |
| `target` | ✅ | 目标对象（07 的目标格式）：要采的方块、要收获的作物、要捡的掉落物 |
| `block` | | 配 `position` 目标用：要采的方块 ID |
| `item` | | 认为会掉出的东西，用于确认；不给按实际掉落记录 |
| `radius` | | 捡掉落物时的范围，单位格 |

结果细节：无（收了什么、挖了什么在 `changes`，没确认的交互在 `unconfirmed`）。

## 9 验收

**离线场景测试**（判断类用替身接口，任务用动作替身）：

1. obtain 的参数校验：item 缺失 / 物品 ID 未知 / 标签为空 / count 非法 → 一次报全，不进游戏。
2. obtain 的来源问询：身上现货够 → 第 0 步直接完成；现货不够按代价排序逐源尝试；每源做完重新清点。
3. obtain 的递归补料：缺工具、缺工作台、缺燃料压成前置需求；配方循环被防环拦下；深度到顶如实失败。
4. obtain 的结算：部分拿到 → partial + remaining；全部试完 → NEED_ITEM + attempts；未确认交互不被"数量达标"覆盖。
5. obtain 的容量：要满时先走 M5 腾挪次序；腾不动 → INVENTORY_FULL。
6. gather 的工具门槛：工具不够格 → NEED_ITEM 写清等级；身上有够格的先换手。
7. gather 的作物：只收成熟的；补种失败保留已收进度。
8. gather 的拾取：冷却中的掉落物等待不误报；数量变化确认；归属交给服务器结算。
9. radius 语义：给了就冻结在范围内，没给用默认。

**实机验收**（追加到冒烟清单）：

1. 身上没有火把时让它拿 8 个火把 → 它砍木、做台、合成，结果写明每步来源与数量。
2. 让它"再做 2 个木板"（ `via=craft`）→ 只走合成，不去挖原木。
3. 记忆里有个箱子装着面包，让它拿 3 个面包 → 走到箱子、开箱、取出，箱子里没那么多就如实 partial。
4. 让它采一片成熟小麦 → 收进包并补种；拔掉几株再让它采 → 只收剩下的成熟株。
5. 徒手（或木镐）让它挖黑曜石 → NEED_ITEM，写清需要钻石镐，而不是"没有可行路径"（131）。
6. 让它挖 1 个砾石堆出燧石，连续不出 → 多试几轮后才结束，不会一轮就报全部来源作废（010）。
7. 合成中途把工作台拆掉 → 它重新盘来源（再做台或换配方），已消耗的材料如实出现在 changes。
8. 随它背包快满时让它合成一批东西 → 先合并、进随身包或附近箱子，不动贵重品，合成照常完成。
9. 让它 `via=trade` 买东西 → UNSUPPORTED"交易还没接入"，不空转。

## 10 待两位决定

| # | 问题 | 建议 |
| --- | --- | --- |
| 1 | gather 时身上没有够格的工具，要不要自动先 obtain 一把（131 的 v1 版） | 不自动。NEED_ITEM 写清缺什么等级的工具；备一把镐可能是采矿石加合成的一大串事，gather 悄悄做完会让结果难读。LLM 一句话 `obtain` 再 `gather` 就能组合，符合"能力是薄的" |
| 2 | obtain 走到烧炼这步但附近没有熔炉时，要不要就地放一个 | 就地放（在 `change_blocks` 许可内）。v0 已这么做过；熔炉是常用设施，留下不回收，位置记进世界记忆 |

| 4 | 收获庄稼要不要顺手补种 | 补种（玩家常识：收完把种子种回去）。种子从本次收获里出，没有就不补，不额外去找 |

| 6 | 采掘候选要不要"看得见或见过"（审规格时补的缺口） | 定（所有者 2026-10-09 选甲）：只算从角色眼睛看得见的，与 find 的"只算看得见的"一致，不透视；埋在石头里的不算，要先下矿洞、挖开或走近。"记得见过的"等感知把看见的矿记进世界记忆后补上 |
