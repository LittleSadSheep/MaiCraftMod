# 领域规格：物资

> 状态：已批准（2026-10-09）。起草方 ChangingSelf；所有者委托 Claude 逐项审过第 10 节并授权直接修改：第 10 节 5 项都按建议（第 5 项"不碰玩家的箱子"实现还没做到，见待拍板清单第六节）。改了的做法与实现要跟进的地方见待拍板清单第六节。
> 范围：能力 `obtain`（让背包里某样东西再多几件）、`gather`（采掉、收获、捡起世界里指定的东西），里程碑一。obtain 先做身上、容器、合成、烧炼、采集、采掘六种来源；交易、狩猎、AE2 无线网络、随身背包随里程碑二、三补齐，本规格不展开设计。
> 依据：物资旧逻辑清单（v0 `dev`，`aa97940c9`）108 条。其中吃（E01–E07）、装备（Q01–Q09）、丢弃（D01–D10）与容量腾挪（A46）共 27 条已归吃穿与背包域，本规格不重复归类。
> 边界：吃（`eat`）、穿（`equip`）、丢（`drop`）归吃穿与背包域；饥饿驱动的临时弄吃的任务归战斗与生存需求域。本域的 obtain 是它们背后的取物来源，只保证那个临时任务能直接复用。挖矿的走行、探路归出行域，本域只负责"挖到东西"。放方块与拆方块的原生交互归交互与容器域、建造与采矿域，obtain 内部用到时直接组合。
> 说明：第 5 节"位置"都指 v0（`dev` 分支）的文件；v1 按本规格重写，不移植这些文件。

## 2 真人怎么做

要 8 个火把：先看身上有没有、够不够；不够就想想哪个箱子记得有煤和木棍，或者干脆砍点木头现做；要烧的就去烧。挑最省事的路，做一步看一眼，世界变了就重新盘算；只拿需要的量，不做无用功。缺料、缺台子、缺工具都是先想办法自己补，补不上才说"拿不到，缺什么"。箱子不是见箱子就翻：记得的、眼前看到的才开，别人上锁的、看着像人家家里的不碰。

采东西：看到成熟的庄稼就收，顺手把种子种回去；要挖一块石头就走到跟前换对的工具挖，掉出来的东西捡进包；地上有自己刚砍出来的掉落物，走过去让游戏自己收进包。工具不够格挖不动，就说缺一把什么等级的镐。

## 3 新逻辑

### 3.1 obtain（拿东西）

```text
0 起算       count 是"这次再多拿几件"（A08）：记下点名物品身上原有几件，多出 count 件才算拿够，原有的不算这次拿到的
1 校验       item 必填、count ≥ 1、物品 ID 在注册表里、`#` 标签至少命中一件注册物品
             → 参数校验一次报全，不进游戏
2 盘来源     问 M4 的各物品来源，各给"能拿多少、大概多久、是否超许可"：
               身上（主背包、副手；随身背包随里程碑二补齐）
               容器（M9 世界记忆里记过的、现场看到的箱子；AE2 随里程碑二补齐）
               合成、烧炼（配方从真实配方管理器读；石切台同途径机制）
               采集（成熟作物）、采掘（只算看得见的，不透视；含换不出方块的加工品拒绝）
               交易、狩猎 → 随里程碑二、三补齐，现在写了也是 UNSUPPORTED
             超出这次许可（M7）的来源不参与，不逐个开关
             via 给了 → 只走指定途径；都没给 → 按总代价从低到高全部考虑
3 动手       逐个来源做；做完一个重新清点，还缺就重新盘（世界在变）
             合成、烧炼的原料、工具、工作台、燃料缺口 → 递归回到第 2 步（带深度上限与防环）
             这一次里已经问遍各来源都没拿到的东西，换一种做法又要到它时当场按拿不到算、不再问；
             某样原料一件都弄不来、身上连一份的量都没有 → 放弃这种做法，不再去弄其余原料
             （2026-10-11 所有者定：要床时没有羊毛，不去砍床板的木头、不去采染色的花）
             背包要满 → 先走 M5 腾地方（保留本任务的目标与原料，从低价值往高价值腾）
             容器来源：先走近再开箱（M2 / M11），箱子里有什么开了才算数
4 结算       changes 记 item_gained；部分拿到 → partial + remaining 写清还差几件
             全部来源试完仍不够 → NEED_ITEM，attempts 写清试过哪些来源、各差多少，
             suggestion 建议查 lookup(topic=recipe, id=…) 看还有什么做法
             （2026-10-10 随知识检索规格批准加的一句；obtain 不依赖配方查看器）
             说明每层只写自己问过、试过什么，备料时下一层没拿到的只转述一句结论；
             各层没拿到的东西在最外层摊平讲一次：同一样东西只讲一次，卡在同一处的几样合成一组
             并写明几样，试过的几种做法逐个列出，不按字数截断
             采区真挖空了 → 如实写"附近已采完"；概率掉落（砾石出燧石）允许方差，
             多试几轮再下结论（010 实机）
```

本能力特有的部分只剩：来源问询的组合与代价比较、合成与烧炼作为来源的递归补料。站位、界面、许可、腾背包、进度全是 M2 / M5 / M7 / M8 / M11。

### 3.2 gather（采集、采掘、拾取）

```text
1 校验       target 必填（seen 的方块或实体、position 加 block）；item 可选（认为会掉出的
             东西，用于确认；不给就按实际掉落如实记录）
2 走到       M2 站位到交互距离内；工具不够格 → 结束 NEED_ITEM，写清缺什么等级的工具
             （决定 1）；工具在身上 → 先换到手上再动手
3 动手       作物：只收成熟的；收完顺手把种子种回去（没有种子就不补，不额外去找）
             方块：原生挖掘（M3），挖不动换下一个候选
             掉落物：走近让原版结算拾取；自己刚砍出来的也照收，归属交给服务器结算（021）
4 确认       按背包同类数量变化确认拿没拿到；拾取冷却中的掉落物照常等，不误报"附近没有"
5 结算       changes 记 block_broken 与 item_gained；补种失败不冒充没收成，
             保留已收的进度结束
```

gather 是薄能力：单点动作，不接来源排序，也不递归补料；要"弄到 N 个"用 obtain，它的采掘与采集来源在内部走同一条原生交互。

## 4 能力说明（参数与结果）

gather 的目标用 `target` 定位；obtain 不带 `target`——拿东西是往背包里凑齐，不是对某个东西做动作，范围由 `radius` 与 `max_distance` 表达。可选的 `permissions` 按 M7，obtain 的容器、采掘来源与 gather 的挖掘都受它约束。

### obtain

| 参数 | 必填 | 说明 |
| --- | :---: | --- |
| `item` | ✅ | 要多拿的物品 ID，或 `#` 开头的标签 |
| `count` | | 再多拿几件（不是背包里的总数），默认 1 |
| `via` | | 指定途径：`craft` / `smelt` / `mine` / `harvest` / `trade`；不给就按代价自己挑 |
| `radius` | | 容器与采掘的搜索范围，单位格；不给用当前加载视距，给了就冻结在范围内 |
| `max_distance` | | 愿意为此走多远，单位格 |

结果细节：`obtained_via`（实际拿到东西的途径列表，一条没拿到则为空）。

### gather

| 参数 | 必填 | 说明 |
| --- | :---: | --- |
| `target` | ✅ | 目标对象（07 的目标格式）：要采的方块、要收获的作物、要捡的掉落物 |
| `block` | | 配 `position` 目标用：要采的方块 ID |
| `item` | | 认为会掉出的东西，用于确认；不给按实际掉落记录 |
| `radius` | | 捡掉落物时的范围，单位格 |

结果细节：无（收了什么、挖了什么在 `changes`，没确认的交互在 `unconfirmed`）。

## 9 验收

**离线场景测试**（判断类用替身接口，任务用动作替身）：

1. obtain 的参数校验：item 缺失 / 物品 ID 未知 / 标签为空 / count 非法 → 一次报全，不进游戏。
2. obtain 的来源问询：身上现货够 → 第 0 步直接完成；现货不够按代价排序逐源尝试；每源做完重新清点。
3. obtain 的递归补料：缺工具、缺工作台、缺燃料压成前置需求；配方循环被防环拦下；深度到顶如实失败。
4. obtain 的结算：部分拿到 → partial + remaining；全部试完 → NEED_ITEM + attempts；未确认交互不被"数量达标"覆盖。
5. obtain 的容量：要满时先走 M5 腾挪次序；腾不动 → INVENTORY_FULL。
6. gather 的工具门槛：工具不够格 → NEED_ITEM 写清等级；身上有够格的先换手。
7. gather 的作物：只收成熟的；补种失败保留已收进度。
8. gather 的拾取：冷却中的掉落物等待不误报；数量变化确认；归属交给服务器结算。
9. radius 语义：给了就冻结在范围内，没给用默认。

**实机验收**（追加到冒烟清单）：

1. 身上没有火把时让它拿 8 个火把 → 它砍木、做台、合成，结果写明每步来源与数量。
2. 让它"再做 2 个木板"（ `via=craft`）→ 只走合成，不去挖原木。
3. 记忆里有个箱子装着面包，让它拿 3 个面包 → 走到箱子、开箱、取出，箱子里没那么多就如实 partial。
4. 让它采一片成熟小麦 → 收进包并补种；拔掉几株再让它采 → 只收剩下的成熟株。
5. 徒手（或木镐）让它挖黑曜石 → NEED_ITEM，写清需要钻石镐，而不是"没有可行路径"（131）。
6. 让它挖 1 个砾石堆出燧石，连续不出 → 多试几轮后才结束，不会一轮就报全部来源作废（010）。
7. 合成中途把工作台拆掉 → 它重新盘来源（再做台或换配方），已消耗的材料如实出现在 changes。
8. 随它背包快满时让它合成一批东西 → 先合并、进随身包或附近箱子，不动贵重品，合成照常完成。
9. 让它 `via=trade` 买东西 → UNSUPPORTED"交易还没接入"，不空转。

## 11 AE2 的 ME 终端

> 状态：已批准（2026-10-10，所有者经审查会话答复"都按建议"）。
> 范围：obtain 的一个来源，途径 `ae2`，装了应用能源2（AE2）才有；只取网络里已有的。网络本身（控制器、频道、能量、合成 CPU）的读数与部件、线缆的施工归机器域。

### 11.1 真人怎么做

基地里有 ME 网络：要东西先到终端前看一眼网络里有没有，有就取需要的量——差一组以上整组拿，不足一组就一件一件拿够。终端没电、没频道，就知道这台现在用不了。别人家的 AE 不去翻；一起玩的自家人的网络可以取，不拆不改。

### 11.2 新逻辑

```text
1 找终端     角色周围已加载区块里的 ME 终端（ME 终端、合成终端、样板编码终端），半径用 radius，没给 64 格
             能不能取用问保护判断的"存储能不能取用"（Protection.mayUseStorage，拆改才看 blockProtected）：
             自己或自家人放的才取用，别人的、归属没问清的不碰
2 报价       上次看到的网络存货（本次启动内，五分钟内算数）里有 → 报明确数量，去最近的那台
             没有记得有货的 → 去看一眼，报"不知道有多少"（引擎把它排在数量明确的来源后面）：
             先去没看过的里最近的一台，再是上次看不行的（没连上网络、网络里没有）里最近的一台，报价写明上次看到的情况；
             上次不行不代表现在还不行，旧记录只拿来排先后、不拿来拒绝；
             同一次拿东西里看过一次还不行就不再回头；附近的终端都是别人的 → 给不了
3 走过去点开 靠近到看得见面板、够得着的地方；点在面板上，不点线缆芯；界面打开、网络存货同步过来才算开了
             终端没了 → 交回空，引擎换别的路；界面显示没连上网络 → 这个来源以 NOT_POSSIBLE_HERE 结束
4 取         缺一组以上：Shift 点网络里那一条，一下一组进背包
             不足一组：一件一件取到光标上，凑够了放进背包里能整个装下的一格；只拿需要的量
             同一种东西有几个变体时，先取和默认样子一样的，再按存量从多到少
             每一笔等背包（或光标）里真的多出来才记；一直没动静按没取到，不重点；对不上记进 unconfirmed
             拿够、网络里没了、背包放不下 → 收场：光标上还有东西先放进背包能整个装下的一格，背包放不下就放回网络，
             光标空了再关界面（不留给关界面的流程去还，背包满了它会把东西丢在地上）
5 结算       关之前记下这次看到的网络存货；引擎按身上清点，obtained_via 记 ae2
```

### 11.3 定下的做法

| # | 问题 | 定下的做法 |
| --- | --- | --- |
| 1 | 现货不够、但网络有样板能合成 | 这一轮只取现货。之后单独做：用网络里已有的样板下单（不补缺料、不加样板），在终端前等，作业有进展就等，停滞一段时间就以 partial 结束，写清"作业还在网络里跑"。做的时候再定它归 `ae2` 这条途径还是另起一个取值 |
| 2 | 别人搭的 AE 网络 | 任务许可里不加开关。实例配置里列"自家人"（所有者信任的玩家），自家人放的终端与箱子一样可以取用（不拆），别人的照旧不碰；容器来源一起管 |
| 3 | 没开过的终端排在数量明确的来源后面 | 维持。LLM 用 `via=ae2` 就直接去 AE；开过一次之后有记录就正常比价 |
| 4 | 上次看到的网络存货要不要跨重启保存 | 只在本次启动内 |
| 5 | 身上带着无线终端时直接用物品打开 | 下一轮做 |
| 6 | 找终端算不算透视 | 已加载区块里半径内的都算：终端是自家基地的固定设施，隔着墙知道它在隔壁屋是玩家常识，和存东西找容器的现场扫描一致 |
| 7 | 上次看没连上网络、或网络里没有这样东西的终端，这次还去不去（实测时发现原先"不去、等记录过时"是凭旧记录预判拒绝） | 照样去看，排在记得有货的与没看过的后面，报价写明上次看到的情况；同一次拿东西里看过一次还不行就不再回头 |

### 11.5 验收

**离线**：挑终端（记得有货去最近、都没看过去最近一台、别人的与断网的与看过没有的不去，原因逐类写清）；怎么取（整组、单件、放下、背包满、网络没了、默认样子的先取）；取货确认（整组、单件、放下各自的算数与对不上）；上次看到的网络存货（按物品合计、五分钟过时、按维度与终端分开）；联动入口（装了且版本在范围内才登记、读写端对不上就停用）。

**实机**（开发客户端，AE2 19.2.17）：

1. 装了、没装、版本范围改窄，三种各启动一次，日志里那一行分别是已登记、没装跳过、版本不在范围不登记。
2. 网络里放 69 个圆石，让它拿 69 个圆石（`via=ae2`）→ 走到终端、点开，一下整组加五次单件，`obtained_via` 为 `ae2`，背包里多 69 个。
3. 终端挂在线缆中间（同一格有线缆芯）→ 照样点开，不点到线缆。
4. 断开网络电源后再要 → 这个来源如实结束，换别的路或以 NEED_ITEM 结束并写清"没连上网络"。
5. 背包只剩一格时要 100 个 → 取进能装下的部分，放不下就停，不往地上掉。
6. 取货中途被生存需求打断（例如饿了去吃东西）→ 这次取货就此收场、界面关上，取到多少由引擎清点后再决定要不要回来接着取；这是设计如此，不是取货中断的 bug。

## 12 交易、狩猎与随身背包

> 范围：obtain 补齐的三个来源——和村民交易（途径 `trade`）、狩猎（途径 `hunt`）、随身背包（并入"身上"）。头部引言里"交易、狩猎、AE2 无线网络、随身背包随里程碑二、三补齐，本规格不展开设计"一句由本节接管：三个来源在本节定稿，AE2 已在第 11 节。
> 接缝：走近村民、点开与关上交易界面按交互与容器域的既有做法（站位、右键、界面会话）；狩猎的攻击执行归战斗域，本节只管"狩猎作为取物来源"的选目标与收掉落；往随身包里塞东西是腾地方（M5）的既有一步，本节只管"从随身包取出来"。依据：钓鱼附魔交易狩猎旧逻辑清单的交易组（T01–T28）、狩猎组（H01–H21）、随身背包组（B01–B04）；第 5.1 节标着"随里程碑二补齐"的 A12、A13、A36–A43、A49 在本节落定。

旧门槛不再有：狩猎不再要求产地线索与显式伤害开关，参与由许可决定（A36、H01–H03）；交易不再有付款物品名单与"一条报价独自满足全部缺额"的限制（T13、T15，定下的做法 1、6）；商人离保护地标 12 格就排除的旧规则由保护判断取代（T09）；界面身份与关闭归属的缺口归界面会话的既有规矩（T25、T26）；取货没能确认不重买，进 unconfirmed（T21）。

### 12.1 真人怎么做

买东西：村里的村民各做各行，要什么找做这行的——面包找农民，弓箭找制箭师。走到跟前右键搭话，看他摆出来的报价，哪个便宜用哪个，要几件买几件，付钱拿货走人。不还价，他摆多少就是多少；同一笔货买多了他会临时抬价，抬了就换下一条报价或换个村民。付不起先去把绿宝石凑齐再回来。傻子和没干活的村民不摆货，不去搭话。别人的宠物、圈起来的牲畜不碰。

打猎：要羊毛、生肉、皮革这类东西，看看附近有没有对得上的动物，挑最近的一只打倒，掉出来的捡走。不打幼崽（不掉东西）、不打有主的和圈养的；要白羊毛就挑白羊，剪过毛的羊身上没有羊毛。一击没倒就追着打完；打不过就撤，不硬拼。打了一只没见到要的东西，换下一只，不在一棵树上吊死。

随身背包：要的东西包里可能就有——开包翻一下，有就拿几件出来，关上。包是身上的仓库，口袋是手边。

### 12.2 交易（trade）

```text
1 找村民     已加载、radius 内扫村民与流浪商人（radius 不给用当前加载视距，给了冻结在范围内，
             同找容器的现场扫描）。合格候选：成年、有业（无业与傻子的村民开不出交易界面）、
             不在保护判断里（有名字、拴绳、圈养、在记住的区域里，M7）
             附近没有合格候选 → 这条来源给不了；都试完还不够 → 按看到的原因如实结束，
             缺付款、没货、没有合格村民分开写，不统一叫找不到
2 报价       有合格候选 → 报"能买到，有多少要开了才知道"（引擎把它排在数量明确的来源后面），
             代价按到最近候选的路程加每笔交换的动作数
3 逐个试     走到最近的候选，右键点开交易界面；界面没开成、不是这个村民的界面 → 换下一个；
             付款格或结果格里已有东西 → 不碰，换下一个（M11 的外来内容规矩）
4 成交       卖这件东西的报价里挑付款件数最少的，在报价列表里点那一条（同价商品排在一起也不会买错条）；
             付款按这条报价放进两格，结果槽的货搬进背包（取货计划同容器），背包真多出来才算这笔成交
             缺几件买几件：一条报价买完还缺接着买下一条，这个村民卖完换下一个；只买装得下的量
             付款不够 → 按 M4 递归补付款（同合成原料，深度上限与防环都在）；补不到 → 这单如实结束，引擎换来源
             每一笔按界面当时的价付；同一笔报价买多了原版会临时涨价，涨了就换报价或换商人
             取货没能确认 → 不重付，记进 unconfirmed；关界面前光标清空，付款格余货交给游戏的关闭流程还回
5 结算       引擎重新清点；obtained_via 记 trade
```

村子在哪归勘察与出行：obtain 只跟已经加载的村民交易，不自己跑图找村子；附近没有就如实结束，LLM 要先 `travel` 或 `find` 再来。交易不伤人也不改方块，不设专门许可；付款物品是稀有消耗品的报价照 `use_rare_items` 挡。

### 12.3 狩猎（hunt）

```text
1 找猎物     哪种动物或生物掉这件东西，查写死的原版对照（客户端读不到生物的掉落表，同采掘的方块对照）；
             候选在已加载、radius 内：类型对得上、活着、非幼崽（幼崽不掉东西，也不打幼崽）、
             羊毛需求里已剪毛与颜色不对的羊不算、保护判断里的不算（有名字、驯服、拴绳、圈养）
2 问许可     动物按 kill_animals、敌对生物按 fight 逐只判断；一只都不许动 → 这条来源不参与，写明卡在哪项许可
3 锁定       最近的一只；没出手前出现明显更近的同类可以改道，出了手就盯住这只（H13）
4 打         交给战斗域的攻击动作：走位、武器、出手与确认都按它的规矩；打不过 → 撤，这一单如实结束
             （猎不还手的动物不该被拒战线拦下——092 的死锁，这条归战斗域的威胁评估）
             期间每刻核对目标：被拴绳、被命名、进了保护区 → 停手，记下原因换下一只（事实核对，不是拦截）
5 收         击杀确认后把可归属、够得着的掉落收进包（同 gather 的拾取）；没收回的如实写进结果，
             不冒充"收干净了"——目标物品够数就算这一单拿到（拾荒与击败分开结算，同 fight 的既有做法）
             目标物品没见到 → 这只记进本次排除（"打了一只 X，没见到 Y"），换下一只；
             概率掉落（兔子脚这类）多试几轮再下结论（010 的耐心），进度跟踪收着不无限打
6 结算       引擎重新清点；obtained_via 记 hunt
```

已加载范围里没有候选时：愿意走就按 `max_distance` 出去找，走到一片再看一片；没给 `max_distance` 就如实结束，不把身体带进没有上限的搜索（078）。要的东西只在别的维度有 → 如实写明，跨维度随出行域补齐（A43）。

### 12.4 随身背包（并入"身上"）

```text
清点     "身上有多少"照旧只数主背包与副手；随身背包是身上的仓库：包里有的取出来就算拿到，
         起算的原有数不含包里的
问价     身上有精妙背包 → 上次开包读到的存货（本次启动内，五分钟内算数）报明确数量，代价只算开包取货的动作；
         没读过报"包里可能有，不知道有多少"（排在数量明确的后面，同网络存货）；
         读不到（联动停用、版本对不上）→ 如实"未证实"，不是空包，不冒充身上没有
执行     用模组自己的打开请求按格开包（对应玩家在背包里对着那只包按 B 键），等界面同步；身上不止一只包时
         一只一只开，这只没有或不够就关上开下一只，打不开、读数对不上也换下一只；背在饰品栏里按不了格的
         退回模组自己找第一只（所有者 2026-10-11 定）；问价把五分钟内看过的几只加起来，还有没看过的就报
         "看过的有几件，另有几只没开过"；只看主存储，升级槽与幽灵槽不算货；
         按要的量搬进主背包（取货计划同容器），每笔以主背包真多出来为准；主背包放不下就停，已取的照算；
         光标清空才关界面（M11）
结算     取出来的算拿到；它本来就是身上的，obtained_via 记 carried，不另立取值
```

从随身包取出来归 obtain；往随身包里塞是腾地方（M5）的既有一步，obtain 不另写。开包读过的数过时就重开一次再报价，不为问价反复开关界面。

### 12.6 定下的做法

| # | 问题 | 做法 |
| --- | --- | --- |
| 1 | 付款要不要限定只付绿宝石 | 不设名单：报价两格要什么就付什么（附魔书是书加绿宝石，真人也这么买）；付款物品超出 `use_rare_items` 许可的报价不参与。付款不够按 M4 递归补（同合成原料，深度上限与防环都在）；补不到如实结束，引擎换来源 |
| 2 | 非动物也非敌对的野生生物（鱿鱼、鳕鱼这类不伤人的）按哪个许可狩猎 | 与 `kill_animals` 同档：为具体需要处理野生生物是同一条常识的自然延伸；动物照 `kill_animals`、敌对生物照 `fight` 不变 |
| 3 | 狩猎候选按已加载范围算，还是只算看得见的 | 已加载、radius 内都算候选（猎物少且会走动，按看见筛会漏掉墙后走着的羊；矿石成片埋在石头里才要"看不见等于没有"），出手前必须看得见才攻击（M3 的射线核对把关）；这和采掘"只算看得见的"不同 |
| 4 | 击杀后副产物没收完怎么算 | 如实写进结果、不影响这一单拿到（拾荒与击败分开结算，战斗规格已定）；不再像旧规则那样整单失败（A41 的"不冒充收干净"保留为如实报告） |
| 5 | 随身包存货的报价读数留多久 | 上次开包读的数本次启动内、五分钟内算数，过期重开一次（同网络存货的既有做法）；不为问价反复开关界面 |
| 6 | 同一界面多条报价接连买 | 允许：缺几件买几件，一条买完接着下一条、下一个村民；旧的单条报价独自满足全部缺额是过严的能力边界，按约束登记不再保留（T13） |
| 7 | 不给 via 时交易参不参与；一笔怎么成交 | 不参与：交易要花付款，绿宝石的稀有度是普通、`use_rare_items` 拦不住，所以只有点名 `via=trade` 才买（所有者 2026-10-11 定）。一笔一点：左键把结果格那一份拿到光标再放进背包；不 shift 点结果格——点选报价时原版把付款格自动摆满一组，shift 会拿着这一组一直成交下去 |

### 12.7 验收

**离线场景测试**（判断类用替身接口，任务用动作替身）：

1. 交易候选：幼年、无业、傻子、有名字、圈养、在记住区域里的逐类排除并写明原因，合格的按距离排。
2. 报价挑选：多条报价按付款件数最少挑；在列表里点选那一条，付款只按这条算；接连买凑够缺额；存货不够换报价，商人试完换下一个。
3. 付款：递归补付款带防环与深度上限；稀有付款物品按许可挡；补不到如实结束；每笔以背包增长确认，没能确认不重付。
4. 狩猎筛选：类型对照命中才选；幼崽、已剪毛、颜色不对、保护逐类排除；许可逐只判断，一只都不许动时来源不参与并写明卡在哪项。
5. 狩猎执行：出手后不因更近同类反复改道；击杀后掉落收集与"预期掉落未观察到记排除"；概率掉落多轮耐心；搜索不越 `max_distance`。
6. 随身背包：存货读数五分钟过时重开；读不到按未证实不是空包；只拿需要的量；主背包放不下停、已取的照算。
7. via 语义：`via=carried` 含随身背包；`via=trade`、`via=hunt` 只走各自的来源。

**实机验收**（追加到冒烟清单）：

1. 村民摆着面包报价，让它拿 5 个面包（`via=trade`）→ 走到村民、点开、点报价、付款、取货，`obtained_via` 记 `trade`，背包多 5 个。
2. 身上没绿宝石时按拍板 1 的结论验证：递归去凑或如实 NEED_ITEM，不空开界面。
3. 同一村民连买多笔触发涨价 → 换报价或换商人，结果写明原因。
4. 附近只有傻子和幼年村民 → 如实结束，不反复右键探界面。
5. 精妙背包里装 20 个火把，让它拿 10 个 → 开包取出 10 个，`obtained_via` 记 `carried`；联动停用时如实"读不到背包"，走别的来源。
6. `kill_animals` 默认时让它拿羊毛 → 挑白羊击杀、收羊毛与羊肉，没收回的副产物如实写。
7. `kill_animals=none` 时要羊毛 → 狩猎来源不参与，attempts 写明许可。
8. 打了一只羊没见到羊毛（罕见）→ 记排除换下一只，不重复打同一只。

## 13 机械动力物流网络的库存请求器

> 状态：待批（2026-10-11 起草，里程碑三 Create 会话；所有者已定 C6"当 obtain 的一条来源，和 AE2 取现货同一种写法"，这一节是写法）。
> 范围：obtain 的一个来源，途径 `stock_ticker`，装了机械动力（6.0）才有；只要网络里的现货，不让请求器替你合成。请求器的现货读数归机器域（`machine_inspect` 已读）。

### 13.1 真人怎么做

基地里搭了 Create 的物流网络：仓库的箱子装着打包机和库存链接，前台放一台库存请求器，旁边坐着库存管理员，请求器边上一只包裹青蛙港（或邮筒）写着自家的地址。要东西时右键库存管理员打开请求界面，看一眼网络里有没有，有就下单、地址填前台那只青蛙港；打包机把东西打成包裹，顺着链条输送机送到青蛙港。走过去把包裹从青蛙港里拿出来，右键拆开，东西进背包。网络被锁上、请求器不是自己人的，不去下单。

### 13.2 新逻辑

```text
1 找请求器   角色周围已加载区块里的库存请求器，半径用 radius，没给 64 格
             能不能用问保护判断的"存储能不能取用"（Protection.mayUseStorage）：自己或自家人放的才用；
             旁边要坐着库存管理员（坐在座位上的生物，水平四邻、同高或高一格里恰好只有这一台请求器）：
             没有 → 这台不用，写明"请求器旁边没有坐着的库存管理员"；
             网络上了锁、角色不在能用的人里（Create 的 mayInteract）→ 这一台不用，写明"网络锁着"
2 定取货口   这台请求器附近（同一片已加载区块、32 格内）收包裹的包裹端口（包裹青蛙港、邮筒），
             写了地址、开着"收包裹"、自己或自家人放的；请求器上次用过的地址有对应的端口就用它，
             否则用离请求器最近的一只。一只都没有 → 这台给不了，写明"附近没有写了地址的取货口"
3 报价       请求器同步到客户端的现货摘要五秒内算数：里面有 → 报明确数量（不超过现货），去这台
             摘要过时或没看过 → 报"不知道有多少"（引擎排在数量明确的来源后面），到了再看
4 走过去下单 走到够得着库存管理员的地方，右键它打开请求界面（菜单 create:stock_keeper_request，布局证明认它）；
             界面一开现货摘要就同步过来，不另发刷新；网络里没有 → 关界面，这个来源以 NOT_POSSIBLE_HERE 结束
             下单件数 = min(还缺的件数, 现货)；在开着的界面里照"发送"那样发下单（OpenedMenu.submitModAction，
             和 AE2 终端同一套规矩），地址写第 2 步的取货口；发完关界面
5 等包裹     走到取货口跟前等；端口里的包裹（读包裹里装的东西）合计够下单的件数就去取；
             一分钟里包裹一件没多 → 不再等，取已经到的；最多等五分钟
6 取与拆     点开端口，把装着要的东西的包裹快速移动进背包；主手拿包裹一件件右键拆开，东西进背包
             （拆包时背包放不下的东西 Create 会扔在脚边，背包满了先停，不拆）；
             包裹里顺带的别的东西也照收，写进结果
7 结算       引擎按身上清点，obtained_via 记 stock_ticker；下了单没到的件数写进 notes（"还在路上"），不重下单
```

### 13.3 拟定的做法（待批）

| # | 问题 | 拟定的做法 |
| --- | --- | --- |
| 1 | 现货不够、请求器能合成（界面里的合成预览） | 这一轮只要现货；合成预览不算现货（机器域已这样读） |
| 2 | 取货口挑哪一只 | 第 2 步：上次用过的地址优先，没有就离请求器最近、写了地址、收包裹的那只；不另加参数。LLM 要寄到别处时自己去那边用 `machine_*` 或手动拿 |
| 3 | 包裹在路上卡住（链条断了、地址没人收） | 五分钟上限、一分钟无增长就收场，写明下了几件、到了几件；不重下单，免得卡住的单再多一份 |
| 4 | 端口里原本就有别人的包裹 | 只拿装着要的东西的包裹；先记下下单前端口里已有的包裹，只拿下单后新到的 |
| 5 | 下单算不算"花东西" | 不算：东西本来就是自家仓库的；和容器来源同一个许可口径（存储能不能取用） |

### 13.4 游戏事实的归属

| 事实 | 位置 |
| --- | --- |
| 玩家下单要经库存管理员：右键坐在请求器旁边的管理员（`StockTickerInteractionHandler.interactWithLogisticsManagerAt`，管理员旁边恰好一台请求器，`getStockTickerPosition`）才查 `mayInteract`、打开请求界面并把现货摘要发过来；右键请求器方块只开分类界面，没有管理员时提示 `keeper_missing` | `compat.create` 的物流读写接缝；来源第 1、4 步 |
| 请求器的现货摘要在请求界面打开时与开着时同步（`LogisticalStockRequestPacket`），摘要里的合成预览不算现货 | `compat.create` 的物流读写接缝 |
| 下单是请求界面里发的 `PackageOrderRequestPacket(请求器, 清单, 地址, false)`；服务器只按 `BlockEntityConfigurationPacket` 核对距离，所以角色只在开着的请求界面里发，不绕过管理员；网络锁看 `Create.LOGISTICS.isLocked / mayInteract` | 同上 |
| 包裹端口十八格只收包裹，写了 `addressFilter`、`acceptsPackages`，库存与地址都同步给客户端；界面 `create:package_port` | 同上；界面布局证明 |
| 包裹里装的东西在包裹物品的数据组件里，主手拿着右键拆开，放不下的掉在脚边 | 同上 |

### 13.5 验收

**离线**：挑请求器（别人的、没有库存管理员的、锁着的、附近没有取货口的逐类排除并写明原因）；挑取货口（上次地址优先、最近、没写地址与不收包裹的不选）；报价（摘要新鲜报数、过时报不知道）；下单件数；等包裹（够了就取、一分钟无增长、五分钟上限）；只拿下单后新到、装着要的东西的包裹；拆包背包满先停。

**实机**（开发客户端，Create 6.0.11）：

1. 仓库箱子里放 40 个铁锭，打包机、库存链接、请求器、青蛙港（地址 home）连好；让它拿 20 个铁锭（`via=stock_ticker`）→ 走到库存管理员跟前右键、在请求界面下单、走到青蛙港等包裹、取出拆开，`obtained_via` 为 `stock_ticker`，背包多 20 个。
2. 网络锁上、角色不在能用的人里 → 这个来源不用，写明"网络锁着"；把库存管理员请走 → 写明旁边没有管理员。
3. 青蛙港没写地址 → 写明附近没有取货口。
4. 把链条拆断再要 → 等到上限，写明下了几件、到了几件，不重下单。
