## 2 主流程

按代码调用链写（v0 的 LLM 宿主通过 `plan`/`execute` 提交 Goal，由 `IntentTask` 调 `GeneralAbilityAdapter.adapt`）：

**翻译层（客户端，逐能力）**

1. `adapt`（GeneralAbilityAdapter.java:101）先拒绝直接指定执行细节字段（`EXECUTION_FIELDS`：button、slot、entity_id 等），命中即返回决策，不进任何能力。
2. `useItem`（:137）→ 校验 `item_id` 与背包持货 → 蓄力时长 >1200 刻的物品提问换专门活动 → 坐标目标走 `interactExactBlock`（一次定点）；`count>1` 或给 `ingredient_item_id` 走 `UseItemBatchTaskRecord`（批次）；否则 `InteractAtTaskRecord.useHeldItemOnly`（沿当前视线持用）。
3. `interact`（:636，`maicraft:interact` 与 `maicraft:use_container` 共用，`containerOnly` 区分）→ `purpose=attack/break` 指回战斗/采矿 → 实体筛选分支编译成 Tool `interact_entity` → 方块分支：精确坐标走 `interactExactBlock`，非坐标走 `interactBlock`（`TargetIndex` 已加载索引查询，默认 radius 64、最多 8 个候选）→ `compileBlockInteraction`（:929）编译 Tool `interact_at` 参数（`required_block_id`、`empty_hand`、`expected_effect=ignite`、`observe_menu`、`approach=true`）。锄地（`purpose=till`）无道具时由 `WorkToolPreparation` 找锄并串一条 `acquire_items`。
4. `manageContainer`（:278）→ 校验 operation、物品选择器、count/target_count 互斥、容器选择器 → 编译 Tool `manage_container` 参数。
5. Tool 通道：`SemanticContainerTool.onGameCall` 把参数转 `SemanticContainerTaskRecord`；`InteractAtTool`/`InteractEntityTool` 把内部工具参数转对应任务单。

**定点交互执行（InteractAtCompanionTask，继承 GoToThenDoTask）**

1. 前置：指定物品必须在背包（NO_MATERIAL）；空桶面对流水 → 出手前 `not_a_source_block` 失败。
2. `buildNav`：`FirstPersonInteractionTargeting.visibleInteractionStances` 生成能看见目标的候选站位（点火时"能成门"的站位排前），走到"身体站稳且从眼位真能看见目标"。
3. 导航失败：站位无效（STANCE_DUD）排除该脚位重建（<4 次）；允许改地形时失败后转开路重试。
4. `act`：写字前按原版 Done 退出遗留编辑屏 → 空手准备（快捷栏空格或机器停车流程）→ 选物（`FirstPersonActionGate` 原生交换 + `CarriedItemVariants` 组件身份核对）→ 在目标可见轮廓上挑瞄准点 → 等真实镜头收敛（`ActualViewConvergenceGate`）→ 原生射线核对命中（`blockedByWorld` 判遮挡，命中者写进失败原文）→ 冻结提交快照 `submissionFacts` → 提交 `Interaction`（一次点击 / 固定时长按住 / 持续按住）。
5. 确认：交互对象逐刻推进；`DONE` 后按请求分支结算——开菜单观察（最多 40 刻，不重放点击）、告示牌写字（等编辑屏出现 60 刻 → 屏幕事件填字 → 等告示牌真实文字逐行一致 60 刻）、点火对账（观察落火格 20 刻，区分火/传送门/熄灭并附门框审计）、产物核对（`expectedOutputItem` 库存增加，等 40 刻，不重复使用）。
6. 遮挡或台面够不着时 `retryFromDifferentStance` 自动换站位一次（`forcingNewStance` 由 act 自驱导航）。
7. 回执：`changes` 对账、`target_observation`、`interaction_approach`、UNCERTAIN 时附 `post_expiry_facts`、`menu_open_verified`、`sign_write`、点火时间线等。

**实体交互执行（InteractEntityCompanionTask）**：解析实体（不在/不活/不可点击即失败）→ 导航跟随到 3 格内且视线通 → 空手准备（开菜单时）→ 瞄准并等准星实际命中该实体（≤80 刻，超时 OCCLUDED）→ 提交左/右键（羊属性不符不点；剪毛后只结算一次回执）→ 目标消失按是否已出手分别报告。

**批量持用（UseItemBatchCompanionTask）**：循环"备副手原料 → 备主手工具 → 一次原生持用（复用 InteractAt 的持用分支）→ 只认子回执里的正库存增量"直到新增产物达到 count；任何一步失败或被停止即锁死整批，报告已完成/剩余。

**容器存取（SemanticContainerCompanionTask，SURVEY→OPEN→WAIT_MENU→PLAN→TRANSFER→CLEANUP）**

1. SURVEY：按精确坐标 / 地标中心 / 玩家脚边，在已加载区块里按 `radius` 扫容器方块实体；排除受保护地标 12 格内与受保护自定义名字；`unique` 要求唯一候选，否则 `ambiguous_container`；排序为名字匹配 > 距离 > 方块 id > 位置；6 格盒内有别的活玩家 → `other_player_near_container`。
2. OPEN：复核目标身份（还在、还是 Container、类型没变、`getMenuProvider` 非 null——"上方被堵"在这里判）；锁着的箱子 `container_locked`；已由原生工具开过的同箱直接接续菜单；否则发一条空手右键子任务（`InteractAtTaskRecord.withEmptyHand().withApproach().withMenuObservation()`）。
3. WAIT_MENU：最多 80 刻等"新菜单对象可见且光标为空"；光标有物 → `menu_cursor_not_empty`；菜单被换 → `container_menu_lost`。
4. PLAN：`classify` 分出玩家 36 槽侧与容器侧（原版箱/潜影盒/漏斗/发射器/熔炉有已知规则，其他 mod 菜单需"普通槽 + 单一容器"可证明，AE2 拒绝）→ 按 operation 定方向与数量（count 为增量、target_count 为终态、都不给搬来源侧全部）→ `buildPlan` 在菜单副本上把剩余量完整分配到目标槽（先并同类堆再占空格，服从 `mayPlace` 与槽容量），装不下在任何点击前失败。
5. TRANSFER：每笔前核对菜单身份与内容指纹、光标为空、旁人条件，外部改动时对未提交部分重新规划 → 交给 `ContainerTransferCompanionTask`（整堆走快速移动，尾数由 `ContainerSplitPlanner` 拆半堆/逐件）→ `verifyTransfer` 核对玩家侧精确增减 + 容器侧反向增减（机器存入按"源格扣减 + 光标空"结算），一致才累计 `movedCount` 并按进度续时（每次 +120 秒）。
6. CLEANUP：交还原生返还的菜单余物后关页；失败时保留最早失败原因、保留已确认搬运量，附 `recoveryOptions`。

## 4 向 LLM 提问的出口（逐个列出问题和选项）

翻译层（`GeneralAbilityAdapter.decision`，问题 + 选项 + facts，选项通常为 retry / recover / replace_goal / skip / cancel 的子集）：

1. 参数里出现执行细节字段（button、slot_index、clicks、container_id 等）→ "这是执行细节，请描述语义目标"（retry/cancel）。
2. use_item 缺 item_id（retry/cancel）；物品不在背包（recover=先取物 / replace_goal / cancel）。
3. use_item 长蓄力物品 → "需要专门活动"（replace_goal/cancel）。
4. use_container 带 transfer/deposit/withdraw → 指回 manage_container（replace_goal/cancel）。
5. purpose=attack/break → 指回战斗/采矿（replace_goal/cancel）。
6. 实体与方块目标混用（retry/cancel）；use_container 指实体（replace_goal/cancel）。
7. 实体候选为空（recover=去加载 / replace_goal / cancel）；多候选无 nearest（retry=加 nearest 或缩条件 / cancel）。
8. 未注册的 entity_type_id / block_id / item_id / tag / container block_id（retry/cancel）。
9. 无目标可选："应该用哪个方块/实体/容器？"（retry/cancel）。
10. 地标解析失败："目标不是权威同维地点，拒绝在玩家附近替代搜索"（recover / replace_goal / cancel）。
11. 已加载区无匹配方块（recover / replace_goal / cancel）。
12. 多方块候选无 nearest（retry=selection=nearest / cancel）。
13. 精确坐标：异维度、未加载、目标已空、类型不符、空气无点火支撑（recover / replace_goal / cancel，facts 带requested vs observed）。
14. 写字：用于容器/实体/带道具、目标不是告示牌、text 缺失或超 4 行超长（retry/cancel）。
15. manage_container：operation 缺失、item_ids 非数组、未知物品、选择器二选一、count/target_count 冲突或越界、balance 缺 target_count、无容器选择器、selection 非法、protected_labels 非数组（均 retry/cancel）。

任务层（容器任务通过 `decision.required=true, reason_code, recovery_options` 在回执里给恢复建议，LLM 读后另发请求；其余任务以失败原文自带建议）：

16. ambiguous_container → retry with selection=nearest / 缩小 block_id 或 landmark / cancel。
17. other_player_near_container → 等稳定后重试 / 换箱 / cancel。
18. specialized_storage_required → 用专用存取能力 / 选普通箱 / cancel。
19. insufficient_source / source_slots_locked → 降数量或换源 / 先取物再重试 / cancel。
20. destination_full_or_locked → 腾容量或换箱 / 降数量 / cancel。
21. container_locked → 取得授权或钥匙 / 换箱 / cancel。
22. unsupported_modded_slots / unsupported_menu_layout → 用专用能力 / 换原版箱 / 手动搬运 / cancel。
23. 部分完成时 → 按已确认 moved_count 只请求余量，或用幂等的 target_count。
