## 2 真人怎么做

**看机器**：走到跟前看一眼：这是压机配置物台，上面的轴在转，带子往东送；戴上工程师护目镜看网络有多少应力、用了多少；看 ME 终端亮不亮、控制器闪不闪。看完能说出"这台机器由哪几块组成、缺什么、哪里和图纸不一样"。看不见的东西（箱子里的、机器内部的）要打开界面才知道。

**设计与建造**：先在脑子里（或者 Ponder 里）想清楚要放哪些方块、怎么连，再去建。建的时候和盖房子一样：清场、备料、逐格放；传送带这种东西要先放两头的轴，再用传送带把它们连起来；AE 部件是装在线缆上的；水和岩浆最后再倒。建完对着图纸看一遍，哪里不对改哪里，但"结构和图纸一样"不等于"机器能转"——还得接上动力、配好设置、投料试一次。

**接网络**：机器不转就看它有没有接到转的轴；没接就从最近的动力源拉一条轴或链条过来，接上看转不转、过载不过载。AE 部件装在没连到核心的线缆上就是没用的，要把线缆接回去，频道不够要加控制器或换粗线。

**配置**：Mekanism 机器拿配置器在面上点，点一次换一种模式，看面上的颜色变了没有；分拣机开界面加一条规则。

**用机器**：把料放进去（置物台顶面、盆里、输入箱），拉杆开机，等一会儿，看出口有没有东西，拿走。机器不出东西就看是不是没转、没料、过载，不会一直傻等。

**用别人的机器**：别人的机器一样能看；对方让用（LLM 点名）才投料、开关、拿产物、拆改；自家人（实例配置里信得过的玩家）的机器当自己的用，但拆改照样看那格是谁放的。

## 3 新逻辑

### 3.1 共同模型：机器、网络、档案

```text
机器方块      被某个机器类型（MachineType，由联动模组登记）认领的一格方块：压机、轴、ME 控制器……
              每格有角色：动力源 / 传动 / 加工 / 物流 / 存储 / 控制 / 线缆 / 网络核心
一台机器      一组相邻的机器方块，加上它们之间的容器与原版方块；边界由档案给（有档案时）
              或由"相邻且同属一个网络"的连通块给（没档案、现场看到时）；给 LLM 的观察编号是 m#
网络          把机器连在一起的东西：应力网络（Create）、ME 网络（AE2）、能量网络（FE）、
              流体与物品管网（Mekanism 管道）；每种网络由一个网络读取器回答"这格属于哪张网、那张网怎样"
端口          一台机器上和外界交换东西的面：输入 / 输出，介质（物品、流体、能量、动力、化学品、ME）
              由机器类型按方块与朝向给出，例如"压机的加工面在正下方两格内"、"Mekanism 机器的每一面按侧面配置"
档案          MachineArchive：名字、维度、锚点、整机蓝图（冻结的逐格目标 + 机器附加条目）、
              引用的设计编号、接过的网络、最近一次整机比对的时间与结论。按世界存在能力自己的文档里；
              世界记忆记一条"机器 X 在哪"让 observe(world_memory) 看得到
```

机器的身份靠档案名（LLM 起的名字，和地标一样）或观察编号；不再有"快照编号"这种临时票据：能力到现场看一眼就知道变没变，变了如实写进结果，不要求 LLM 先观察再拿着编号来。

### 3.2 蓝图：一种格式，建在建造的蓝图之上

v0 有三种输入（组件关系图、逐格蓝图、Ponder 结构地址），v1 只有一种：**机器蓝图 = 建造的逐格蓝图 + 四种机器附加条目**。

```text
MachineBlueprint
  cells[]          逐格目标 PlannedCell：offset、block、properties；就是建造规格的 Blueprint
                   省略的格子保留；写成 minecraft:air 的格子要清空；流体源格写成 minecraft:water / lava，
                   由施工引擎在实心格放完后收源格、倒桶（建造规格），机器不另做
  parts[]          部件条目 PartCell：offset、side、item     —— 装在宿主方块某一面上的部件（AE2 线缆上的终端、总线）
  installations[]  原生安装段 Installation：kind、cells     —— 只能用模组自己的方式成型的一组格子
                   （create:belt 两端轴之间的带段、create:chain_conveyor 两轮之间的连接）
  settings[]       安装后设置 Setting：offset、设置项         —— 放好之后要改的设置（Mekanism 侧面、分拣过滤、样板）
  processes[]      声明的工序（可选）：机器格 offset、配方或产物 —— 只给审阅用，不是施工目标
```

- 来源只有 LLM 自己写（含从 `lookup` 拿到的思索结构里抄方块集合：`blocks` 加到某一帧为止的改动）或引用已保存的设计编号 `design_id`（建造的 `DesignStore`）。不再有 `blueprint_uri`。
- 锚点来自 `target`（地标、观察编号、坐标、这里）；`offset` 相对锚点。档案里的机器以档案锚点为准，补丁的 `offset` 和原蓝图同一个原点。
- 校验在计划阶段一次报全：方块与物品存在、属性合法、同格不重复、部件面合法、安装段形状合法（直线、长度不超过模组配置）、设置项是该机器类型认的。超出预算（格数、半径）按建造规格的预算，机器不另设一套。

### 3.3 机器类型与网络读取器（spi，`ability.machine.spi`）

联动模组登记的是"这种机器"和"这种网络"，机器能力只认接口：

```text
MachineType（一种机器，例如 Create 压机、Mekanism 冶金灌注机、AE2 控制器；一个模组登记很多个）
  id、名字、模组
  covers(方块状态)            这格是不是这种机器
  role                        动力源 / 传动 / 加工 / 物流 / 存储 / 控制 / 线缆 / 网络核心
  ports(方块状态, 位置)       端口：面、介质、输入或输出；加工面在哪（压机下方、锯的前方……）
  state(位置)                 运行状态（只读客户端能看到的）：在转 / 停着 / 过载、转速、进度、台面上的东西、是否在线
  install(安装段或部件)       怎么用原生方式装：返回逐刻推进的动作（放两端轴后用传送带连；手持部件右键线缆面）
  installRules                安装段的形状规则（直线、最长几格——读模组配置）、部件能装在哪种宿主上
  settings(位置)              这台机器有哪些设置项、现在的值、怎么改（返回动作：手持配置器点面、开界面加规则）
  feed / take(位置, 物品)     往这台机器投料、从出口拿东西怎么做：置物台是手持右键顶面、盆是右键、带界面的走 M11
  （界面布局不在这里：联动入口直接向登记表登记 registry.menuLayout(入口, MenuLayoutProof)，
   登记过的界面，开箱取货、存东西、机器的界面操作都认得）
  部件的靠近与点击用部件框：InteractionTarget.ofBlockPart、Interactions.useBlockPart、ClientMenuOpening 收部件框

NetworkReader（一种网络：应力、ME、能量、流体管网、物品管网、化学品管网）
  kind                        网络种类与一句说明
  membership(位置)            这格属于哪张网（网络编号），不属于任何网给空
  summary(网络编号)           那张网怎样：应力网络给容量 / 当前应力 / 成员数 / 转速；ME 网络给控制器状态 / 频道模式与用量 /
                              能量是否在线 / 存储总量 / 合成 CPU；能量网络给存量与上限
  读数来源                    客户端能读的直接读（Create 把网络的应力容量、当前应力、成员数同步到每个成员的方块实体）；
                              只能在服务端读的（AE2 的 IGrid 服务）经服务端操作读（第 3.9 节）
```

两个接口都只用 Minecraft 与 Java 的类型；模组的类只出现在 NeoForge 模块的读写端。机器类型的 `install` / `feed` / `take` / `settings` 返回的是动作，要用进世界后才有的玩家行为（靠近、交互、保护、界面），所以联动登记表为它们加的槽（`machineType`、`networkReader`）和 `itemSource(module, services -> …)` 一样存的是建法，进世界时带着玩家行为建，不另造一套。这两个槽由实现会话在同一个提交里照现有样子加（出错撤回、停用包装），动手前先告诉审查会话。没装对应模组时，机器能力照常登记，只是认不出那个模组的机器：`machine_inspect` 报"这格是 create:mechanical_press，没有认得它的机器类型"，`machine_build` 照样能按蓝图放方块（放方块不需要认识它），`machine_run` / `machine_configure` 对认不出的机器以 UNSUPPORTED 结束并写明缺哪个联动。

### 3.4 `machine_inspect`（只读）

```text
1 定范围     target 是档案名 → 档案范围；是观察编号 m# → 那台机器的连通块；是 b# / 坐标 / 地标 / 这里 + radius → 那片地方
             只看已加载、角色看得见的格子（未加载的记 UNKNOWN，不按空气算）
2 认机器     范围内每格问遍机器类型：认领的归入机器，按相邻与同网络分成一台台，各给 m#
3 读状态     每台机器：组成（按角色分组的方块列表）、端口、运行状态（机器类型的 state）
             每张网络：读取器的 summary；客户端读不到的经服务端操作读，读不到就写"读不到：服务器没装 MaiCraft 的 AE2 读数"
4 比档案     有档案 → BlueprintCheck.compare(档案蓝图, 只读世界) + 机器附加条目各自的核对
             → 每格 MATCHES / WRONG_BLOCK / WRONG_STATE / MISSING / UNKNOWN，范围内未声明格有东西 → EXTRA（只作信息）；
               安装段与部件的格引擎标 CHECKED_BY_MACHINE，由机器按最终结构核对
             没档案 → 只给现状，不凭空生成参考设计
5 交付       结果细节（第 4 节），默认完整；数量很大按机器分组并给总数，不截断
```

看不见的东西（机器内部的槽、箱子里的）不在这里读：要看就 `use` 打开界面（M11 列出内容）。Create 的置物台、传送带、盆上的东西是画出来的，客户端能读，算看得见。

"结构和档案一致"不等于"能转"，结果里 `check` 与 `running` 分开给，说明文字固定写这一句。

### 3.5 `machine_review`（只读）

```text
1 校验       同 3.2，计划阶段一次报全（这是参数校验，不是审阅结论）
2 逐格       每格方块能不能放、属性合不合法；部件能不能装在那种宿主上；安装段形状
3 工序       processes 里每条：问 RecipeLookup.atWorkstation(这台机器) 有没有这道配方；配方要的输入从哪来（蓝图里有没有输入端）
4 动力       蓝图里每个动力消费者有没有通过传动连到蓝图里的动力源，或连到 target 附近现场已有的轴；
             估一下应力：消费者的应力影响之和与动力源容量之和（读 Create 的 BlockStressValues 与方块转速），只作估计
5 网络       ME 部件所在的线缆有没有连到蓝图或现场的控制器 / 网络；频道估计
6 材料       整份蓝图要哪些材料、身上有多少、缺多少（M4 只问价不动手）
7 交付       issues[]（每条：位置、是什么问题、建议）、materials、估计值；没有"通过 / 不通过"的结论
```

审阅永远不是开工的门：`machine_build` 不要求先审阅，审阅报了问题也照建。这是 AGENTS.md 的规矩（不预测设计会失败就提前拦着），审阅只是把 LLM 自己看不出来的事（应力够不够、带子超不超长、这台机器做不做得了这道配方）算出来给它看。

### 3.6 `machine_build`

```text
0 已满足     目标档案的整机比对全部 MATCHES（含附加条目）→ 完成，"开始时已和蓝图一致"
1 校验       同 3.2；operation=remove 时蓝图可省略（拆档案里的整台）
2 许可       LLM 点名的档案 / 观察编号视为对那台机器范围内格子的许可（M7 的规矩，点名即许可）；
             范围外、归属记录在别人名下的格子 → NEED_APPROVAL，写明哪些格；自家人放的方块也照归属看
3 绝对化     锚点 + offset → 绝对坐标；目标是已有档案 → 补丁：新声明的格覆盖同位旧目标，范围外旧目标保留
4 拆分       普通格与流体源格 → 建造的 ConstructionTask（替换档、许可、备料走 M4、清障、临时方块、
             流体在实心格放完后收源格再倒桶、逐格核对、取消时收回）
             安装段与部件的格 → 标 placedBy=MACHINE：引擎不放不清障，仍算进场地范围与保护；核对时出 CHECKED_BY_MACHINE
5 施工       ConstructionTask 先做普通格与流体（流体容器要封的口子，在蓝图里写成普通实心格即可）
             → 安装段：每段先核对它依赖的普通格已就位（两端的轴），再运行机器类型的 install 动作，按最终结构核对
             → 部件：宿主格已就位后，手持部件右键那一面，确认该面出现部件且物品少一（创造模式不少）
             → 设置：settings 逐条交给 machine_configure 的同一套动作（3.8），逐条读回核对
6 整机比对   补丁合并进档案（没档案就新建，名字用 name；没给名字按锚点起"机器@x,y,z"，不问）
             BlueprintCheck.compare(档案蓝图, 世界, 由机器核对的格) 整台：普通格出 MATCHES 这组结论，
             安装段与部件的格由机器按最终结构核对；分几刻做完，结果完整进 details.check
7 结算       动作成没成（changes / unconfirmed）、结构对不对（check）、机器能不能转（不判，留给 machine_run）三件事分开
             施工子任务失败 → 按它的问题结束，已放的不回滚；比对有 UNKNOWN → check.complete=false，不给"整机一致"的结论
```

- 每台机器最多几个链条输送机：按实例配置（默认 1，待拍板 C1），跨任务累计算档案里已有的；纯拆除不受限。
- 取消或超时：施工子任务自己收回临时方块（建造规格，184）；已放的机器方块留下；档案按"已完成的格"更新，不记成已建成。
- 拆整台（`operation=remove`）：按档案范围逐格拆（扳手或正确工具，由机器类型给出拆法——Create 方块用扳手右键整块掉落），掉落物捡回；拆完档案标为已拆除（保留蓝图，LLM 可以再建）。
- 别人的机器：点名即许可（M7）；自己挑到的、没点名的别人的机器不动，NEED_APPROVAL 列出格子。自家人的机器建、拆、接线路照样按归属看，没点名也要问。

### 3.7 `machine_connect`

```text
1 认两端     target 是要接的机器（档案 / m# / b#）；source 是接到哪（另一台机器、一根轴、一段线缆、一张网络里的任一格；
             省略时在 radius 内找最近的、在转的 / 在线的那张网络）；network 指明是哪种网络
2 已满足     目标已经在 source 所在的网络里（membership 相同）且（动力）转速不为零 → 完成，"已经接着"，不再放一根轴
3 规划       按网络种类规划一条线：
               应力  轴、齿轮箱、链式传动箱、链条输送机（按材料、转向、长度、现场障碍选，v0 的经济传动规划按本规格重写）
               能量  Mekanism 通用电缆 / 能量导管，端点面必须是能量接口
               ME    线缆（同色或透明），到最近的网络格；频道估计超了就报告"要加控制器或粗线"，照接
               流体 / 物品  管道，端点面按侧面配置
             线路上每格过许可；穿过别人的方块 → NEED_APPROVAL
4 施工       线路编成一份机器蓝图（cells + installations），交给 3.6 的流程；缺料走 M4
5 核对       两端 membership 相同；应力网络还要目标转速不为零、不过载；能量网络目标面确为能量输入
             接上了但过载 / 转速为零 → done 但 details.joined=true、running=false，写清读数；不判设计对错
```

线路的具体选法（优先直线轴、换向用齿轮箱、跨距用链条、避开别人的格子）是机器自己的判断类 `RoutePlanner`，纯函数，离线测试。

### 3.8 `machine_configure`

```text
1 认机器     target 是一格机器方块（b# / 坐标 / 档案 + offset）；机器类型给出它的设置项与当前值
2 校验       settings 的键必须是这台机器认的设置项（计划阶段一次报全）；值的形状由机器类型给
3 已满足     每项现在就是要的值 → 完成
4 动手       逐项：机器类型的 settings 动作（手持配置器对着那一面点、每点一次读回模式；开界面加规则、保存前核对；
             把样板放进样板供应器的槽）；缺配置器 → M4 拿一个；要开界面走 M11
5 核对       每项改完读回，读回不等于要的值 → 继续点（配置器是循环切换）直到相等或转满一圈；转满一圈还不对 → NOT_POSSIBLE_HERE
6 结算       changes 用 BLOCK_CHANGED，note 写"北面：输入 → 输出"
```

别人的机器：点名即许可（同 `use`）；自家人（实例配置 `trustedPlayers` 里的玩家）的机器视同自己的，不用点名；归属记录在别人名下且 LLM 没点名 → NEED_APPROVAL。

### 3.9 `machine_run`

```text
0 认机器     target（档案 / m# / b#）→ 一台机器；机器类型认不出 → UNSUPPORTED
1 选工序     item（要做的东西）→ RecipeLookup.making(item) 与 atWorkstation(这台机器) 取交集；做不了 → NOT_POSSIBLE_HERE，
             写清这台机器能做什么；转速门槛这类配方里没有的要求由机器类型给
             （没给 item：只开机，不投料）
2 备料       配方输入 × 批次（count 件产物要几批）→ M4 拿到（许可内，预算内）；拿不齐 → NEED_ITEM
3 投料       机器类型的 feed：置物台 / 盆是手持右键；带界面的经 M11 放进输入槽；输入箱经 deposit 的流程
4 开机       有开关（拉杆、按钮、机器自带的）且现在是关 → `use` 的动作拨一次；已经开着不拨（M137）
             动力网络转速为零 → 不预判，先投料开机，等不到产物时把"转速 0 / 过载"写进事实
5 等产物     出口（机器类型的 take 位置：置物台台面、出口箱、传送带末端的容器）里目标物品的增长是进展（ProgressTracker）
             记开始时出口里已有的数量，只算这次新增；max_seconds 到或长时间无进展 → partial，写清已出多少、机器读数
6 收产物     collect=true（默认）→ 从出口拿进背包（M11 / gather 捡台面上的）；false → 留在出口，结果写在哪
             没加工完的原料留在机器里不收回（下一次 machine_run 接着用），结果写明留了什么
7 结算       changes：ITEM_CONSUMED（投料）、ITEM_GAINED（收到）；details 第 4 节
```

别人的机器：投料、开关、拿产物点名即可；自家人的机器不用点名；没点名的别人的机器 → NEED_APPROVAL。

`machine_run` 不是生产线编排：一条线上有几台机器就是几次 `machine_run`，或者 LLM 用 `sequence`。它只保证"这台机器这次做了几件"。

此刻能不能打断：投料、开机的交互在等确认时 UNSAFE_TO_STOP；等产物时 BETWEEN_ACTIONS（可以插生存需求，回来接着等）。

### 3.10 服务端模组读数

`server` 不能依赖 `compat`，所以服务端的接法另起一套平行结构，规则和客户端一样：

```text
server.compat                      ServerCompatModule（服务端联动入口，call() 把 LinkageError 转成 ModApiMismatch 并停用）
                                   ServerCompatRegistry（服务端登记表：收各入口登记的只读操作，交给 ServerOperationRegistry）
server.compat.<模组>               这个模组在服务端要读什么的接缝接口（只用 Minecraft 与 Java 的类型）+ 联动入口 + 操作实现
neoforge.compat.<模组>             服务端读写端，直接调模组的类；和客户端读写端并排
ServerCompatCatalog（NeoForge）    每行一个支持的模组：模组 ID、版本范围、怎么创建服务端联动入口（行的类型由服务端自己定，实现时定）
```

- 操作只读、按请求回答：`ae2.network`（某格所在 ME 网络的摘要）、`create.network`（应力网络摘要，客户端读不到时的后备）、`mekanism.machine`（机器当前配方、进度、侧面配置的权威值）。不替角色动手、不提供透视（只回答网络级的汇总，不列箱子里的东西）。
- 客户端的 `NetworkReader` 实现里，先用客户端读数；读不到的经 `game.serverlink` 发请求；握手时没协商到这个操作（服务器没装对应模组、所有者策略关了）→ summary 回答"读不到"并写原因。
- 服务器所有者策略：`ServerOperationRegistry.setPolicy` 照旧；机器读数都是不改世界的操作。
- `ServerCompatModule` 的停用包装和客户端的 `CompatModule` 会重复几十行：分层不许共用，接受重复，两边类注释互相指一下。

### 3.11 组合的模型

- `machine_inspect`：M9（档案与世界记忆）、M12（看得见才算）。
- `machine_review`：M4（只问价）、知识检索。
- `machine_build`：建造的 `ConstructionTask`（M2 / M3 / M4 / M5 / M7 / M8 在它里面）、M11（设置要开界面时）、M9。
- `machine_connect`：同上 + `RoutePlanner`。
- `machine_configure`：M2、M3、M4（拿配置器）、M7、M11。
- `machine_run`：M2、M3、M4、M5、M7、M8、M11，以及 `use` 的拉杆动作。

本能力特有的只有：机器与网络的认领与分组（`MachineGrouping`）、档案与补丁合并（`MachineArchive`）、机器附加条目的施工顺序（`MachineBuildTask` 的阶段）、线路规划（`RoutePlanner`）、工序选择与投料收料（`MachineRunTask`）。

## 4 能力说明

共同的事：`target` 接受 `seen`（m#、b#）、`landmark`（档案名或地标）、`position`、`here`；`previous` 等内核记下各步骤确认过的位置再接。许可按 M7；机器相关的许可就是 `change_blocks`（建、改、拆、接线路）与点名（用别人的）。

### `machine_inspect`

| 参数 | 必填 | 说明 |
| --- | :---: | --- |
| `radius` | | 没给档案时看多大范围，单位格，默认 16 |

结果细节：`machines[]`（每台：`id` m#、`name` 档案名、`types`（按角色分组的方块）、`ports`、`running`（机器类型给的运行状态）、`networks[]`（种类、网络编号、summary）、`check`（有档案时：`complete`、各格状态计数与明细、`extra`））；`unrecognized[]`（看着像机器但没有机器类型认领的格子，写明缺哪个联动）。

### `machine_review`

| 参数 | 必填 | 说明 |
| --- | :---: | --- |
| `blueprint` | ✅ | 机器蓝图（3.2）；和 `design_id` 二选一 |
| `design_id` | | 已保存的设计编号 |

结果细节：`issues[]`（`offset`、`what`、`suggestion`）、`materials[]`（物品、需要、身上有、缺）、`power`（消费应力估计、来源容量估计）、`channels`（估计）。

### `machine_build`

| 参数 | 必填 | 说明 |
| --- | :---: | --- |
| `blueprint` | | 机器蓝图；和 `design_id` 二选一；`operation=remove` 时省略 |
| `design_id` | | 已保存的设计编号 |
| `name` | | 新机器的档案名；目标是已有档案时不用给 |
| `operation` | | `build`（默认）/ `remove`（拆档案里的整台） |

结果细节：`archive`（档案名、锚点）、`check`（整机比对，同 inspect）、`cells`（每格结局，来自 ConstructionTask）、`installations[]`（每段：装成没有、核对结果）、`parts[]`、`settings[]`（每项：读回的值）。

### `machine_connect`

| 参数 | 必填 | 说明 |
| --- | :---: | --- |
| `network` | ✅ | 接哪种网络：`kinetic` 应力 / `energy` 能量 / `me` ME 网络 / `fluid` 流体管 / `item` 物品管（可选值由已登记的网络读取器决定，装了才出现） |
| `source` | | 接到哪：目标对象的写法（档案名、m#、b#、坐标）；不给就在 `radius` 内找最近的在转 / 在线的那张网 |
| `radius` | | 找来源的范围，单位格，默认 32 |

结果细节：`route[]`（放了什么、在哪）、`joined`（两端是否同一张网）、`running`（动力：转速、过载；能量：是否供电）、`network`（接上的那张网的 summary）。

### `machine_configure`

| 参数 | 必填 | 说明 |
| --- | :---: | --- |
| `settings` | ✅ | 要改成什么：键是这台机器认的设置项（在 `lookup` 的能力说明里按已装模组列出，例如 Mekanism 的 `side.north = "output:items"`、分拣机的 `filter.add = {item, exact}`） |

结果细节：`applied[]`（每项：改前、改后读回的值）。

### `machine_run`

| 参数 | 必填 | 说明 |
| --- | :---: | --- |
| `item` | | 要做出什么；不给就只开机 |
| `count` | | 要做几件，默认 1 |
| `collect` | | 做完要不要拿回背包，默认 `true` |
| `max_seconds` | | 最多等多久，默认 300 |

结果细节：`recipe`（用的配方、批次）、`fed[]`（投了什么）、`produced`（出口新增多少）、`left_in_machine[]`（留在机器里的）、`machine`（结束时的运行状态与网络读数）。

能力说明（写给 LLM 的那一段）每个能力各一篇；里面不塞模组行为事实（哪台机器怎么运转去 `lookup`），只写怎么用、什么算完成、不做什么。

## 9 验收

**离线场景测试**（判断类用替身，任务用动作替身，不用 `Unsafe`）：

1. 参数校验：蓝图未知字段、同格重复、部件面非法、安装段不是直线或超长、设置项不认 → 一次报全，不进游戏。
2. `MachineGrouping`：相邻且同网的机器方块分成一台；两张网各一台；没有机器类型认领的格进 `unrecognized`。
3. `MachineArchive`：补丁覆盖同位旧目标、范围外保留；存不进只记问题；拆除后标记保留蓝图。
4. 整机比对：MATCHES / WRONG_BLOCK / WRONG_STATE / MISSING / UNKNOWN / EXTRA 各一例；有 UNKNOWN 时 `complete=false`；安装段按最终结构核对，不拿准备轴比带子。
5. `machine_build` 的阶段顺序：普通格与流体（施工子任务）→ 安装段（依赖未就位先等）→ 部件 → 设置；安装段与部件的格标 placedBy=MACHINE，引擎不放、核对出 CHECKED_BY_MACHINE；施工子任务失败不回滚已放的；取消经子任务收回临时方块。
6. `RoutePlanner`：直线优先、换向用齿轮箱、跨距用链条；穿过别人的格子 → NEED_APPROVAL；已在同一张网 → 已满足。
7. `machine_connect` 核对：接上但过载 → done、`running=false`、读数在结果里。
8. `machine_configure`：循环切换直到相等；转满一圈不对 → NOT_POSSIBLE_HERE；每项读回。
9. `machine_run`：配方由知识检索替身给；备料走 M4 替身；开关已开不拨；出口只算新增；无进展到上限 → partial 并附机器读数；`collect=false` 留在出口。
10. 网络读取器：客户端能读的直接读；服务端操作没协商到 → "读不到"并带原因；`LinkageError` → 停用 → 后续回答不支持。
11. 许可：别人的机器点名即许可；自家人的机器投料、开关、改设置不用点名，建拆接线按归属；没点名的别人的机器 → NEED_APPROVAL 列出格子。

**实机验收**（追加到里程碑三的清单）：

1. 在空地建"水车 → 轴 → 压机 + 置物台"：建成后 `machine_inspect` 的 `check` 全 MATCHES，`running` 显示压机在转；`machine_run` 做 4 块铁板，产物进背包。
2. （024）修改一台机器：拆一格隔板让水流进岩浆格 → 整机比对把黑曜石如实报 WRONG_BLOCK 或 EXTRA，施工本身 done。
3. （184）建到一半取消 → 脚手架全部收回，已放的机器方块留下，档案只记已完成的格。
4. （186）悬空贴附的目标格 → 一格一格试站位，到得了的照放，到不了的单独报。
5. （023）在自己刚建的机器上接链条 → 不被任何白名单挡。
6. `machine_connect` 把一台没动力的锯接到 20 格外在转的轴 → 线路建成、两端同网、锯在转；故意超载时结果 `running=false` 附读数。
7. AE2：把终端装到一根没连核心的线缆上 → `machine_inspect` 报这张网没有控制器 / 频道不够；`machine_connect network=me` 接回核心后终端在线。
8. Mekanism：`machine_configure` 把冶金灌注机北面设为物品输出 → 读回一致；配置器不在身上时先去拿。
9. 别人的机器：不点名时 `machine_run` 问 NEED_APPROVAL；点名后照投料、开机、拿产物、拆改；自家人的机器不点名也能用，拆它要点名。
10. （033 / 066）LLM 不读能力说明也能靠 `lookup` 查到"压机下面要放置物台"。
11. 服务器没装 AE2 读数时 `machine_inspect` 的 ME 网络摘要写"读不到：…"，其余照常。
12. 重启后恢复一个暂停的 `machine_build` → 重看现场，从未完成的格接着建，不重放已确认的安装。

## 10 待两位决定

| # | 问题 | 建议 |
| --- | --- | --- |
| 1 | 能力拆成六个（inspect / review / build / connect / configure / run），还是按 v0 的五个 | 六个：每个一句话说得清、结果不重叠；build 吞掉 modify（补丁合并进档案），operate 拆成 configure 与 run，其余交给 use / deposit / obtain |

| 3 | 后台观察生产（v0 的 watch_production）要不要保留 | 不保留：角色投料开机后可以去做别的，之后 LLM 再 `machine_inspect` 或 `obtain`；省掉一套服务端登记与事件 |
| 4 | `machine_run` 要不要做多台机器的生产线编排 | 不做：一台机器一次；多台用 `sequence`。编排是 v0 最重、最难验的部分，先把单机跑通 |
| 5 | 每台机器的链条输送机上限（C1） | 实例配置，默认 1 |
| 6 | `machine_connect` 的 `source` 用目标对象的写法放在参数里 | 用：和 `target` 同一种写法，LLM 不用学第二种；`ParamNames` 登记 `source` |
| 7 | 机器档案存在哪 | 能力自己的文档（`kernel.storage`），按世界；世界记忆只记一条 `MACHINE`（在哪、叫什么）供 observe |
| 8 | 没给 `name` 的新机器怎么起档案名 | 按锚点起"机器@x,y,z"，不问 LLM；LLM 之后可以用 `remember` 改名吗——不行，档案名不是地标。建议：`machine_build` 的 `name` 可以对已有档案改名 |
| 9 | 审阅里的应力与频道估计要不要做 | 做，只作估计写进结果，不拦建造；没有读到配置时写"估不出" |
| 10 | 服务端读数的接法（3.10） | 按 3.10：接缝放 `server.compat.<模组>`，平行的服务端联动入口与登记表，分层规则不改 |
| 11 | 别人的机器怎么算许可 | 照 M7：点名即许可，建、改、拆、接线路也一样，范围只到那台机器的档案格；自家人（实例配置 `trustedPlayers`）的机器投料、开关、拿产物、改设置不用点名，建、拆、接线路照样按归属看。若两位想让机器施工比 M7 更严（点名之外还要 `change_blocks=any`），改这一项并写明理由 |
| 12 | 蓝图里 `processes`（声明工序）要不要保留 | 保留但只给审阅用；不写也能建 |

**本规格新起的名字**（批准后补进 09 与 `ParamNames`）：能力 `machine_inspect` / `machine_review` / `machine_build` / `machine_connect` / `machine_configure` / `machine_run`；观察编号前缀 `m#`；`MachineBlueprint`、`PartCell`、`Installation`、`Setting`；`MachineType`、`NetworkReader`（`ability.machine.spi`）；`MachineGrouping`、`MachineArchive`、`MachineArchives`、`RoutePlanner`、`MachineBuildTask`、`MachineRunTask`；`server.compat`、`ServerCompatModule`、`ServerCompatRegistry`，操作 `ae2.network` / `create.network` / `mekanism.machine`；参数 `blueprint`、`design_id`、`settings`、`network`、`source`、`collect`；记忆种类 `MACHINE`。
