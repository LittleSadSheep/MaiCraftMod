# 探索与寻找 旧逻辑清单（v0 dev 提交 aa97940c9）

术语说明：v0 把公开能力叫「语义能力」，把一次能力调用产生的执行单元叫「任务单」，把任务完成后的结构化返回叫「回执」；「航点」「前沿腿」「换锚」指探索任务内部自选的中途移动目标、逐段推进的一段行程、以及小半径更换出发位置。下文直接使用这些原叫法。

## 1 范围

能力：`maicraft:explore`（有界跑图与群系/海岸发现，经适配层分发到内部工具 `explore`）、`maicraft:find_block`（已加载区块内可见方块证据只读扫描，内部工具 `find_block`）、`maicraft:find_entity`（有界第一人称实体证据搜索，内部工具 `find_entity`）。三者的共同底座是扫描几何（环螺旋、分段游标）、视线闸与最近写入预核查。`maicraft:find_structure` 的结构搜索任务在「出行」清单已记录，本文只记它借用的共享底座与事故交点；`locate_biome` 是独立的定向定位能力，不在本文。走行本身归「出行」清单；找到之后的挖取、攻击、交互归各自领域。

## 2 主流程

1. **`maicraft:explore` 入口**：`AbilityAdapter.adapt`（86 行）→ `ExplorationIntent.adapt`。先裁决参数：不接受已定位目标；`biome_id`/`biome_tag`/`structure_id`/`semantic_target` 最多给一个；`structure_id` 整单转投 `find_structure` 适配入口；`reach_structure`/`allow_rare_consumables` 只跟结构；未定位探索只认 auto/ground 交通方式；`max_distance` 夹取语义在公开层是硬校验（64..2048 之外拒绝）。规划期 `SemanticGoalContract` 还会先跑一遍兴趣白名单。之后组装内部工具 `explore` 的参数（target、方向扇区、interests）。
2. **`explore` 工具**（`SemanticExploreTool` → `SemanticExploreApi.newRecord`）→ 建 `SemanticExploreTaskRecord`：`coast` 改写为 `minecraft:beach`；jetpack/elevator 方式在构造器再拦一次；直接入口绕过计划校验的兴趣值按同一白名单再核；初始期限 = 60 秒 + 距离×12 刻，夹在 3–20 分钟。航点上限由半径推出（64 格一环，环数平方×4，至少 8），注释说明覆盖范围由目标区域决定而非尝试次数上限。
3. **`SemanticExploreCompanionTask.onStart`**：记录出发点与出发朝向，扇区在此刻固定方位（forward/backward/left/right 按当时视角换算）；建跑图记忆（绑定当前世界身份）与穿水探针；按当前维度可解析的结构证据画像建 sighting 扫描器。目标解析失败（客户端注册表里没有该群系/标签）→ `UNSUPPORTED` 失败并提示用 perceive 查可用清单。
4. **观察阶段（OBSERVE）**：以当前位置为圆心，对半径 112 格内每 4 格一列的圆形网格按由近到远排序逐列抽样，每刻预算 192 列；每列先记沿途群系与地形要素（熔岩湖），再沿高度 32 格一步自上而下找目标群系的可站/可游样本。列抽样没跑完时每刻给任务续期，不烧语义期限；sighting 聚类轮未结算时驻留最多 400 刻再出发。
5. **目标候选**：扇区外或视线不可见的证据格不当场出发；可见且在扇区内的候选 → 记忆落账 → 起一段精确移动子任务（`MoveToCompanionTask`，期限 90 秒租约）→ 到达后核实脚下群系与扇区，核实通过交付 `verified_position`；核实不过把候选格记入拒绝集、记一条路段失败，回到观察。
6. **无候选或候选走失败** → 起航点航段：有方向时 `ExplorationFrontiers.next` 在扇区内 17 条射线 × 80→16 格距离打分选已加载新落点（穿水候选整体让位，全穿水仍选最优；16 格内已试过的邻域不再选）；无方向时方形螺旋外扩，沿途截取最远 80 格的已加载路段（优先不穿水）。航段失败按 `FrontierLegBreaker` 升级：最近 5 段失败满 4 次先垂直方位换锚（±90°、约 32 格、至多 2 次），再顺时针 45° 轮换扇区（至多 7 次），耗尽后 `NO_PATH` 受阻，失败说明逐项列出换锚/轮换历史并建议远距换区。
7. **行进涉水守卫**：每刻检查身体是否在水中；连续滞水 600 刻，或 100 刻内不再逼近当前段目标，即放弃该段换向（与结构搜索共用 `WaterCrossingProbe.waterLegExpired` 的同一组阈值），回执注明「涉水楔死，探索改向而非原地漂浮」。
8. **跑图收尾**：survey（无预设目标）身体进入 `max_distance - 到达容差`（容差 = min(8, 半径/8)）即 `radius_reached` 成功收尾，取消在途子任务；越过 `max_distance + 8` 硬边界即越界截停失败（`radius_bound_exit`，不冒用无路）。航点预算耗尽时 survey 已到过航点则按 `reachable_frontiers_exhausted` 成功，否则失败。全部结束回执交付观察统计、探索记忆、未加载边界样本与建议。
9. **顺带兴趣**：`interests` 声明的目标（lava_pool 或有证据画像的结构 id）出现新记录时置位待询问并冻结推进（期限逐刻续期）；语义层（`IntentTask.relayExploreInterestDecision`）把发现拉起 `continue/stop` 决策；同一 finding 只问一次，答复 continue 恢复推进，stop 按成功收尾但保留发现、明示主目标未核实。
10. **`maicraft:find_block` 入口**：`GeneralAbilityAdapter.findBlock` 把 `block_ids` 数组与单个 `block_id` 合并去重；未注册名集中退回修正（决策 retry/cancel）；`purpose=portal_casting` 时选择器为空自动补岩浆、给了非岩浆则退回。→ `SemanticBlockSearchTaskRecord`：至少一种目标、至多 32 种、count 夹取 1..32、距离夹取 4..128；浇筑用途只接受岩浆（构造器抛异常）。
11. **`SemanticBlockSearchCompanionTask`**：不移动身体。开扫先取最近写入快照（每刻至多核查 8 个）保证刚落格的方块先于数量收束被核查；随后 `LoadedBlockScan` 沿环螺旋列序逐段推进（每刻 4096 格且 2ms 墙钟封顶；调色板不含目标的段整段跳过；卸载段跳过不回头），命中格先复核实际状态、再过视线闸；含岩浆且是浇筑用途时扫完整个范围后分刻做连通池分析（浇筑起始行 + 源块余量）。数量达标即成功（浇筑用途需池分析完成）；扫完仍不足按四种失败码区分「有一个但不够 / 全无 / 池不合格 / 池不够」。命中格写入共享观察记忆（挖矿公平闸的「已观察」半边），最近命中坐标与 3D 距离进回执并附下一步指路话术。
12. **`maicraft:find_entity` 入口**：`GeneralAbilityAdapter.findEntity` 合并 `entity_type_ids`/`entity_type_id`/目标标签，未注册名退回修正；关系取参数或目标描述，默认 any，非法值退回；羊特征（毛色/幼年/剪毛）接单前校验。→ `GenericEntitySearchTaskRecord`：1..32 种注册类型、count 与距离夹取、内部可附排除身份与伤害意图标志。
13. **`GenericEntitySearchCompanionTask`**：观察阶段对身边 112 格已加载实体盒扫描：类型、范围、内部排除、视线闸、关系、羊特征逐层过滤；多部件实体（末影龙）折叠到逻辑主体；伤害意图下不可攻击者记入受保护计数。数量达标即成功（行进中达标会立刻取消当前路段，不等走完）；不足则选下一条前沿腿：目标类型全部是地面生成时按 16 方向射线采样干地落点（开放水域不作终点，完整观察整段水域且对岸有同等长度干地才允许跨水终点；身处水中先找最近干岸返回，返岸不受新颖度约束），否则地形中性螺旋外扩；越界（+8 容差）截停失败。航点预算耗尽或扫不出新前沿按六种失败码如实区分（部分证据 / 只有受保护证据（需决策）/ 无干地采样证据 / 前沿全部走不到（无路）/ 全无证据）。

## 4 向 LLM 提问的出口（逐个列出问题和选项）

- **find_entity 类型不可用**（`GeneralAbilityAdapter.findEntity` 422–455 行）：`find_entity received unknown or invalid namespaced entity types: <列表>`，选项 retry（只用注册类型重试）/ cancel。
- **find_entity 缺类型**（449–455 行）：`find_entity needs one or more semantic entity_type_ids; runtime IDs and coordinates are not accepted.`，选项 retry / cancel。
- **find_entity 关系未知**（458–464 行）：`Unknown entity relationship '<值>'`，选项 retry（wild/hostile/unowned/any 之一）/ cancel。
- **find_block 方块 id 不可用**（`findBlock` 495–506 行）：列出非法项，选项 retry / cancel。
- **find_block 缺选择器**（508–514 行）：retry（给语义 block_ids）/ cancel。
- **find_block 浇筑用途给了非岩浆**（514–518 行）：`portal_casting searches minecraft:lava only.`，选项 retry（改用岩浆或省略 block_ids）。
- **explore 顺带兴趣决策**（`IntentTask.exploreInterestDecision`）：`decision_kind=explore_interest`，问题陈述新发现的目标 id、方位、距离与坐标，说明发现已存入探索记忆并带 `exploration:` 标签；选项 continue（继续探索，同一发现不再问）/ stop（立即收尾，发现保留、主目标标记未核实）。中继纯函数（`exploreInterestRelayAction`）区分放行、原地等答复与发起新决策，防止答复消费前重提。
- **find_entity 只见受保护证据**（回执 `requires_decision=true`，`only_protected_or_ambiguous_entity_evidence`）：不是模态决策窗口，而是回执级要求叙述——建议换明确无主的群体、不得用运行时 id 削弱保护。
- 其余参数问题（explore 的目标互斥、交通方式、范围越界、兴趣非法）一律规划期直接拒绝并附合法值清单，不产生任务、不开提问窗口。

## 10 v0 直播中在这个领域出过的问题（来自 v0 维护记录）

摘自 v0 维护记录归档（编号 + 一句话事实/结论）：

- **040**：find_block 命中坐标没有交接给挖取链路（后来回执带 `nearest_match_position` 与指路话术）。
- **062**：末影龙实体扫描按 9 个碰撞部件返回 9 条，无血量字段，调用方误判龙已死提前宣布击杀（→ N-10 部件聚合 + N-23 血量快照）。
- **072**：结构类探索 OBSERVE 阶段每腿停滞 2–4 分钟且无进度事件；定因是索引每刻构建段数上限过小，非调度卡死（→ 提升构建预算 + 观察驻留上限 + 观察期进度字段）。
- **073**：探索前沿路线反复长距离穿水泅渡，依赖换气反射兜底（→ WaterCrossingProbe 与穿水让位）。
- **075**：前沿腿连续 route_failed 不换向，39 腿 37 败空转直到人工取消（→ FrontierLegBreaker）。
- **078**：hunt/搜索前沿无距离约束，多次把满状态玩家带进夜间怪群至濒死；定因是 acquire 路径死常量 512 且契约无线距参数（→ max_distance 参数与越界截停、进度字段）。
- **091**：跑图沿途地形要素（岩浆池）不入探索记忆，模型对「顺路有什么可利用」无感知通道（→ 地形要素类别 + notable_findings + interests 询问链）。
- **093**：探索/找结构前沿腿在复杂出发点反复失败回拉同一位置形成活锁（→ 换锚一级升级与失败占比触发）。
- **097**：find_entity 长搜每数分钟自动 paused；定因是自卫回位白名单缺该能力，被按驻点任务计划走回接管点（→ 白名单纳入 find_entity；find_block 维持驻点语义）。
- **098**：hunt 搜索子任务阶段字段早生命周期为 null，调试面板读行动自述即崩客户端（→ 声明处初始化 + 全量同类扫描）。
- **099**：find_block 对刚放置方块有盲区，nearest 报远处同类方块，差点把正确落格判成「放置偏移」；定因含格序收束与「最近」语义错位及一次性采样无重扫（→ 最近写入预核查 + write_visibility_note）。
- **103**：跑图沿途不记录注册结构（村庄），证据画像机器现成未接入；二轮修复发现画像过严（钟+3 生活方块在屋内凑不齐）与扫描器不注册索引、命中不入队、驻留不够三重根因（→ 联合锚点画像 + 扫描器接线 + 观察驻留）。
- **130**：勘察路线把角色带进河里溺水告急；后批补证全浸横渡均半分钟内上岸无伤害，深水连段判穿水、浅滩与短促渡水豁免（→ WaterCrossingProbe 深度感知）。
- **145**：explore 顺带兴趣决策答复后任务冻结/同一发现循环重提；continue 分支复验通过，recover 型答复的消费路径仍有同族缺口（→ 决策状态机 PASS_THROUGH/PARK/ISSUE 中继与补期）。
- **147**：同一出发点勘察连续全败且两次失败回执统计逐字相同，换出发点一切正常，疑似残留失败规划状态污染（换点后修复验证通过）。
- **165**：勘察首个航点可落在半径外，身体越界被截停后整任务失败，终态误报 no_path（→ radius_reached 提前收尾 + radius_bound_exit 独立失败码）。
- **168**：acquire 挖取查询把身体留在浪花里漂移（涉水行为，返岸恢复相关；修复另行跟踪）。
- **175**：航点落在水面上会把身体领进海里（→ 落点列纯水面候选不选，短促渡水豁免保留）。
- **193**：explore 行进分段冻结数分钟、无进度事件无终态，身体静止而分段计数不动；mlg 谓词修复后未再复现，单段最长恒定降到约 90 秒。
