# 03 玩家行为模型

这份文档回答一个问题：**一个正常玩家会怎么做？** 然后把今天散落在几十个文件里、各写一遍的同类逻辑，合并成同一套做法。

每个模型的结构都一样：

- **真人怎么做**：用游戏里的话描述，作为判断对错的标准；
- **统一逻辑**：新实现的流程；
- **吸收掉的现有实现**：v0 里被这个模型取代的东西，v1 不再出现；
- **保留的游戏事实**：旧代码里用实机换来的真知识，换个地方继续生效；
- **删掉的补丁 / 拦截**；
- **需要拍板**：会明显改变行为的取向问题，由两位决定。

模型编号与 02 的包对应：M2 `behavior.approach`、M3 `behavior.interaction`、M4 `behavior.acquire`、M5 `behavior.inventory`、M6 `behavior.survival`、M7 `behavior.permission`、M8 `behavior.retry`、M9 `behavior.worldmemory`、M10 `behavior.travel`、M11 `behavior.menu`、M12 `behavior.perception`、M13 `behavior.construction`。M1 是内核里 `GoalRunner` 的行为。名字与术语以 [09-命名与术语](09-命名与术语.md) 为准。

贯穿所有模型的两条取舍（LittleSadSheep，2026-10-08）：**怎么合理怎么来**；这是直播项目，**能做事就不干等**——除了真正的极端情况，不让角色站在原地耗时间。

## M1 做一件事的总流程

**真人怎么做**：接到"去做 X"，先看是不是已经做到了；再想需要什么（工具、材料、位置），缺什么就先去弄；然后动手，看结果；中途饿了吃一口、被怪打了还手，处理完回来接着干；真做不下去，就说清楚卡在哪、要什么才能继续。

**统一逻辑**（每个步骤都一样）：

```text
0 已满足？        是 → 直接完成，结果写"开始时已满足"，不做任何动作
1 决定            decide(step) → 这一步下一件做什么（每刻可重算，世界会变）
2 缺的自己补      缺工具、缺材料、站位不对 → 交给 M4 / M2 在这一步里补齐，不升级成新步骤，也不问 LLM
3 做              任务交给 ChildTaskRunner 运行，ProgressTracker 判断有没有在前进
4 核对            完成的证据来自真实世界（背包、方块、角色状态），不来自"交互已提交"
5 失败            交给 M8：换办法；办法用尽 → 带完整事实结束
插入              生存需求（M6）在能打断时插进来，处理完回到原步骤，不影响原步骤的计时
```

**吸收掉的现有实现**：`IntentTask` 里的全部能力特例；各能力分别写的"已满足"判断（如 `settleAlreadyHarvestedStep`）；适配器里为缺东西向 LLM 提问的分支。

**对 LLM 的影响**：LLM 只说要什么结果。"睡觉"不需要先写"去弄一张床"，"做铁镐"不需要先写"去挖铁"。`sequence` 保留，用于 LLM 自己想按顺序做的多件事。

**需要拍板**：缺的东西自己补能走多远？建议：身上、随身背包、记得的容器、合成、烧炼可以随意用；去世界里采集要受预算限制（见 M4）；交易、稀有消耗品必须有许可（见 M7）。

## M2 站位与靠近

**真人怎么做**：要对一个方块或实体做事，就走到一个够得着、看得见、站得稳的位置。这个位置不行就换一个。实在找不到，就挖开挡着的东西或垫一块（前提是被允许）。

**统一逻辑**：

```text
StandSpots.find(目标, 交互种类) → 候选站位，按下面四项打分排序：
  能到   寻路给出的路径代价
  够得着 按交互种类取规则：方块用玩家属性 blockInteractionRange；实体用 entityInteractionRange；
         床用服务端的床距离（床底面中心 |dx|≤3、|dy|≤2、|dz|≤3）；三者同时满足才算
  看得见 从站位的眼睛位置（潜行会降低眼高）到目标面的射线，必须先命中目标
  站得稳 脚下实心、头顶两格空、不在深落差边缘、不在液体或岩浆旁、不踩受保护的格子（M7）

Approach（一个动作 Action）：
  走到第一个候选 → 到了再核对（已落地、够得着、看得见）
  核对不过 → 下一个候选
  候选用尽 → 许可允许改方块时，生成"挖出或搭出站位"的候选（挖开遮挡 / 垫一块），作为最后手段
  仍失败 → 问题 UNREACHABLE，附上试过几个站位、各自失败在哪一项
```

**吸收掉的现有实现**：`GoToThenDoTask`、`BuildStanceNavigation`、`CollectItemsApproach`、`PortalApproach`、`AssemblyApproach`、`OnboardControlApproach`、`PhysicalStructureApproach`、`StructureEditApproach`、`JetpackDepartureApproach`、睡觉的站位计算与换位重试、`NightRestTask` 的床距离判断、挖矿 / 交互 / 工作台各自的伸手距离常量；`STANCE_DUD`、`OCCLUDED`、`OUT_OF_REACH` 三种失败（变成 M2 内部换位，不再上报给 LLM）。

**保留的游戏事实**：交互距离以玩家属性为准（创造模式、药水、模组都会改它）；服务端对床有单独的距离判定；服务端拒绝把方块放进玩家自己的碰撞箱；射线必须先命中目标，中途撞到别的方块就是看不见；潜行改变眼高。

**删掉的补丁**：10 多处硬编码距离常量；每个任务自写的站位搜索；"看不见就问 LLM"的决策。

## M3 瞄准 → 交互 → 确认

**真人怎么做**：看准，点下去，看有没有反应。没反应就想想为什么（够不着？被挡了？工具不对？），换个角度最多再试一次。拿不准刚才那一下到底点没点上，就不会再花一次材料去赌。

**统一逻辑**：

```text
AimAndInteract（一个动作，内部持有这次交互的确认状态）
  瞄准   转向目标点，等实际视角转到位；"发出转头"不算转到位
  核对   射线必须命中目标（指定方块的某个面 / 指定实体）
  提交   通过游戏接口层提交一次原生交互
  确认   每刻检查；连续几刻稳定才算确认
  结论   APPLIED       生效了
         NOT_APPLIED   没生效（附原因：最近的动作栏提示语、方块没变、物品没少……）
         UNEXPECTED    变成了预料之外的样子
         UNCONFIRMED   提交了但确认不了
  收尾   任务结束时自动交还本刻的交互机会，任何退出路径都不会漏

全仓一致的重试规则
  NOT_APPLIED 且原因能靠换位解决（遮挡、距离） → 交给 M2 换站位，最多再试一次
  UNCONFIRMED 且涉及消耗 → 绝不盲目重试，记进结果的 unconfirmed
  UNEXPECTED → 如实上报现场，由上层决定
```

**吸收掉的现有实现**：53 个文件里的回执字段、72 处 `poll`、40 处 `retireOneShotForTaskBoundary`、18 处瞄准收敛；睡觉、交互、放置、挖掘各自手写的"看 → 点 → 等"；只有睡觉在读的服务端提示语（`ChatMonitor.latestOverlay`），推广为所有 `NOT_APPLIED` 都附带。

**保留的游戏事实**：客户端会预测，必须连续几刻稳定才能排除回滚；角色或手持在确认前变了，就记为没能确认；每刻只能提交一次交互；挖掘需要持续攻击若干刻，工具等级决定掉不掉落；入睡确认期间日期前进，说明一觉睡到了天亮（睡觉的实机事实，推广为"确认期间目标效果已被更大的效果覆盖"的通用判断）。

## M4 拿到物品

**真人怎么做**：要 N 个 X，先翻身上（含随身背包）；再想想哪个箱子、哪台 AE 里有；身上的东西能直接做出来就做；需要烧就去烧；还不够就去采、挖、砍、打；实在不行再考虑交易。挑最省事的路，边做边重新盘算；只拿需要的量，工具可以多备一点。

**统一逻辑**：

```text
ItemAcquisition.need(物品或标签, 数量, 用途)
  问遍所有已登记的物品来源 ItemSource：能拿到多少、大概要多久、风险、是否超出许可
  选总代价最低的组合（不是写死的固定顺序）；超出许可的来源不参与
  用一个来源 → 重新清点 → 还缺就重新问（世界在变）
  合成、烧炼也是"来源"，它们的原料需求递归回到 ItemAcquisition（带深度上限与防环）

所有内部用途都走这一个入口，带上用途标签：
  施工备料、支撑方块、烹饪原料与燃料、工具准备、搭桥与垫脚方块、火把、食物、传送门材料、机器投料
```

**吸收掉的现有实现**：`SemanticAcquireCompanionTask`（2989 行）、`SemanticBuildSupplyCompanionTask`、`SemanticMaterialSupplyCoordinator`、`BuildSupportSupply`、`CreativeBuildMaterialSupply`、`BuildFood*` 四件套、`LandingMaterialSupply`、`ProductionInputSupply`、`OffhandSupplyTask`、`PortalResourceSearchTask`、`WorkToolPreparation`、`Ae2Supply*` 五件套、`BackpackSupplyTask`、`ContainerSupplySources`。公开能力 `acquire_items`、`craft`、`cook` 变成同一个引擎的不同入口（允许的来源和用途不同）。

**保留的游戏事实**：配方从真实的配方管理器读取（含模组配方）；工具等级决定掉落；烧炼每件 200 刻，燃料按原版燃料表；AE2 自动合成是异步作业；随身背包只能走原生界面存取；箱子里有什么，开了才算数；记忆可能过时，到了要核对。

**需要拍板**：
- 各来源的默认代价怎么估（建议先用简单的"距离 + 动作数"，以后再调）。
- `count` 统一为"这次要多做多少"：拿东西就是再多拿几件，不是背包里的总数（现在 craft、cook、acquire、trade 已经是这个意思），所有能力一致。

## M5 背包空间

**真人怎么做**：背包满了，就把没用的扔掉或者塞进旁边的箱子。工具、贵重品和正在用的材料绝不会扔。扔之前心里有数，扔了什么也说得出来。

**统一逻辑**：

```text
InventorySpace.ensureFree(需要的槽位数, 用途)
  在捡东西、合成取出、交易、开箱取物之前统一调用；任务自己不再处理"满了"

  物品价值分级：本任务预留 > 工具 / 武器 / 护甲 > 稀有贵重 > 食物 > 建材 > 普通掉落 > 垃圾
               （垃圾举例：超过一组的圆石、泥土、沙砾，腐肉）
  顺序：合并堆叠 → 放进随身背包 → 存进附近已知容器或 AE → 丢掉价值最低的物品
       → 只有到了必须动"贵重"一级才停下来问
  每次存放、丢弃都记进结果的 changes
```

**吸收掉的现有实现**：30 多个任务里各自的 `NO_SPACE` 处理、`AcquisitionInventoryTidy`、`InventoryDepositCoordinator`、`SpoilDropCoordinator`、`DiscardRecovery`。

**需要拍板**：默认允许自动丢弃“垃圾”一级吗？建议允许；附近 16 格内有已知容器时优先存放，而不是丢弃。

## M6 生存需求与打断规则

**真人怎么做**：快死了（往下掉、憋气、着火、被埋、被围殴）就立刻自救；饿了找个空当吃一口；天黑了附近有床就去睡；被怪打了还手或者跑；手上停下来会出事的活（悬空搭桥、开飞行器）不会随便停。

**统一逻辑**：两个问题，一条规则。

```text
多快必须处理 Urgency：LATER 找空当 < SOON 尽快 < NOW 立刻
任务此刻能不能打断 Interruptibility：
  BETWEEN_ACTIONS 两个动作之间 < WORKING 正常干活 < UNSAFE_TO_STOP 停下不安全（连续驾驶、等游戏确认、悬空、贴边）

规则：NOW 打断一切；SOON 打断 BETWEEN_ACTIONS 和 WORKING；LATER 只在 BETWEEN_ACTIONS 时插进来
```

| 生存需求 | LATER 找空当 | SOON 尽快 | NOW 立刻 |
| --- | --- | --- | --- |
| 坠落 | — | — | 预计落地伤害 ≥ 当前生命，或下面是虚空 |
| 溺水 | — | 氧气低于三分之一 | 氧气 ≤ 2 泡，或已经在掉血 |
| 着火 / 岩浆 | — | 身上着火 | 人在岩浆里，或生命已低 |
| 被埋（窒息） | — | — | 角色卡在实心方块里 |
| 被攻击 | — | 有敌对生物正在攻击自己 | 生命低于阈值且仍在挨打 → 撤离 |
| 饥饿 | 身上最小的一件普通食物能整份补进去（饱食度 + 它的营养 ≤ 20） | ≤ 6（不能疾跑） | 0 且在掉血 |
| 夜晚 | 可以睡的时间，且能弄到床 | 露天、没有床可睡，且威胁评估为"打不过" | — |
| 站在深落差边缘 | 闲着时（没有任务管身体）退回安全处 | — | — |

**夜晚怎么过**（真人玩家的做法）：

```text
天黑了
  能弄到床（现成的、自带的、现做的；需要时剪羊毛或打野生羊取羊毛） → 找空当去睡，睡醒回到原站位
  弄不到床
    身处安全的地方（地下矿道、屋里、照明充足）或打得过 → 接着干活，不干等
    露天、敌怪多、打不过（或生命低、没护甲） → 极端情况：挖三填一，躲到天亮或威胁解除
```

**威胁评估 `ThreatAssessment`**（纯函数，`behavior.survival` 提供，所有"打还是跑"的判断都用它）：

```text
我方：生命、护甲值、武器伤害、盾牌、食物储备、是否有退路
对方：数量、种类（近战 / 远程 / 爆炸 / 飞行）、是否正在追我、距离
地形：是否会被包围、能不能卡位、附近有没有岩浆或悬崖
结论：能赢 / 有风险 / 打不过
```

它决定：被攻击时还手还是撤离；床边有怪时清怪还是带床换地方；夜里露天要不要躲。"想不想打"由许可（M7 的 `fight`）表达：`self_defense` 表示不主动打，只自卫。

- 吃饭、睡觉、撤离这类临时任务做完就结束，回到主任务。**它们没做成，也绝不会把主任务判失败**（AGENTS.md 已有此原则，这里变成机制）。
- 被打断期间，主任务的进度跟踪不计时。
- 没吃的而且饥饿已到 SOON：作为一个有预算的临时任务，调用 M4 去弄吃的。
- 寻死这类明确的任务，通过 M7 把 `survival_needs` 设为 `off`，不需要在打断规则里开后门。

旧开关到新模型的对应：

| 旧开关 | 新模型 |
| --- | --- |
| `suppressesSurvivalReflexes`（寻死） | M7 许可：`survival_needs = off` |
| `onlyWhenBodyReleased`（贴边退避） | 这个生存需求是 LATER |
| `urgentBodyRescue`（被埋窒息） | 这个生存需求是 NOW |
| `drivesBodyContinuously`（水中攀爬） | 当前任务报 UNSAFE_TO_STOP |
| `yieldsToContinuousDriving`（换气让位） | 换气在氧气尚可时是 SOON，危急时升为 NOW |

**吸收掉的现有实现**：`Task` 上的 5 个开关；`TaskSelector` 的豁免链；6 条自救链（`MLGChain`、`BreathChain`、`SettleChain`、`MobDefenseChain`、`NightRestChain`、`SuicideArmorRestore`）改写为生存需求；施工、打龙、挖矿、战斗里各自的吃饭逻辑；15 处各自读取饥饿值；夜间自动休息改为复用睡觉能力的行为，不再另写一套。各种"提醒"变成"角色自己处理不了的生存需求 → 通过任务事件告诉 LLM"。

**已定**：夜间自动睡觉默认开启。各项阈值在实现时给出初值，按实机观感调整。

## M7 许可与保护

**正常玩家的分寸**：默认会为了干活挖开天然的土、石、木，搭临时方块并在用完后收回，反击敌对生物，为了具体需要（吃的、羊毛、皮革）处理野生动物，使用和取用野外、村庄、遗迹里不属于任何玩家的东西。默认绝不碰玩家的东西：玩家盖的房子、玩家的箱子和机器、记住的区域、有名字或被驯服的动物、围栏里的牲畜；不用稀有消耗品（末影珍珠、不死图腾、钻石……）。

**自家人**：所有者在实例配置里列出的信任玩家（主播自己、一起玩的朋友）。自家人放的箱子、木桶、AE 网络这类存储，角色取用、存放和自己的一样；拆、改他们的方块，伤他们的宠物，仍按别人的东西算。名单只在实例配置里，不经工具参数，LLM 改不了。

这里的"许可"是 LLM 给角色的行事范围，**不是**游戏或服务器的 OP 权限；被服务器拒绝（领地保护、权限不够）属于问题 `REFUSED_BY_GAME`，如实返回。

**统一逻辑**：

```text
Permissions（许可）= 默认值 + 这次任务给的覆盖（goal.permissions）
  change_blocks        none | temporary | natural（默认）| any
                       natural：天然方块，以及不属于任何玩家的东西（村庄的床、废弃矿井的铁轨……；这类放在最后考虑）
                       any：一切不受保护的方块
  fight                self_defense（只自卫）| hostile_mobs（默认，主动处理敌对生物）| any
  use_rare_items       false（默认）| true
  kill_animals         none | wild（默认）| any
                       wild：野生、没起名、没驯服、没拴绳、不在围栏里的普通动物，可以为具体需要而击杀；剪毛、挤奶不算伤害
  survival_needs       on（默认）| off（只有寻死这类明确的任务可以设）
  protected_landmarks  [地标名…]   额外不许碰的地方

Protection（保护判断，全仓只此一处）=
  服务端的方块归属记录 ∪ 记住的区域 ∪ protected_landmarks ∪ 判断为"玩家放置"的方块（含玩家区域里的容器和功能方块）
  ∪ 有名字 / 被驯服 / 拴绳 / 围栏里的生物

存储取用（翻箱子拿东西、往箱子里存、用 AE 终端）= Protection.mayUseStorage：
  有放置记录：自己或自家人放的可用，别人放的不用
  没有记录：在记住的区域里、额外保护的地标旁、推断为玩家放的不用；野外无主的照常用；归属还没问清的按不用
  只决定"能不能取用、存放"；拆、改照旧走上面的保护判断

所有改变世界的动作都经过 PermissionCheck.allows(动作, 目标)，这是唯一的许可检查点
LLM 明确点名的目标（例如"拆掉这面墙"时给的观察编号），视为对这个目标的许可
  例外：有主的生物（有名字、驯服、拴着绳、圈养着）和玩家，点了名也要再确认一次才伤害它们——
  这次任务的 fight（为需要击杀时是 kill_animals）开到 any 才动手；击杀玩家永远不行
被拒时：问题 NEED_APPROVAL（通常伴随一个提问），写清楚需要哪一项许可、涉及哪些格子或生物；不再让 LLM 猜该开哪个开关
```

**对 LLM 的影响**：12 种、共 44 个分散在各能力里的 `may_*` / `allow_*` 开关，收成 `goal` 上一个可选的 `permissions` 对象；`observe(self)` 显示当前许可。"失败 → 带新开关重提"的循环随之消失。

**保留的游戏事实**：客户端无法确定一个方块是天然生成的还是玩家放的。v1 由服务端记录"谁放了哪一格"（02 第 3 节），归属以记录为准；记录之外的方块（例如装上 v1 之前就存在的建筑）仍靠玩家区域和方块类别推断，**拿不准就按受保护处理**。

**已定（2026-10-08）**：采用上面"像正常玩家一样"的默认值，怎么合理怎么来。

**已定（2026-10-10）**：别人的存储怎么放行，用实例配置里的自家人名单，不在任务许可里加开关（见待拍板清单第七节）。

## M8 重试、放弃与提问

**真人怎么做**：一种办法不行就换一种；还在往前推进就继续，原地打转就换办法；都不行就停下来，说清楚做了什么、卡在哪、要什么才能继续。只有真的需要别人拿主意时才开口问。

**统一逻辑**：

```text
进度      ProgressTracker：有真实进展就继续，长时间没进展才算卡住，另有最多能做多久的上限
重试      每个步骤一组排好序的办法
          按问题种类决定：同一个办法再试 / 换下一个办法 / 结束；同一种失败不超过上限
提问      只在三种情况下向 LLM 提问（Question）：
          ① 要做的事超出许可，需要同意（NEED_APPROVAL）
          ② 有几种后果不同的做法，Mod 不该替 LLM 选（拆哪面墙、动哪个箱子里的贵重材料）（CHOOSE_ONE）
          ③ 目标对象本身说不清（例如有几个同名地标）（UNCLEAR_TARGET）
          其他情况一律内部重试，或带着事实结束。永远不问"要不要重试"。
```

**任务结果**（所有能力同一个结构，字段与问题种类的完整说明见 07 第 6.1 节，代码是 `kernel.result`）：

```text
status        done | partial | failed | cancelled（目标达成情况）
summary       一句话结论
changes[]     已确认发生的变化（物品进包、方块变化、消耗、存放、丢弃）
remaining[]   没完成的部分
problem       { kind, message, suggestion }   卡在哪（游戏里的事实）+ 怎样能继续
unconfirmed[] 已提交但没能确认、不能盲目重做的交互
attempts[]    试过的办法摘要（不是逐刻日志）
details       能力特有的细节
```

`problem.kind` 保持小而稳定：`NEED_ITEM`、`NEED_APPROVAL`、`UNREACHABLE`、`TARGET_GONE`、`DANGER`、`REFUSED_BY_GAME`、`WRONG_TIME`、`NOT_POSSIBLE_HERE`、`INVENTORY_FULL`、`STUCK`（换过办法仍原地打转，或超过最多能做的时长）、`UNSUPPORTED`、`INTERNAL_ERROR`。

**吸收掉的现有实现**：`FailureType`（19 种，附带教 LLM 重提的提示）、没人调用的 `RecoveryLadder`、`RecoveryAdvisor`、`RecoveryKnowledge`、`ProgressGate`、447 个失败出口、109 个提问出口里的大部分、各处的效果账本。

这同时把 AGENTS.md 里"原生交互成功与目标达成分开判断"落成了数据结构：`status` 管目标，`changes` 和 `unconfirmed` 管交互。

## M12 感知：LLM 看到玩家看到的

**真人怎么做**：看一眼屏幕就知道：前面是缓坡还是悬崖，左边有条河，右边两只羊，远处有片林子，身后是自己的木屋；听到身后有苦力怕的嘶嘶声就回头。能指着东西说"那只羊""那个洞口""左边那个箱子"。墙后面的东西看不见，但记得。

**现状**（01 症状 9）：LLM 只拿到"7.3 格外有只僵尸"这种没有方向、没有位置、不能指着的列表；项目里现成的以角色为中心的俯视网格（`LookAroundTool`）只是内部工具，LLM 用不上；没有任何声音感知。

**统一逻辑**：

```text
Scene（场景模型）：一份，按需增量更新，所有观察视图都从它整理出来
  角色自己  位置、朝向、生命、饥饿、氧气、手持、护甲、状态效果、落地或入水
  实体      每个一个短期观察编号 e#：类型、名字、方位、距离、高低差、是否看得见、是否敌对、
            是否正盯着我，以及看得出来的特征（羊的颜色、是否剪过毛、幼年、着火、手持物、盔甲）
  声音      原版字幕事件：声音种类 + 方位，用来知道"看不见但就在附近"的东西
  近处      以角色为中心的俯视网格：平地、上台阶、下台阶、落差、墙、水、岩浆（复用 LookAroundTool）
  地形特征  悬崖、水体、洞口、树林、建筑、村庄、结构、岩浆池……每个一个观察编号 f#：方位、距离、规模
  设施      箱子、工作台、熔炉、床等，每个一个观察编号 b#：方位、距离、上次看到的内容
  环境      时间、天气、光照、生物群系

方位说法（全项目统一，结果和直播解说也用它）
  相对朝向：前方、前方偏左、左侧、后方……；东南西北：北、西北……；距离；高低差

"看见"的纪律
  "看见" = 在渲染范围内，且视线没被挡住（刚看见过的保留很短的时间）

观察编号

```

**吸收掉的现有实现**：`mcp` 下的 `PerceiveSections`、`NearbyCollisionPerception`、`NearbyFacilityPerception`、`NearbySignPerception`、`PhysicalStructurePerception`、`PhysicalDeckSampler`、`NavigationOverview`、`StructurePerceptionJson`；`core/tools/perception` 下的 `LookAroundTool`、`ScanBlocksTool`、`ScanNearbyEntitiesTool`、`LocalFloorSense`、`BodyEnvironmentObservation`、`GetSelfStatusTool` 等；各能力里各自实现的"找最近的某种东西"。

## M13 施工

**真人怎么做**：拿着图纸到工地，先对一遍哪些格已经对了；缺料先去拿，挡着的挖掉、坑填上；从地基往上一层一层砌，站在砌好的墙上接着砌，够不着就垫两块土、用完拆掉；门窗这些贴附的东西等墙立好再装；材料用完就去拿，回来接着砌，砌好的不动；某格暂时放不上先砌别处，回头再来；砌完对图检查，门关好；中途不盖了把垫的土收走。

**统一逻辑**：

```text
ConstructionTask(蓝图, 许可, 用途)
  CHECK    逐格核对（BlueprintCheck）：全对 → 完成"开始时已满足"；不可能的格记下照建其余；受保护的格一次提问
  SUPPLY   缺口按未满足的格算，经 M4 去拿；拿不齐建到材料尽头，partial
  CLEAR    要清的格按层从上往下挖；能不能动由 M7 回答；余土交 M5
  PLACE    低层先、同层骨架先、就近连放；站位 M2、点击 M3、放置预测核对落下来是不是要求的状态；
           放不上先做同层别的格，再垫临时方块
  POUR     实心格放完后处理水源、岩浆源：先收走不该在的源，再逐格倒桶
  VERIFY   再核对一遍；只修点名的最终属性（可手开的门按一下）；有限修补，同一批错误重复就停
  CLEANUP  收回自己垫的临时方块；任何终态都收；收不回的列进结果
蓝图是所有施工入口的收敛点：build、light、machine_build 都经这一个任务干活，自己不写放置、清障、备料、临时方块或核对。
```

**吸收掉的现有实现**：`FirstPersonBuildCompanionTask` 的 23 个阶段、`BuildTaskRecord`、`ReplaceMode` 与清障白名单、`BuildClearanceSurvey` 的整单拒绝与选址建议、`BuildRegions` / `BuildLayerFrontier` / `BuildWorksitePlanner` / `BuildStanceNavigation` / `BuildPlacementAccess*` / `BuildEdge*`（站位与贴边）、`BuildSupportAccess`、`BuildScaffold*`、`SemanticBuildSupplyCompanionTask`、`BuildProjectStore` 与支撑 sidecar、`ConstructionOwnership`、`BuildPreviewGate`、`BuildTraversabilityVerifier`、`SemanticLightAreaCompanionTask` 的放灯部分、机器的施工部分。

**保留的游戏事实**：门、床放下一半时另一半由游戏生成，床头朝向随点击时的视角；原版放置状态由点击面、视角、潜行决定，贴附物品对着实墙落成墙式；会开界面的方块要潜行才能往它上面放；雪层、蜡烛、双层半砖要多次放置；堆肥、炼药锅、蜂蜜、孵化、浆果、含水、活塞伸出是运行态，树叶要 persistent 才不腐烂，耕地与土径按泥土；服务端拒绝把方块放进自己的碰撞箱；客户端先显示方块不算数；挖脚下前下一格要落得稳；水源可收流水不可收，水倒进岩浆成黑曜石、圆石，源格可能被原版自补。

**删掉的补丁 / 拦截**：预检整单拒绝（地形冲突、受保护格、缺料）、自注册导航保护对目标格的豁免、Dev 审图门、期限估算公式、诊断条数上限、可走通契约、选址建议。

**需要拍板**：已定（建造规格第 10 节，2026-10-10）：引擎放玩家行为层；缺料建到材料尽头；不可能与受保护的格逐格处理；临时方块从身上挑最不值钱的整块。

## 4. 怎样把旧逻辑归类进模型

实现一个领域之前，执行 Agent 先把 v0 中该领域的旧逻辑逐条清点出来，做成"旧逻辑清单"（模板见 05）。每一条都归入下面五类之一：

| 类 | 判断标准 | 处理 | 例子 |
| --- | --- | --- | --- |
| **F 游戏事实** | 原版或模组本身就这样运作，与我们的设计无关 | 保留；放进它该归属的模型或游戏接口层，全仓只留一份 | 下界、末地用床会爆炸；醒来的实体包和时间包不在同一刻到达；服务端的床距离；客户端预测需要连续几刻稳定才能确认 |
| **C 玩家常识** | 正常玩家本来就会这么做 | 保留，作为模型里的策略 | 背包满先扔垃圾；挖之前先换对的工具；睡觉前先确认够得着床 |
| **P 补丁** | 为了弥补别的组件的缺陷而加的 | 删除；由重新设计的模型从根上解决，并用原事故场景验证 | `Task` 上的 5 个打断开关；睡觉的"白天门"决策中继与防重问三态；睡觉专用的换位重试 |
| **G 预判拦截** | 还没尝试，就因为"预测会失败"而拒绝 | 删除（AGENTS.md 明令禁止） | "床区高度核验不了，所以拒绝前往"——改为先走近，到了再看 |
| **S 过严 / 无意义** | 拒绝了玩家本来会直接去做的事，或者只为校验而校验 | 删除或放宽 | 许可开关全部默认关闭；参数宽松和严格两套标准并存；能自己补的东西却去问 LLM |

注释里出现的实机事故编号（如"177 实机""145 批七"）是很重要的线索：它说明这条规则背后有一个真实场景。**删除 P、G、S 类规则时，要用这个场景验证新模型确实处理好了它**——进离线场景测试，或者进实机验收清单。
