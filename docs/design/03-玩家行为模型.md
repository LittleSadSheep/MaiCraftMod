# 03 玩家行为模型

这份文档回答一个问题：**一个讲道理的真人玩家会怎么做？** 然后把今天散落在几十个文件里、各写一遍的同类逻辑，合并成同一套做法。

每个模型的结构都一样：

- **真人怎么做**：用游戏里的话描述，作为判断对错的标准；
- **统一逻辑**：新实现的流程；
- **吸收掉的现有实现**：v1 里被这个模型取代的东西，v2 不再出现；
- **保留的游戏事实**：旧代码里用实机换来的真知识，换个地方继续生效；
- **删掉的补丁 / 门控**；
- **需要拍板**：会明显改变行为的取向问题，由两位决定。

模型编号与 02 的包对应：M2 `behavior.reach`、M3 `behavior.act`、M4 `behavior.procure`、M5 `behavior.inventory`、M6 `behavior.upkeep`、M7 `behavior.mandate`、M8 `behavior.attempt`、M9 `behavior.memory`、M10 `behavior.travel`、M11 `behavior.menu`、M12 `behavior.perception`。M1 是内核里 `GoalRunner` 的行为。

贯穿所有模型的两条取舍（LittleSadSheep，2026-10-08）：**怎么合理怎么来**；这是直播项目，**能做事就不干等**——除了真正的极端情况，不让角色站在原地耗时间。

## M1 做一件事的总流程

**真人怎么做**：接到"去做 X"，先看是不是已经做到了；再想需要什么（工具、材料、位置），缺什么就先去弄；然后动手，看结果；中途饿了吃一口、被怪打了还手，处理完回来接着干；真做不下去，就说清楚卡在哪、要什么才能继续。

**统一逻辑**（每个步骤都一样）：

```text
0 已满足？        是 → 直接完成，回执写"开始时已满足"，不做任何动作
1 翻译            plan(step) → 下一个动作（每刻可重算，世界会变）
2 前置自己补      缺工具、缺材料、站位不对 → 交给 M4 / M2 在步骤内部补齐，不升级成新步骤，也不问 LLM
3 执行            子任务交给 ChildSupervisor 驱动，ProgressMeter 判断有没有在前进
4 核验            完成的证据来自真实世界（库存、方块、身体状态），不来自"动作已发出"
5 失败            交给 M8：换办法；办法用尽 → 带完整事实结束
插入              身体维护（M6）在可打断时插进来，结清后回到原步骤，不影响原步骤的计时
```

**吸收掉的现有实现**：`IntentTask` 里的全部能力特例；各能力分别写的"已满足"判断（如 `settleAlreadyHarvestedStep`）；适配器里为前置条件向 LLM 提问的分支。

**对 LLM 的影响**：LLM 只说要什么结果。"睡觉"不需要先写"去弄一张床"，"做铁镐"不需要先写"去挖铁"。`sequence` 保留，用于 LLM 自己想按顺序做的多件事。

**需要拍板**：前置自补能走多远？建议：身上、随身背包、记得的容器、合成、烧炼可以随意用；去世界里采集要受预算限制（见 M4）；交易、稀有消耗品必须有授权（见 M7）。

## M2 工位与靠近

**真人怎么做**：要对一个方块或实体做事，就走到一个够得着、看得见、站得稳的位置。这个位置不行就换一个。实在找不到，就挖开挡着的东西或垫一块（前提是被允许）。

**统一逻辑**：

```text
Workspot.plan(目标, 动作类型) → 候选站位，按下面四项打分排序：
  可达   步行引擎给出的路径代价
  够得着 按动作类型取规则：方块用玩家属性 blockInteractionRange；实体用 entityInteractionRange；
         床用服务端的床距离盒（床底面中心 |dx|≤3、|dy|≤2、|dz|≤3）；三者同时满足才算
  看得见 从站位的眼睛位置（注意潜行会降低眼高）到目标面的射线，必须先命中目标
  站得稳 脚下实心、头顶两格空、不在深落差边缘、不在液体或岩浆旁、不踩保护格（M7）

Approach（一个可逐刻推进的步骤）：
  走到第一候选 → 到场复核（已落地、够得着、看得见）
  复核不过 → 下一个候选
  候选用尽 → 授权允许改地形时，生成"开辟工位"候选（挖开遮挡 / 垫一块），作为最后手段
  仍失败 → blocker = UNREACHABLE，附上试过几个站位、各自失败在哪一项
```

**吸收掉的现有实现**：`GoToThenDoTask`、`BuildStanceNavigation`、`CollectItemsApproach`、`PortalApproach`、`AssemblyApproach`、`OnboardControlApproach`、`PhysicalStructureApproach`、`StructureEditApproach`、`JetpackDepartureApproach`、睡觉的站位计算与换位重试、`NightRestTask` 的床距离判定、挖矿 / 交互 / 工作台各自的伸手距离常量；`STANCE_DUD`、`OCCLUDED`、`OUT_OF_REACH` 三种失败（变成 M2 内部换位，不再上报给 LLM）。

**保留的游戏事实**：伸手距离以玩家属性为准（创造模式、药水、模组都会改它）；服务端对床有独立的距离盒；服务端拒绝把方块放进玩家自己的碰撞箱；射线必须先命中目标，中途撞到别的方块就是看不见；潜行改变眼高。

**删掉的补丁**：10 多处硬编码距离常量；每个任务自写的站位搜索；"看不见就问 LLM"的决策。

## M3 瞄准 → 操作 → 确认

**真人怎么做**：看准，点下去，看有没有反应。没反应就想想为什么（够不着？被挡了？工具不对？），换个角度最多再试一次。拿不准刚才那一下到底点没点上，就不会再花一次材料去赌。

**统一逻辑**：

```text
NativeAct（可组合的步骤，内部持有回执）
  瞄准   转向目标点，等实际视角收敛；"发出转头"不算转到位
  复核   射线必须命中目标（指定方块的某个面 / 指定实体）
  提交   通过 NativeActionPort 提交，拿到回执
  对账   每刻 poll；连续稳定刻满足才确认
  判定   APPLIED
         NOT_APPLIED（附原因：最近的动作栏提示语、方块没变、物品没少……）
         DIVERGED（变成了第三种状态）
         UNCERTAIN（提交了但确认不了）
  收尾   任务边界自动归还操作额度，任何退出路径都不会漏

全局一致的重试规则
  NOT_APPLIED 且原因能靠换位解决（遮挡、距离） → 交给 M2 换工位，最多再试一次
  UNCERTAIN 且涉及消耗 → 绝不盲目重试，记进回执的 uncertain
  DIVERGED → 如实上报现场，由上层决定
```

**吸收掉的现有实现**：53 个文件里的回执字段、72 处 `poll`、40 处 `retireOneShotForTaskBoundary`、18 处瞄准收敛；睡觉、交互、放置、挖掘各自手写的"看 → 点 → 等"；只有睡觉在读的服务端提示语（`ChatMonitor.latestOverlay`），推广为所有 `NOT_APPLIED` 都附带。

**保留的游戏事实**：客户端会预测，必须用连续稳定刻排除回滚；身体或控制版本变了就判不确定；每刻只能提交一次操作；挖掘需要持续攻击若干刻，工具等级决定掉不掉落；入睡确认窗口内日期前进，说明一觉睡到了天亮（睡觉的实机事实，推广为"确认窗口内目标效果已被更大的效果覆盖"的通用判定钩子）。

## M4 物品获取

**真人怎么做**：要 N 个 X，先翻身上（含随身背包）；再想想哪个箱子、哪台 AE 里有；身上的东西能直接做出来就做；需要烧就去烧；还不够就去采、挖、砍、打；实在不行再考虑交易。挑最省事的路，边做边重新盘算；只拿需要的量，工具可以多备一点。

**统一逻辑**：

```text
Procurement.need(物品或标签, 数量, 用途)
  向所有已注册来源 MaterialSource 询价：可得数量、预估耗时、风险、是否超出授权
  选总代价最低的组合（不是写死的固定顺序）；超出授权的来源不参与
  执行一个来源 → 重新盘点 → 还缺就重新询价（世界在变）
  合成、烧炼也是"来源"，它们的原料需求递归回到 Procurement（带深度上限与防环）

所有内部用途都走这一个入口，带上用途标签：
  施工备料、支撑方块、烹饪原料与燃料、工具准备、桥接与垫脚方块、火把、食物、传送门材料、机器投料
```

**吸收掉的现有实现**：`SemanticAcquireCompanionTask`（2989 行）、`SemanticBuildSupplyCompanionTask`、`SemanticMaterialSupplyCoordinator`、`BuildSupportSupply`、`CreativeBuildMaterialSupply`、`BuildFood*` 四件套、`LandingMaterialSupply`、`ProductionInputSupply`、`OffhandSupplyTask`、`PortalResourceSearchTask`、`WorkToolPreparation`、`Ae2Supply*` 五件套、`BackpackSupplyTask`、`ContainerSupplySources`。公开能力 `acquire_items`、`craft`、`cook` 变成同一个引擎的不同入口（允许的来源和用途不同）。

**保留的游戏事实**：配方从真实的配方管理器读取（含模组配方）；工具等级决定掉落；烧炼每件 200 刻，燃料按原生燃料表；AE2 自动合成是异步作业；随身背包只能走原生界面存取；箱子里有什么，开了才算数；记忆可能过时，到场要复核。

**需要拍板**：
- 各来源的默认代价怎么估（建议先用简单的"距离 + 动作数"，以后再调）。
- `count` 统一为"再多几件"（现在 craft、cook、acquire、trade 已经是这个意思），所有能力一致。

## M5 背包空间

**真人怎么做**：背包满了，就把没用的扔掉或者塞进旁边的箱子。工具、贵重品和正在用的材料绝不会扔。扔之前心里有数，扔了什么也说得出来。

**统一逻辑**：

```text
InventorySpace.ensureFree(需要的槽位数, 用途)
  在拾取、合成取出、交易、开箱取物之前统一调用；任务自己不再处理"满了"

  物品价值分级：本任务预留 > 工具 / 武器 / 护甲 > 稀有贵重 > 食物 > 建材 > 普通掉落 > 垃圾
               （垃圾举例：超过一组的圆石、泥土、沙砾，腐肉）
  动作顺序：合并堆叠 → 放进随身背包 → 存进附近已知容器或 AE → 丢弃价值最低的物品
           → 只有到了必须动"贵重"一级才停下来问
  每次存放、丢弃都写进回执的 achieved
```

**吸收掉的现有实现**：30 多个任务里各自的 `NO_SPACE` 处理、`AcquisitionInventoryTidy`、`InventoryDepositCoordinator`、`SpoilDropCoordinator`、`DiscardRecovery`。

**需要拍板**：默认允许自动丢弃"垃圾"一级吗？建议允许；附近 16 格内有已知容器时优先存放，而不是丢弃。

## M6 身体维护与反射仲裁

**真人怎么做**：快死了（往下掉、憋气、着火、被埋、被围殴）就立刻自救；饿了找个空档吃一口；天黑了附近有床就去睡；被怪打了还手或者跑；手上的细活不会随便停下。

**统一逻辑**：两个维度，一条规则。

```text
需求有多急 Urgency：COMFORT（舒适） < HARMFUL（有害） < LETHAL（致命）
任务此刻能不能打断 Interruptibility：FREE（步骤之间） < BUSY（正常干活） < DELICATE（连续驾驶、确认窗口、悬空、贴边）

规则：LETHAL 打断一切；HARMFUL 打断 FREE 和 BUSY；COMFORT 只在 FREE 时插进来
```

| 需求 | COMFORT | HARMFUL | LETHAL |
| --- | --- | --- | --- |
| 坠落 | — | — | 预计落地伤害 ≥ 当前生命，或下面是虚空 |
| 溺水 | — | 氧气低于三分之一 | 氧气 ≤ 2 泡，或已经在掉血 |
| 着火 / 岩浆 | — | 身上着火 | 人在岩浆里，或生命已低 |
| 被埋（窒息） | — | — | 身体在实心方块里 |
| 被攻击 | — | 有敌对目标正在攻击自己 | 生命低于阈值且仍在挨打 → 撤离 |
| 饥饿 | 饱食度 < 20 且身上有吃的 | ≤ 6（不能疾跑、不回血） | 0 且在掉血 |
| 夜晚 | 可睡窗口，且能弄到床 | 露天、没有床可睡，且威胁评估为"打不过" | — |
| 站在深落差边缘 | 身体空闲时退回安全处 | — | — |

**夜晚怎么过**（真人玩家的做法）：

```text
天黑了
  能弄到床（现成的、自带的、现做的；需要时剪羊毛或打野生羊取羊毛） → 找空档去睡，睡醒回工位
  弄不到床
    身处安全的地方（地下矿道、屋里、照明充足）或打得过 → 接着干活，不干等
    露天、敌怪多、打不过（或生命低、没护甲） → 极端情况：挖三填一，躲到天亮或威胁解除
```

**威胁评估 `ThreatAssessment`**（纯函数，`behavior.upkeep` 提供，所有"打还是跑"的决定都用它）：

```text
我方：生命、护甲值、武器伤害、盾牌、食物储备、是否有退路
对方：数量、种类（近战 / 远程 / 爆炸 / 飞行）、是否正在追我、距离
地形：是否会被包围、能不能卡位、附近有没有岩浆或悬崖
结论：能赢 / 有风险 / 打不过
```

它决定：被攻击时还手还是撤离；床边有怪时清怪还是带床换地方；夜里露天要不要躲。"想不想打"由授权（M7 的 `combat`）表达：`defend` 表示不主动打，只自卫。

- 吃饭、睡觉、撤离这类"差事"做完就结清，回到原任务。**它们没做成，也绝不会把主任务判失败**（AGENTS.md 已有此原则，这里变成机制）。
- 被抢占期间，主任务的进度表暂停计时。
- 没吃的而且饥饿已到 HARMFUL：作为一件有预算的差事，调用 M4 去弄吃的。
- 寻死这类显式任务，通过 M7 把维护设为"暂停"，不需要在仲裁里开后门。

旧开关到新模型的映射：

| 旧开关 | 新模型 |
| --- | --- |
| `suppressesSurvivalReflexes`（寻死） | M7 授权：`upkeep = SUSPENDED` |
| `onlyWhenBodyReleased`（贴边退避） | 该需求的紧急程度是 COMFORT |
| `urgentBodyRescue`（被埋窒息） | 该需求的紧急程度是 LETHAL |
| `drivesBodyContinuously`（水中攀沿） | 当前任务报 DELICATE |
| `yieldsToContinuousDriving`（换气让位） | 换气需求在氧气尚可时是 HARMFUL，危急时升为 LETHAL |

**吸收掉的现有实现**：`Task` 上的 5 个开关；`TaskSelector` 的豁免链；6 条反射链（`MLGChain`、`BreathChain`、`SettleChain`、`MobDefenseChain`、`NightRestChain`、`SuicideArmorRestore`）改写为需求；施工、打龙、挖矿、战斗里各自的吃饭逻辑；15 处各自读取饥饿值；夜间自动休息改为复用睡觉能力的行为，不再另写一套。各种"提醒"变成"伙伴自己解决不了的需求 → 通过 Attention 告诉 LLM"。

**已定**：夜间自动睡觉默认开启。各项阈值在实现时给出初值，按实机观感调整。

## M7 授权与保护

**真人伙伴的分寸**：默认会为了干活挖开天然的土、石、木，搭临时方块并在用完后收回，反击敌对生物，为了具体需要（吃的、羊毛、皮革）处理野生动物，使用和取用野外、村庄、遗迹里不属于任何玩家的东西。默认绝不碰玩家的东西：玩家盖的房子、玩家的箱子和机器、记住的区域、有名字或被驯服的动物、围栏里的牲畜；不用稀有消耗品（末影珍珠、不死图腾、钻石……）。

**统一逻辑**：

```text
Mandate（授权）= 默认档 + 本次任务的覆盖（goal.mandate）
  terrain     none | temporary | natural（默认）| any
              natural：天然方块，以及不属于任何玩家的物件（村庄的床、废弃矿井的铁轨……；这类放在最后考虑）
              any：一切不受保护的格子
  combat      defend（只自卫）| hostile（默认，主动处理敌对生物）| any
  rare_items  false（默认）| true
  animals     none | wild（默认）| any
              wild：野生、无名、未驯服、未拴绳、不在围栏里的普通动物，可以为具体需要而击杀；剪毛、挤奶不算伤害
  upkeep      on（默认）| off（只有寻死这类显式任务可以设）
  protect     [地标名…]   额外不许碰的地方

Protection（保护判定，全仓只此一处）=
  玩家施工归属记录 ∪ 记住的区域 ∪ protect 列表 ∪ 判定为"玩家放置"的方块（含玩家区域里的容器和功能方块）
  ∪ 有名字 / 被驯服 / 拴绳 / 围栏里的生物

所有改变世界的动作都经过 Mandate.permits(动作, 目标)，这是唯一的授权检查点
LLM 明确点名的目标（例如"拆掉这面墙"的 seen 句柄），视为对这个目标的授权
被拒时：blocker = NEED_CONSENT，写清楚需要哪一档授权、涉及哪些格子或生物；不再让 LLM 猜该开哪个开关
```

**对 LLM 的影响**：12 种、共 44 个分散在各能力里的 `may_*` / `allow_*` 开关，收成 `goal` 上一个可选的 `mandate` 对象；`observe(self)` 显示当前默认授权。"失败 → 带新开关重提"的循环随之消失。

**保留的游戏事实**：客户端无法确定一个方块是天然生成的还是玩家放的。v2 由服务端记录"谁放了哪一格"（02 第 3 节），归属以记录为准；记录之外的方块（例如装上 v2 之前就存在的建筑）仍靠玩家区域和方块类别推断，**拿不准就按受保护处理**。

**已定（2026-10-08）**：采用上面的"讲道理的伙伴"默认档，怎么合理怎么来。

## M8 尝试、放弃与求助

**真人怎么做**：一种办法不行就换一种；还在往前推进就继续，原地打转就换办法；都不行就停下来，说清楚做了什么、卡在哪、要什么才能继续。只有真的需要别人拿主意时才开口问。

**统一逻辑**：

```text
进度      ProgressMeter：真实进展续期，停滞超过窗口才算卡住，另有硬上限
尝试      Attempts：每个步骤一组排好序的策略
          按 blocker 类型决定：同一策略再试 / 换下一个策略 / 结束；同一种失败不超过上限
求助      只在三种情况下向 LLM 提问（Decision）：
          ① 需要超出授权的同意（NEED_CONSENT）
          ② 存在后果不同的多个选择，Mod 不该替人选（拆哪面墙、动哪个箱子里的贵重材料）
          ③ 目标本身有歧义（例如有几个同名地标）
          其他情况一律内部重试，或带着事实结束。永远不问"要不要重试"。
```

**统一回执**（所有能力同一个结构）：

```text
outcome     done | partial | failed | cancelled
achieved[]  已确认发生的效果（物品入包、方块变化、消耗、存放、丢弃）
remaining[] 没完成的部分
blocker     { kind, fact, unblock }   卡点（游戏事实）+ 什么能解除它
uncertain[] 已提交但未确认、不能盲目重试的操作
attempts[]  尝试过的策略摘要（不是逐刻日志）
```

`blocker.kind` 保持小而稳定：`NEED_ITEM`、`NEED_TOOL`、`NEED_CONSENT`、`UNREACHABLE`、`TARGET_GONE`、`DANGER`、`NATIVE_REFUSED`、`TIME_WINDOW`、`WORLD_RULE`、`INVENTORY_FULL`、`STALLED`（换过办法仍原地打转）、`UNSUPPORTED`、`INTERNAL`。定义见 `kernel.outcome.Blocker`。

**吸收掉的现有实现**：`FailureType`（19 种，附带教 LLM 重提的提示）、没人调用的 `RecoveryLadder`、`RecoveryAdvisor`、`RecoveryKnowledge`、`ProgressGate`、447 个失败出口、109 个提问出口里的大部分、效果账本。

这同时把 AGENTS.md 里"原生动作成功与目标达成分开判断"落成了数据结构：`outcome` 管目标，`achieved` 和 `uncertain` 管动作。

## M9 世界记忆

**真人怎么做**：记得箱子在哪、里面大概有什么；记得在哪见过矿、村庄、结构；记得家和床的位置。到了现场会再看一眼确认。太久以前的记忆不会全信。

**统一逻辑**：`WorldMemory` 存带类型的事实：`{种类, 位置或区域, 内容, 观察时刻, 来源（亲眼看见 / 打开过 / 推断）}`。可以按种类和距离查询。使用方到场必须复核（项目已有"索引结果使用前必须核对实际世界"的纪律，这里推广为所有记忆）。可信度随时间下降。按世界身份存在 SQLite 里。

**吸收掉的现有实现**：地标、容器记忆、资源目击记忆（`ObservedSourceMemory`）、`ExplorationMemoryStore`、结构目击、地形特征记忆，以及 46 处通过 `IntentRuntime.get()` 取记忆的调用。

## M10 出行

**真人怎么做**：近的走过去；远的疾跑、骑乘或飞；有电梯就坐电梯；跨维度走传送门；路被挡就绕，绕不过去才挖或搭（被允许的话）；不在悬崖边乱跳；天黑带火把。

**统一逻辑**：

```text
TravelPlanner.plan(目的地, 授权) → 若干段行程，每段由一个 TravelProvider 负责
  步行（Baritone 引擎，地形权限来自 M7）、喷气背包、飞行器、Create 电梯、传送门、船
进度：以剩余距离为进展信号（M8）
锚点纪律：不把高度未核实的坐标直接交给步行引擎
  → 先走到那一列附近，到场后再解析出可站立的格子
  （这是睡觉"177 实机"事故的通用版：引擎会对着永远到不了的高度空转）
```

**吸收掉的现有实现**：`MoveToCompanionTask`、`RegionalTravelTool`、`TravelSurfaceTool`、`BoardStructureTool`、`JetpackRoute` / `JetpackDepartureApproach`、`ElevatorTravelIntent`、`AircraftTravelIntent`、`DimensionTravelCompanionTask`、`PortalApproach`、睡觉里的 `verifiedGroundAnchor`。

## M12 感知：LLM 看到玩家看到的

**真人怎么做**：看一眼屏幕就知道：前面是缓坡还是悬崖，左边有条河，右边两只羊，远处有片林子，身后是自己的木屋；听到身后有苦力怕的嘶嘶声就回头。能指着东西说"那只羊""那个洞口""左边那个箱子"。墙后面的东西看不见，但记得。

**现状**（01 症状 9）：LLM 只拿到"7.3 格外有只僵尸"这种没有方向、没有位置、不能指着的列表；项目里现成的以角色为中心的俯视网格（`LookAroundTool`）只是内部工具，LLM 用不上；没有任何声音感知。

**统一逻辑**：

```text
Scene（场景模型）：一份，按需增量更新，所有视图都从它投影
  身体      位置、朝向、生命、饥饿、氧气、手持、护甲、状态效果、落地或入水
  实体      每个一个短期句柄 e#：类型、名字、方位、距离、高低差、是否看得见、是否敌对、
            是否正盯着我，以及看得出来的特征（羊的颜色、是否剪过毛、幼年、着火、手持物、盔甲）
  声音      原版字幕事件：声音种类 + 方位，用来知道"看不见但就在附近"的东西
  近场      以角色为中心的俯视语义网格：平地、上台阶、下台阶、落差、墙、水、岩浆（复用 LookAroundTool）
  地形特征  悬崖、水体、洞口、树林、建筑、村庄、结构、岩浆池……每个一个句柄 f#：方位、距离、规模
  设施      箱子、工作台、熔炉、床等，每个一个句柄 b#：方位、距离、上次看到的内容
  环境      时间、天气、光照、生物群系

方位语言（全项目统一，回执和直播解说也用它）
  相对朝向：前方、前方偏左、左侧、后方……；罗盘方向：北、西北……；距离；高低差

可见性纪律
  "看见" = 在渲染范围内，且视线没被挡住（刚看见过的保留很短的时间）
  墙后的东西不报成看见；声音只给方位和远近，不给精确位置
  写进 M9 记忆时标明来源：看见、听见、推断

句柄
  e# / f# / b# 在同一会话里短期有效；所有能力的 target 都接受 {kind: "seen", ref}
  句柄过期时，能力以 TARGET_GONE 结束，并说明最后一次在哪个方位看到它
  同时也给出坐标，LLM 需要时可以用，但不要求 LLM 用坐标思考
```

**吸收掉的现有实现**：`mcp` 下的 `PerceiveSections`、`NearbyCollisionPerception`、`NearbyFacilityPerception`、`NearbySignPerception`、`PhysicalStructurePerception`、`PhysicalDeckSampler`、`NavigationOverview`、`StructurePerceptionJson`；`core/tools/perception` 下的 `LookAroundTool`、`ScanBlocksTool`、`ScanNearbyEntitiesTool`、`LocalFloorSense`、`BodyEnvironmentObservation`、`GetSelfStatusTool` 等；各能力里各自实现的"找最近的某种东西"。

**对 LLM 的影响**：视图形状见 07 第 7 节。LLM 可以指着东西下指令；直播解说可以直接复述 `summary` 里的方位速写。

**保留的原则**：AGENTS.md 的"不得在中间层悄悄删掉决策事实"。场景列表默认完整；数量很大时按距离分组并给出总数，而不是截断。

## 4. 怎样把旧逻辑分诊进模型

实现一个领域之前，执行 Agent 先把 v1 中该领域的旧逻辑逐条清点出来，做成"规则清册"（模板见 05）。每一条都归入下面五类之一：

| 类 | 判断标准 | 处理 | 例子 |
| --- | --- | --- | --- |
| **F 游戏事实** | 原版或模组本身就这样运作，与我们的设计无关 | 保留；放进它该归属的模型或平台层，全仓只留一份 | 下界、末地用床会爆炸；醒来的实体包和时间包不在同一刻到达；服务端床距离盒；客户端预测需要连续稳定刻确认 |
| **C 玩家常识** | 讲道理的玩家本来就会这么做 | 保留，作为模型里的策略 | 背包满先扔垃圾；挖之前先换对的工具；睡觉前先确认够得着床 |
| **P 补丁** | 为了弥补别的组件的缺陷而加的 | 删除；由重设计的模型从根上解决，并用原事故场景验证 | `Task` 上的 5 个反射开关；睡觉的"白天门"决策中继与防重问三态；睡觉专用的换位重试 |
| **G 预测门控** | 还没尝试，就因为"预测会失败"而拒绝 | 删除（AGENTS.md 明令禁止） | "床区高度核验不了，所以拒绝前往"——改为先走近，到场再看 |
| **S 过严 / 无意义** | 拒绝了玩家本来会直接去做的事，或者只为校验而校验 | 删除或放宽 | 授权开关全部默认关闭；参数宽松和严格两套标准并存；能自己补的前置却去问 LLM |

注释里出现的实机事故编号（如"177 实机""145 批七"）是很重要的线索：它说明这条规则背后有一个真实场景。**删除 P、G、S 类规则时，要用这个场景验证新模型确实处理好了它**——进离线场景测试，或者进实机验收清单。

## 5. 领域规格模板

每个领域实现之前，都要有一份按这个模板写的规格，经两位批准后才开工。完整样板见 [06-试点规格-睡觉](06-试点规格-睡觉.md)。

```text
1  范围         包含哪些能力；涉及的旧文件清单与行数
2  真人怎么做   一段话
3  新逻辑       流程；组合了哪些模型（M1–M12）；本能力自己特有的部分
4  契约         参数表（ParamSpec）；回执里本能力特有的字段
5  旧逻辑分诊表 编号 | 位置 | 内容 | 类别（F/C/P/G/S）| 去向（保留到哪 / 删除 / 由 Mx 取代）
6  行为变化清单 之前 → 之后，供拍板逐条过目
7  游戏事实归属 每条 F 类事实的新位置
8  删除清单     要删除的类、方法、测试
9  验收         离线场景测试清单 + 实机验收清单（包含第 5 节里所有 P/G/S 规则的原事故场景）
10 待拍板
```

## 6. 领域顺序

v2 按里程碑实现领域，每个里程碑对应一类直播可以从 v1 切过来（详见 04）：

| 里程碑 | 领域（v2 能力，见 07 第 8 节） | 主要依赖的模型 |
| --- | --- | --- |
| 一 生存开局 | 睡觉（试点，06）、`eat` / `equip` / `drop`、`use` / `container`、`obtain`（基础来源）/ `gather`、`travel`（步行）/ `find`、`fight`（基础）/ `follow` / `wait`、`remember` / `chat` / `sequence` | M1–M12 的基础部分 |
| 二 建造与采矿 | `build` / `blueprint` / `light`、`explore`、`fish`、`enchant`；`obtain` 补齐交易、狩猎、随身背包；`travel` 补齐跨维度 | M4、M10 补全 |

横切模型不一次做完：做到当前里程碑用得到的程度即可。
