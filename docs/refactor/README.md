# MaiCraftMod 重构设计总览

> 设计：Claude（Opus 5.5），2026-10-08
> 执行：ChangingSelf 及其 Agent
> 拍板：LittleSadSheep、ChangingSelf

## 结论

先把整个项目从入口到测试、从 Mod 到 Amaidesu 宿主逐层看了一遍（[00-全景审查](00-全景审查.md)），再下的结论：

> **新仓库重建 v2，v1 冻结维护。**

- v1 冻结：不再加功能，只修影响直播的问题；继续承担直播，直到 v2 在对应里程碑达到切换标准。
- v2 在新仓库从零按新架构建设。v1 里已证明正确的底座按移植清单搬过去：身体端口与对账协议、导航与 Baritone、SQLite、MCP 传输、知识库、构建与 CI。其余全部按领域规格重写。
- 直播按里程碑分批切到 v2：生存开局 → 建造与采矿 → 机器 → 载具与飞行。
- Amaidesu 新增面向 v2 的 Minecraft Agent，通过配置在 v1 / v2 之间选择。

为什么不原地重构、为什么不在同一个仓库里渐进替换、要付出什么代价、怎样防止 v2 重新长成一座屎山，见 00 的结论一节。

总的取舍原则（LittleSadSheep，2026-10-08）：**怎么合理怎么来**；这是直播项目，**能做事就不干等**。

## 完成标准（整体）

- 内核层（`kernel`）和平台层（`platform`）不认识任何具体能力：不出现能力 ID 字面量，也不出现具体任务单类型。由 ArchUnit 强制。
- 新增一个能力只需要：写它自己的包，在启动清单里加一行，再补契约资源、能力文档和更新日志。
- 同一条游戏事实（伸手距离、睡眠窗口、背包满、饥饿……）全仓只有一处实现。
- LLM 通过 `observe` 能看到玩家视野里的地形和实体，知道它们在哪个方向、多远，并能用观察句柄直接指定目标。
- 每个能力都有契约快照和场景测试；测试不反射进私有实现。
- 任何"拒绝执行 / 提前失败"都登记了类别（03 第 4 节五类），P、G、S 类不存在。
- 四个里程碑全部达标，所有直播使用 v2，v1 归档。
