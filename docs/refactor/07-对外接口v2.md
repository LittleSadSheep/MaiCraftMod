# 07 对外接口 v2

对外接口是 LLM 认识这个伙伴的唯一途径。它要做到两件事：**LLM 不用读说明书就能猜对怎么用**，以及**LLM 能看到玩家看到的东西**。v1 两件都没做好（见 01 症状 9，以及 00 第 1、2 层的发现）。

接口的使用方有两个：

- **LLM**：通过 Amaidesu 宿主调用，宿主会把工具改名为 `maicraft_*`；
- **宿主程序**：开局读取状态、等待任务事件、分页回读回执。

v2 为这两个使用方分别设计，不再让一个工具同时服务两者。

## 1. 设计原则

1. **一个工具只做一件事；一个参数只有一种含义。** v1 的 `perceive` 一身兼五职（观察、查能力、查知识库、上网、等事件），`focus` 一个参数有六种含义。
2. **工具描述里不写具体能力的特例。** 某个能力的用法只写在它自己的契约里。
3. **平铺的 schema，不用 `anyOf` / `oneOf`。** 已经实测有宿主（MiniMax）解析不了 `anyOf`。要表达"多选一"，就拆成两个工具或两个字段。
4. **藏执行细节，不藏观察事实。** 路线、点击、槽位不给 LLM；看到的东西是什么、在哪、怎么指着它，全部给。
5. **同一个概念全接口只有一个名字**（第 5 节词汇表）。
6. **所有返回同一个信封**（第 6 节），所有能力同一个回执结构（03-M8）。
7. **默认值就是讲道理的玩家会做的事**：授权用 M7 的默认档；数量、范围有合理默认；布尔参数默认 `false` 时表示"不做特别的事"，不用布尔参数表示许可。

## 2. 工具集

| 工具 | 给谁 | 做什么 | 取代 v1 |
| --- | --- | --- | --- |
| `observe` | LLM | 看世界和自己：身体与背包、周围场景、某个观察对象的细节、记忆里的地点 | `perceive` 的 situation / surroundings / landmarks / exploration |
| `lookup` | LLM | 查资料：能力目录与契约、离线知识库、Minecraft Wiki、配方 | `perceive` 的 abilities / knowledge / web_knowledge |
| `execute` | LLM | 开始做一件事；`dry_run=true` 只检查、不动手 | `execute` + `plan` |
| `task` | LLM | 查看、暂停、恢复、取消任务，回答任务提出的问题，分页读证据 | `task` |
| `wait` | 宿主（也可开放给 LLM） | 等任务事件，用游标续读 | `perceive(view=attention)` |

依然是 LLM 面对 4 个工具，但每个都只做一件事。

一些 v1 里塞在 `perceive` 里的**领域分析**（施工场地勘测 `construction_site`、Create 动力源 `kinetic_sources`、机器菜单、探索目录），改为**只读能力**，通过 `execute` 调用并当场返回报告。它们有自己的参数和契约，不再污染观察工具的参数表。原则是：**`observe` 只管"玩家此刻能看见什么"；需要分析、计算的，都是能力。**

### 2.1 `observe`

| 参数 | 含义 |
| --- | --- |
| `what` | `self`（身体、背包、装备、当前任务一句话、当前授权）、`scene`（周围场景，默认）、`detail`（一个观察对象的细节）、`memory`（记住的地点、已知容器、目击过的资源与结构） |
| `ref` | 只在 `what=detail` 时用：观察句柄（`e12`、`f3`、`b5`）或地标名 |
| `grid` | 只在 `what=scene` 时用：`true` 时附带近场俯视语义网格（原 `LookAroundTool`） |

返回内容见第 7 节。

### 2.2 `lookup`

| 参数 | 含义 |
| --- | --- |
| `topic` | `abilities`（默认）、`knowledge`、`wiki`、`recipe` |
| `id` | 精确条目：能力 ID、知识 URI、物品 ID |
| `query` | 关键词搜索；与 `id` 二选一 |
| `url` | 只在 `topic=wiki` 时用：直接读一篇条目 |

不带 `id` / `query` 的 `lookup()` 返回全部能力的一行签名：名称、用途、参数名与类型。宿主开局可以直接把它放进上下文。

### 2.3 `execute`

| 参数 | 含义 |
| --- | --- |
| `goal` | 目标（第 3 节） |
| `dry_run` | `true` 时只做校验和预检（原 `plan`），返回 `plan_id` 和发现的问题 |
| `plan_id` | 执行一次 `dry_run` 通过的计划；与 `goal` 二选一 |
| `request_key` | 网络重试用的幂等键；不给时由入口自动生成 |

只读能力（`mode=READ_ONLY`）在 `execute` 里当场返回报告，不占身体，也不产生后台任务。

### 2.4 `task`

保持 v1 的动作集合：`get`、`list`、`pause`、`resume`、`cancel`、`answer`。改动只有一处：工具描述里不再出现任何能力的特例，问题的选项说明写在问题本身里。

### 2.5 `wait`

参数：`task_id`、`stream_id`、`after_cursor`、`wait_ms`，语义与 v1 的 attention 完全相同（游标、重同步、唤醒原因）。拆成单独工具，是为了让宿主可以只把它留给自己用。

### 2.6 去掉的东西

| 去掉 | 原因 |
| --- | --- |
| 每个工具都带的 `server_id` | Mod 里没有任何代码读取它；如果宿主路由需要，由宿主自己处理 |
| 附加在每个工具返回值里的 `reminders` | 伙伴自己能处理的需求交给 M6；处理不了的作为 Attention 事件推送，并显示在 `observe(self)` 里，不再随每次调用重复出现 |
| `perceive` 的 `detail=names/summary/signatures`、`sections`、`limit/offset` 混用 | `lookup()` 默认就返回签名；分页只出现在确实需要分页的地方（`task get` 的证据） |

## 3. 目标（goal）

```json
{
  "ability": "maicraft:sleep",
  "outcome": "天黑了，去睡觉",
  "target": { "kind": "landmark", "name": "家" },
  "parameters": {},
  "mandate": { "combat": "defend" },
  "children": [],
  "on_failure": "stop"
}
```

| 字段 | 必填 | 说明 |
| --- | :---: | --- |
| `ability` | ✅ | 能力 ID |
| `outcome` | | 一句话说明想要什么，只用于日志和直播解说，Mod 不据此行动。v1 是必填，v2 改为可选 |
| `target` | | 统一目标模型（第 4 节） |
| `parameters` | | 本能力的参数，由它的 `ParamSpec` 定义 |
| `mandate` | | 本次任务的授权覆盖（03-M7），省略时使用默认档 |
| `children` | | 只用于 `maicraft:sequence` |
| `on_failure` | | 只用于 `sequence` 的子步骤：`stop` / `continue` |

**删除 `preferences` 和 `constraints`**：v1 里没有任何一个能力接受它们（所有声明都是空的），却要求每次调用都带上这两个空字段。

## 4. 统一目标模型（target）

全接口只有这一种"指一个地方或一个东西"的方式：

| kind | 字段 | 含义 | 取代 v1 |
| --- | --- | --- | --- |
| `here` | — | 当前位置 | `current_place` |
| `seen` | `ref` | 观察句柄：`e#` 实体、`f#` 地形特征、`b#` 方块或设施 | `entity`、`nearest` 的大部分用法 |
| `landmark` | `name` | 记住的地点，或附近告示牌上的文字 | `landmark`、`area` |
| `position` | `x`、`z`，可选 `y`、`dimension` | 坐标；**`y` 可以省略**，到场后再解析可站高度（M10） | `coordinates`，以及 `travel` 的 `parameters.destination` 特例 |
| `player` | `name` | 一位玩家 | `player` |
| `direction` | `bearing`、`distance` | 方向加距离："往北 100 格"、"往前 20 格" | 新增 |
| `previous` | 可选 `step` | 前面某一步确认过的位置 | `prior_result` |

- "某片区域"等于任意 target 加上 `parameters.radius`。
- "最近的某种东西"不再是一种 target：要么先 `observe` 拿到句柄再用 `seen`，要么由能力自己按参数去找最近的（例如 `use` 一台熔炉时只给 `block`）。
- 句柄过期（实体走远、方块被拆）时，能力以 `blocker = TARGET_GONE` 结束，并说明最后一次看到它的方位。

## 5. 参数词汇表

| 概念 | 名字 | 类型与规则 | v1 的各种写法 |
| --- | --- | --- | --- |
| 物品 | `item` / `items` | 物品 ID，或 `#` 开头的标签（`#minecraft:logs`） | `item_id`、`item_ids`、`item_tag`、`item_tags`、`item_resource_id`、`ingredient_item_id`、`output_item_id`…… |
| 方块 | `block` / `blocks` | 方块 ID 或标签 | `block_id`、`block_ids` |
| 实体类型 | `entity` | 实体类型 ID | `entity_type_id`、`entity_type_ids` |
| 数量 | `count` | 获取类能力表示"**再多几件**"；动作类能力表示"**做几次**"。每个能力的契约里明确写是哪一种 | 已统一的部分保留 |
| 范围 | `radius` | 工作或搜索范围，单位格 | `radius`、`search_radius`、`max_search_radius`、`horizontal_radius`、`source_radius`…… |
| 距离上限 | `max_distance` | 出行或搜索的最远距离，单位格 | `max_distance`、`max_search_distance`、`max_resource_search_distance`、`max_portal_search_radius`…… |
| 时间上限 | `max_seconds` | 单位秒，不用游戏刻 | `max_wait_seconds`、`max_duration_ticks`、`timeout_seconds` |
| 子动作 | `action` | 一个能力内部的少数几种操作（`enable` / `disable` / `status`，`deposit` / `withdraw`） | 各种 `op`、`mode`、`operation` |
| 保护 | `mandate.protect` | 不许碰的地标名 | 散在各能力里的 `protected_labels` |
| 许可 | `mandate.*` | 地形、战斗、稀有物品、伤害动物 | 12 种 `may_*` / `allow_*` 共 44 个开关 |

规则：

- 单位用人能直接理解的：格、秒、件。
- 新能力**只能**使用词汇表里的名字；确实需要新概念时，先加进词汇表，再在能力里使用。
- 宽松写法（`"6"` → `6`、`"true"` → `true`、参数放错一层）只由入口统一处理，并在返回的 `notes` 里说明做过哪些规范化。

## 6. 返回信封与错误

所有工具返回同一个结构：

```json
{
  "ok": true,
  "data": { },
  "notes": ["parameters.count: \"6\" 按整数 6 处理"],
  "next": { "tool": "wait", "arguments": { "task_id": "…", "stream_id": "…", "after_cursor": 42, "wait_ms": 30000 } }
}
```

失败时：

```json
{
  "ok": false,
  "error": {
    "code": "invalid_parameter",
    "field": "goal.parameters.count",
    "message": "count 必须是 1 到 256 的整数",
    "expected": "integer 1..256",
    "example": { "ability": "maicraft:obtain", "parameters": { "item": "minecraft:torch", "count": 8 } }
  }
}
```

- `error.code` 是一个小而稳定的枚举：`invalid_parameter`、`unknown_ability`（附相近能力建议）、`unknown_ref`、`not_in_world`、`busy`、`internal`。
- 校验错误一次报全，而不是改一个错报下一个。
- 任务的结果走 03-M8 的统一回执，不放进错误：**工具调用成功、任务失败**是两回事。

## 7. 感知视图（`observe`）

M12 的设计见 03。这里只定义 LLM 看到的形状。

### 7.1 `observe(what="scene")`

```json
{
  "time": "夜晚，距天亮约 4 分钟", "weather": "晴", "light": 4, "biome": "minecraft:plains",
  "facing": "北",
  "summary": {
    "前方": "缓坡向上，约 30 格外有一片橡树林（f2）；12 格外一只僵尸正朝我走来（e7）",
    "左侧": "一条河，宽约 8 格（f3）",
    "右侧": "开阔草地，两只羊（e8、e9）",
    "后方": "我搭的木屋（f1，记住的地点“家”），门开着",
    "上下": "脚下是草方块，地下 4 格处听到流水"
  },
  "entities": [
    { "ref": "e7", "type": "minecraft:zombie", "bearing": "前方偏左", "compass": "西北", "distance": 12, "dy": 1,
      "visible": true, "hostile": true, "targeting_me": true },
    { "ref": "e8", "type": "minecraft:sheep", "bearing": "右侧", "distance": 9, "visible": true,
      "traits": { "color": "white", "sheared": false, "baby": false } }
  ],
  "heard": [ { "sound": "苦力怕嘶嘶声", "bearing": "后方", "distance": "很近" } ],
  "features": [
    { "ref": "f2", "kind": "tree_cluster", "species": "oak", "bearing": "前方", "distance": 30, "size": "约 20 棵" },
    { "ref": "f3", "kind": "water", "bearing": "左侧", "distance": 6, "size": "河流，宽约 8 格" }
  ],
  "facilities": [ { "ref": "b5", "block": "minecraft:chest", "bearing": "后方", "distance": 7, "inside": "f1" } ]
}
```

- `summary` 是给 LLM 和直播解说用的方位速写，由场景模型生成。它和下面的结构化列表一致，不是另编的文字。
- 列表是完整的（AGENTS.md：不得悄悄截断决策事实）；只有数量真的很大时，才按距离分组并给出总数，而不是丢掉条目。
- `visible=false` 的实体只会出现在 `heard` 或记忆里，不会冒充"看见了"。

### 7.2 其他

| 视图 | 内容 |
| --- | --- |
| `observe(what="self")` | 生命、饥饿、氧气、护甲、状态效果；坐标与朝向、维度、是否落地或入水；背包（按物品合并）、装备、手持；当前任务一句话；当前授权；伙伴自己解决不了的需求（原提醒） |
| `observe(what="detail", ref=…)` | 实体：可观察特征、手持与盔甲、是否正盯着我；地形特征：范围、边界、可通行性；容器：最近一次打开时看到的内容与时间；告示牌：全文 |
| `observe(what="memory")` | 记住的地点、已知容器、目击过的资源与结构，按距离排序，每项带句柄与记录时间（M9） |

## 8. 能力目录 v2（草案）

v1 有约 50 个能力，粒度从"吃一口东西"到"拿到鞘翅"不等，好几组能力的结果互相重叠，契约一半中文一半英文。v2 的规则：

- **一个能力等于一个玩家能用一句话说清的意图**，并且有明确的完成标准；
- **两个能力的结果不重叠**；需要区分途径时，用参数（例如 `via`），不新开能力；
- **长线目标由 LLM 规划**，不在 Mod 里写死。Mod 只提供 LLM 无法实时完成的部分（例如打龙时躲龙息、射水晶这类快速反应），Amaidesu 已有 `skills/progression` 这类攻略文档；
- 契约统一用中文（直播和解说都用中文），字段名用英文。

| v2 能力 | 一句话 | 吸收的 v1 能力 |
| --- | --- | --- |
| `obtain` | 让背包里某样东西再多几件；可用 `via` 指定途径 | `acquire_items`、`craft`、`cook`、`stonecut`、`trade` |
| `gather` | 采掉、收获、捡起世界里指定的东西 | `harvest_block`、`collect_items` |
| `fish` | 钓鱼 | `fish` |
| `travel` | 去一个地方（含跨维度、乘电梯、飞行） | `travel`、`travel_dimension`、`prepare_portal`，以及 `fly_vehicle` 的出行部分 |
| `find` | 找到某种方块、生物、结构或群系，返回句柄 | `find_block`、`find_entity`、`find_structure`，以及 `explore` 的发现部分 |
| `explore` | 往某个方向勘察地形 | `explore` |
| `fight` | 打指定目标，或清掉一片区域的敌怪；包括末影龙 | `combat`、`defeat_ender_dragon` |
| `use` | 对一个方块或实体使用手上的东西（开门、按按钮、拉杆、剪羊毛、挤奶、骑乘、点火……） | `interact`、`use_item`、`use_container` |
| `container` | 往容器里存、取、整理 | `manage_container` |
| `equip` | 穿戴、手持、卸下 | `equip` |
| `eat` | 吃东西 | `consume` |
| `drop` | 丢掉指定物品 | `drop_items` |
| `sleep` | 睡觉 | `sleep` |
| `follow` | 跟随 | `follow` |
| `wait` | 等一个条件 | `wait_for_condition` |
| `chat` | 发消息或命令 | `chat` |
| `remember` | 记住或忘掉一个地点 | `remember_place` |
| `blueprint` | 设计、修改、预览建筑模型（只读，不动手） | `design_build` |
| `build` | 按模型施工（单个方块就是一格的模型） | `build`、`place_block` |
| `light` | 给一片区域补光，或开关随行补光 | `light_area`、`auto_light` |
| `enchant` | 附魔 | `enchant` |
| `machine_*` | 机器的查看、设计审阅、施工与修改、操作、接动力 | `inspect / design / build / modify / operate_machine`、`connect_mechanical_power`；具体拆分在机器领域规格里定 |
| `vehicle_*` | 物理载具的组装、配平、操控、飞行 | `physical_assembly`、`physical_balance`、`physical_control`、`fly_vehicle`；具体拆分在载具领域规格里定 |
| `quest` | FTB 任务的提交与领奖 | `quest_action` |
| `suicide` | 主动寻死（keepInventory 下用于回家） | `suicide` |
| `sequence` | 按顺序做几件事 | `sequence` |
| （删除） | 由 LLM 按攻略规划 | `reach_milestone`、`obtain_elytra` |

能力 ID 统一用"动词"或"领域_动词"形式。目录从约 50 个收到约 30 个。**这是草案**：每一行的最终取舍，在对应领域规格里决定，并经两位批准。

## 9. 迁移方式

- v2 从第一天起只提供本接口，不兼容 v1 的四个工具和 v1 的能力目录。
- Amaidesu 新增一个面向 v2 的 Minecraft Agent，通过配置在 v1 / v2 之间选择（Harness 本来就支持按配置选 Agent）。v1 的 Agent 原样保留，继续服务还没切换的直播类型。
- 能力目录随里程碑增长（04）。每加一个能力，契约快照的 diff、`CHANGELOG.md`、v2 Agent 的提示词与 skills 同步更新。
