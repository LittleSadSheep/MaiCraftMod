# 08 实现规范（v2 的代码怎么写）

02 定的是"包和层"，03 定的是"游戏行为"，这一份定的是**一个类、一个方法该怎么写**。v1 的很多问题出在这一层：

| 现状 | 数量 |
| --- | ---: |
| 执行层（`core/task`、`core/integration`）里直接读写 `JsonObject` 的文件 | 193 |
| `Map<String, Object>` 的出现次数（回执、进度、诊断几乎全用它） | 1129 |
| 一个执行器的私有字段数（`FirstPersonBuildCompanionTask`） | 108 |
| 同一个执行器里的 `if` | 525 |
| 静态工具类 `*Ops` | 13 个，2038 行 |
| `TaskRecord.setState` | 不校验状态迁移，任何状态都能改成任何状态 |
| 失败类型 | 一部分用字符串比较（`"occluded".equals(...)`） |

本规范约束 v2 的全部代码，包括从 v1 移植过来、又做过整理的文件。

## 1. 一个能力包的标准结构

```text
ability/sleep/
├─ SleepModule.java          注册入口：描述符、翻译、执行器工厂（唯一对外的类）
├─ SleepParams.java          类型化参数 record + ParamSpec
├─ SleepPlanner.java         翻译：Goal + 现场 → 下一个动作（纯函数为主）
├─ SleepExecutor.java        执行器：按阶段推进
├─ SleepFacts.java           本能力特有的回执事实 record
├─ BedChooser.java           本能力特有的决策（纯函数，可离线测试）
└─ （api/、spi/ 仅在确有外部使用方时才建）

resources/assets/maicraft/abilities/sleep.md      契约正文
test/…/ability/sleep/                             离线场景测试
```

除了 `SleepModule`，包里的类一律包内可见（不写 `public`），让 Java 本身挡住跨能力的内部依赖。

## 2. 类型纪律

| 规则 | 说明 |
| --- | --- |
| **`JsonObject` 只出现在入口** | `ParamSpec` 在入口把参数解析成 record，翻译和执行器只用 record。执行器从不 `getAsInt` |
| **回执用 record，不用 Map** | 每个能力定义自己的 `Facts` record；统一回执（03-M8）由 `Outcome` record 表达；序列化成 JSON 是入口的事 |
| **失败用枚举** | `Blocker.Kind` 是枚举；任何地方不比较失败字符串 |
| **状态用枚举阶段，不用布尔字段** | 执行器的进度是一个 `Phase` 枚举，加上每个阶段自己的少量数据。禁止用 `boolean enteredSleep; boolean morningObserved; boolean nightSkipped…` 拼出隐式状态机 |
| **任务单是不可变输入** | 任务单（record）只描述"要做什么"；执行中的可变状态只在执行器里。状态迁移由内核校验（`PENDING → RUNNING → 终态`，终态不可再改） |
| **不用静态可变状态** | 服务从构造函数注入（`RuntimeServices`、行为模型）。不写 `X.get()` 单例，不写 `static` 可变字段 |
| **不用静态工具类装业务逻辑** | 业务规则属于某个模型或能力；纯几何、纯数学的小工具可以是静态方法 |
| **时间单位** | 内部用游戏刻；对外（参数、回执）用秒；换算只在入口和回执组装处做 |

## 3. 执行器的写法：阶段

v2 所有执行器都继承同一个基类：

```java
/** v2 执行器的基类：按阶段逐刻推进，每个阶段只关心自己的事。 */
public abstract class PhasedExecutor<P extends Enum<P>, R extends TaskRecord> implements Task {

    /** 进入某个阶段时调用一次：创建这个阶段要用的子步骤（靠近、操作、菜单、取物……）。 */
    protected abstract void enter(P phase);

    /** 每刻推进当前阶段，返回留在原阶段、换阶段、完成或失败。 */
    protected abstract Next<P> tick(P phase, Ctx ctx);

    /** 本能力特有的回执事实。 */
    protected abstract Facts facts();

    // 基类统一负责，执行器不再各写一遍：
    //  - 阶段切换写日志，并发 Attention 进度事件（"睡觉：到床边了"）
    //  - 调试面板的一句话（阶段名 + 当前子步骤的描述），不再手写 describeCurrentAction
    //  - ProgressMeter：子步骤报告真实进展就续期，停滞超过窗口就以 STALLED 结束
    //  - 被抢占时暂停子步骤；结束时收尾子步骤（归还操作额度、关闭自己开的菜单、松开按键）
    //  - 组装统一回执：outcome + achieved + remaining + blocker + uncertain + attempts + facts
    //  - 汇报可打断程度（03-M6）：默认在阶段之间报 FREE，子步骤处于确认窗口时报 DELICATE
}

/** 阶段的走向。 */
sealed interface Next<P> {
    record Stay<P>() implements Next<P> {}
    record Go<P>(P phase, String why) implements Next<P> {}
    record Done<P>(Outcome outcome) implements Next<P> {}
    record Fail<P>(Blocker blocker) implements Next<P> {}
}
```

行为模型（M2 靠近、M3 操作、M11 菜单、M4 取物差事……）都实现同一个子步骤接口：

```java
/** 一个可逐刻推进、可暂停、能自己收尾的子步骤。 */
public interface Step {
    StepStatus tick(Ctx ctx);   // RUNNING / DONE / FAILED（附 Blocker）
    void pause();               // 被抢占：停下动作，保留进度
    void close();               // 结束：结算回执、释放占用
    String describe();          // 给面板和日志的一句话
}
```

`StepStatus.then(...)` 是一个小语法糖：子步骤还在跑就留在本阶段，失败就把失败原样上抛，完成才执行给定的转移。

### 样例：睡觉执行器的骨架

按 06 规格，只展示结构，不是最终实现。

```java
/** 公开“睡觉”的执行器：选床 -> （没床就放自带床或现做一张）-> 走到床边 -> 躺下。 */
final class SleepExecutor extends PhasedExecutor<SleepExecutor.Phase, SleepRecord> {

    enum Phase { CHOOSE_BED, GET_BED, PLACE_BED, APPROACH, LIE_DOWN }

    private final BedChooser chooser;
    private final Behaviors behaviors;
    private BedChoice bed;                       // 选中的床：世界里原有的，或刚放下的自带床
    private BedSource source = BedSource.WORLD;
    private Step step;                           // 当前阶段的子步骤，由 enter() 创建

    @Override protected void enter(Phase phase) {
        step = switch (phase) {
            case CHOOSE_BED -> null;
            // 身上没床：用身上、随身背包、已知箱子里的材料拿到一张床（M4），优先现成的，其次合成
            case GET_BED -> behaviors.procure().errand(Need.of(ItemTags.BEDS, 1, Purpose.SLEEP));
            // 把床放到站位能看见床头、又不会压到自己的两格上（M2 选位 + M3 放置）
            case PLACE_BED -> behaviors.place().carriedBed(mandate());
            // 走到同时满足服务端床距离盒、交互距离和视线的工位；被挡住时由 M2 换工位
            case APPROACH -> behaviors.reach().approach(Workspot.forBed(bed.head()));
            // 右键床头并确认真的躺下；确认窗口内日期前进，说明一觉睡到了天亮，也算成功（M3）
            case LIE_DOWN -> behaviors.act().use(bed.head(), SleepConfirmation.INSTANCE);
        };
    }

    @Override protected Next<Phase> tick(Phase phase, Ctx ctx) {
        return switch (phase) {
            case CHOOSE_BED -> chooseBed(ctx);
            case GET_BED -> step.tick(ctx).then(() -> {
                source = BedSource.CRAFTED;
                return new Next.Go<>(Phase.PLACE_BED, "拿到了床");
            });
            case PLACE_BED -> step.tick(ctx).then(() -> {
                bed = BedChoice.placedAt(behaviors.place().lastPlaced());
                if (source == BedSource.WORLD) source = BedSource.CARRIED;
                return new Next.Go<>(Phase.APPROACH, "床放好了");
            });
            case APPROACH -> step.tick(ctx).then(() -> new Next.Go<>(Phase.LIE_DOWN, "到床边了"));
            case LIE_DOWN -> lieDown(ctx);
        };
    }

    private Next<Phase> chooseBed(Ctx ctx) {
        // 下界、末地用床会爆炸，这是原版规则：不提问，直接结束并说明
        if (!WorldRules.bedsWork(ctx.level())) return new Next.Fail<>(Blocker.worldRule("这个维度用床会爆炸"));
        Optional<BedChoice> found = chooser.choose(ctx.world(), memory(), mandate(), record().area());
        // 已加载范围分几刻扫完；没扫完不能当成"附近没有床"
        if (found.isEmpty() && !chooser.scanComplete()) return new Next.Stay<>();
        if (found.isPresent()) {
            bed = found.get();
            return new Next.Go<>(Phase.APPROACH, "选中了" + bed.describe());
        }
        // 附近没有能用的床：身上有就放自带的，没有就先去弄一张
        return ctx.inventory().has(ItemTags.BEDS)
                ? new Next.Go<>(Phase.PLACE_BED, "附近没有能用的床，放自带的")
                : new Next.Go<>(Phase.GET_BED, "附近没有床，身上也没有，先弄一张");
    }

    private Next<Phase> lieDown(Ctx ctx) {
        StepStatus status = step.tick(ctx);
        if (status.running()) return new Next.Stay<>();
        if (status.done()) return new Next.Done<>(Outcome.done());
        // 被服务端拒绝时，按提示语分流（完整分流见 06 第 3 节）：被占用就换床，床边有怪交给威胁评估
        return switch (SleepRefusal.of(status)) {
            case OCCUPIED -> { chooser.exclude(bed); yield new Next.Go<>(Phase.CHOOSE_BED, "床被占了，换一张"); }
            case MONSTERS_NEARBY -> new Next.Go<>(Phase.CHOOSE_BED, "床边有怪，重新选床");
            case NOT_NIGHT -> new Next.Fail<>(Blocker.timeWindow(WorldTime.untilSleepable(ctx.level())));
            case OTHER -> new Next.Fail<>(status.blocker());
        };
    }

    @Override protected Facts facts() {
        return new SleepFacts(source, step instanceof NativeUse use && use.coveredByLargerEffect());
    }
}
```

和 v1 的 `SleepCompanionTask` 加上 `AbilityAdapter.sleep()` 对比：瞄准、确认、回执归还、换工位、面板描述、停滞判定、回执组装全都不在这里了；这里只剩"睡觉"这件事本身的流程。

## 4. 决策与执行分开

- **决策类**（`BedChooser`、`Workspot` 的选位、`ThreatAssessment`、`Procurement` 的询价）写成纯函数：输入只读接口（`WorldQuery`、`InventoryView`、`MemoryView`、`MandateView`），输出结论 record。不碰身体，不读 `Minecraft.getInstance()`。
- **执行类**（执行器、子步骤）只负责把结论变成原生操作，并如实对账。
- 好处：决策类可以用替身做离线测试，覆盖率要求 100%；执行类用"子步骤替身"测试（第 8 节）。

## 5. 规则常量

每个会改变角色行为的常量（距离、阈值、上限、窗口），都写成命名常量，并在注释里标明类别与来源：

```java
/** 醒来的实体包和时间包不在同一刻到达，醒后留出的同步窗口。F 游戏事实，来源：122 实机。 */
static final int WAKE_SYNC_TICKS = 200;
```

类别用 03 第 4 节的五类。**v2 不允许出现 P、G、S 类常量**：发现需要它们，说明某个模型有缺陷，应该修模型。

## 6. 每刻预算

昂贵的扫描（找方块、找床、场景感知、路线探测）不得在单刻内跑完，也不得各自实现分帧。统一使用平台层的分帧扫描服务：提交查询，之后每刻查询进度，结果带"是否扫完"。"没扫完"永远不能当成"没有"。

## 7. 日志、面板与事件

- 阶段切换、子步骤开始和结束、阻塞原因，由基类统一记录，同时驱动调试面板和 Attention 进度事件。
- 能力代码里只在出现领域特有的关键事实时才写日志，并使用 `Log.of(能力名)`，不再手写 `[maicraft-sleep]` 这类前缀。

## 8. 测试

| 被测对象 | 写法 |
| --- | --- |
| 决策类 | 用 `FakeWorld`（Map 模拟方块与实体）、`FakeInventory`、`FakeMemory` 构造场景，直接断言结论 |
| 执行器 | 用"子步骤替身"：给 `Behaviors` 注入脚本化的子步骤（"靠近在第 3 刻成功"、"右键被拒，提示语是有怪"），逐刻推进，断言阶段走向、最终回执和事实 |
| 行为模型 | 决策部分同"决策类"；执行部分用平台端口替身（脚本化的回执结果） |
| 能力契约 | 契约快照（WP-2.4） |
| 真实游戏 | 只在实机验收清单里验证，离线测试不模拟 Minecraft 物理 |

- 测试不使用 `Unsafe`，不用反射改私有字段。
- 断言统一用公共 `Check` 工具（WP-1.3），不再每个测试私有一份 `check()`。
- 每个领域规格第 9 节的场景，都要有对应的离线测试或实机验收项。

## 9. 线程

- 所有游戏状态只在客户端线程读写。网络线程只在入口层通过 `onClient` 把请求交给客户端线程（沿用 v1 的做法，它是对的）。
- 禁止自己开线程或使用 `CompletableFuture` 链访问游戏对象。联网资料等确需后台线程的工作，集中放在 `gateway.knowledge`。

## 10. 大小上限

| 对象 | 上限 | 超过怎么办 |
| --- | ---: | --- |
| 类 | 800 行 | 拆阶段或拆决策类；确需例外，登记在 `architecture-exemptions.txt` 并写明理由 |
| 方法 | 80 行 | 拆方法 |
| 执行器的字段 | 15 个 | 阶段私有的数据收进阶段自己的小 record |
| 一个阶段的 `tick` | 40 行 | 说明这个阶段做了不止一件事，再拆 |

## 11. 术语对照（一个概念只有一个名字）

| 中文 | 类名 | 含义 |
| --- | --- | --- |
| 能力 | `AbilityModule` | LLM 能下达的一种意图 |
| 任务单 | `TaskRecord` | 一件具体工作的不可变输入 |
| 执行器 | `PhasedExecutor` | 逐刻做事的对象 |
| 阶段 | `Phase` | 执行器流程中的一段 |
| 子步骤 | `Step` | 行为模型提供的可组合动作 |
| 工位 | `Workspot` | 能对目标做某个动作的站位 |
| 差事 | `Errand` | 为主任务或身体维护顺带做的一件小事（取物、吃饭、睡觉） |
| 需求 | `Need` | 身体维护的一项需要，带紧急程度 |
| 授权 | `Mandate` | 允许伙伴改变世界到什么程度 |
| 句柄 | `Ref` | 观察对象的短期编号（`e12`、`f3`、`b5`） |
| 卡点 | `Blocker` | 任务做不下去的原因，以及解除它需要什么 |
| 结果 | `Outcome` | 统一回执 |
| 事实 | `Facts` | 能力特有的回执字段 |
