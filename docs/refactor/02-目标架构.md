# 02 目标架构（v2）

> 前提：按 [00-全景审查](00-全景审查.md) 的结论，v2 在新仓库从零按本架构建设；v1 冻结维护，作为直播版本和资料来源。

## 1. 设计原则

1. **一样东西只归一个地方。** 一个能力的知识归它自己的包；一条游戏事实归一个实现；一条约束归一条登记过的规则；一项服务归一层。
2. **内核不认识能力。** 调度、目标推进、子任务监护、进度、持久化框架对所有能力一视同仁。能力需要特殊处理时，通过扩展点挂进来，不改内核。
3. **能力是薄的，行为模型是厚的。** "怎么像个人一样靠近、瞄准、拿东西、腾背包、吃饭、看、放弃、求助"写一次，放在行为层；能力只负责"这件事要达成什么、按什么顺序组合行为"。
4. **决策和执行分开。** 决策写成读接口、出结论的纯函数，可以离线测试；执行器只负责把结论变成原生操作，并如实对账。
5. **依赖只往下走，并由构建强制。** 规则写进 `check`，从第一天起严格执行，没有"历史违规基线"。
6. **v2 不含旧代码。** 需要的 v1 代码只能按移植清单显式搬入，并记录来源；其余一律按规格重写。
7. **LLM 看到玩家看到的。** 藏执行细节（路线、点击、槽位），不藏观察事实（是什么、在哪）。
8. **客户端动手，服务端作证。** 角色的一切动作都由客户端以第一人称完成，观众看到的就是它做的；服务端提供权威结果、归属记录和模组数据，但不替角色动手，也不提供透视。

## 2. 分层

```text
L5 bootstrap      启动装配：按已安装模组注册能力模块和联动模块
L4 gateway        对外入口：MCP 传输、对外接口 v2（07）、视图投影、知识库
L3 ability        能力模块：每个能力（或能力族）一个包            L3 integration  联动模组：只实现 SPI
L2 behavior       玩家行为模型 M2–M12（03）+ 步行引擎
L1 kernel         内核：调度仲裁、任务模型、子任务监护、进度表、目标推进、能力注册框架、事件、持久化框架
L0 platform       平台：身体端口、原生操作与回执、菜单端口、世界读取、输入、mixin、与服务端的协议客户端
```

旁路上下文：

| 上下文 | 位置 | 规则 |
| --- | --- | --- |
| 服务端 | `server` | 只依赖 `protocol` 与 Minecraft 服务端；客户端任何层都不直接引用它 |
| 协议 | `protocol` | 客户端与服务端共用的消息定义、版本协商；不依赖任何一侧 |
| 步行引擎 | `behavior.navigation` | 全仓只有 `behavior.navigation.baritone` 可以碰 Baritone 的非 `baritone.api` 包 |
| 调试界面 | `debug` | 只读，可以依赖到 L2；不得被任何层依赖 |

### 依赖规则表

| 谁 | 可以依赖 | 不可以依赖 |
| --- | --- | --- |
| platform | `protocol`、Minecraft 客户端 | 任何上层 |
| kernel | platform | behavior、ability、integration、gateway |
| behavior | kernel、platform | ability、integration、gateway |
| ability.X | behavior、kernel、platform、`ability.Y.api`、`ability.Y.spi` | ability.Y 的内部包、integration、gateway |
| integration.X | behavior、kernel、platform、`ability.*.spi` | 其他 integration、ability 的内部包、gateway |
| gateway | kernel（注册表、事件、目标存储）、behavior（只读视图）、`ability.*.api` | ability 和 integration 的内部包 |
| bootstrap | 全部 | — |
| server | `protocol`、Minecraft 服务端 | 客户端的任何包 |

**Minecraft 客户端的写操作只允许出现在 platform**：`MultiPlayerGameMode`、`ClientPacketListener` 的发送、按键状态、输入驱动。读取类的值类型（`BlockPos`、`BlockState`、`ItemStack`、`Vec3`，以及只读地使用 `LocalPlayer` / `ClientLevel`）各层都可以用。

## 3. 客户端与服务端分工

v1 自 2026-10-04 起已要求服务器安装 MaiCraft，但架构仍按"服务端可选、缺了就回退"组织。v2 把服务端当作必需组件，重新划分职责：

| 事情 | 由谁做 | 说明 |
| --- | --- | --- |
| 角色的一切动作（走、看、点、挖、放、开菜单） | 客户端 | 第一人称原生输入，观众看到的就是它做的 |
| 原生操作的结果确认 | 客户端为主，服务端作旁证 | 客户端照旧"提交 → 对账"；服务端可以回报"这个玩家刚才破坏 / 放置 / 交互了哪一格"，作为权威旁证，用来更快、更确定地结清回执 |
| 方块归属：哪些方块是哪位玩家放的 | 服务端 | 监听放置事件记账；M7 保护判定从"客户端猜测"变成"服务端记录" |
| 模组数据：机器状态、AE2 网络库存与合成作业、Create 动力网络、Mekanism 配置、生产事件 | 服务端 | 客户端读不到或读不准的数据，由服务端读取后回报 |
| 场景感知（M12） | 客户端 | 以玩家视野为准；**服务端不提供透视**：墙后的实体、没去过的地方、别人箱子里的东西都不报 |
| 世界记忆、任务、检查点 | 客户端 | 存在客户端的 SQLite，按世界身份隔离 |

协议沿用 v1 已经成熟的部分（版本协商、能力清单、请求账本、只认已认证连接的玩家身份），只保留必需组件的语义，删除"可选"与客户端回退的双后端结构。

## 5. 核心抽象

以下是接口草图，用来统一执行 Agent 的实现方向。字段名可以在实现时微调，但职责边界不能改。代码层面的写法见 [08-实现规范](08-实现规范.md)。

### 5.1 能力模块：一个能力的唯一入口

```java
/** 一个能力的全部知识都从这里进入；内核和入口只通过它认识能力。 */
public interface AbilityModule {
    AbilityDescriptor descriptor();

    /** 翻译：看现场，决定当前步骤的下一个动作。必须便宜、无副作用，每刻都可能被重复调用。 */
    IntentAction plan(StepContext step);

    /** 本能力的任务单类型和执行器工厂。 */
    default void executors(ExecutorRegistry registry) {}

    /** 本能力对内核扩展点的实现；绝大多数能力用不到。 */
    default StepHooks hooks() { return StepHooks.NONE; }

    /** 本能力需要跨重启保存的步骤私有状态；没有就返回 null。 */
    default StepStateCodec<?> stepState() { return null; }
}

public record AbilityDescriptor(
        String id,                    // "maicraft:sleep"
        String summary,               // 能力目录里的一句话用途
        ContractText contract,        // 契约正文，从 assets/maicraft/abilities/<名>.md 读取
        ParamSpec params,             // 参数的唯一定义：生成字段说明、校验、规范化、产出类型化参数
        Set<TargetKind> targets,      // 允许的 target.kind（07 第 4 节）
        ExecutionMode mode,           // BODY / READ_ONLY / LOCAL_MEMORY
        Set<Requirement> requires,    // 需要哪些联动能力；有提供方才算可用
        List<String> knowledgeRefs,   // 相关知识条目
        Visibility visibility) {}     // 是否在能力目录里默认展示
```

能力 ID 字面量只允许出现在本能力的包里（以及测试和契约资源）。其他地方需要"某类能力"时，查描述符上的属性，不比对 ID。

### 5.2 参数规格：契约、校验、规范化同出一源

```java
static final ParamSpec PARAMS = ParamSpec.of(
        param("item", ParamType.ITEM_OR_TAG).required().doc("要多拿的物品或标签"),
        param("count", ParamType.INT).range(1, 256).defaultValue(1).doc("要再多几件，不是最终持有数"));

/** 类型化参数：翻译和执行器只用它，不自己解析 JSON。 */
record ObtainParams(ItemOrTag item, int count) {
    static ObtainParams from(ParsedParams p) { return new ObtainParams(p.itemOrTag("item"), p.integer("count")); }
}
```

- 字段说明由 `ParamSpec` 生成；契约正文只写"做什么、怎样算完成、回执怎么读"。
- 参数名只能取自 07 第 5 节的词汇表。
- 宽松写法（`"6"` → `6`）由入口统一处理并写进 `notes`；其余严格校验，一次报全。

### 5.3 翻译结果 `IntentAction`

```java
sealed interface IntentAction {
    enum Pending implements IntentAction { INSTANCE }
    record Report(Outcome outcome) implements IntentAction {}
    record Run(TaskRecord record, boolean reobserveAfterSuccess) implements IntentAction {}
    /** 一组按顺序执行的动作；每个任务单到它执行时才构造，保证期限和副作用顺序正确。 */
    record Chain(List<Supplier<TaskRecord>> steps) implements IntentAction {}
    record Ask(Decision decision) implements IntentAction {}       // 只用于 03-M8 允许的三种提问
    record Remember(String name, WorldPosition position) implements IntentAction {}
    record Wait(Condition condition, long notBeforeTick) implements IntentAction {}
}
```

### 5.4 内核扩展点：任务单特征接口 + 能力钩子

`GoalRunner` 不对具体任务单类型做 `instanceof`，也不比对能力 ID。它只认两种东西：

**(a) 任务单特征接口**：任务单声明自己具备某种通用特征，内核按特征处理。

```java
/** 子任务确认了一个位置，后续步骤可以引用（target.kind = previous）。 */
interface ReportsVerifiedPosition { Optional<WorldPosition> verifiedPosition(); }
/** 子任务登记了自己施工或搭建的区域，后续步骤要避开。 */
interface ReportsProtectedArea { List<AreaProtection> protectedAreas(); }
/** 子任务有单次原生消费，必须绑定父任务的持久身份，防止重启后重复消费。 */
interface OneShotSubmission { void bindTo(SubmissionIdentity identity); }
```

**(b) 能力钩子**：只有能力自己知道的特殊处理。

```java
public interface StepHooks {
    StepHooks NONE = new StepHooks() {};
    /** 子任务启动前：把步骤级记忆（例如"本步开始时已有几件"）交给子任务单。 */
    default void beforeChild(StepContext step, TaskRecord child) {}
    /** 子任务运行中：子任务发现了需要调用方选择的情况时，返回提问。 */
    default Optional<IntentAction.Ask> duringChild(StepContext step, TaskRecord child) { return Optional.empty(); }
    /** 子任务结束：可以补充回执，或给出替代动作。 */
    default ChildOutcome afterChild(StepContext step, TaskRecord child, Outcome outcome) { return ChildOutcome.accept(outcome); }
}
```

钩子是例外通道。每加一个钩子实现，都要在领域规格里说明为什么行为模型解决不了。

### 5.5 子任务监护、进度表、身体仲裁

- **`ChildSupervisor`**：子任务的创建、启动、逐刻推进、截止检查、异常捕获、停止转发、收结果、松手，全仓只写这一次。
- **`ProgressMeter`**：真实进展就续期，停滞超过窗口才算卡住；暂停与被抢占的时间不计。
- **`BodyArbiter`**：需求有紧急程度（COMFORT / HARMFUL / LETHAL），任务此刻有可打断程度（FREE / BUSY / DELICATE）；唯一规则是"LETHAL 打断一切，HARMFUL 打断 FREE 与 BUSY，COMFORT 只在 FREE 时插入"（03-M6）。**没有第二个身体使用者**：v1 里绕过仲裁的随行补光，在 v2 中作为一种需求参与仲裁。

### 5.6 服务注入

```java
public record RuntimeServices(
        GoalStore goals,            // 任务表、请求键
        AttentionBus events,        // 事件
        WorldMemory memory,         // 世界记忆（M9）
        Scene scene,                // 场景感知（M12）
        Mandate mandate,            // 当前授权（M7）
        ServerLink server,          // 服务端旁证、归属、模组数据
        StateStore state,           // 检查点与持久化
        AbilityRegistry abilities) {}
```

执行器和行为模型从构造函数拿到服务。不写 `X.get()` 单例，不写 `static` 可变字段。

### 5.7 联动 SPI

| SPI | 定义在 | 实现方 |
| --- | --- | --- |
| `MaterialSource` | `behavior.procure.spi` | 背包、容器记忆、合成、烧炼、采掘、收获、狩猎、交易（行为层自带）；随身背包、AE2（联动） |
| `TravelProvider` | `behavior.travel.spi` | 步行（行为层自带）；喷气背包、飞行器、Create 电梯、传送门、船（联动） |
| `ObstacleProvider` | `behavior.navigation.spi` | 物理结构（联动） |
| `BreakAccelerator` | `behavior.act.spi` | FTB Ultimine（联动） |
| `MachineTypeProvider` | `ability.machine.spi` | Create、Mekanism、AE2（联动） |
| `KnowledgeSource` | `gateway.knowledge` | 原版、配方、FTB 任务、Ponder、Wiki |

`bootstrap` 按模组是否安装注册实现；能力是否可用，由它声明的 `requires` 是否有提供方决定。

## 8. 持久化

- 沿用 v1 的 SQLite 底座（按分区、世界身份、文档键存文档；WAL；消费前强制落盘）。数据文件与 v1 分开存放，互不覆盖。
- 每种文档有版本号；能力私有的步骤状态由各能力的 `StepStateCodec` 负责。
- **v2 不读取 v1 的任务检查点**。提供一次性导入工具，把 v1 的地标、蓝图、机器档案导入 v2。
